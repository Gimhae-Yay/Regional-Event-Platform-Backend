# 로컬스탬프 MVP 페르소나

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.1 |
| 최종 수정일 | 2026-07-23 |
| 기준 문서 | [로컬스탬프 MVP PRD](local-stamp-platform-prd.md) |
| 대상 릴리스 | 김해시·동해시 2개 지역 무료 예약 MVP |

## 1. 페르소나 활용 원칙

이 문서는 김해시와 동해시에서 **지역 콘텐츠 탐색 → 무료 예약 → 현장 체크인 → 인증 후기** 흐름을 검증하는 초기 MVP의 사용자와 운영 주체를 정의한다.

- MVP의 최우선 방문자는 **주말 나들이 방문자**, 최우선 공급자는 **예약형 행사·체험 운영자**다.
- 지역 주민·재방문 사용자는 방문자와 같은 무료 예약·체크인 흐름을 이용하는 보조 방문자 페르소나다.
- 지역 관리자와 전체 관리자는 구매 고객이 아니라 지역 권한과 파일럿 운영을 가능하게 하는 필수 운영 주체다.
- 가게·관광지의 비예약형 현장 인증, 유료 예약·결제, 쿠폰, 스탬프북, 지역 미션, 추천 코스, 개인화 추천, 고도화된 통계 대시보드는 초기 MVP 페르소나의 핵심 기대에서 제외한다.

## 2. 주말 나들이 방문자 — 김서연, 29세

- **직업/상황:** 직장인. 주말마다 친구·연인과 다른 지역의 행사나 체험을 찾으며, 김해시·동해시처럼 익숙하지 않은 지역에서도 반나절 또는 하루 일정을 계획한다.
- **목표:** 믿을 만한 행사·체험을 한곳에서 비교하고, 실제 예약 가능 여부를 확인해 방문까지 확실히 마치고 싶다.
- **현재 행동:** SNS, 지도 앱, 지역 커뮤니티를 오가며 정보를 수집하고 별도 예약 링크나 전화로 신청한다. 현장에서는 문자나 예약자 명단으로 참가 여부를 확인한다.
- **핵심 불편:**
  - 행사 정보, 회차, 잔여 정원과 신청 방법이 여러 채널에 흩어져 있다.
  - 예약 신청과 확정 여부가 명확하지 않거나 현장 확인 절차가 번거롭다.
  - 실제 방문자가 작성했는지 알 수 없는 후기는 신뢰하기 어렵다.
- **MVP 기대:**
  - 지역별 행사·체험 목록과 유형·예약 가능 여부 필터
  - 위치, 운영 시간, 유의사항, 회차, 잔여 정원, 취소 기준과 인증 후기를 포함한 상세 정보
  - 10분 동안 정원이 보장되는 무료 예약과 명확한 확정·취소 상태
  - 확정된 예약에 연결된 일회성 QR과 빠른 현장 체크인
  - 체크인한 방문자만 작성할 수 있는 별점·텍스트 후기
- **핵심 이용 흐름:** 공개 지역 선택 → 행사·체험 탐색 → 회차·인원 선택 → 10분 홀드 내 무료 예약 확정 → 예약 QR 제시 → 체크인 → 인증 후기 작성
- **성공 판단:** 원하는 콘텐츠를 찾은 뒤 다른 도구로 이동하지 않고 예약과 체크인을 완료하며, 예약·QR 상태를 스스로 이해할 수 있다.
- **대표 문장:** “어디를 가야 할지부터 남은 자리와 예약 확정 여부까지 한 번에 알고 싶어요.”

## 3. 지역 주민·재방문 사용자 — 이민호, 35세

- **직업/상황:** 김해시 또는 동해시 거주자. 가족과 함께할 주말 활동을 자주 찾지만 익숙한 지역의 새 프로그램을 제때 발견하기 어렵다.
- **목표:** 가까운 곳에서 열리는 새로운 행사·체험을 발견하고 가족 일정에 맞는 회차를 안정적으로 예약하고 싶다.
- **현재 행동:** 지역 커뮤니티, 지인 추천과 기관 SNS를 참고하고 아이의 연령, 준비물과 이동 시간을 직접 확인한다.
- **핵심 불편:**
  - 지역 행사를 늦게 알거나 신청 채널을 찾지 못한다.
  - 가족이 참여할 수 있는 조건과 남은 정원을 한 번에 비교하기 어렵다.
  - 한 번 참여한 뒤 비슷한 새 콘텐츠를 다시 찾기 어렵다.
- **MVP 기대:**
  - 선택한 지역의 공개 행사·체험을 한곳에서 확인
  - 연령, 준비물, 회차, 잔여 정원과 취소 기준을 예약 전에 확인
  - 무료 예약, QR 체크인과 인증 후기까지 일관된 이용 경험
- **핵심 이용 흐름:** 지역 홈 → 행사·체험 탐색 → 가족에게 맞는 회차 선택 → 무료 예약 → 현장 QR 체크인 → 인증 후기 작성
- **성공 판단:** 지역 기관이나 운영자의 여러 채널을 따로 확인하지 않고 새로운 콘텐츠를 발견해 실제 참여까지 완료한다.
- **대표 문장:** “우리 동네의 새 프로그램을 놓치지 않고, 가족이 갈 수 있는 시간과 자리를 바로 확인하고 싶어요.”

## 4. 예약형 행사·체험 운영자 — 최도윤, 38세

- **직업/상황:** 공방 클래스, 투어, 플리마켓, 공연 등 회차와 정원이 있는 지역 프로그램을 기획·운영한다.
- **목표:** 콘텐츠 등록, 회차별 예약자 관리와 현장 참가 확인을 하나의 흐름으로 처리하고 싶다.
- **현재 행동:** SNS로 홍보하고 전화·메신저·폼으로 신청을 받은 뒤 스프레드시트에 명단을 옮긴다. 현장에서는 수기 명단이나 메시지로 참가 여부를 확인한다.
- **핵심 불편:**
  - 신청, 명단 관리와 현장 확인이 분리되어 누락과 중복 처리가 발생한다.
  - 회차별 정원 초과, 취소, 노쇼를 일관된 상태로 관리하기 어렵다.
  - 예약자와 실제 참가자를 구분하거나 인증 후기를 연결하기 어렵다.
- **MVP 기대:**
  - 지역 관리자에게 콘텐츠·회차 등록 및 수정 승인을 요청하는 표준 절차
  - 10분 홀드와 확정 예약을 반영한 정확한 회차별 정원
  - 자신에게 연결된 콘텐츠의 예약자만 조회하는 소유권 경계
  - 이름 `김*수`, 연락처 `010-****-1234` 형식으로 마스킹된 최소 예약자 정보
  - 일회성 QR 스캔, 중복 체크인 방지와 예약 번호 보조 조회
  - QR 예외 처리의 사유·처리자·시각 기록
- **핵심 이용 흐름:** 운영자 승인 → 콘텐츠·회차 등록 요청 → 지역 관리자 승인 → 예약자 확인 → 현장 QR 체크인 → 예외 기록 → 인증 후기 확인
- **성공 판단:** 초과 예약이나 중복 방문 기록 없이 담당 회차의 예약자와 실제 참가자를 구분하고, 현장 예외를 추적 가능한 방식으로 처리한다.
- **대표 문장:** “신청자 명단과 현장 참가자를 따로 대조하지 않고, 담당 회차만 정확하게 관리하고 싶어요.”

## 5. 지역 관리자 — 박지은, 42세

- **직업/상황:** 김해시 또는 동해시의 관광재단, 문화재단, 상인회나 지역 활성화 운영사에서 지역 콘텐츠와 운영자를 관리한다.
- **목표:** 담당 지역의 운영자와 콘텐츠 공개 품질을 통제하고, 예약·QR 현장 문제를 최소 운영 도구로 처리하고 싶다.
- **현재 행동:** 사업자 정보와 콘텐츠를 문서·메신저로 전달받아 검토하고, 담당자별 스프레드시트로 승인 결과와 현장 이슈를 관리한다.
- **핵심 불편:**
  - 사업자, 담당 지역과 콘텐츠 소유 관계를 일관되게 확인하기 어렵다.
  - 콘텐츠의 승인·반려·공개·종료 상태와 처리 이력이 여러 문서에 흩어진다.
  - QR 실패나 예약자 보조 확인 같은 현장 예외의 원인과 처리 결과가 남지 않는다.
- **MVP 기대:**
  - 사업자 정보·담당 지역·콘텐츠 소유 관계 확인을 통한 운영자 수동 승인
  - 담당 지역 콘텐츠의 승인·반려, 공개·비공개 전환, 종료 및 소프트 삭제 관리
  - 반려와 예외 처리의 사유·처리자·시각을 남기는 감사 이력
  - QR 실패와 예약 번호 보조 조회 내역을 사유별로 확인할 수 있는 보호된 최소 화면 또는 API
  - 김해시와 동해시 사이의 데이터·권한 교차 접근 차단
- **핵심 이용 흐름:** 운영자 자격·소유 관계 확인 → 운영자 승인 → 콘텐츠 검토·승인/반려 → 공개·종료 상태 관리 → QR 예외 조회 → 필요 시 전체 관리자에게 에스컬레이션
- **성공 판단:** 다른 지역 데이터에 접근하지 않은 채 담당 지역의 승인과 핵심 현장 예외를 처리하고, 모든 조치의 근거를 사후 확인할 수 있다.
- **대표 문장:** “담당 지역의 공개 기준과 현장 예외를 통제하되, 누가 왜 처리했는지 반드시 남아야 해요.”

## 6. 전체 관리자 — 정현우, 40세

- **직업/상황:** 로컬스탬프 플랫폼의 초기 파일럿 운영과 공통 정책을 책임진다.
- **목표:** 김해시와 동해시의 데이터 경계를 유지하면서 지역과 역할을 설정하고, 지역 수준에서 해결할 수 없는 문제를 통제하고 싶다.
- **현재 행동:** 지역별 담당자와 운영 기준을 문서로 관리하고 권한 요청이나 운영 이슈를 개별적으로 조정한다.
- **핵심 불편:**
  - 지역 생성, 관리자 역할 부여와 공통 정책 변경의 책임 경계가 불명확할 수 있다.
  - 지역 관리자의 권한을 벗어난 이슈가 일관된 경로로 전달되지 않는다.
  - 파일럿 지역별 기술 검증 결과와 실패 원인을 같은 기준으로 비교하기 어렵다.
- **MVP 기대:**
  - 지역 생성과 지역 관리자·운영자 역할 부여
  - 공통 운영 기준과 지역 권한 경계 관리
  - 지역 관리자가 에스컬레이션한 운영 예외 확인
  - 홀드·예약·체크인·후기 상태 전이와 실패 원인을 지역·콘텐츠·회차별로 재현할 수 있는 로그
- **핵심 이용 흐름:** 지역 생성 → 지역 관리자 역할 부여 → 공통 운영 기준 설정 → 에스컬레이션 확인 → 기술 검증 결과 점검
- **성공 판단:** 두 파일럿 지역의 권한과 데이터가 분리되고, 동일한 기준으로 핵심 상태 전이와 운영 예외를 검증할 수 있다.
- **대표 문장:** “두 지역이 같은 운영 기준을 따르면서도 서로의 데이터에는 접근하지 못해야 해요.”

## 7. MVP 우선 타깃과 검증 흐름

### 7.1 우선순위

| 구분 | 대상 | MVP에서 검증할 가치 |
|---|---|---|
| 최우선 방문자 | 주말 나들이 방문자 | 낯선 지역의 콘텐츠 발견이 무료 예약과 실제 체크인으로 이어지는가 |
| 보조 방문자 | 지역 주민·재방문 사용자 | 익숙한 지역에서도 새 콘텐츠를 발견해 같은 예약·체크인 흐름을 이용하는가 |
| 최우선 공급자 | 예약형 행사·체험 운영자 | 회차·정원·예약자·현장 참가를 하나의 흐름으로 정확히 관리할 수 있는가 |
| 필수 운영 주체 | 지역 관리자 | 지역별 운영자·콘텐츠 승인과 QR 예외 처리를 권한 범위 안에서 수행할 수 있는가 |
| 공통 운영 주체 | 전체 관리자 | 지역·역할·공통 기준을 설정하고 다지역 격리를 유지할 수 있는가 |

### 7.2 핵심 검증 흐름

**운영자·콘텐츠 승인 → 방문자의 지역별 탐색 → 10분 정원 홀드와 무료 예약 확정 → 일회성 QR 체크인 → 체크인에 연결된 인증 후기 → 지역별 상태·예외 검증**

이 흐름에서는 다음 결과를 우선 확인한다.

- 마지막 잔여 정원에 동시 요청이 발생해도 초과 예약이 없다.
- 만료된 홀드, 취소된 예약, 다른 회차 QR과 권한 없는 체크인을 거부한다.
- 같은 예약 확정 또는 QR 체크인 요청을 반복해도 결과가 중복 생성되지 않는다.
- 운영자와 지역 관리자는 담당 콘텐츠·지역 밖의 데이터에 접근할 수 없다.
- 운영자에게 보이는 예약자 이름과 연락처는 확정된 형식으로 마스킹된다.
- 체크인 완료 방문당 후기 한 건만 작성할 수 있으며, 작성 후 30일 동안 수정하고 언제든 삭제할 수 있다.

## 8. 후속 MVP에서 다시 검토할 기대

## 9. 체크인 요청 멱등성

체크인 요청 멱등성은 별도 HTTP 엔드포인트가 아니다.
두 체크인 명령의 `Idempotency-Key` 헤더와 MySQL `idempotency_record`로 네트워크 재시도 결과 재생과 중복 방문 방지를 보장한다.

### 적용 API

| 명령 | 경로 | `operation` |
| --- | --- | --- |
| QR 검증·체크인 | `POST /operator/check-ins` | `CHECK_IN` |
| 예약번호 보조 체크인 | `POST /operator/check-ins/manual` | `CHECK_IN` |

QR 발급·조회와 지역 관리자 QR 예외 조회에는 이 멱등 계약을 적용하지 않는다.

### 요청 식별자 계약

| 항목 | 계약 |
| --- | --- |
| 전달 위치 | `Idempotency-Key` 요청 헤더 |
| 도메인 의미 | 한 번의 체크인 시도를 식별하는 `checkInRequestId` |
| 필수 여부 | 두 체크인 명령에서 필수 |
| 재사용 | 통신 실패로 같은 명령을 재전송할 때만 같은 값을 사용 |
| 새 값 | 새로운 QR 스캔 또는 별도 보조 체크인 시도에는 새 값을 사용 |
| 논리 유일 범위 | `(actor_user_id, operation = CHECK_IN, idempotency_key_hash)` |

### 요청 해시

1. `request_hash`는 개인정보 원문을 제외하고 체크인 방식과 정규화된 명령 의미를 포함해 계산한다.
2. QR 체크인은 QR 토큰 원문을 저장하지 않고 토큰의 암호학적 다이제스트와 `QR` 방식을 해시에 반영한다.
3. 보조 체크인은 조회한 예약 식별자, `RESERVATION_NUMBER` 방식과 확인 사유를 해시에 반영한다. 예약번호 원문은 저장하지 않는다.
4. 같은 키를 다른 토큰, 예약, 회차, 체크인 방식 또는 사유에 사용하면 `409 IDEMPOTENCY_KEY_CONFLICT`로 거부한다.

### 처리 상태별 계약

| 상태 | 같은 키·같은 요청 처리 | 결과 참조 |
| --- | --- | --- |
| `PROCESSING` | 새 도메인 작업을 실행하지 않고 `409 IDEMPOTENCY_REQUEST_IN_PROGRESS` 반환 | 없음 |
| `SUCCEEDED` | 예약 상태와 QR 현재 만료를 다시 검증하지 않고 저장된 최초 성공 응답 반환 | `result_visit_id` 필수 |
| `FAILED` | API 명세에서 저장 대상으로 정한 결정적 실패의 저장 결과 코드 재반환 | 결과 FK 없음, `result_code` 사용 |

같은 키와 다른 요청 해시는 저장 상태와 관계없이 `409 IDEMPOTENCY_KEY_CONFLICT`다.

### 네트워크 재시도와 새로운 스캔

1. 동일 `Idempotency-Key`와 동일 요청은 최초 명령의 네트워크 재시도다. QR 토큰이 재시도 시점에 만료됐더라도 완료 결과를 재생한다.
2. 다른 `Idempotency-Key`의 QR 요청은 새로운 스캔이다. 토큰 형식·서명·만료, 체크인 창, 활성 회원 연결, 예약·회차 상태와 현재 운영자 권한을 모두 다시 검증한다.
3. 유효한 새로운 스캔에서 같은 예약의 기존 방문이 확인되면 새 방문을 만들지 않고 기존 방문을 결과로 반환한다.
4. 서로 다른 성공 멱등 기록이 같은 `visit`을 참조할 수 있으므로 `result_visit_id`에는 유일 제약을 두지 않는다.
5. 만료·무권한·상태 충돌인 새로운 스캔은 기존 방문이 있어도 성공 결과로 대체하지 않는다.

### 원자성과 실패

- 멱등 키 점유, 예약 상태 전이, 방문 생성, 성공 결과 참조와 성공 감사 이벤트는 하나의 MySQL 트랜잭션에서 커밋한다.
- `visit.reservation_id` 유일 제약과 예약 `CONFIRMED → CHECKED_IN` 조건부 전이로 다른 멱등 키의 동시 요청도 방문 한 건만 만들 수 있다.
- 상태 충돌처럼 같은 현재 상태에서 재시도해도 결과가 바뀌지 않는 실패는 `FAILED`와 `result_code`로 저장할 수 있으며 각 체크인 API의 오류 표를 따른다.
- 입력·인증·인가·대상 부재 오류와 트랜잭션 롤백이 필요한 일시적 서버 오류는 성공 결과로 기록하지 않는다.
- 실제 멱등 기록 보관 기간은 허용할 최대 네트워크 재시도 기간을 포함하도록 출시 전 운영 설정으로 확정한다.

### 보안 및 개인정보

- 멱등 키 원문은 저장하지 않고 해시만 저장한다.
- `request_hash`와 저장 응답에는 QR 토큰, `qr_reference`, 예약번호, 이름·연락처와 사용자 식별자 원문을 포함하지 않는다.
- 탈퇴 처리 시 사용자 기반 멱등 키와 actor 연결을 제거하고 비개인 결과 참조만 보존한다.

# 웹 프런트엔드

| 항목 | 내용 |
| --- | --- |
| 상위 명세 | [로컬스탬프 P2 명세](../p2-spec.md) |
| 참고 문서 | [로컬스탬프 제품 PRD](../local-stamp-platform-prd.md) |
| 소유 범위 | 방문자·운영자·관리자 웹 화면, API 연동, 역할별 접근 흐름 |

> P2의 프런트엔드 채널은 웹으로만 제작한다. 네이티브 모바일 앱은 이 문서의 범위에 포함하지 않는다.

## 1. 범위

### P2-FR-07. 웹 프런트엔드

- 방문자는 웹에서 지역 탐색, 예약·방문·후기, 스탬프·미션·쿠폰, 결제·환불과 신고 관련 기능을 이용한다.
- 콘텐츠 운영자와 지역 관리자, 전체관리자는 웹에서 자신에게 허용된 운영 기능을 이용한다.
- 웹 화면은 P0~P2에서 확정된 API 계약을 사용하고, 권한·상태·오류 판단을 임의로 재정의하지 않는다.
- 모바일 웹을 포함한 브라우저 사용성, 접근성, 인증 상태 유지와 오류 안내의 기준은 구현 전에 확정한다.

## 2. 유저 시나리오

### US-P2-04. 방문자가 웹에서 지역 참여 흐름을 이용한다

- **주체:** 방문자
- **목표:** 별도 앱 설치 없이 브라우저에서 탐색부터 예약·방문 이후 혜택과 후기 관리까지 이용한다.
- **선행 조건:** 공개 지역과 필요한 P0·P1 API 계약이 제공된다.

#### 기본 흐름

1. 방문자가 웹에서 공개 지역과 콘텐츠를 탐색한다.
2. 로그인한 방문자는 예약·QR·방문 기록과 본인 혜택·결제·환불을 확인한다.
3. 방문자는 인증 후기, 신고, 내 신고 상태와 지역 후기 피드를 이용한다.
4. 웹은 API 응답의 상태와 오류 코드를 사용자에게 이해 가능한 방식으로 표시한다.
5. 권한이 없는 경로·기능은 웹에서 안내하되, 서버 요청도 동일하게 거부된다.

#### 예외 흐름

- 세션 만료·권한 변경·네트워크 실패 시 웹은 민감 데이터를 화면이나 저장소에 남기지 않고 재인증 또는 재시도 안내를 제공한다.
- 동일 쓰기 요청의 중복 전송은 서버 멱등성 계약을 따르며, 화면은 처리 중 상태를 명확히 표시한다.
- 웹 주소를 직접 입력하거나 요청을 변조해도 서버 권한 검증을 우회할 수 없다.

**적용 정책:** `WEB-01`~`WEB-04`

### US-P2-05. 운영 주체가 웹에서 담당 범위를 운영한다

- **주체:** 콘텐츠 운영자, 지역 관리자, 전체관리자
- **목표:** 담당 범위의 콘텐츠·혜택·거래·후기·통계 기능을 브라우저에서 안전하게 사용한다.
- **선행 조건:** 역할, `region_id`, 콘텐츠 소유 관계와 API 권한 계약이 확정돼 있다.

#### 기본 흐름

1. 운영 주체가 웹에 로그인하면 역할별 허용 기능으로 이동한다.
2. 웹은 담당 지역·콘텐츠 범위의 목록, 상세와 작업 화면을 제공한다.
3. 운영 주체가 공개·종료·답글·환불 재처리·신고 조치 등 보호된 작업을 요청한다.
4. 서버가 권한·상태·입력을 검증한 결과를 웹이 표시한다.
5. 웹은 성공 결과의 처리 시각·상태와 실패 결과의 공개 오류 정보를 제공한다.

#### 예외 흐름

- 웹 화면에 표시된 권한과 현재 서버 권한이 다르면 서버 결과를 우선한다.
- 다른 지역·콘텐츠 식별자를 조작한 요청은 서버가 거부하고 웹은 상세 데이터를 노출하지 않는다.
- 특권 변경·거래 수동 처리처럼 확인 절차가 필요한 동작은 확정된 사용자 경험과 감사 계약 없이 제공하지 않는다.

**적용 정책:** `WEB-01`~`WEB-04`

## 3. 웹 프런트엔드 정책

- `WEB-01`:
  P2 프런트엔드는 웹 브라우저를 유일한 사용자 채널로 한다.
  방문자·운영자·관리자 화면의 정확한 우선순위와 출시 단위는 P0~P2 API 준비 상태에 따라 구현 백로그로 확정한다.
- `WEB-02`:
  웹은 [API 명세서](../api-specification.md)의 요청·응답·오류 계약을 소비한다.
  클라이언트 상태는 서버가 반환한 최종 상태를 기준으로 갱신하며, 서버 API의 권한·유효성·멱등성 검증을 대체하지 않는다.
- `WEB-03`:
  인증 정보, 개인정보, 결제 비밀값, QR 원문과 내부 오류 상세는 브라우저 화면·로그·분석 도구에 불필요하게 저장하거나 노출하지 않는다.
  인증 토큰 보관 방식, 세션 만료 처리, 브라우저 보안 정책은 기술 결정으로 확정한다.
- `WEB-04`:
  화면은 키보드 사용, 명확한 입력 오류, 로딩·재시도 상태, 작은 화면에서의 사용성과 색상 외 정보 전달을 고려한다.
  구체적인 접근성 수준, 지원 브라우저와 반응형 기준은 구현 전에 확정한다.

## 4. 구현 전 확정 항목

| 항목 | 확정할 내용 |
| --- | --- |
| 기술 구성 | 프레임워크, 상태 관리, 빌드·배포 방식, 백엔드와 저장소 경계 |
| 인증 처리 | 토큰·세션 보관, 갱신·만료, 로그아웃, 브라우저 보안 정책 |
| 화면 범위 | P0·P1·P2 기능별 방문자·운영자·관리자 화면 우선순위와 출시 기준 |
| 접근성·반응형 | 지원 브라우저, 화면 크기, 키보드·스크린리더·오류 안내 기준 |
| 관측 | 프런트 오류·성능 수집 범위와 개인정보·결제 정보 제외 기준 |

## 5. 데이터·연동 요구사항

| 대상 | 핵심 연동 정보 | 용도 |
| --- | --- | --- |
| 인증·인가 API | 로그인 상태, 역할, 허용 범위, 공개 오류 코드 | 역할별 화면·경로 제어 |
| P0·P1 도메인 API | 콘텐츠·예약·방문·후기·혜택·거래 상태 | 방문자·운영 기능 |
| P2 도메인 API | 대시보드, 신고·조치, 답글, 지역 후기 피드 | 운영·후기 확장 기능 |
| 웹 오류·관측 | 요청 식별자, 공개 오류 코드, 성능 정보 | 사용자 안내와 장애 추적 |

웹 자체의 영속 데이터가 필요해지면 목적·보관 기간·개인정보 영향과 함께 [ERD](../erd.md)에 먼저 확정한다.

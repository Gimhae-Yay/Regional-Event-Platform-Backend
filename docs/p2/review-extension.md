> 이 문서는 P2 후기 확장의 기능 계약을 정의한다. P0 후기의 작성 자격·수정·삭제·원문 파기 규칙은 유지한다.

## 1. 범위

### P2-FR-03. 후기 신고·내 처리 상태

- 방문자는 공개 후기를 신고하고 본인 신고의 처리 상태를 조회한다.
- 신고는 후기 원문과 별도로 보관하며, 신고자와 신고 내용은 공개 피드나 무관한 운영 화면에 노출하지 않는다.

### P2-FR-04. 신고 검토·조치

- 권한 있는 검토자는 담당 범위의 신고를 검토하고 조치·사유·처리 이력을 기록한다.
- 조치가 후기 공개 상태에 영향을 주는 경우에도 원인과 처리 경로를 재현할 수 있어야 한다.

### P2-FR-05. 후기 답글

- 권한 있는 콘텐츠 운영 주체는 담당 콘텐츠의 공개 후기에서 답글을 작성·수정·삭제한다.
- 답글의 작성자, 대상 후기와 변경 이력을 보존한다.

### P2-FR-06. 지역별 후기 피드

- 방문자는 지역별 공개 후기 피드를 조회한다.
- 삭제·비공개 또는 확정된 조치 기준에 맞지 않는 후기는 피드에서 제외한다.

## 2. 유저 시나리오

### US-P2-02. 방문자가 부적절한 후기를 신고하고 처리 상태를 확인한다

- **주체:** 방문자
- **목표:** 공개 후기의 문제를 신고하고 자신의 요청이 어떻게 처리됐는지 확인한다.
- **선행 조건:** 신고 대상 후기가 공개 조회 가능한 상태다.

#### 기본 흐름

1. 방문자가 후기 상세 또는 피드에서 신고 사유를 선택·입력한다.
2. 시스템은 신고 대상의 공개 상태와 신고자 권한을 검증한다.
3. 시스템은 신고 이력을 저장하고 신고자에게 접수 상태를 제공한다.
4. 방문자는 내 신고 목록에서 대상 후기와 본인 신고의 최신 처리 상태를 확인한다.
5. 권한 있는 검토자가 신고를 검토하고 조치·사유를 기록하면 상태가 갱신된다.

#### 예외 흐름

- 다른 사용자의 신고 상세 또는 증빙은 조회할 수 없다.
- 같은 신고의 반복 전송은 중복 접수 이력을 만들지 않는다.
- 이미 삭제된 후기나 검토 종결된 신고의 처리 방식은 확정된 정책에 따라 안내한다.

**적용 정책:** `REVX-01`~`REVX-03`

### US-P2-03. 콘텐츠 운영 주체가 담당 후기에 답글을 관리한다

- **주체:** 권한 있는 콘텐츠 운영 주체
- **목표:** 담당 콘텐츠의 공개 후기에 책임 범위 안에서 답글을 남긴다.
- **선행 조건:** 대상 후기가 공개 상태이며 답글 작성 권한이 부여돼 있다.

#### 기본 흐름

1. 운영 주체가 담당 콘텐츠의 후기에서 답글 작성을 요청한다.
2. 시스템은 콘텐츠 소유 관계, 지역 권한과 대상 후기의 상태를 검증한다.
3. 시스템은 답글과 작성자·시각을 저장해 후기와 연결한다.
4. 작성자는 허용된 범위에서 답글을 수정하거나 삭제한다.
5. 방문자는 지역 후기 피드 또는 후기 상세에서 공개 가능한 답글을 확인한다.

#### 예외 흐름

- 담당하지 않은 콘텐츠·지역의 후기에는 답글을 작성·수정·삭제할 수 없다.
- 삭제되거나 비공개가 된 후기의 답글 처리 방식은 확정된 수명주기 규칙을 따른다.
- 답글 중복, 후기당 답글 수, 수정·삭제 후 노출은 구현 전 확정된 정책 없이 임의로 처리하지 않는다.

**적용 정책:** `REVX-04`, `REVX-05`

## 3. 후기 확장 정책

- `REVX-01`:
  신고는 신고자, 대상 후기, 사유와 접수 시각을 연결한 별도 이력이다.
  신고 접수 자체가 후기 공개 상태를 자동 변경하는지 여부와 신고 사유·중복 기준은 구현 전 확정한다.
- `REVX-02`:
  신고자는 본인이 접수한 신고의 처리 상태와 공개 가능한 결과만 조회한다.
  검토자 정보, 다른 신고자 정보, 내부 증빙과 비공개 검토 메모는 권한 없는 사용자에게 노출하지 않는다.
- `REVX-03`:
  검토·조치는 권한 있는 담당자와 담당 지역 범위에서만 수행한다.
  조치 유형, 사유, 처리자, 시각, 대상 후기의 변경 전후 상태를 남기며, 원후기 원문을 감사 이력으로 복제하지 않는다.
- `REVX-04`:
  답글은 대상 후기, 작성자, 콘텐츠·지역 소유 관계를 연결한다.
  작성·수정·삭제 권한, 후기당 허용 개수, 수정·삭제 수명주기와 후기 삭제 시 답글 처리 방식은 구현 전 확정한다.
- `REVX-05`:
  지역 후기 피드는 공개 가능한 후기와 답글만 지역 기준으로 제공한다.
  정렬·페이지 방식, 조치된 후기의 노출, 신고자 정보와 개인정보의 제외 기준은 API 계약으로 명시한다.

## 4. 구현 전 확정 항목

| 항목 | 확정할 내용 |
| --- | --- |
| 신고 사유·중복 | 허용 사유, 사용자당 중복 신고, 첨부·증빙 수집 여부 |
| 검토·조치 | 검토자 역할, 상태 전이, 조치 종류, 이의 처리와 보관 기간 |
| 공개 상태 연계 | 신고 접수·조치가 후기와 답글 노출에 미치는 영향 |
| 답글 모델 | 작성 권한, 후기당 개수, 수정·삭제 가능 기간, 후기 삭제 후 처리 |
| 피드 계약 | 지역 필터, 정렬·페이지, 비식별 작성자 표기와 차단 기준 |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 후기 | `review_id`, `visit_id`, `content_id`, `region_id`, 공개·삭제 정보 | 신고·답글·피드의 원본 |
| 후기 신고 | `review_report_id`, `review_id`, `reporter_id`, 사유, 접수·처리 정보 | 신고 접수·내 상태 |
| 신고 조치 이력 | 신고, 처리자, 조치, 사유, 시각, 후기 상태 변화 | 검토·감사 |
| 후기 답글 | `review_reply_id`, `review_id`, 작성자, 콘텐츠·지역 연결, 변경 정보 | 운영자 답글 |
| 피드 조회 기준 | `region_id`, 공개 상태, 정렬·페이지·기준 시각 | 공개 후기 피드 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [ERD](../erd.md)에 확정한다.

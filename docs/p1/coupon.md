# 쿠폰

| 항목 | 내용 |
| --- | --- |
| 상위 명세 | [로컬스탬프 P1 명세](../p1-spec.md) |
| 소유 범위 | 쿠폰 정책 생성·수정·공개·종료, 발급, 내 쿠폰 조회, 사용 가능 판단, 사용 확정, 사용 이력 |
| API 명세 | [API 명세서](../api/api-specification.md) |
| 데이터 모델 | [P0 ERD](../erd.md), [P1 ERD](../p1-erd.md) |

> 이 문서는 P1 쿠폰 정책의 단일 기준이다. 쿠폰 적용 범위, 할인 방식, 발급 근거와 취소·환불 복구 규칙은
> `CPN-01`~`CPN-05`와 [ADR-0068](../adr/0068-use-immutable-coupon-lifecycle-and-evidence-sources.md)에 확정한다.

## 1. 범위

### P1-FR-05. 쿠폰 정책 운영

- 권한 있는 콘텐츠 운영자는 본인이 소유한 콘텐츠 범위에서 쿠폰 정책을 생성·수정·공개·종료한다.
- 공개된 정책만 쿠폰 발급과 사용자 노출의 근거가 된다.
- 정책 변경·공개·종료는 처리자와 사유를 기록한다.

### P1-FR-06. 쿠폰 발급·조회·사용

- 쿠폰 발급은 정책, 사용자와 발급 근거를 검증하고 멱등하게 처리한다.
- 방문자는 내 쿠폰 목록과 상세, 사용 가능한 쿠폰, 사용 이력을 조회한다.
- 쿠폰 사용 확정은 사용 가능 조건을 검증하고 동일 쿠폰을 한 번만 사용 처리한다.

## 2. 유저 시나리오

### US-P1-05. 운영 주체가 쿠폰 정책을 공개한다

- **주체:** 권한 있는 콘텐츠 운영 주체
- **목표:** 담당 범위의 재방문 혜택을 정책으로 관리한다.
- **선행 조건:** 대상 지역·콘텐츠의 운영 권한과 정책에 필요한 조건이 확정돼 있다.

#### 기본 흐름

1. 콘텐츠 운영자가 본인 소유 콘텐츠, 정액 할인 금액, 최소 결제 금액, 발급 가능 기간, 발급 뒤 유효 일수와 단일 발급 경로를 입력해 `DRAFT` 정책을 만든다. 발급 경로는 `VISIT`, `MISSION_REWARD`, `STAMPBOOK_COMPLETION` 중 하나다.
2. 시스템은 현재 역할, 콘텐츠 지역과 소유권, 필수 정책 정보를 검증해 `DRAFT` 정책을 저장한다.
3. 콘텐츠 운영자가 공개하면 정책을 `PUBLISHED`로 전이한다.
4. 콘텐츠 운영자가 정책을 종료하면 신규 발급을 중단하고 종료 이력을 남긴다. 공개 중인 미션·스탬프북이 완료 보상으로 참조하면 먼저 해당 기능을 종료해야 한다.

#### 예외 흐름

- 현재 `OPERATOR` 역할이 아니거나 다른 지역·비소유 콘텐츠의 정책 생성·수정·공개·종료 요청은 거부한다.
- 공개되지 않았거나 종료된 정책을 근거로 새 쿠폰을 발급할 수 없다.
- 공개 중인 미션·스탬프북이 참조하는 정책의 종료 요청은 거부한다.
- 기존 발급 쿠폰에 대한 종료 영향은 확정된 정책 없이 임의로 변경하지 않는다.
- `PUBLISHED` 또는 `ENDED` 정책의 할인 금액·최소 결제 금액·유효 일수·발급 경로·적용 콘텐츠를 수정할 수 없다.

**적용 정책:** `CPN-01`

### US-P1-06. 방문자가 쿠폰을 발급받고 사용한다

- **주체:** 방문자
- **목표:** 자격이 있는 혜택을 한 번만 발급받고, 사용할 수 있는 시점에 안전하게 확정한다.
- **선행 조건:** 공개된 쿠폰 정책과 발급 근거가 존재한다.

#### 기본 흐름

1. 시스템 또는 사용자의 발급 요청이 쿠폰 정책, 사용자와 발급 근거를 함께 전달한다.
2. 시스템은 발급 자격과 같은 발급 결과의 기존 처리 이력을 확인한다.
3. 최초 요청이면 쿠폰과 발급 이력을 만들고, 재시도이면 기존 결과를 반환한다.
4. 방문자가 내 쿠폰 목록에서 사용 가능한 쿠폰을 조회한다.
5. 방문자가 결제 생성 요청에 쿠폰을 선택하면 시스템은 소유자, 정책, 유효 기간과 사용 조건을 검증하고 가격 스냅샷에 선점한다.
6. 최종 금액이 0원이면 결제 생성에서, 양수이면 PortOne 웹훅의 서버 검증 승인에서 예약 확정·쿠폰 사용·사용 이력과 상태 이력을 한 처리 단위로 반영한다.

#### 예외 흐름

- 다른 사용자의 쿠폰 조회·사용 요청은 거부한다.
- 만료·이미 사용·조건 불충족 쿠폰은 사용 확정할 수 없다. 정책 종료는 이미 발급된 쿠폰의 자체 만료 시각을 바꾸지 않는다.
- 발급 또는 사용 요청이 반복되거나 동시 요청되면 쿠폰·사용 이력을 중복 생성하지 않는다.
- 환불 완료 전이거나 회차 시작 뒤 취소된 경우에는 쿠폰을 복구하지 않는다.

**적용 정책:** `CPN-02`~`CPN-05`

## 3. 쿠폰 정책

- `CPN-01`:
  쿠폰 정책은 운영자가 소유한 콘텐츠 하나에 적용하며 콘텐츠의 지역을 정책 지역으로 사용한다. 정책은 작성 중, 공개, 종료를 구분한다.
  공개된 정책만 신규 발급의 근거가 되며 종료는 신규 발급을 중단한다. 공개 중인 미션·스탬프북이 완료 보상으로 참조하는 정책은 종료할 수 없다.
  이미 발급된 쿠폰은 정책 종료 뒤에도 자체 만료 시각과 사용 조건으로 사용 가능 여부를 판정한다.
- `CPN-02`:
  쿠폰 발급은 정책, 사용자, 발급 근거를 검증하고 동일 발급 결과를 식별할 수 있어야 한다.
  방문 쿠폰은 정책·수령자당 한 번만 발급하며 방문 식별자는 발급 자격의 증거로 보존한다. 미션·스탬프북 쿠폰은 정책·수령자·보상 근거별로 한 번만 발급한다.
  같은 발급 식별 키의 재시도·중복 이벤트·동시 요청은 하나의 쿠폰과 발급 이력으로 수렴한다.
- `CPN-03`:
  쿠폰 목록·상세는 본인 쿠폰만 제공한다. 사용 가능 목록은 현재 시각, 쿠폰 상태, 정책 콘텐츠와 예약 콘텐츠의 일치 여부,
  적용 조건을 함께 반영하며 조건 판단 기준 시각과 시간대는 API 계약으로 명시한다.
- `CPN-04`:
  결제 생성 시 쿠폰을 해당 가격 스냅샷에 선점한다. 최종 금액이 0원이면 결제 생성에서, 양수이면 PortOne 웹훅의 서버 검증 승인에서 예약과 쿠폰 사용을 함께 확정한다. 별도 쿠폰 사용 확정 HTTP API는 제공하지 않는다.
  예약당 쿠폰은 최대 하나이며 사용 이력은 적용 쿠폰이 일치하는 가격 스냅샷과 그 스냅샷의 홀드에서 생성된 확정 예약을 함께 가리켜야 한다.
  동일 쿠폰의 동시 요청에는 원자적 상태 전이와 활성 사용 이력의 고유성이 보장돼야 한다.
  최종 금액 0원 예약은 회차 시작 전 취소 성공 시, 양수 결제 예약은 회차 시작 전 사용자 또는 운영자 취소의 전액 환불이 완료되면 기존 사용 이력을 삭제하지 않고 반전 상태로 남긴다.
- `CPN-05`:
  발급·선점·선점 해제·사용·만료·복구 등 쿠폰 상태 변화는 원인, 처리자 또는 시스템 주체, 시각과 연결해 이력으로 남긴다.
  유료 예약 취소·환불과 연결된 복구는 [결제·환불](payment-refund.md) 정책과 같은 근거를 사용한다. 양수 결제는 환불 완료 전에는 복구하지 않고, 결제·환불 행이 없는 최종 금액 0원 예약은 회차 시작 전 취소 성공과 함께 복구하며,
  복구 시 원래 만료 시각이 지났으면 `AVAILABLE`이 아니라 `EXPIRED`로 전이한다.

## 4. 확정 정책

| 항목 | 확정 내용 |
| --- | --- |
| 혜택 정의 | 콘텐츠 하나에 적용하는 정액 할인. 예약당 쿠폰은 최대 하나이며 최소 결제 금액을 만족해야 한다. |
| 발급 근거 | `VISIT`, `MISSION_REWARD`, `STAMPBOOK_COMPLETION`만 허용하며 운영자 임의 지급은 허용하지 않는다. |
| 발급 멱등 키 | 방문은 정책·수령자, 미션·스탬프북은 정책·수령자·보상 근거 조합을 사용한다. |
| 정책 종료 영향 | 신규 발급만 중단하고 기존 쿠폰의 만료 시각과 사용 조건은 변경하지 않는다. |
| 복구 규칙 | 회차 시작 전 사용자·운영자 취소의 전액 환불 완료 시 복구한다. 원래 만료 시각은 연장하지 않는다. |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 쿠폰 정책 | `coupon_policy_id`, `content_id`, `region_id`, 혜택·기간·조건, 공개·종료 정보 | 발급·사용 기준과 운영자 소유권 검증 |
| 쿠폰 | `coupon_id`, `coupon_policy_id`, `user_id`, 발급·만료·사용 정보 | 사용자 혜택 상태 |
| 발급 이력 | 쿠폰, 발급 근거, 멱등 식별자, 발급 시각 | 중복 발급 차단 |
| 상태 이력 | 쿠폰, 이전·이후 상태, 사유, 처리 주체, 시각 | 추가 전용 상태 전이 재현 |
| 사용 이력 | 쿠폰, 가격 스냅샷, 확정 예약, 확정·반전 상태와 시각 | 중복 사용 차단과 재현 |
| 복구·보정 이력 | 쿠폰, 원인 거래 또는 요청, 처리자, 사유, 시각 | 거래 연계와 감사 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [P1 ERD](../p1-erd.md)에 확정하고, P0 재사용 테이블은 [P0 ERD](../erd.md)를 따른다.

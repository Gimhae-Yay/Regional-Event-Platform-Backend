# 쿠폰

| 항목 | 내용 |
| --- | --- |
| 상위 명세 | [로컬스탬프 P1 명세](../p1-spec.md) |
| 소유 범위 | 쿠폰 정책 생성·수정·공개·종료, 발급, 내 쿠폰 조회, 사용 가능 판단, 사용 확정, 사용 이력 |
| API 명세 | [API 명세서](../api/api-specification.md) |
| 데이터 모델 | [P0 ERD](../erd.md), [P1 ERD](../p1-erd.md) |

> 이 문서는 P1 쿠폰 정책의 단일 기준이다. P1은 지역 전체 유료 콘텐츠에 적용되는 정액 할인 쿠폰만 제공하며,
> 발급·사용·복구 규칙은 ADR-0068 및 P1 ERD를 따른다.

## 1. 범위

### P1-FR-05. 쿠폰 정책 운영

- 콘텐츠 운영자는 담당 지역에서 `DRAFT` 쿠폰 정책을 생성·수정하고 검토를 요청한다. 정책은 해당 지역의 모든 현재·신규 유료 콘텐츠에 적용한다.
- 담당 지역 관리자가 승인한 `PUBLISHED` 정책만 쿠폰 발급과 사용자 노출의 근거가 된다.
- `PUBLISHED` 뒤에는 핵심 값 수정 없이 종료만 허용하며, 정책 변경·검토 요청·승인·반려·종료는 처리자와 사유를 기록한다.

### P1-FR-06. 쿠폰 발급·조회·사용

- 쿠폰 발급은 정책, 사용자와 발급 근거를 검증하고 멱등하게 처리한다.
- 방문자는 내 쿠폰 목록과 상세, 사용 가능한 쿠폰, 사용 이력을 조회한다.
- 쿠폰 사용 확정은 사용 가능 조건을 검증하고 동일 쿠폰을 한 번만 사용 처리한다.

## 2. 유저 시나리오

### US-P1-05. 운영 주체가 쿠폰 정책을 공개한다

- **주체:** 권한 있는 콘텐츠 운영 주체
- **목표:** 담당 범위의 재방문 혜택을 정책으로 관리한다.
- **선행 조건:** 대상 지역·콘텐츠의 운영 권한과 정책에 필요한 조건이 확정돼 있다.

#### 기본 흐름

1. 콘텐츠 운영자가 적용 지역, 정액 할인 금액, 발급 뒤 1~365일의 유효 일수와 단일 발급 경로를 입력해 `DRAFT` 정책을 만든다. 발급 경로는 `VISIT`, `MISSION_REWARD`, `STAMPBOOK_COMPLETION` 중 하나다.
2. 시스템은 권한과 필수 정책 정보를 검증한 뒤 `PENDING_REVIEW` 검토 요청을 저장한다.
3. 담당 지역 관리자가 승인하면 정책을 `PUBLISHED`로 전이한다. 반려하면 `DRAFT`로 돌려 수정 후 재요청하게 한다.
4. 운영 주체가 정책을 종료하면 신규 발급을 중단하고 종료 이력을 남긴다. 공개 중인 미션·스탬프북이 완료 보상으로 참조하면 먼저 해당 기능을 종료해야 한다.

#### 예외 흐름

- 담당 범위 밖의 정책 생성·수정·검토 요청·승인·종료 요청은 거부한다.
- 공개되지 않았거나 종료된 정책을 근거로 새 쿠폰을 발급할 수 없다.
- 공개 중인 미션·스탬프북이 참조하는 정책의 종료 요청은 거부한다.
- 기존 발급 쿠폰에 대한 종료 영향은 확정된 정책 없이 임의로 변경하지 않는다.
- `PUBLISHED` 또는 `ENDED` 정책의 할인 금액·유효 일수·발급 경로·적용 지역을 수정할 수 없다.

**적용 정책:** `CPN-01`

### US-P1-06. 방문자가 쿠폰을 발급받고 사용한다

- **주체:** 방문자
- **목표:** 자격이 있는 혜택을 한 번만 발급받고, 사용할 수 있는 시점에 안전하게 확정한다.
- **선행 조건:** 공개된 쿠폰 정책과 발급 근거가 존재한다.

#### 기본 흐름

1. 시스템 또는 사용자의 발급 요청이 쿠폰 정책, 사용자와 발급 근거를 함께 전달한다.
2. 시스템은 발급 자격과 같은 발급 결과의 기존 처리 이력을 확인한다.
3. 최초 요청이면 쿠폰과 발급 이력을 만들고, 재시도이면 기존 결과를 반환한다.
4. 방문자가 내 쿠폰 목록에서 사용 가능한 쿠폰을 조회한다.
5. 쿠폰 사용 확정 요청이 들어오면 시스템은 소유자, 정책, 유효 기간과 사용 조건을 검증한다.
6. 조건을 만족하면 쿠폰 사용, 가격 스냅샷·확정 예약에 연결한 사용 이력과 상태 이력을 한 처리 단위로 반영한다.

#### 예외 흐름

- 다른 사용자의 쿠폰 조회·사용 요청은 거부한다.
- 만료·이미 사용·조건 불충족 쿠폰은 사용 확정할 수 없다. 정책 종료는 이미 발급된 쿠폰의 자체 만료 시각을 바꾸지 않는다.
- 발급 또는 사용 요청이 반복되거나 동시 요청되면 쿠폰·사용 이력을 중복 생성하지 않는다.
- 취소·환불로 쿠폰 복구가 필요해도 확정된 복구 정책과 근거 없이 상태를 바꾸지 않는다.

**적용 정책:** `CPN-02`~`CPN-05`

## 3. 쿠폰 정책

- `CPN-01`:
  쿠폰 정책은 `DRAFT → PENDING_REVIEW → PUBLISHED → ENDED` 수명주기를 사용하며, 반려는 `PENDING_REVIEW → DRAFT`다.
  콘텐츠 운영자가 작성·검토 요청하고 담당 지역 관리자가 승인해야 공개된다. 핵심 값은 `DRAFT`에서만 수정하며, 공개된 정책만 신규 발급의 근거가 되고 종료는 신규 발급을 중단한다.
  발급 뒤 유효 일수인 `valid_days`는 1 이상 365 이하여야 한다.
  공개 중인 미션·스탬프북이 완료 보상으로 참조하는 정책은 종료할 수 없다. 이미 발급된 쿠폰은 정책 종료 뒤에도 자체 만료 시각과 사용 조건으로 사용 가능 여부를 판정한다.
- `CPN-02`:
  쿠폰 발급은 `VISIT`, `MISSION_REWARD`, `STAMPBOOK_COMPLETION` 중 하나의 불변 근거만 사용하며 운영자의 임의 지급은 허용하지 않는다.
  정책별 발급 경로와 근거 유형을 일치시키고, `VISIT`은 사용자·정책별 한 장만, 미션·스탬프북 보상은 각 완료 보상 근거별 한 장만 발급한다. 같은 발급 근거의 재시도·중복 이벤트·동시 요청은 하나의 쿠폰과 발급 이력으로 수렴한다.
  `MISSION_REWARD` 발급은 모든 관련 행 잠금 획득 직후 DB 현재 시각을 한 번만 읽은 `operation_at`을 수령 자격의 종료 경계 판정과 수령·쿠폰·발급·최초 상태 이력의 발생 시각으로 함께 사용한다.
  쿠폰 만료 시각은 발급 시각에 정책의 `valid_days`일을 더해 계산하고, 최초 상태 이력은
  `null → AVAILABLE`, `reason_code = MISSION_REWARD_ISSUED`, `actor_kind = USER`로 기록한다.
- `CPN-03`:
  쿠폰 목록·상세는 본인 쿠폰만 제공한다. 사용 가능 목록은 현재 시각, `AVAILABLE` 상태, 자체 만료 시각과 동일 지역 유료 콘텐츠 조건을 함께 반영하며, 정책 종료 뒤에도 자체 만료 시각까지 사용할 수 있다.
- `CPN-04`:
  쿠폰 사용은 가격 스냅샷 생성 때 소유자·지역·만료·`AVAILABLE` 상태를 검증해 `RESERVED`로 전이하고, 0원 예약 확정 또는 양수 결제 서버 승인 때만 `USED`와 `coupon_redemption(CONFIRMED)`을 함께 기록한다.
  예약당 쿠폰은 최대 하나이며, 사용 이력은 적용 가격 스냅샷과 확정 예약을 함께 가리켜야 한다. 회차 시작 전 취소·환불로 복구하면 기존 사용 이력은 삭제하지 않고 `REVERSED`로 남긴다.
- `CPN-05`:
  발급·사용·만료·복구 등 쿠폰 상태 변화는 원인, 처리자 또는 시스템 주체, 시각과 연결해 이력으로 남긴다.
  유료 예약 취소·환불과 연결된 복구는 [결제·환불](payment-refund.md) 정책과 같은 근거를 사용한다.

## 4. 확정된 핵심 제약

| 항목 | 내용 |
| --- | --- |
| 혜택 정의 | 정액 할인 금액과 발급 뒤 1~365일의 유효 일수만 둔다. 정률 할인·최소 결제 금액·할인 상한·다중 쿠폰은 P1에서 제외한다. |
| 적용 대상 | 정책은 한 지역의 모든 현재·신규 유료 콘텐츠에 적용하며, 정책-콘텐츠 매핑은 만들지 않는다. |
| 발급 근거 | `VISIT`, `MISSION_REWARD`, `STAMPBOOK_COMPLETION` 중 정책당 하나만 사용한다. 운영자 임의 지급은 허용하지 않는다. |
| 발급 멱등성 | `issuance_identity_hash`로 같은 근거·정책·수령자의 발급을 한 쿠폰으로 수렴시킨다. |
| 정책 종료·복구 | 종료 뒤 기존 쿠폰은 자체 만료 시각까지 사용한다. 회차 시작 전 취소·환불 성공 때만 원래 만료 시각을 유지해 복구하고 기존 사용 이력은 `REVERSED`로 남긴다. |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 쿠폰 정책 | `coupon_policy_id`, `region_id`, `issuance_type`, `discount_amount`, `valid_days`, 상태 | 발급·사용 기준 |
| 쿠폰 | `coupon_id`, `coupon_policy_id`, `user_id`, 상태, 발급·원래 만료 시각 | 사용자 혜택 상태 |
| 발급 이력 | 쿠폰, 정책·수령자, 정확히 하나의 발급 근거 FK, `issuance_identity_hash`, 발급 시각 | 중복 발급 차단 |
| 상태 이력 | 쿠폰, 이전·이후 상태, 사유, 처리 주체, 시각 | 추가 전용 상태 전이 재현 |
| 사용 이력 | 쿠폰, 가격 스냅샷, 확정 예약, `CONFIRMED`·`REVERSED` 상태와 시각 | 중복 사용 차단과 복구 재현 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [P1 ERD](../p1-erd.md)에 확정하고, P0 재사용 테이블은 [P0 ERD](../erd.md)를 따른다.

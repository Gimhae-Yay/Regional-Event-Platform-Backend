> 이 문서는 P1 쿠폰의 기능 계약을 정의한다. 할인 산식, 발급 근거, 취소·환불에 따른 복구 규칙은
> 구현 전에 별도 정책으로 확정한다.

## 1. 범위

### P1-FR-05. 쿠폰 정책 운영

- 권한 있는 운영 주체는 담당 지역·콘텐츠 범위에서 쿠폰 정책을 생성·수정·공개·종료한다.
- 공개된 정책만 쿠폰 발급과 사용자 노출의 근거가 된다.
- 정책 변경·공개·종료는 처리자와 사유를 기록한다.

### P1-FR-06. 쿠폰 발급·조회·사용

- 쿠폰 발급은 정책, 사용자와 발급 근거를 검증하고 멱등하게 처리한다.
- 방문자는 내 쿠폰 목록과 상세, 사용 가능한 쿠폰, 사용 이력을 조회한다.
- 쿠폰 사용 확정은 사용 가능 조건을 검증하고 동일 쿠폰을 한 번만 사용 처리한다.

## 2. 유저 시나리오

### US-P1-05. 운영 주체가 쿠폰 정책을 공개한다

- **주체:** 권한 있는 콘텐츠 운영 주체
- **목표:** 담당 범위의 재방문 혜택을 정책으로 관리한다.
- **선행 조건:** 대상 지역·콘텐츠의 운영 권한과 정책에 필요한 조건이 확정돼 있다.

#### 기본 흐름

1. 운영 주체가 적용 대상, 혜택 내용, 발급·사용 기간과 사용 조건을 입력한다.
2. 시스템은 권한과 필수 정책 정보를 검증한다.
3. 정책을 공개하면 이후 발급·사용 가능 판단은 공개된 정책을 기준으로 수행한다.
4. 운영 주체가 정책을 종료하면 신규 발급을 중단하고 종료 이력을 남긴다.

#### 예외 흐름

- 담당 범위 밖의 정책 생성·수정·공개·종료 요청은 거부한다.
- 공개되지 않았거나 종료된 정책을 근거로 새 쿠폰을 발급할 수 없다.
- 기존 발급 쿠폰에 대한 종료 영향은 확정된 정책 없이 임의로 변경하지 않는다.

**적용 정책:** `CPN-01`

### US-P1-06. 방문자가 쿠폰을 발급받고 사용한다

- **주체:** 방문자
- **목표:** 자격이 있는 혜택을 한 번만 발급받고, 사용할 수 있는 시점에 안전하게 확정한다.
- **선행 조건:** 공개된 쿠폰 정책과 발급 근거가 존재한다.

#### 기본 흐름

1. 시스템 또는 사용자의 발급 요청이 쿠폰 정책, 사용자와 발급 근거를 함께 전달한다.
2. 시스템은 발급 자격과 같은 발급 결과의 기존 처리 이력을 확인한다.
3. 최초 요청이면 쿠폰과 발급 이력을 만들고, 재시도이면 기존 결과를 반환한다.
4. 방문자가 내 쿠폰 목록에서 사용 가능한 쿠폰을 조회한다.
5. 쿠폰 사용 확정 요청이 들어오면 시스템은 소유자, 정책, 유효 기간과 사용 조건을 검증한다.
6. 조건을 만족하면 쿠폰 사용과 사용 이력을 한 처리 단위로 반영한다.

#### 예외 흐름

- 다른 사용자의 쿠폰 조회·사용 요청은 거부한다.
- 만료·종료·이미 사용·조건 불충족 쿠폰은 사용 확정할 수 없다.
- 발급 또는 사용 요청이 반복되거나 동시 요청되면 쿠폰·사용 이력을 중복 생성하지 않는다.
- 취소·환불로 쿠폰 복구가 필요해도 확정된 복구 정책과 근거 없이 상태를 바꾸지 않는다.

**적용 정책:** `CPN-02`~`CPN-05`

## 3. 쿠폰 정책

- `CPN-01`:
  쿠폰 정책은 작성 중, 공개, 종료를 구분한다. 공개된 정책만 신규 발급의 근거가 되며,
  종료는 신규 발급을 중단한다. 기존 쿠폰의 사용 가능 여부와 정책 변경 적용 방식은 구현 전 확정한다.
- `CPN-02`:
  쿠폰 발급은 정책, 사용자, 발급 근거를 검증하고 동일 발급 결과를 식별할 수 있어야 한다.
  같은 발급 근거의 재시도·중복 이벤트·동시 요청은 하나의 쿠폰과 발급 이력으로 수렴한다.
- `CPN-03`:
  쿠폰 목록·상세는 본인 쿠폰만 제공한다. 사용 가능 목록은 현재 시각, 정책 상태, 쿠폰 상태와
  적용 조건을 함께 반영하며, 조건 판단 기준 시각과 시간대는 API 계약으로 명시한다.
- `CPN-04`:
  쿠폰 사용 확정은 소유자, 사용 가능 여부와 사용 대상 조건을 확인한다.
  동일 쿠폰은 한 번만 사용 효과를 만들며, 동시 요청에는 원자적 상태 전이와 사용 이력의 고유성이 보장돼야 한다.
- `CPN-05`:
  발급·사용·만료·복구 등 쿠폰 상태 변화는 원인, 처리자 또는 시스템 주체, 시각과 연결해 이력으로 남긴다.
  유료 예약 취소·환불과 연결된 복구는 [결제·환불](payment-refund.md) 정책과 같은 근거를 사용한다.

## 4. 구현 전 확정 항목

| 항목 | 확정할 내용 |
| --- | --- |
| 혜택 정의 | 할인 방식·금액·최소 조건·중복 사용·적용 대상 |
| 발급 근거 | 방문·미션 보상·운영자 지급 등 발급 사유와 정책별 발급 한도 |
| 발급 멱등 키 | 사용자·정책·근거·요청 키의 조합, 보관 기간과 충돌 응답 |
| 정책 종료 영향 | 종료 후 기존 쿠폰의 사용 가능 여부와 사용자 안내 |
| 복구 규칙 | 예약 취소·환불·운영자 취소에서 사용 쿠폰 복구 여부와 재사용 제한 |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 쿠폰 정책 | `coupon_policy_id`, `region_id`, 대상 범위, 혜택·기간·조건, 공개·종료 정보 | 발급·사용 기준 |
| 쿠폰 | `coupon_id`, `coupon_policy_id`, `user_id`, 발급·만료·사용 정보 | 사용자 혜택 상태 |
| 발급 이력 | 쿠폰, 발급 근거, 멱등 식별자, 발급 시각 | 중복 발급 차단 |
| 사용 이력 | 쿠폰, 사용 대상, 확정 시각, 처리 결과 | 중복 사용 차단과 재현 |
| 복구·보정 이력 | 쿠폰, 원인 거래 또는 요청, 처리자, 사유, 시각 | 거래 연계와 감사 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [ERD](../erd.md)에 확정한다.

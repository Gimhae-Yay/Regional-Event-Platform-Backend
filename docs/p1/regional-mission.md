# 지역 미션

| 항목 | 내용 |
| --- | --- |
| 상위 명세 | [로컬스탬프 P1 명세](../p1-spec.md) |
| 소유 범위 | 미션 생성·수정·공개·종료, 목록·상세, 참여, 진행도, 완료 보상 수령 |
| API 명세 | [API 명세서](../api/api-specification.md) |
| 데이터 모델 | [P0 ERD](../erd.md), [P1 ERD](../p1-erd.md) |

> 이 문서는 P1 지역 미션 정책의 단일 기준이다. 완료 조건은 `VISIT_COUNT` 또는 `CONTENT_SET`이고,
> 완료 보상은 쿠폰 수령 요청으로만 지급한다. 미션 종료 또는 `ends_at` 도달과 동시에 미수령 권리는 만료된다.

## 1. 범위

### P1-FR-03. 지역 미션 운영·조회

- 콘텐츠 운영자는 담당 지역의 제목이 있는 `DRAFT` 미션을 생성·수정하고 검토를 요청하며, 담당 지역 관리자는 제목과 공개 조건·보상을 검토한 뒤 승인하면 즉시 공개한다. 별도 자동 공개 Scheduler는 두지 않는다.
- 방문자는 공개 중인 지역 미션 목록과 상세를 조회한다.
- `PUBLISHED` 뒤에는 핵심 값 수정 없이 종료만 허용하며, 종료된 미션은 신규 참여와 신규 진행도 반영 대상에서 제외한다.

### P1-FR-04. 참여·진행도·보상 수령

- 방문자는 참여 가능한 미션에 참여한다.
- 유효 방문 기록을 기준으로 본인 진행도를 계산·조회한다.
- 완료 조건을 충족한 사용자는 보상을 수령한다.
- 완료 보상 수령 요청은 멱등하게 처리한다.

## 2. 유저 시나리오

### US-P1-03. 운영 주체가 지역 미션을 공개한다

- **주체:** 권한 있는 지역 운영 주체
- **목표:** 특정 지역의 방문 활동을 하나의 참여 목표로 제공한다.
- **선행 조건:** 주체에게 대상 `region_id`의 운영 권한이 있다.

#### 기본 흐름

1. 콘텐츠 운영자가 제목, 대상 지역, 종료 시각, `VISIT_COUNT` 또는 `CONTENT_SET` 완료 조건과 보상 정보를 입력해 `DRAFT` 미션을 만든다. 완료 보상은 같은 지역의 `MISSION_REWARD` 쿠폰 정책만 선택할 수 있고, `CONTENT_SET` 목표는 같은 지역의 비삭제 콘텐츠만 연결한다.
2. 시스템은 필수 정보와 권한을 검증한 뒤 `PENDING_REVIEW` 검토 요청을 저장한다.
3. 담당 지역 관리자가 미션 제목과 공개 조건·보상을 확인하고 승인하면, 잠근 완료 보상 정책과 모든 `CONTENT_SET` 목표 콘텐츠가 `PUBLISHED`인지 확인한 뒤 미션을 즉시 `PUBLISHED`로 전이한다. 반려하면 `DRAFT`로 돌려 수정 후 재요청하게 한다.
4. 미션은 공개 즉시 시작하며 `ends_at`에 자동 종료된다. 종료되면 신규 참여·진행도·보상 수령을 중단하고 미완료 참여를 `ENDED_INCOMPLETE`로 보존한다.

#### 예외 흐름

- 다른 지역의 미션을 생성·수정·종료하려는 요청은 거부한다.
- 다른 지역·발급 경로의 쿠폰 정책을 완료 보상으로 연결하거나, 비공개 정책으로 미션을 공개하려는 요청은 거부한다.
- 공개 전·종료 후 미션은 방문자 참여 목록에 노출하지 않는다.
- 공개 조건이나 보상 정의가 확정되지 않은 미션은 공개할 수 없다.
- `PUBLISHED` 또는 `ENDED` 미션의 기간·조건·보상은 수정할 수 없다.
- 보상 정책은 작성·수정·검토 요청 때 `DRAFT`, `PUBLISHED`만 연결할 수 있고 `ENDED`는 연결할 수 없다.
- 제목이 누락됐거나 양끝 공백 제거 뒤 비어 있거나 255자를 넘으면 생성·수정을 거부한다.

**적용 정책:** `MSN-01`

### US-P1-04. 방문자가 미션에 참여하고 보상을 수령한다

- **주체:** 방문자
- **목표:** 실제 방문으로 진행도를 채우고 완료 보상을 한 번만 수령한다.
- **선행 조건:** 미션이 공개 중이고 사용자가 참여 자격을 충족한다.

#### 기본 흐름

1. 방문자가 미션 상세에서 참여를 요청한다.
2. 시스템은 참여 이력과 미션 상태를 확인해 참여 결과를 저장한다.
3. 방문 완료 이벤트가 전달되면 시스템은 참여 중인 미션의 조건을 평가한다.
4. 시스템은 최초 근거 방문에 대해서만 진행도를 반영한다.
5. 완료 조건을 만족하면 사용자는 보상 수령을 요청한다.
6. 시스템은 완료 여부와 기존 수령 이력을 확인해 최초 수령 결과 또는 기존 결과를 반환한다.

#### 예외 흐름

- 종료됐거나 참여 자격이 없는 미션에는 참여할 수 없다.
- 같은 방문의 중복 전달은 진행도를 중복 증가시키지 않는다.
- 완료 전 보상 수령과 다른 사용자의 보상 수령은 거부한다.
- 동일 보상 수령 요청이 반복되면 새 보상이나 새 수령 이력을 만들지 않는다.
- 미션이 종료되거나 `ends_at`에 도달한 뒤의 신규 보상 수령은 완료 여부와 관계없이 거부한다. 종료 전에 생성된 기존 수령 결과의 멱등 재조회만 허용한다.

**적용 정책:** `MSN-02`~`MSN-05`

## 3. 지역 미션 정책

- `MSN-01`:
  미션은 `DRAFT → PENDING_REVIEW → PUBLISHED → ENDED` 수명주기를 사용하며, 반려는 `PENDING_REVIEW → DRAFT`다.
  콘텐츠 운영자가 작성·검토 요청하고 담당 지역 관리자가 승인해야 공개된다. 공개 즉시 시작하고 `ends_at`에 자동 종료하며, 핵심 값은 `DRAFT`에서만 수정한다.
  미션은 방문자 표시 제목을 직접 소유한다. 제목은 필수이며 양끝 공백을 제거하고 내부 공백은 보존한다. 정규화한
  제목은 Unicode code point 기준 1자 이상 255자 이하이고 별도 문자 allowlist를 두지 않는다. 같은 지역·상태 또는 서로 다른 지역의 제목
  중복을 허용한다. 제목은 핵심 값이므로 `DRAFT`에서만 수정하고 이후 상태에서는 변경하지 않는다.
  담당 지역 관리자의 미션 목록과 상세 조회는 같은 저장 제목을 반환하며, 지역 관리자는 승인 전에 제목을 조건·보상과 함께 검토한다.
  방문자 공개 목록·상세에는 `region.is_public = true`인 지역의 미션만 노출하며, 비공개 지역은 대상 부재와 동일하게 처리한다.
  생성·수정·검토 요청·승인·반려·종료에는 대상 지역, 처리자, 사유와 시각을 기록한다. 완료 보상은 같은 지역의 `MISSION_REWARD` 정책이어야 한다. 작성·수정·검토 요청 때는 `DRAFT`, `PUBLISHED` 정책만 연결하고, 공개 때 잠근 정책도 `PUBLISHED`여야 한다.
  제목 수정은 기존 `MISSION_UPDATED` 감사로 수정 발생만 기록하고 제목 전·후 값의 별도 변경 이력을 만들지 않는다.
  감사 이벤트와 구조화 로그에는 제목 값을 남기지 않는다.
  `CONTENT_SET`은 작성·수정 때 같은 지역의 비삭제 콘텐츠만 연결한다. 승인 때 모든 목표 콘텐츠를 식별자 순으로
  잠근 뒤 같은 지역의 비삭제 `PUBLISHED` 상태인지 재검증하며, 하나라도 충족하지 않으면 공개하지 않는다.
- `MSN-02`:
  참여는 `region.is_public = true`인 공개·운영 지역에서 공개 중이고 `ends_at` 전인 미션에만 가능하며, 사용자와 미션의 관계로 관리한다. 같은 사용자의 같은 미션 참여 요청은 하나의 참여 결과로 수렴한다.
  신규 참여는 미션과 지역 행 잠금 획득 직후 DB 현재 시각을 한 번만 읽은 `operation_at`으로 종료 전 여부를 판정하고 `joined_at`을 기록한다.
  참여 이전 방문은 인정하지 않으며 P1은 참여 취소·재참여 기능을 제공하지 않는다.
- `MSN-03`:
  진행도는 참여 뒤의 유효 방문 기록과 미션 조건을 함께 검증해 계산한다. `VISIT_COUNT`는 같은 지역의 서로 다른
  유효 방문을 세므로 같은 콘텐츠의 재방문도 `visit_id`가 다르면 진행도에 반영한다. `CONTENT_SET`은 지정 콘텐츠마다
  최초 유효 방문만 반영하며, 같은 콘텐츠의 이후 방문은 `visit_id`가 달라도 진행도를 늘리지 않는다.
  동일 `visit_id`가 같은 사용자·미션의 진행도를 두 번 증가시키지 않도록
  `UNIQUE (mission_participation_id, visit_id)` 처리 이력을 둔다. `CONTENT_SET`의 콘텐츠 중복 판정은 미션 행 다음
  참여 행을 잠근 상태에서 기존 `(mission_participation_id, content_id)` 근거를 확인하는 조건부 쓰기로 처리한다.
  진행도 반영 전 `visit.region_id = mission.region_id`와 `visit.checked_at >= mission_participation.joined_at`을
  재검증해 타 지역 방문과 참여 이전 방문을 반영하지 않는다.
  같은 유효 방문은 조건을 만족하는 여러 미션에는 각각 반영될 수 있다.
  진행도 반영과 수동·자동 종료는 미션 행을 먼저 잠그고 참여 행을 식별자 순으로 잠근다. 진행도 반영은 모든 잠금 획득 직후 DB 현재 시각을 한 번만 읽은 `operation_at`으로 종료 전 여부를 판정하고 `recorded_at`과 완료 시 `completed_at`을 기록한다. 잠금 획득 뒤 미션 상태·종료 시각과 참여 상태를 다시 확인해 진행도 반영과 종료 중 먼저 커밋된 결과만 허용한다.
- `MSN-04`:
  보상 수령은 완료 상태인 참여 이력에서만 가능하다. 수령 이력의 쿠폰 정책은 원본 미션의 완료 보상 정책과 같아야 하며, 동일 참여 이력의 반복·동시 수령 요청은 한 건의 보상 효과와 수령 이력만 만들고 최초 결과를 반환한다.
  신규 보상 수령은 모든 관련 행 잠금 획득 직후 DB 현재 시각을 한 번만 읽은 `operation_at`을 기준으로 미션이 `PUBLISHED`이고 `ends_at` 전일 때만 허용한다. 수령·쿠폰·발급·최초 상태 이력의 발생 시각도 같은 `operation_at`으로 기록한다. 미션이 수동·자동 종료되거나 Scheduler 처리 전이라도 `ends_at`에 도달하면 완료·미수령 참여자의 수령 권리는 즉시 만료되며 별도 유예 기간과 수동 지급을 제공하지 않는다. 종료 전에 생성된 기존 수령 결과의 멱등 재조회는 허용한다.
- `MSN-05`:
  방문자는 본인의 참여 상태·진행도·완료 여부·보상 수령 결과만 조회할 수 있다.
  콘텐츠 운영자의 `GET /api/v1/operator/missions` 목록 조회는 현재 활성 `OPERATOR` 배정의 담당 `region_id`와
  `mission.region_id`가 같은 모든 미션을 대상으로 한다. 상태 필터를 생략하면 모든 상태를 조회하며,
  같은 지역의 다른 운영자와 연결된 보상 정책 또는 대상 콘텐츠가 있어도 목록에서 제외하지 않는다.
  다른 지역의 미션은 조회할 수 없고, 이 목록 범위는 생성·수정·검토 요청 등 변경 권한이나 보상 상세 노출 범위를
  확대하지 않는다.

## 4. 확정된 핵심 제약과 잔여 결정

| 항목 | 내용 |
| --- | --- |
| 미션 제목 | `mission`이 직접 소유한다. 필수이며 양끝 공백 제거 뒤 Unicode code point 기준 1~255자다. 내부 공백은 보존하고 문자 allowlist와 중복 제한을 두지 않는다. `DRAFT`에서만 수정한다. |
| 완료 조건 | `VISIT_COUNT`는 양의 `required_visit_count`를, `CONTENT_SET`은 하나 이상의 `mission_target_content`를 사용한다. 복잡한 AND/OR·타 지역 조건은 P1에서 제외한다. |
| 참여 시점 | 명시적으로 참여한 뒤의 유효 방문만 인정하며 참여 취소·재참여는 제공하지 않는다. |
| 보상 모델 | 같은 지역의 `MISSION_REWARD` 쿠폰 정책 하나를 완료 보상으로 사용하며, 미션이 `PUBLISHED`이고 `ends_at` 전일 때 완료 사용자의 수령 요청으로 한 번만 지급한다. |
| 종료 권리 | 종료 시 미완료 참여는 `ENDED_INCOMPLETE`로 보존하고 추가 진행·신규 보상 수령을 중단한다. 종료 전 완료·미수령 참여자의 권리도 종료 또는 `ends_at` 도달과 동시에 만료된다. |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 지역 미션 | `mission_id`, `region_id`, 제목, `condition_type`, `required_visit_count`, `reward_coupon_policy_id`, 상태·예정·실제 종료 시각 | 방문자 표시와 참여·진행도 기준 |
| 목표 콘텐츠 | `mission_id`, `content_id` | `CONTENT_SET` 미션의 완료 대상 |
| 미션 참여 | `mission_participation_id`, `mission_id`, `user_id`, 참여·완료 정보 | 사용자별 진행도와 수령 자격 |
| 진행도 근거 | 참여 이력, `visit_id`, 반영 시각, 처리 결과 | 중복 반영 차단과 재현 |
| 보상 수령 이력 | 참여 이력, 보상 식별자, 수령 시각, 처리 결과 | 멱등 수령과 감사 |
| 방문 | `visit_id`, `user_id`, `region_id`, `content_id` | 완료 조건의 원본 근거 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [P1 ERD](../p1-erd.md)에 확정하고, P0 재사용 테이블은 [P0 ERD](../erd.md)를 따른다.

# 지역 미션

| 항목 | 내용 |
| --- | --- |
| 상위 명세 | [로컬스탬프 P1 명세](../p1-spec.md) |
| 소유 범위 | 미션 생성·수정·공개·종료, 목록·상세, 참여, 진행도, 완료 보상 수령 |
| API 명세 | [API 명세서](../api/api-specification.md) |

> 이 문서는 P1 지역 미션 정책의 단일 기준이다. 완료 조건은 `VISIT_COUNT` 또는 `CONTENT_SET`이고,
> 완료 보상은 쿠폰 수령 요청으로만 지급한다. 종료된 뒤 완료·미수령 참여자의 수령 기한만 미확정이다.

## 1. 범위

### P1-FR-03. 지역 미션 운영·조회

- 콘텐츠 운영자는 담당 지역의 `DRAFT` 미션을 생성·수정하고 검토를 요청하며, 담당 지역 관리자가 승인해 공개한다.
- 방문자는 공개 중인 지역 미션 목록과 상세를 조회한다.
- `PUBLISHED` 뒤에는 핵심 값 수정 없이 종료만 허용하며, 종료된 미션은 신규 참여와 신규 진행도 반영 대상에서 제외한다.

### P1-FR-04. 참여·진행도·보상 수령

- 방문자는 참여 가능한 미션에 참여한다.
- 유효 방문 기록을 기준으로 본인 진행도를 계산·조회한다.
- 완료 조건을 충족한 사용자는 보상을 수령한다.
- 완료 보상 수령 요청은 멱등하게 처리한다.

## 2. 유저 시나리오

### US-P1-03. 운영 주체가 지역 미션을 공개한다

- **주체:** 권한 있는 지역 운영 주체
- **목표:** 특정 지역의 방문 활동을 하나의 참여 목표로 제공한다.
- **선행 조건:** 주체에게 대상 `region_id`의 운영 권한이 있다.

#### 기본 흐름

1. 콘텐츠 운영자가 대상 지역, 종료 시각, `VISIT_COUNT` 또는 `CONTENT_SET` 완료 조건과 보상 정보를 입력해 `DRAFT` 미션을 만든다. 완료 보상은 같은 지역의 `MISSION_REWARD` 쿠폰 정책만 선택할 수 있다.
2. 시스템은 필수 정보와 권한을 검증한 뒤 `PENDING_REVIEW` 검토 요청을 저장한다.
3. 담당 지역 관리자가 승인하면, 잠근 완료 보상 정책이 `PUBLISHED`인지 확인한 뒤 미션을 `PUBLISHED`로 전이한다. 반려하면 `DRAFT`로 돌려 수정 후 재요청하게 한다.
4. 미션은 공개 즉시 시작하며 `ends_at`에 자동 종료된다. 종료되면 신규 참여·진행도 반영을 중단하고 미완료 참여를 `ENDED_INCOMPLETE`로 보존한다.

#### 예외 흐름

- 다른 지역의 미션을 생성·수정·종료하려는 요청은 거부한다.
- 다른 지역·발급 경로의 쿠폰 정책을 완료 보상으로 연결하거나, 비공개 정책으로 미션을 공개하려는 요청은 거부한다.
- 공개 전·종료 후 미션은 방문자 참여 목록에 노출하지 않는다.
- 공개 조건이나 보상 정의가 확정되지 않은 미션은 공개할 수 없다.
- `PUBLISHED` 또는 `ENDED` 미션의 기간·조건·보상은 수정할 수 없다.

**적용 정책:** `MSN-01`

### US-P1-04. 방문자가 미션에 참여하고 보상을 수령한다

- **주체:** 방문자
- **목표:** 실제 방문으로 진행도를 채우고 완료 보상을 한 번만 수령한다.
- **선행 조건:** 미션이 공개 중이고 사용자가 참여 자격을 충족한다.

#### 기본 흐름

1. 방문자가 미션 상세에서 참여를 요청한다.
2. 시스템은 참여 이력과 미션 상태를 확인해 참여 결과를 저장한다.
3. 방문 완료 이벤트가 전달되면 시스템은 참여 중인 미션의 조건을 평가한다.
4. 시스템은 최초 근거 방문에 대해서만 진행도를 반영한다.
5. 완료 조건을 만족하면 사용자는 보상 수령을 요청한다.
6. 시스템은 완료 여부와 기존 수령 이력을 확인해 최초 수령 결과 또는 기존 결과를 반환한다.

#### 예외 흐름

- 종료됐거나 참여 자격이 없는 미션에는 참여할 수 없다.
- 같은 방문의 중복 전달은 진행도를 중복 증가시키지 않는다.
- 완료 전 보상 수령과 다른 사용자의 보상 수령은 거부한다.
- 동일 보상 수령 요청이 반복되면 새 보상이나 새 수령 이력을 만들지 않는다.

**적용 정책:** `MSN-02`~`MSN-05`

## 3. 지역 미션 정책

- `MSN-01`:
  미션은 `DRAFT → PENDING_REVIEW → PUBLISHED → ENDED` 수명주기를 사용하며, 반려는 `PENDING_REVIEW → DRAFT`다.
  콘텐츠 운영자가 작성·검토 요청하고 담당 지역 관리자가 승인해야 공개된다. 공개 즉시 시작하고 `ends_at`에 자동 종료하며, 핵심 값은 `DRAFT`에서만 수정한다.
  생성·수정·검토 요청·승인·반려·종료에는 대상 지역, 처리자, 사유와 시각을 기록한다. 완료 보상은 같은 지역의 `MISSION_REWARD` 정책이어야 하며, 공개 때 해당 정책도 `PUBLISHED`여야 한다.
- `MSN-02`:
  참여는 공개 중이고 `ends_at` 전인 미션에만 가능하며, 사용자와 미션의 관계로 관리한다. 같은 사용자의 같은 미션 참여 요청은 하나의 참여 결과로 수렴한다.
  참여 이전 방문은 인정하지 않으며 P1은 참여 취소·재참여 기능을 제공하지 않는다.
- `MSN-03`:
  진행도는 참여 뒤의 유효 방문 기록과 미션 조건을 함께 검증해 계산한다. `VISIT_COUNT`는 같은 지역의 모든 유효 방문을 세고, `CONTENT_SET`은 지정 콘텐츠를 각각 한 번 방문해야 완료한다.
  동일 `visit_id`가 같은 사용자·미션의 진행도를 두 번 증가시키지 않도록 `UNIQUE (mission_participation_id, visit_id)` 처리 이력을 둔다. 같은 유효 방문은 조건을 만족하는 여러 미션에는 각각 반영될 수 있다.
- `MSN-04`:
  보상 수령은 완료 상태인 참여 이력에서만 가능하다. 수령 이력의 쿠폰 정책은 원본 미션의 완료 보상 정책과 같아야 하며, 동일 참여 이력의 반복·동시 수령 요청은 한 건의 보상 효과와 수령 이력만 만들고 최초 결과를 반환한다.
  종료된 미션에서 이미 완료했지만 미수령인 참여자의 수령 가능 기간은 별도 사용자 결정 전까지 API·구현 계약으로 확정하지 않는다.
- `MSN-05`:
  방문자는 본인의 참여 상태·진행도·완료 여부·보상 수령 결과만 조회할 수 있다.
  운영 주체의 지역별 조회 범위와 보상 상세 노출은 권한·개인정보 계약에 따라 제한한다.

## 4. 확정된 핵심 제약과 잔여 결정

| 항목 | 내용 |
| --- | --- |
| 완료 조건 | `VISIT_COUNT`는 양의 `required_visit_count`를, `CONTENT_SET`은 하나 이상의 `mission_target_content`를 사용한다. 복잡한 AND/OR·타 지역 조건은 P1에서 제외한다. |
| 참여 시점 | 명시적으로 참여한 뒤의 유효 방문만 인정하며 참여 취소·재참여는 제공하지 않는다. |
| 보상 모델 | 같은 지역의 `MISSION_REWARD` 쿠폰 정책 하나를 완료 보상으로 사용하며, 완료 뒤 사용자의 수령 요청으로 한 번만 지급한다. |
| 종료 권리 | 종료 시 미완료 참여는 `ENDED_INCOMPLETE`로 보존하고 추가 진행·보상은 중단한다. 단, 종료 전 완료·미수령 참여자의 수령 기한은 미확정이다. |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 지역 미션 | `mission_id`, `region_id`, `condition_type`, `required_visit_count`, `reward_coupon_policy_id`, 상태·예정·실제 종료 시각 | 참여·진행도 기준 |
| 목표 콘텐츠 | `mission_id`, `content_id` | `CONTENT_SET` 미션의 완료 대상 |
| 미션 참여 | `mission_participation_id`, `mission_id`, `user_id`, 참여·완료 정보 | 사용자별 진행도와 수령 자격 |
| 진행도 근거 | 참여 이력, `visit_id`, 반영 시각, 처리 결과 | 중복 반영 차단과 재현 |
| 보상 수령 이력 | 참여 이력, 보상 식별자, 수령 시각, 처리 결과 | 멱등 수령과 감사 |
| 방문 | `visit_id`, `user_id`, `region_id`, `content_id` | 완료 조건의 원본 근거 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [P1 ERD](../p1-erd.md)에 확정하고, P0 재사용 테이블은 [P0 ERD](../erd.md)를 따른다.

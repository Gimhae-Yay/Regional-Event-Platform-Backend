> 이 문서는 P1 스탬프북 정책의 단일 기준이다. 적립 수치와 보상은 구현 전 정책 결정으로 남긴다.

## 1. 범위

### P1-FR-01. 스탬프북 운영

- 권한 있는 운영 주체는 담당 지역·콘텐츠 범위에서 스탬프북을 생성하고 수정한다.
- 검토를 통과한 스탬프북만 방문자에게 공개한다.
- 공개된 스탬프북은 종료할 수 있으며 종료 시점과 처리 사유를 기록한다.
- 생성·수정·공개·종료는 다른 지역 또는 소유 범위 밖에서 수행할 수 없다.

### P1-FR-02. 방문 기반 스탬프 적립과 조회

- P0에서 생성된 유효 방문 기록을 근거로 스탬프 적립을 반영한다.
- 방문자는 본인에게 공개된 스탬프북 목록, 스탬프북 상세와 적립 이력을 조회할 수 있다.
- 적립 처리의 재시도 또는 같은 방문 이벤트의 중복 전달은 새 적립을 만들지 않는다.

## 2. 유저 시나리오

### US-P1-01. 운영 주체가 스탬프북을 공개하고 종료한다

- **주체:** 권한 있는 콘텐츠 운영 주체
- **목표:** 담당 지역의 반복 방문 활동을 하나의 스탬프북으로 안내한다.
- **선행 조건:** 주체에게 담당 `region_id`와 필요한 콘텐츠 소유 권한이 있다.

#### 기본 흐름

1. 운영 주체가 대상 지역·콘텐츠와 적립 조건을 입력해 스탬프북을 생성한다. 완료 보상은 같은 지역의 `STAMPBOOK_COMPLETION` 쿠폰 정책만 선택할 수 있다.
2. 시스템은 소유 관계와 필수 정책 정보를 검증한다.
3. 공개 조건을 만족하면 스탬프북을 방문자에게 노출한다.
4. 운영 주체가 운영을 마치면 종료 요청과 사유를 남긴다.
5. 시스템은 종료 후 신규 적립 대상에서 제외하고 기존 이력은 보존한다.

#### 예외 흐름

- 권한 없는 지역 또는 콘텐츠에 연결하려는 요청은 거부한다.
- 다른 지역·발급 경로의 쿠폰 정책을 완료 보상으로 연결하거나, 비공개 정책으로 스탬프북을 공개하려는 요청은 거부한다.
- 공개되지 않았거나 종료된 스탬프북은 방문자 목록에 노출하지 않는다.
- 종료된 스탬프북의 적립 조건을 우회해 신규 적립을 만들 수 없다.

**적용 정책:** `STB-01`, `STB-02`

### US-P1-02. 방문자가 방문 완료 후 적립 이력을 확인한다

- **주체:** 방문자
- **목표:** 실제 방문이 어떤 스탬프북에 반영됐는지 신뢰할 수 있게 확인한다.
- **선행 조건:** 방문자에게 유효 방문 기록이 있다.

#### 기본 흐름

1. 방문 완료 이벤트가 유효 방문 기록을 가리켜 전달된다.
2. 시스템은 현재 공개 중이고 해당 방문에 적용되는 스탬프북을 판별한다.
3. 시스템은 방문 기록과 스탬프북의 조합으로 이미 처리한 적립인지 확인한다.
4. 최초 처리라면 적립 이력과 현재 진행도를 같은 처리 단위로 반영한다.
5. 방문자는 내 스탬프북 상세에서 적립 시각과 근거를 확인한다.

#### 예외 흐름

- 동일 방문 이벤트가 반복되면 기존 적립 결과를 반환하고 새 이력을 만들지 않는다.
- 취소·무효 처리된 방문 기록은 적립 근거로 사용할 수 없다.
- 다른 사용자의 스탬프북 상세나 적립 이력은 조회할 수 없다.

**적용 정책:** `STB-03`, `STB-04`

## 3. 스탬프북 정책

- `STB-01`:
  스탬프북은 작성 중, 공개, 종료를 구분하는 수명주기를 가진다.
  공개 전에는 방문자에게 노출하거나 적립하지 않고, 종료 후에는 신규 적립을 중단한다.
  상태 코드와 허용 전이는 구현 전 ADR·API·ERD 계약에서 확정한다.
- `STB-02`:
  생성·수정·공개·종료는 역할, `region_id`, 대상 콘텐츠 소유 관계를 모두 검증한다.
  완료 보상은 같은 지역의 `STAMPBOOK_COMPLETION` 정책이어야 하며, 공개 때 해당 정책도 `PUBLISHED`여야 한다.
  완료 보상 이력의 쿠폰 정책은 원본 스탬프북의 완료 보상 정책과 같아야 한다.
  모든 수명주기 변경에는 처리자, 이전·이후 상태, 사유와 시각을 기록한다.
- `STB-03`:
  적립은 유효 방문 기록과 공개된 적립 조건을 모두 만족할 때만 반영한다.
  동일한 `visit_id`와 스탬프북의 적립 처리는 한 번만 효과를 만들며,
  재시도·중복 이벤트·동시 처리에는 최초 결과를 반환한다.
  중복 판단 키와 스탬프 수량·상한은 구현 전 확정한다.
- `STB-04`:
  방문자는 본인 스탬프북의 현재 진행도, 적립 시각과 근거 방문 정보를 조회할 수 있다.
  적립 이력은 원본 근거를 덮어쓰지 않으며, 운영 보정이 필요하면 별도 보정 이력과 사유를 남긴다.

## 4. 구현 전 확정 항목

| 항목 | 확정할 내용 |
| --- | --- |
| 적립 조건 | 콘텐츠·회차·방문 유형별 적용 범위와 방문 한 건당 적립 단위 |
| 진행도 제한 | 사용자별 적립 상한, 동일 콘텐츠 재방문 인정 여부와 기간 기준 |
| 종료 처리 | 종료 직전 발생한 방문의 인정 기준과 보정 권한·절차 |
| 공개 권한 | 운영자 단독 공개 여부와 지역 관리자 검토 필요 여부 |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 스탬프북 | `stampbook_id`, `region_id`, 대상 범위, 공개·종료 정보 | 스탬프 적립 규칙과 방문자 노출 |
| 스탬프 적립 이력 | `stamp_earn_id`, `stampbook_id`, `user_id`, `visit_id`, 적립 시각 | 중복 적립 차단과 사용자 이력 |
| 스탬프북 운영 이력 | 대상, 처리자, 이전·이후 상태, 사유, 시각 | 공개·종료와 보정 감사 |
| 방문 | `visit_id`, `user_id`, `content_id`, 방문 완료 시각 | 적립 자격의 원본 근거 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [ERD](../erd.md)에 확정한다.

> 이 문서는 확정된 P1 ERD의 전체관리자 정책을 사용한다. 공통 감사 보관 기간만 P1 ERD의 미해결 항목으로 남는다.

## 1. 범위

### P1-FR-09. 전체관리자와 지역·역할 관리

- 고권한 계정을 생성하고 비활성화한다.
- 지역을 생성·조회하고 공개 가능 여부를 변경한다.
- 일반 계정에 지역 관리자 역할을 임명하고 회수한다.
- 모든 특권 변경은 대상, 처리자, 사유, 증빙 참조와 시각을 감사 이력으로 남긴다.

### P1-FR-10. 거래 예외 수동 처리

- 결제 불일치와 환불 실패를 식별·조회한다.
- 전체관리자는 증빙과 사유를 남기고 P1 ERD가 허용한 조치를 수행한다.
- 수동 처리는 원본 외부 거래 정보와 자동 처리 이력을 지우거나 임의로 덮어쓰지 않는다.

## 2. 유저 시나리오

### US-P1-09. 전체관리자가 지역과 관리자 역할을 관리한다

- **주체:** 활성 `PLATFORM_ADMIN` 또는 `SUPER_ADMIN`
- **목표:** 지역 운영에 필요한 지역과 지역 관리자 연결을 최소 권한으로 관리한다.
- **선행 조건:** 처리자에게 활성 `platform_admin_assignment`가 있다.

#### 기본 흐름

1. 전체관리자가 지역을 생성하거나 `is_public` 변경을 요청한다.
2. 시스템은 지역 식별자와 공개 해제 조건을 검증한다. 비공개 전환은 삭제되지 않은 콘텐츠가 없을 때만 허용한다.
3. 시스템은 지역 변경과 감사 이력을 함께 저장한다.
4. 전체관리자가 일반 계정에 지역 관리자 역할을 임명하거나 회수한다.
5. 시스템은 계정 유형, 담당 지역, 활성 역할과 충돌 여부를 검증한다.
6. 시스템은 `user_role_assignment`의 활성·회수 이력과 감사 이력을 함께 저장한다.

#### 예외 흐름

- 고권한 계정에는 일반 역할을 부여하지 않는다.
- 일반 방문자·운영자·지역 관리자는 지역·역할 변경을 수행할 수 없다.
- 역할을 삭제하지 않고 `ACTIVE → REVOKED`로 회수한다.

**적용 정책:** `ADM-01`~`ADM-03`

### US-P1-10. 전체관리자가 결제 불일치 또는 환불 실패를 수동 처리한다

- **주체:** 활성 `PLATFORM_ADMIN` 또는 `SUPER_ADMIN`
- **목표:** 자동 처리로 종결되지 않은 거래 예외를 증거 기반으로 해결한다.
- **선행 조건:** 결제 불일치 또는 환불 시도 이력에 해결되지 않은 예외가 있다.

#### 기본 흐름

1. 전체관리자가 결제 불일치 또는 환불 실패 건을 조회한다.
2. 시스템은 내부 이력, 외부 거래 식별자, 이전 시도와 권한 범위를 제공한다.
3. 전체관리자가 증빙 참조와 처리 사유를 입력한다.
4. 시스템은 불일치 종결 또는 P1 ERD가 허용한 전액 환불 조치를 기록한다.
5. 시스템은 처리 결과와 감사 이력을 남긴다.

#### 예외 흐름

- 증빙 또는 처리 사유가 없으면 수동 처리를 완료할 수 없다.
- 이미 종결된 거래를 중복 종결하지 않는다.
- 수동 처리로 예약·결제의 성공 또는 취소 상태를 강제로 바꾸지 않는다.

**적용 정책:** `ADM-04`, `ADM-05`

## 3. 전체관리자 정책

- `ADM-01`: `app_user.account_kind = PRIVILEGED` 계정에만 `platform_admin_assignment`를 둔다. 배정 등급은 `SUPER_ADMIN` 또는 `PLATFORM_ADMIN`, 상태는 `ACTIVE` 또는 `INACTIVE`다. 최초 슈퍼관리자는 내부 부트스트랩으로 준비하고, 활성 슈퍼관리자만 고권한 계정을 생성·비활성화한다. 비활성화는 배정 행을 `ACTIVE → INACTIVE`로 바꾸며 `app_user` 상태는 바꾸지 않는다. 자기 자신과 마지막 활성 슈퍼관리자는 비활성화할 수 없다.
- `ADM-02`: 지역 수명주기는 별도 상태가 아닌 `region.is_public`으로 표현한다. `true → false`는 삭제되지 않은 콘텐츠가 없을 때만 허용한다.
- `ADM-03`: `user_role_assignment`에는 `VISITOR`, `OPERATOR`, `REGION_ADMIN`만 저장한다. 일반 계정만 역할을 가질 수 있으며, 역할은 삭제하지 않고 `ACTIVE`와 `REVOKED` 이력으로 관리한다.
- `ADM-04`: 결제 불일치와 환불 실패의 수동 처리는 증빙과 사유를 근거로 한다. P1에서는 불일치 종결 또는 전액 환불만 허용하며, 결제·예약 상태를 강제로 성공 또는 취소로 바꾸지 않는다.
- `ADM-05`: 고권한 배정, 일반 역할, 지역, 거래 예외의 변경에는 처리자, 대상, 이전·이후 상태, 증빙 참조, 사유, 시각과 `requestId`를 남긴다. 탈퇴 뒤 처리자 연결이 비식별화되어도 대상 식별자와 감사 이력은 보존한다. 비밀번호, 토큰, 결제 비밀값과 전체 결제수단 정보는 기록하지 않는다.

## 4. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 고권한 계정 | `app_user.account_kind`, `platform_admin_assignment`, 등급·상태·비활성화 정보 | 전역 관리 권한 |
| 지역 | `region_id`, `is_public`, 콘텐츠 존재 여부 | 지역 공개 가능 여부 |
| 일반 역할 연결 | `role_assignment_id`, `user_id`, `region_id`, 역할, `ACTIVE`·`REVOKED` 이력 | 지역 관리자 권한 |
| 특권 감사 이력 | 처리자, 대상 유형·식별자, 변경 전후, 사유, 증빙 참조, 시각 | 권한·지역·거래 변경 재현 |
| 거래 예외 처리 | 결제 또는 환불, 예외 유형, 증빙, 조치, 처리자, 결과 | 수동 운영 처리 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [P1 ERD](../p1-erd.md)에 확정한다.

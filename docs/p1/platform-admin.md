> ADR-0009의 전체관리자 제외는 P0 범위의 결정이다. P1에서 전역 권한을 구현하기 전에는

## 1. 범위

### P1-FR-09. 전체관리자와 지역·역할 관리

- 전체관리자 계정을 생성하고 비활성화한다.
- 지역을 생성·조회하고 운영 상태를 변경한다.
- 지역 관리자 역할을 임명하고 회수한다.
- 모든 특권 변경은 대상, 처리자, 사유와 시각을 감사 이력으로 남긴다.

### P1-FR-10. 거래 예외 수동 처리

- 결제 불일치와 환불 실패를 식별·조회한다.
- 전체관리자는 증빙과 사유를 남기고 승인된 수동 처리 절차를 수행한다.
- 수동 처리는 원본 외부 거래 정보와 자동 처리 이력을 지우거나 임의로 덮어쓰지 않는다.

## 2. 유저 시나리오

### US-P1-09. 전체관리자가 지역과 관리자 역할을 관리한다

- **주체:** 전체관리자
- **목표:** 지역 운영에 필요한 지역과 지역 관리자 연결을 최소 권한으로 관리한다.
- **선행 조건:** 전체관리자 권한 모델과 최초 계정 준비 절차가 승인돼 있다.

#### 기본 흐름

1. 전체관리자가 새 지역 생성 또는 기존 지역 상태 변경을 요청한다.
2. 시스템은 처리자 권한과 지역 식별자 중복·상태 전이 조건을 검증한다.
3. 시스템은 지역 변경과 감사 이력을 함께 저장한다.
4. 전체관리자가 대상 사용자에게 지역 관리자 역할을 임명하거나 기존 역할을 회수한다.
5. 시스템은 대상 사용자, 담당 지역, 기존 역할과 충돌 여부를 검증한다.
6. 시스템은 역할 연결과 감사 이력을 함께 저장한다.

#### 예외 흐름

- 일반 방문자·운영자·지역 관리자는 지역 생성·상태 변경·관리자 역할 변경을 수행할 수 없다.
- 존재하지 않거나 비활성 상태인 사용자에게 역할을 부여하지 않는다.
- 자기 권한 변경, 마지막 운영 가능 관리자 회수와 같은 고위험 변경은 확정된 보호 규칙 없이 처리하지 않는다.

**적용 정책:** `ADM-01`~`ADM-03`

### US-P1-10. 전체관리자가 결제 불일치 또는 환불 실패를 수동 처리한다

- **주체:** 전체관리자
- **목표:** 자동 처리로 종결되지 않은 거래 예외를 증거 기반으로 해결한다.
- **선행 조건:** 결제 검증 이력 또는 환불 시도 이력에 해결되지 않은 예외가 있다.

#### 기본 흐름

1. 전체관리자가 결제 불일치 또는 환불 실패 건을 조회한다.
2. 시스템은 내부 이력, 외부 거래 식별자, 이전 시도와 권한 범위를 제공한다.
3. 전체관리자가 증빙 참조와 처리 사유를 입력해 승인된 조치를 선택한다.
4. 시스템은 수동 처리 기록, 관련 상태 변경 또는 재처리 요청을 함께 남긴다.
5. 시스템은 처리 결과를 방문자·담당 운영자 조회 범위에 맞게 반영한다.

#### 예외 흐름

- 증빙 또는 처리 사유가 없으면 수동 처리를 완료할 수 없다.
- 이미 종결된 거래를 새 수동 처리로 중복 종결하지 않는다.
- 권한 없는 사용자가 수동 처리 경로를 호출하면 내부 증빙·외부 거래 상세를 노출하지 않는다.

**적용 정책:** `ADM-04`, `ADM-05`

## 3. 전체관리자 정책

- `ADM-01`:
  전체관리자 계정은 생성과 비활성화를 구분한다. 비활성화된 계정의 새 특권 요청은 허용하지 않는다.
  인증 수단, 세션 무효화 시점과 최초 계정 준비 절차는 구현 전 확정한다.
- `ADM-02`:
  지역은 고유 식별자와 운영 상태를 가진다. 지역 생성·상태 변경은 전체관리자 전용 유스케이스에서만 수행하며,
  상태 변경이 공개 콘텐츠·예약·혜택에 미치는 영향은 정책으로 명시한다.
- `ADM-03`:
  관리자 역할의 임명·회수는 대상 사용자와 담당 지역의 관계를 검증한다.
  권한은 명시적으로 부여·회수하며 역할 변경으로 다른 지역 또는 콘텐츠 소유 권한이 암묵적으로 확대되지 않는다.
- `ADM-04`:
  결제 불일치와 환불 실패의 수동 처리는 자동 처리 이력, 외부 거래 식별자와 증빙을 근거로 한다.
  수동 조치의 종류, 이중 승인 필요 여부, 고객 통지와 재처리 방식은 구현 전 확정한다.
- `ADM-05`:
  전체관리자 계정·지역·역할·거래 예외의 모든 변경에는 actor, 대상, 이전·이후 상태,
  증빙 참조, 사유, 시각과 `requestId`를 남긴다. 비밀번호, 토큰, 결제 비밀값과 전체 결제수단 정보는 기록하지 않는다.

## 4. 구현 전 확정 항목

| 항목 | 확정할 내용 |
| --- | --- |
| 최초 계정 | 최초 전체관리자 생성 경로, 다중 관리자 허용 여부와 비상 복구 절차 |
| 계정 비활성화 | 세션·토큰 무효화 시점, 재활성화 권한과 감사·보관 정책 |
| 지역 상태 | 상태 종류, 상태 변경이 공개 콘텐츠·예약·혜택에 미치는 효과 |
| 역할 보호 | 자기 권한 변경, 마지막 관리자 회수, 복수 승인·분리 의무 |
| 수동 거래 처리 | 허용 조치, 증빙 형식, 이중 승인, 고객 안내와 외부 거래 정정 방식 |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 전체관리자 계정 | `user_id`, 계정 상태, 생성·비활성화 정보 | 전역 관리 권한 |
| 지역 | `region_id`, 지역 식별 정보, 운영 상태, 상태 변경 이력 | 지역 수명주기 |
| 관리자 역할 연결 | `user_id`, `region_id`, 역할, 임명·회수 정보 | 지역 관리자 권한 |
| 특권 감사 이력 | actor, 대상, 변경 전후, 사유, 증빙 참조, 시각 | 권한·지역 변경 재현 |
| 거래 예외 처리 | 결제 또는 환불, 예외 유형, 증빙, 조치, 처리자, 결과 | 수동 운영 처리 |

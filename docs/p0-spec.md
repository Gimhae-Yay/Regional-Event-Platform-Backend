# 로컬스탬프 P0 명세

| 항목 | 내용 |
| --- | --- |
| 분할 기준 원문 | [로컬스탬프 제품 PRD v1.6](local-stamp-platform-prd.md) |
| 원문 기준일 | 2026-07-25 |
| 대상 릴리스 | 김해시·동해시 2개 지역 무료 예약 MVP |
| 문서 성격 | 원문을 기반으로 현재 P0 정책과 채택 ADR을 반영한 구현 계약 |

> 이 문서는 현재 릴리스의 P0 구현 계약을 기능 단위로 분할한 문서다.
> P0 범위는 이 문서와 `p0/` 아래 소유 문서의 명시로 판단한다. 원문 PRD에 남아 있는
> 후속 기능·기술 문구는 P0 범위를 확장하지 않는다. 현재 P0에서 별도로 확정한 정책과 채택 ADR은
> 이 문서와 소유 문서에 반영하며, 원문 정리는 별도 작업으로 처리한다.

## 1. 문서 사용 원칙

- 현재 무료 예약 MVP의 목표, 범위, 요구사항, 정책과 출시 수용 기준은 현재 릴리스의 구현 계약이다.
- 유저 시나리오는 주체별 이용 흐름, 기능 요구사항은 구현할 능력,
  정책 카탈로그는 상태·수치·예외·처리 주체, 출시 수용 기준은 검증 결과를 정의한다.
- 분할본 내부에서 기능별 상세 정책은 `p0/` 아래의 소유 문서 한 곳에만 두며,
  이 문서에서는 요구사항과 완료 기준으로 연결한다.
- 원문과 현재 P0 정책이 다르면 이 문서와 소유 문서에 명시된 현재 P0 계약을 적용하고
  차이는 채택 ADR 또는 확정된 제품 정책으로 추적한다.
- API 요청·응답 계약은 [API 명세서](api-specification.md), 테이블·제약·계산식은 [ERD](erd.md)를 기준으로 한다.
- 이 문서에서 새로 확정한 행위가 API 명세서나 ERD에 아직 정의되지 않았다면 추측해 구현하지 않고,
  해당 API·DB 계약을 별도 문서 작업으로 확정한 뒤 구현한다.

## 3. 제품 흐름

핵심 흐름은 다음과 같다.

```text
지역 콘텐츠 탐색
→ 최대 10분 정원 홀드
→ 무료 예약 확정
→ 체크인 창에서 단기 서명 QR 발급·갱신
→ 권한 있는 운영자의 현장 체크인
→ 방문 기록에 근거한 인증 후기
```

## 4. P0 목표

### 4.1 핵심 목표

1. **핵심 전환 검증:**
   김해시와 동해시에서 사용자가 행사·체험을 발견하고 무료 예약한 뒤 실제 QR 체크인까지 완료할 수 있는지 검증한다.
2. **예약 및 방문 데이터의 신뢰성 확보:**
   최대 10분 정원 홀드, 예약 상태, 단기 QR, 예약당 한 건의 방문 기록을 일관되게 연결하고 중복·초과 처리를 방지한다.
3. **인증 후기 체계 검증:**
   체크인 완료 방문에만 후기 작성 권한을 부여하고 수정·삭제 정책이 정확히 동작하는지 검증한다.
4. **최소 운영 가능성 검증:**
   운영자의 콘텐츠·회차 등록과 QR 체크인, 지역 관리자의 승인·반려 및 예외 조회가
   최소 도구로 수행 가능한지 확인한다.
5. **다지역 격리 기반 확보:**
   사용자 권한, 콘텐츠, 회차, 예약, 방문, 후기를 `region_id`와 연결해
   김해시와 동해시의 데이터와 권한을 분리한다.

## 5. P0 범위

### 5.1 포함 범위

상세 정책의 단일 소유 문서는 다음과 같다.

- [인증·프로필](p0/auth-profile.md): `FR-01`, `FR-09` 인증, 역할, 지역 권한, 운영자 승인·소유권과 개인정보
- [지역·콘텐츠 카탈로그](p0/content-catalog.md): `FR-02`~`FR-04`, `FR-14` 탐색, 등록, 승인과 콘텐츠 수명주기
- [정원 홀드·무료 예약](p0/reservation.md): `FR-05`, `FR-06` 회차 정원과 무료 예약
- [예약 QR·체크인](p0/check-in.md): `FR-07` 단기 예약 QR, 일회 체크인과 방문 기록
- [인증 후기](p0/review.md): `FR-08` 방문 기록 기반 후기
- 이 문서의 `FR-10` 최소 운영 도구와 `FR-11` 감사 및 운영 로그

### 5.2 비목표

다음 항목은 현재 MVP 범위에 포함하지 않는다.

- 유료 예약, 결제 승인·웹훅·취소·환불과 결제 정합성 검증
- 쿠폰 발급·사용·복구
- 스탬프북, 지역 미션, 포인트, 현금성 보상
- 고도화된 운영자·지역 관리자 통계 대시보드
- 후기 확장: 후기 신고, 내 신고 처리 상태, 신고 검토·조치, 운영자 답글 작성·수정·삭제, 지역별 후기 피드
- 전체 관리자 역할·계정·화면·API와 지역 생성, 지역 관리자 임명·변경, 공통 운영 기준의 런타임 관리
- 운영자·지역 관리자 계정의 셀프 탈퇴, 담당 지역 해제와 콘텐츠 소유권 이전·재배정
- 프런트엔드 사용자 채널(Web)과 사용자용 화면 구현
- 예약 확정·행사 전 리마인드·취소·변경·체크인 성공 알림 이벤트 발행
- 로그인·예약 확정·QR 스캔의 사용자/IP 기준 요청 제한과 `429` 정책

공통 콘텐츠 모델은 P0 행사·체험을 위한 범위만 구현한다.
[ADR-0006](adr/0006-use-shared-content-root-with-type-specific-details.md)을 따른다.

## 6. 사용자와 권한

| 사용자 | MVP 역할 | 핵심 니즈 |
| --- | --- | --- |
| 주말 나들이 방문자 | 지역 선택, 탐색, 무료 예약, QR 제시, 인증 후기 작성 | 믿을 만한 체험을 한곳에서 찾고 예약·방문까지 완료 |
| 지역 주민·재방문 사용자 | 방문자와 동일한 무료 예약·체크인 흐름 | 익숙한 지역의 새 콘텐츠 발견과 참여 |
| 행사·체험 운영자 | 담당 지역 콘텐츠·회차 등록, 수정본 제출·철회, 콘텐츠 철회 요청, 회차 취소, 마스킹된 예약자 조회와 QR 체크인 | 신청·명단·현장 참가를 하나의 흐름으로 관리 |
| 지역 관리자 | 담당 지역 운영자 승인·반려, 콘텐츠·수정본 심사, 운영 중단·철회 승인, 상태별 공개 전 삭제, 마스킹된 예약자 예외 조회 | 지역별 권한·공개 품질과 운영 이슈 통제 |

MVP의 최우선 고객은 **주말 나들이 방문자**, 최우선 공급자는 **예약형 행사·체험 운영자**다.
지역 관리자는 구매 고객보다 서비스 운영을 가능하게 하는 필수 주체로 본다.

## 8. 공통 기술·운영 규칙

### 8.1 기술 구성

- 실제 버전·의존성과 공통 기술 구성은 [기술 스택 문서](local-stamp-platform-tech-stack.md)를 참조하되,
  현재 P0 기능 범위는 이 문서의 포함·비목표와 8.2절을 적용한다.
- 초기 MVP는 백엔드 API와 보호된 최소 운영 API를 범위로 한다.
- 프런트엔드 프레임워크, 사용자 채널(Web), API 문서화 도구는
  현재 MVP의 출시 기준으로 간주하지 않으며 화면 구현 착수 전에 별도 기술 결정으로 확정한다.

### 8.2 설계 원칙

- Redis는 지역 홈·공개 콘텐츠 목록·상세 캐시와 [ADR-0023](adr/0023-manage-refresh-token-revocation-in-redis.md)의 Refresh Token 회전·폐기 TTL 키 공간에 사용한다.
- 로그인·예약 확정·QR 스캔의 애플리케이션 요청 제한과 `429` 계약은 5.2절에 따라 P0에서 제외한다.
- [ADR-0001](adr/0001-use-mysql-conditional-update-for-capacity-consistency.md)의 정원 정합성 결정은 유지하되,
  그 문서의 요청 제한 용도 문구는 현재 P0 범위를 확장하지 않는다.
- 잔여 정원과 예약 가능 여부는 캐시하지 않으며 예약 정합성과 동시성 제어의 최종 책임은 MySQL이 가진다.
- 초기 MVP 예약 경로에는 Redis 분산 락을 사용하지 않는다.
- 예약 확정과 체크인은 재시도를 전제로 멱등하게 설계한다.

### 8.3 보안·개인정보

- QR 토큰의 온디맨드 발급·갱신, 서명과 유효 기간은 [체크인 정책](p0/check-in.md#qr-01)과
  [ADR-0010](adr/0010-issue-short-lived-qr-on-demand-and-separate-retry-idempotency.md)을 적용한다.
- 개인정보, JWT 키와 QR 원문을 로그에 남기지 않는다.
- 역할·지역·소유권 검증과 최초 소유자 설정은
  [ADR-0011](adr/0011-bootstrap-operator-ownership-on-content-creation.md)을 적용한다.
- 예약자 마스킹과 회원 탈퇴 후 작성자 연결 제거는
  [인증·프로필 정책](p0/auth-profile.md#auth-privacy-policies)을 적용한다.
- 회원 탈퇴 후 작성자 연결이 제거된 후기 원문과 방문 사실의 보존은
  [ADR-0012](adr/0012-retain-author-unlinked-reviews-and-visits-after-withdrawal.md)을 적용한다.

### 8.4 정합성·신뢰성

- 예약과 체크인의 정합성·멱등성은 각 소유 정책과 출시 수용 기준으로 검증한다.
- 정책 위반과 실패 사유는 감사 기록으로 추적할 수 있어야 한다.

### 8.5 관측 가능성

- 모든 요청에 `requestId`를 부여하고 홀드·예약·방문 ID 및 상태 전이를 구조화 로그로 연결한다.
- 홀드 만료·정원 복구, 예약 확정 실패, QR 실패 사유, 권한 거부와 오류율을 관찰한다.
- 상태 전이 기록을 지역, 콘텐츠, 회차별로 재현할 수 있어야 한다.

### 8.6 성능·가용성

- 지역 홈과 공개 콘텐츠 조회는 캐시 적용 전후를 같은 조건으로 측정해 병목과 효과를 확인한다.
- 응답 시간·가용성 목표 수치는 예상 트래픽과 운영 시간이 확정된 뒤 SLO로 정의한다.

### 8.7 최소 운영 도구

`FR-10`은 고도화된 대시보드 없이도 다음 작업을 수행할 수 있는 역할별 내부용 최소 화면 또는 보호된 운영 API를
요구한다. 운영자는 소유 콘텐츠, 지역 관리자는 담당 지역으로 범위를 제한하며 전체 관리자나 지역 범위 우회
기능을 포함하지 않는다.

- 지역 관리자의 운영자 승인 요청 사업자 정보·요청 지역 확인과 승인·반려
- 지역 관리자의 콘텐츠 승인·반려, 수정본 심사, 운영 중단, 전체 콘텐츠 철회 승인과 상태별 공개 전 삭제
- 운영자의 소유 콘텐츠 예약자 목록·예약 번호 조회와 지역 관리자의 QR 예외 단건 조회
- 운영자와 지역 관리자에게 노출되는 예약자 이름·연락처의 동일 형식 마스킹
- QR 실패·보조 조회 예외의 사유, 처리자와 처리 시각 기록

지역 관리자의 운영 예외 처리에 대한 유저 시나리오는 [US-05. 지역 관리자가 운영 예외를 처리한다](local-stamp-platform-prd.md#us-05-지역-관리자가-운영-예외를-처리한다)를 참조한다.

### 8.8 감사 및 운영 로그

`FR-11`은 콘텐츠와 홀드→예약→체크인→후기 상태 전이 및 실패 사유를 감사 기록으로 재현할 것을 요구한다.
외부 전송을 위한 이벤트 발행·전달·재시도·소비는 P0 구현 계약에 포함하지 않으며,
[ADR-0013](adr/0013-defer-transactional-outbox-from-p0.md)을 따른다.

- 감사 로그는 `requestId`, actor, entity, transition, 사유가 필요한 전이의 reason, timestamp를 연결한다.
- 예약·홀드·체크인·권한·후기 상태 전이와 실패 원인을 지역·콘텐츠·회차별로 재현할 수 있어야 한다.
- 운영자 승인·반려와 역할·지역 부여, 최초 콘텐츠 소유자 설정, 콘텐츠 승인·반려·자동 공개·수정 심사·
  운영 중단·철회·종료·삭제의 처리 주체와 시각을 구분한다.
- 회원 탈퇴 후에는 감사·멱등 기록을 포함한 간접 연결로도 탈퇴 회원을 역참조할 수 없게 한다.

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 감사 로그 | requestId, 활성 actor 또는 모든 탈퇴 방문자에게 동일한 공통 actor `WITHDRAWN_MEMBER`, entity, transition, 상태별 사유, timestamp | 운영 추적, 상태 전이 재현과 탈퇴 후 역참조 차단 |

## 9. 테스트 및 출시 수용 기준

MVP 출시 전 다음 자동화 테스트와 운영 검증을 모두 통과해야 한다.
이 표는 정책을 새로 정의하지 않고 정책 카탈로그의 요구사항이 관찰 가능한 결과로 충족됐는지 판정한다.

| ID | 연결 정책 | 합격 기준 |
| --- | --- | --- |
| `AC-01` | `RSV-01`, `RSV-02` | 마지막 1자리에 동시 홀드 요청이 발생해도 `ACTIVE` 홀드는 하나만 생성되고 활성 홀드와 유효 예약이 확보한 인원은 회차 정원을 초과하지 않는다. |
| `AC-02` | `RSV-01` | 홀드는 최대 10분 동안만 활성이고 회차 시작이나 정책 무효화가 먼저면 즉시 종결되며, 만료·무효화에 성공한 최초 처리만 정원을 한 번 복구하고 종결 홀드로 예약을 확정할 수 없다. |
| `AC-03` | `RSV-03` | 동일 사용자의 동일 예약 확정 요청을 반복해도 예약과 `ACTIVE → CONSUMED` 전이는 각각 한 번만 발생하고 홀드 생성 때 차감한 정원은 다시 변경되지 않는다. |
| `AC-04` | `QR-01`, `QR-02` | 체크인 창 안의 확정 예약에만 단기 QR이 발급·갱신되고 체크인 창 밖·취소·만료 예약·취소 회차·다른 회차·위변조 QR과 권한 없는 운영자 요청은 모두 거부된다. |

| `AC-09` | `CON-05` | 공개 콘텐츠 수정 심사 중 기존 공개본을 유지하고 승인본만 반영한다. 공개 전 `APPROVED` 콘텐츠의 수정 요청은 후보 `publish_at`과 함께 원본을 `PENDING`으로 전이해 자동 공개를 차단하며, 승인된 후보만 반영해 다시 `APPROVED`로 전이한다. 공개 전 수정본의 반려·철회 뒤 원본은 `PENDING`을 유지한다. 반복 철회는 같은 `EDIT_WITHDRAWN` 결과를 반환하고 승인·반려·철회 중 최초 종결 전이 뒤의 다른 전이는 거부되어 원본에 영향을 주지 않는다. |

| `AC-11` | `CON-06` | 콘텐츠 운영 중단 시 중단 시각·처리자·사유가 기록되고 방문자에게 중단 안내와 사유가 표시된다. |

| `AC-13` | `REV-01`, `REV-03` | 체크인 완료 방문당 후기 한 건만 작성할 수 있고 체크인 없는 사용자의 작성과 등록 후 30일이 지난 후기의 수정은 거부된다. |
| `AC-14` | `REV-04` | 후기 삭제 즉시 공개 조회에서 제외되고 복구되지 않으며 삭제 시점 30일 후 별점·텍스트 원문이 영구 삭제된다. |

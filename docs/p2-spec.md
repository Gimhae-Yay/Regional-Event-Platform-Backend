# 로컬스탬프 P2 명세

| 항목 | 내용 |
| --- | --- |
| 참고 문서 | [로컬스탬프 제품 PRD](local-stamp-platform-prd.md) |
| 기준일 | 2026-07-27 |
| 대상 릴리스 | 운영 성과 판단, 후기 신뢰 운영, 웹 사용자 채널 |
| 문서 성격 | 이번 P2 구현 목록을 기준으로 새로 작성한 기능 계약 |

> 이 문서는 PRD의 장기 방향을 참고하되, 원문을 기능별로 재배치한 문서가 아니다.
> P2에 필요한 지표·후기·웹 범위를 이 문서와 `p2/`의 소유 문서에서 새로 정의한다.

## 1. 문서 사용 원칙

- P2는 P0·P1에서 확정된 예약·방문·후기·혜택·거래 데이터를 소비한다. 기존 원본 상태를 통계나 화면 편의를 위해 수정하지 않는다.
- 기능별 상세 정책은 `p2/` 아래의 소유 문서 한 곳에만 둔다.
- 지표의 이름, 분자·분모, 집계 기간, 시간대, 포함 상태와 갱신 주기는 구현 전에 명세·API·ERD로 확정한다.
- 후기 확장은 P0의 후기 작성 자격, 수정·삭제·원문 파기 계약을 변경하지 않는다.
- 웹은 유일한 프런트엔드 채널로 제공하며, 인증·인가의 최종 판단은 항상 서버가 수행한다.
- 프런트엔드 기술 선택, 신고 조치 규칙, 답글 권한과 지표 산식처럼 선택지가 있는 항목은 ADR 결정 전 구현하지 않는다.

## 3. P2 제품 목표

P2는 P0·P1에서 누적된 운영 데이터를 지역과 콘텐츠 맥락에서 읽을 수 있게 하고,
후기 신뢰 문제를 처리하며, 방문자·운영자·관리자가 실제로 사용할 웹 채널을 제공하는 단계다.

핵심 흐름은 다음과 같다.

```text
예약·방문·혜택·거래 이력
→ 고정된 기준의 운영 지표
→ 역할별 대시보드 확인

후기 게시
→ 신고·검토·조치 또는 운영자 답글
→ 지역 후기 피드와 처리 상태 확인

브라우저
→ 방문자·운영자·관리자 웹 화면
→ 서버 권한 검증을 거친 API
```

### 3.1 핵심 목표

1. **운영 판단 가능성:**
   콘텐츠별·회차별 예약과 방문 지표를 동일한 기준으로 비교할 수 있게 한다.
2. **후기 신뢰 운영:**
   신고와 조치를 분리된 이력으로 처리하고, 콘텐츠 운영 주체가 책임 범위 안에서 답글을 관리하게 한다.
3. **웹 사용성:**
   별도 네이티브 앱 없이 브라우저에서 P0~P2 기능을 역할별로 이용할 수 있게 한다.
4. **개인정보·권한 보호:**
   통계에는 비식별 집계만 제공하고, 웹 화면이 숨겼다는 이유로 서버 권한 검증을 생략하지 않는다.

## 4. P2 범위

### 4.1 포함 범위

- 운영 통계 대시보드
- 콘텐츠별 또는 회차별 예약 및 방문 지표
- 후기 신고
- 내 신고 처리 상태
- 신고 검토 및 조치
- 후기 답글 작성·수정·삭제
- 지역별 후기 피드
- 웹 프런트엔드

### 4.2 비목표

- 네이티브 모바일 앱 또는 별도 앱 스토어 배포
- 개인 단위 행동 추적·프로파일링 또는 식별 가능한 통계 내보내기
- 자동 추천·AI 기반 신고 판정·자동 후기 생성
- P1 범위 밖의 신규 결제·혜택 정책 변경
- P3 알림 전달과 요청 제한

## 5. 사용자와 권한

| 사용자 | P2에서의 역할 |
| --- | --- |
| 방문자 | 공개 후기 피드를 조회하고, 본인이 작성한 후기의 신고와 신고 처리 상태를 확인한다. |
| 콘텐츠 운영자 | 담당 콘텐츠 범위의 운영 지표를 확인하고 권한이 있는 후기에 답글을 관리한다. |
| 지역 관리자 | 담당 지역의 운영 지표와 신고 검토 업무를 수행한다. |
| 전체관리자 | 확정된 전역 범위의 집계·감사·에스컬레이션을 수행한다. |

지표 조회와 신고·답글 조치는 역할, `region_id`, 콘텐츠 소유 관계로 제한한다.
각 역할에 제공할 지표의 세부 범위와 신고 검토 권한은 구현 전에 확정한다.

## 7. 공통 기술·운영 규칙

### 7.1 지표 계약과 데이터 품질

- 모든 지표는 지표명, 버전, 분자·분모, 기간, 시간대, 필터, 포함·제외 상태와 데이터 기준 시각을 명시한다.
- 콘텐츠·회차 지표는 같은 지역·기간·지표 정의를 공유할 때만 비교 가능하다고 표시한다.
- 집계 지연, 원본 데이터 보정, 재집계와 지표 정의 변경은 결과에 반영된 기준 시각과 버전을 남긴다.
- 대시보드는 원본 거래 상태를 변경하는 수단이 아니다.

### 7.2 후기 신뢰·개인정보

- 후기 신고, 검토, 조치와 답글의 변경은 원후기와 분리된 이력으로 보존한다.
- P0의 유효 방문 기록당 후기 한 건, 작성 후 30일 수정, 삭제 즉시 비공개와 원문 파기 정책을 계속 적용한다.
- 신고자 정보와 신고 증빙은 공개 후기 피드·답글·운영자 화면에 불필요하게 노출하지 않는다.

### 7.3 웹 채널

- P2 프런트엔드는 웹으로만 제공한다. 브라우저 종류나 화면 크기에 따라 역할·권한·데이터 범위가 달라지지 않는다.
- 화면의 메뉴 숨김, 라우팅 제어, 입력 검증은 보조 수단이며 서버 API의 인증·인가·유효성 검증을 대체하지 않는다.
- 웹 화면은 API 명세의 성공·실패 응답을 사용하며, 임의의 오류 형식이나 권한 판정을 만들지 않는다.

### 7.4 관측·감사

- 대시보드 조회에는 지표 정의 버전·기간·지역·대상 범위를, 신고·답글·조치에는 actor, 대상, 사유, 시각과 `requestId`를 남긴다.
- 공개 후기나 통계 응답에 토큰, 신고 원문, 연락처 등 민감 데이터를 포함하지 않는다.

## 8. 구현 전 확정 항목

| 항목 | 구현 전 확정할 내용 | 결정 필요 이유 |
| --- | --- | --- |
| 지표 사전 | 예약·방문 지표의 산식, 포함 상태, 시간대, 갱신 주기와 권한별 조회 범위 | 같은 숫자를 서로 다르게 해석하지 않게 한다. |
| 신고 정책 | 신고 사유, 중복 신고, 검토 상태, 조치 종류, 이의·보관 규칙 | 신고와 후기 공개 상태의 관계를 명확히 해야 한다. |
| 답글 정책 | 답글 작성 권한, 후기당 개수, 수정·삭제 후 노출과 후기 삭제 시 처리 | 콘텐츠 소유권과 사용자 경험에 영향을 준다. |
| 피드 정책 | 정렬, 페이징, 지역 필터, 조치된 후기의 노출 기준 | 공개 범위와 신뢰 운영을 함께 결정해야 한다. |
| 웹 기술 | 프레임워크, 인증 토큰 보관, 라우팅·배포·접근성 기준 | 웹만 제공한다는 채널 결정 이후의 기술 선택이다. |

## 9. 테스트 및 출시 수용 기준

| ID | 연결 정책 | 합격 기준 |
| --- | --- | --- |
| `P2-AC-01` | `DST-01`, `DST-03` | 같은 지역·기간·지표 정의의 콘텐츠·회차 결과는 동일 원본 데이터에서 재계산한 결과와 일치하고 기준 시각·버전을 표시한다. |
| `P2-AC-02` | `DST-02`, `DST-04` | 운영자·지역 관리자·전체관리자는 허용된 지역·소유 범위를 넘는 집계나 개인 식별 정보를 조회할 수 없다. |
| `P2-AC-03` | `REVX-01`, `REVX-02` | 방문자는 본인이 만든 신고의 상태만 조회하며, 반복 신고 요청이 중복 처리 이력을 만들지 않는다. |
| `P2-AC-04` | `REVX-03` | 신고 검토·조치는 처리자, 사유, 시각과 결과를 남기고 후기 공개 상태를 바꾸는 경우에도 원인을 재현할 수 있다. |
| `P2-AC-05` | `REVX-04` | 권한 있는 주체만 담당 후기의 답글을 작성·수정·삭제할 수 있고, 다른 콘텐츠 또는 다른 지역 후기는 처리할 수 없다. |
| `P2-AC-06` | `REVX-05` | 지역 피드는 공개 가능한 후기만 표시하며 삭제·비공개·조치 기준에 맞지 않는 후기와 신고자 정보는 노출하지 않는다. |
| `P2-AC-07` | `WEB-01`~`WEB-04` | 주요 방문자·운영자·관리자 흐름을 웹에서 수행할 수 있고, 클라이언트 우회 요청도 서버의 권한·검증 규칙에 의해 거부된다. |

## 10. 구현 작업 체크리스트

- [ ] `P2-FR-01`과 `P2-FR-02`의 지표 사전, API·ERD·집계 검증 계약을 확정하고 구현한다.
- [ ] `P2-FR-03`부터 `P2-FR-06`까지의 신고·답글·피드 정책 ADR, API·ERD·권한 테스트 계약을 확정하고 구현한다.
- [ ] `P2-FR-07`의 웹 기술 ADR, 화면 범위·API 연동·접근성·보안 테스트 계약을 확정하고 구현한다.
- [ ] `P2-AC-01`부터 `P2-AC-07`까지 자동화·운영 검증을 통과한다.

## 11. 다음 우선순위 경계

- P3의 알림 이벤트와 요청 제한은 [P3 명세](p3-spec.md)에서 다룬다.
- 알림 전달 채널, 네이티브 앱, 개인화·추천은 이 릴리스의 구현 범위에 포함하지 않는다.

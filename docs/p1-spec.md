| 항목 | 내용 |
| --- | --- |

| 대상 릴리스 | 방문 기반 혜택, 유료 거래, 플랫폼 운영 확장 |
| 문서 성격 | 이번 P1 구현 목록을 기준으로 새로 작성한 기능 계약 |

## 1. 문서 사용 원칙

- P1의 구현 범위와 완료 기준은 이 문서를 기준으로 한다.
- 기능별 상태, 예외, 데이터 요구사항은 `p1/` 아래의 소유 문서 한 곳에서만 상세화한다.
- API 요청·응답, HTTP 상태, 오류 코드와 페이지 계약은 구현 전에 [API 명세서](api/api-specification.md)에 확정한다.
- P0 재사용 테이블은 [P0 ERD](erd.md), P1 추가·변경 테이블·제약·멱등성 보장 수단은 [P1 ERD](p1-erd.md)를 기준으로 한다.
- 이 문서가 `구현 전 잔여 확정`으로 표시한 항목은 선택지 비교, 사용자 결정, ADR 기록을 마치기 전까지 구현하지 않는다.
- P0의 무료 예약·방문·후기 불변 조건을 유지한다. 유료 예약은 P1 결제 계약이 확정된 범위에서 확장하고,
  스탬프·미션·쿠폰은 P0에서 확정된 방문 기록을 근거로 사용한다.

## 3. P1 제품 목표

P1은 P0에서 만들어진 신뢰 가능한 방문 기록을 재방문 혜택과 지역 참여로 연결하고,
유료 예약의 결제·환불 상태를 운영 가능한 방식으로 관리하는 단계다.
플랫폼 전체를 다루는 운영 주체를 도입해 지역 추가, 역할 변경, 거래 예외를 감사 가능한 절차로 처리한다.

핵심 흐름은 다음과 같다.

```text
방문 완료
→ 스탬프·미션 진행도 반영
→ 조건 충족 시 보상·쿠폰 발급 또는 수령
→ 유료 예약 결제 승인·웹훅 확인
→ 취소·환불과 운영 예외 추적
```

### 3.1 핵심 목표

1. **방문 기반 혜택의 신뢰성 확보:**
   방문 기록 하나가 중복 적립·중복 보상·중복 발급으로 이어지지 않게 한다.
2. **유료 거래 정합성 확보:**
   예약, 결제, 환불을 분리된 상태로 관리하고 외부 결제 결과와 내부 기록의 불일치를 추적한다.
3. **권한 있는 플랫폼 운영:**
   전체관리자가 지역·관리자 역할·거래 예외를 다루되, 지역 경계와 최소 권한 원칙을 유지한다.
4. **재시도 가능한 운영 흐름:**
   사용자 요청, PortOne 웹훅, 운영자 재처리가 반복돼도 최초 처리 결과와 감사 이력이 일관되게 남게 한다.

## 4. P1 범위

### 4.1 포함 범위

- 스탬프북 `DRAFT` 작성·수정, 검토 요청, 지역 관리자 승인·반려, 공개·종료
- 방문 완료 기반 이벤트 적립
- 내 스탬프북 목록, 상세와 적립 이력 조회
- 지역 미션 `DRAFT` 작성·수정, 검토 요청, 지역 관리자 승인·반려, 공개·종료
- 지역 미션 목록·상세, 참여와 내 진행도 조회
- 미션 완료 보상 수령과 멱등성 처리
- 쿠폰 정책 `DRAFT` 작성·수정, 콘텐츠 소유 운영자 공개·종료
- 쿠폰 발급과 멱등성 처리
- 내 쿠폰 목록·상세, 사용 가능한 쿠폰, 쿠폰 사용 이력 조회
- 쿠폰 사용 확정
- PortOne 결제 생성, 승인 확인, 상태 조회와 웹훅 수신
- 유료 예약 취소·환불 요청, 내 환불 상태, 담당 예약의 결제·환불 상태 조회와 환불 재시도
- 고권한 계정·배정 생성·비활성화, 지역 생성·조회·공개 여부 변경, 이력형 지역 관리자 역할 임명·회수
- 결제 불일치와 환불 실패의 수동 처리

### 4.2 비목표

- 비예약형 가게·관광지의 새 방문 인증 수단
- 스탬프 또는 미션 보상으로서의 포인트·현금성 지급·정산
- 다중 쿠폰 조합, 장바구니 할인 계산, 자동 정산
- P2의 통계 대시보드·후기 확장·웹 사용자 화면
- P3의 알림 전달과 요청 제한

## 5. 사용자와 권한

| 사용자 | P1에서의 역할 |
| --- | --- |
| 방문자 | 본인 방문으로 생성된 스탬프·미션 진행도를 확인하고, 본인 쿠폰·결제·환불을 조회·처리한다. |
| 콘텐츠 운영자 | 자신이 담당한 콘텐츠 범위에서 스탬프북·미션·쿠폰 정책과 담당 예약의 거래 상태를 운영한다. |
| 지역 관리자 | 담당 지역의 공개 품질과 지역 범위 운영을 검토한다. 결제·환불 상태를 직접 변경하지 않는다. |
| 전체관리자 | `SUPER_ADMIN` 또는 `PLATFORM_ADMIN` 활성 배정으로 지역·관리자 역할을 관리하고, 명시된 결제 불일치·환불 실패를 수동 처리한다. 일반 역할과 겸임하지 않는다. |

모든 조회와 변경은 역할, `region_id`, 콘텐츠 소유 관계를 함께 검증한다.
전체관리자의 지역 범위 접근은 이 문서에 명시된 전용 관리 유스케이스로 한정하며 일반 사용자 경로를 우회하지 않는다.

## 7. 공통 기술·운영 규칙

### 7.1 방문·혜택 근거

- 스탬프 적립, 미션 진행과 방문을 근거로 한 쿠폰 발급은 P0의 유효 방문 기록을 기준으로 한다.
- 방문 기록을 새로 만들거나 수정해서 혜택을 맞추지 않는다. 누락·오처리는 보정 이력으로 처리하며 원본 근거를 보존한다.
- 동일한 방문 기반 처리의 중복 차단 기준은 구현 전에 ERD의 고유 제약과 처리 이력으로 함께 명시한다.

### 7.2 상태·멱등성·재시도

- 스탬프북, 미션, 쿠폰 정책, 쿠폰, 결제와 환불은 각각의 수명주기와 이력을 분리해 관리한다.
- 보상 수령, 쿠폰 발급·사용, 결제 승인, 웹훅 처리와 환불 재시도는 동일 요청이 반복될 때 새 효과를 만들지 않고 기존 결과를 반환해야 한다.
- 멱등 키의 범위, 보관 기간, 충돌 응답과 데이터베이스 제약은 API·ERD 계약으로 확정한다.

### 7.3 외부 결제 경계

- PortOne에 대한 승인 조회, 웹훅 검증, 취소·환불 호출은 내부 거래 트랜잭션과 분리한다.
- 클라이언트가 보낸 결제 성공 정보만으로 예약을 확정하지 않는다. 서버가 외부 거래 식별자, 금액과 대상 예약의 일치 여부를 검증한다.
- 외부 호출의 타임아웃·재시도·중복 호출은 내부 결제·환불 이력과 함께 추적하며, 장시간 외부 호출 동안 데이터베이스 잠금을 보유하지 않는다.

### 7.4 권한·감사·개인정보

- 특권 변경, 공개·종료, 혜택 발급·사용, 결제·환불 상태 변경과 수동 보정에는 actor, 대상, 이전·이후 상태, 사유, 시각과 `requestId`를 남긴다.
- 결제 비밀값, 웹훅 원문, 토큰, 전체 결제수단 정보와 개인정보는 로그·감사 이력에 저장하지 않는다.
- 미종결 유료 예약 또는 진행 중 환불이 있으면 탈퇴를 거부한다. 탈퇴 시 미사용 쿠폰은 `INVALIDATED`로 종결하고 혜택·결제·권한 이력의 사용자 연결과 감사 actor 연결을 제거한다. 종결 결제의 `payment_idempotency`만 생성 당시 비-FK 식별값을 최대 24시간 보관한 뒤 행 전체를 삭제한다.

### 7.5 API·DB·테스트 선행 조건

- P1 API 요청·응답, HTTP 상태, 오류 코드와 페이지 계약은 구현 전에 API 명세서에 추가한다. 데이터 모델은 [P1 ERD](p1-erd.md)를 기준으로 하고, 재사용 P0 테이블은 [P0 ERD](erd.md)를 함께 따른다.
- 혜택 공개·보상, 쿠폰, 유료 거래, 전체관리자·지역 권한과 탈퇴 정책은 ADR-0064~ADR-0071 및 P1 ERD가 정의한 내용을 따른다. 아래의 잔여 항목은 사용자 결정을 받은 뒤에만 API·구현 계약에 넣는다.
- 단위·통합 테스트에는 중복 요청, 동시 요청, 외부 응답 지연, 웹훅 재전송, 권한 거부와 수동 처리 이력 검증을 포함한다.

| --- | --- | --- |
| `P1-AC-01` | `STB-01`~`STB-03` | 지역 관리자 승인 전 스탬프북은 공개·적립되지 않고, `PUBLISHED` 뒤 핵심 값 수정은 거부된다. 대상 콘텐츠의 다른 회차 재방문과 같은 유효 방문의 반복 처리 모두 새 적립을 만들지 않는다. |
| `P1-AC-02` | `STB-04` | 사용자는 본인 스탬프북의 현재 진행도와 적립 근거를 조회할 수 있고 다른 사용자의 이력은 조회할 수 없다. |
| `P1-AC-03` | `MSN-01`~`MSN-03` | 지역 관리자 승인 뒤 `PUBLISHED`이고 `ends_at` 전인 미션만 참여할 수 있으며, 참여 전 방문·종료 뒤 방문·유효 방문의 중복 전달은 진행도를 만들거나 중복 증가시키지 않는다. |
| `P1-AC-04` | `MSN-04` | 완료 보상 수령 요청을 반복해도 보상 효과와 수령 이력은 한 번만 생성되고 최초 결과를 반환한다. |
| `P1-AC-05` | `CPN-01`~`CPN-03` | 콘텐츠 비소유 운영자는 정책을 운영할 수 없고, `DRAFT`·종료 정책으로는 쿠폰을 새로 발급할 수 없으며 운영자 임의 지급은 거부된다. 동일 발급 근거의 재시도는 하나의 쿠폰 결과로 수렴한다. |
| `P1-AC-06` | `CPN-04`~`CPN-05` | 사용 가능하지 않은 쿠폰은 가격 스냅샷에 적용·확정할 수 없으며, 같은 쿠폰의 동시 사용 요청 중 하나만 사용 효과를 만든다. 회차 시작 전 취소·환불 복구는 기존 이력을 `REVERSED`로 보존한다. |
| `P1-AC-07` | `PAY-01`~`PAY-03` | 활성 홀드와 불변 가격 스냅샷 없이 결제를 만들 수 없고, 서버 검증 없이 결제 성공·예약 확정이 되지 않는다. 늦은 승인·금액·주문·대상 불일치는 `DISCREPANT`로 기록된다. |
| `P1-AC-08` | `PAY-04` | 동일 웹훅의 재전송과 결제 승인 확인의 경합이 결제·예약 상태를 중복 전이시키지 않고 처리 이력을 남긴다. |
| `P1-AC-09` | `PAY-05`~`PAY-07` | 전액 환불 요청·재시도는 한 환불 건의 상태를 일관되게 전이하고 외부 호출은 총 3회를 넘기지 않는다. `FAILED` 환불은 고권한 관리자만 재시도하며, 방문자는 본인 상태만, 운영자는 담당 예약만 조회한다. |
| `P1-AC-10` | `ADM-01`~`ADM-03` | 일반 역할과 고권한 배정은 상호 배타적이며, 전체관리자가 아닌 사용자는 지역 생성·공개 여부 변경·관리자 역할 임명·회수를 수행할 수 없다. 마지막 슈퍼관리자와 콘텐츠가 있는 지역의 마지막 지역 관리자는 회수할 수 없고, 모든 특권 변경은 감사 이력으로 재현된다. |
| `P1-AC-11` | `ADM-04` | 결제 불일치 또는 환불 실패의 수동 처리는 원인 증빙, 처리자, 사유, 결과를 남기며 원본 외부 거래 정보를 임의로 덮어쓰지 않는다. |

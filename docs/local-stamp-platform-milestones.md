## 1. 적용 원칙

- 마일스톤은 작업량이나 임의의 날짜가 아니라 사용자·운영자가 확인할 수 있는 결과와 검증 증거로 종료한다.
- 구현 일정과 파일럿 시작일은 확정된 근거가 없으므로 이 문서에서 정하지 않는다.
- 파일럿 기간은 PRD에 확정된 6주만 사용한다. 첫 2주는 안정화, 이후 4주는 기술 검증 기간이다.
- 각 마일스톤의 구현 전에 관련 API 계약, 데이터 모델과 기술 결정이 문서에 반영돼 있어야 한다.
- 기능 이슈는 원칙적으로 API 하나를 하나의 이슈로 만들고, 해당 이슈를 주 마일스톤 하나에만 배치한다.
- 지역·소유권 검증, 개인정보 보호, 멱등성, 감사 로그와 자동화 테스트는 별도 후반 작업으로 미루지 않고
  각 기능과 함께 구현한다.
- 사업 KPI는 현재 MVP의 종료 조건으로 사용하지 않는다. M6과 M7은 PRD 13~14장의 기술 검증 기준으로 판정한다.
- M0~M8은 현재 무료 예약 MVP의 실행 마일스톤이다.
- M9~M22는 PRD의 장기 제품 방향을 실행 후보로 구체화한 조건부 마일스톤이다. 현재 구현 범위로 해석하지 않는다.
- 각 확장 단계는 직전 단계의 진입 조건을 충족하고 정책·ADR·API·ERD·수용 기준이 승인된 뒤에만 활성화한다.
- 확장 단계의 사업·제품 지표는 분자·분모, 집계 기간, 지역 범위와 목표치를 별도 운영 계획에서 확정한 뒤 사용한다.

## 2. 마일스톤 구성안 비교

| 안 | 구성 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 결과 중심 수직 분할(추천)** | 권한 → 콘텐츠 → 예약 → 체크인 → 후기 → 통합 검증 | PRD 사용자 흐름과 선후관계가 분명하고, 단계마다 통합 가능한 결과와 수용 테스트가 남는다. | 공통 보안·로그·인프라 작업을 각 단계에서 반복 확인해야 한다. |
| B. 기술 계층 중심 분할 | DB → 도메인 → 서비스 → API → 테스트 | 계층별 작업 배분이 단순하다. | 사용자 흐름이 후반까지 완성되지 않아 권한·정합성 문제를 늦게 발견할 수 있다. |
| C. PRD 제품 단계만 유지 | 현재 기반 → 거래·재방문 → 지역 참여 → 탐색·성과 | 마일스톤 수가 적고 장기 방향이 단순하다. | 단계가 너무 커서 구현 선후관계와 중간 종료 조건을 판정하기 어렵다. |

이 문서는 A안을 기준으로 작성한다. 승인 전까지 확정 정책이 아닌 검토안으로 취급한다.

## 4. 마일스톤 상세

### M0. 구현 계약 확정

**목표**

PRD와 채택된 ADR을 API·DB·테스트에서 해석이 갈리지 않는 구현 계약으로 구체화한다.

**포함 범위**

- `docs/api-specification.md`의 요청·응답, 역할, validation, HTTP status와 오류 코드
- `docs/erd.md`의 엔티티·관계·상태, 외래 키, 고유 제약, 인덱스와 삭제 정책
- 콘텐츠·홀드·예약·방문·후기의 상태 전이와 시간 기반 작업 계약
- 예약 확정과 체크인의 멱등 키 범위, 충돌 응답과 기록 수명주기
- 체크인 허용 시간, QR 만료와 키 관리, 보조 조회 허용 조건
- PRD와 기술 스택 문서 사이의 무료 예약·MySQL 정합성 기준 동기화
- P0 요구사항을 API·테이블·제약·테스트로 연결한 구현 이슈 분해

**완료 조건**

- API 명세와 ERD에 `추후 추가 예정` 항목이 없고 모든 P0 기능의 계약을 추적할 수 있다.
- PRD의 상태와 삭제 정책이 API 상태, DB 제약과 시간 기반 작업에 모순 없이 반영돼 있다.
- ADR-0001~0006의 결정이 API·ERD에 연결되고, 새 결정이 필요하면 구현 전에 별도 ADR로 채택돼 있다.
- 각 구현 이슈에 완료 조건, 정상·경계·실패 테스트와 관련 문서 링크가 있다.

### M1. 멀티리전 인증·권한 기반

**관련 요구사항:** FR-01, FR-09의 운영자 승인, FR-11의 공통 감사 기반

**목표**

방문자·운영자·지역 관리자·전체 관리자를 식별하고 모든 보호 API에서 현재 DB의 지역·소유 관계를 강제한다.

**포함 범위**

- 회원 가입·로그인·토큰 재발급·로그아웃과 계정 상태
- 짧은 수명의 JWT Access Token과 회전형 Refresh Token
- 김해시·동해시 지역, 역할과 담당 지역 부여
- 사업자 정보·담당 지역·콘텐츠 소유 관계를 확인하는 운영자 수동 승인
- 전체 관리자의 지역 생성과 역할 부여
- `requestId`, actor, region, entity를 연결하는 감사·구조화 로그 기반
- 로그인 요청 제한과 공통 인증·인가 실패 응답

**완료 조건**

- 네 역할의 허용·거부 행위가 자동화 테스트로 검증돼 있다.
- 김해시 담당자의 동해시 접근과 동해시 담당자의 김해시 접근이 목록·단건·변경 API 모두에서 차단된다.
- 운영자가 다른 운영자의 콘텐츠 소유 관계를 사용할 수 없다.
- Refresh Token 회전·재사용 탐지·계열 폐기가 검증돼 있다.
- JWT, Refresh Token 원문과 개인정보가 DB 평문 또는 로그에 남지 않는다.

### M2. 콘텐츠 생명주기·공개 탐색

**관련 요구사항:** FR-02, FR-03, FR-04, FR-10의 콘텐츠 운영, FR-14

**목표**

운영자의 행사·체험 및 회차 등록부터 지역 관리자의 심사, 예약 시각 공개와 방문자의 탐색까지 연결한다.

**포함 범위**

- 공통 콘텐츠 루트와 MVP 대상인 행사·체험 상세, 대표 이미지와 회차·정원
- 콘텐츠 초안, 승인 요청, 반려, 승인과 공개 예정 시각 변경 심사
- 승인된 콘텐츠의 예약 시각 자동 공개와 정상 종료
- 공개본을 유지하는 수정본 심사
- 운영 중단, 운영자 철회 요청과 지역 관리자 승인
- 상태별 하드 삭제·소프트 삭제·삭제 금지 정책
- 공개 지역, 지역 홈, 콘텐츠 목록·상세와 유형·예약 가능 여부 필터
- 콘텐츠 승인·반려·중단을 처리하는 보호된 최소 운영 API

**완료 조건**

- `PENDING`과 `APPROVED` 콘텐츠는 공개 조회와 캐시에서 노출되지 않는다.
- 승인된 공개 예정 시각이 도래한 콘텐츠만 한 번 `PUBLISHED`로 전환된다.
- 수정 심사 중 기존 공개본이 유지되고 승인된 수정본만 반영된다.
- `DRAFT`만 하드 삭제되고 `PENDING`·`APPROVED`는 삭제 정보를 남겨 소프트 삭제된다.
- 공개 후 콘텐츠는 삭제되지 않으며 중단·철회·종료 상태와 사유가 보존된다.
- 모든 상태 변경에 처리자, 시각과 사유가 남고 교차 지역·교차 소유 요청이 차단된다.

### M3. 무료 예약·정원 정합성

**관련 요구사항:** FR-05, FR-06, FR-09의 정보 마스킹, FR-11~12의 예약 이벤트

**목표**

회차 정원을 넘지 않는 10분 홀드를 생성하고 중복 요청에도 예약과 정원 차감을 한 번만 확정한다.

**포함 범위**

- MySQL 조건부 갱신을 이용한 정원 확보와 10분 홀드
- 만료 홀드의 조건부 전이와 정원 복구
- 활성 홀드의 멱등 예약 확정
- 회차 시작 전 전체 취소, 회차 시작 후 미체크인 예약의 `EXPIRED` 처리
- 운영자 회차 취소와 연결된 예약 전체 취소
- 방문자의 예약 내역과 운영자의 마스킹된 예약자 목록
- 예약 확정·취소·변경 이벤트의 Outbox 기록
- 예약 API 요청 제한

**완료 조건**

- MySQL Testcontainers의 마지막 잔여 정원 동시 테스트에서 확정 인원이 정원을 초과하지 않는다.
- 홀드는 생성 10분 후 연장 없이 만료되고 정원이 정확히 한 번 복구된다.
- 홀드 만료와 예약 확정이 경합해도 둘 중 하나만 성공하고 정원 수치가 일치한다.
- 동일 확정 요청을 반복해도 예약과 정원 차감은 한 번만 발생하고 이전 결과를 반환한다.
- 취소·만료·노쇼 상태와 부분 취소 금지 정책이 정상·경계·실패 테스트를 통과한다.
- 모든 운영자 조회에서 이름은 `김*수`, 연락처는 `010-****-1234` 형식으로 마스킹된다.

### M4. QR 체크인·현장 운영

**관련 요구사항:** FR-07, FR-10의 QR 운영, FR-11, FR-13의 QR 요청 제한

**목표**

확정 예약에 서명된 일회성 QR을 발급하고 유효한 현장 참여를 중복 없이 방문 기록으로 전환한다.

**포함 범위**

- 예약·회차·만료 시각을 검증하는 HMAC-SHA256 서명 QR
- 예약 상태, 회차, 체크인 시간, 운영자 지역·소유권 검증
- 영속 멱등 기록과 예약별 방문 고유 제약을 함께 적용한 체크인
- 예약 번호 보조 조회와 마스킹된 예약 정보
- 보조 처리 사유, 처리자, 처리 시각과 QR 실패 사유 기록
- QR 스캔 요청 제한과 현장 운영에 필요한 보호 API

**완료 조건**

- 동일 QR의 순차·동시 재스캔에도 방문 기록은 한 건이고 최초 성공 결과를 반환한다.
- 위·변조, 만료, 취소, 다른 회차와 권한 없는 운영자의 QR을 구분해 거부한다.
- 운영자는 담당 콘텐츠의 예약만 조회·체크인할 수 있다.
- 보조 조회와 예외 처리는 사유·처리자·시각을 남기며 동일한 개인정보 마스킹을 적용한다.
- QR 원문, HMAC 키, JWT와 개인정보가 로그에 남지 않는다.

### M5. 인증 후기·개인정보 수명주기

**관련 요구사항:** FR-08, PRD 12.1의 개인정보·탈퇴 정책

**목표**

유효한 방문 기록에만 후기를 허용하고 후기 삭제와 회원 탈퇴 이후의 데이터 수명주기를 보장한다.

**포함 범위**

- 방문 기록당 별점·텍스트 후기 한 건의 작성과 공개 조회
- 작성 후 30일 수정 제한과 기간 제한 없는 삭제
- 삭제 즉시 비노출, 복구 금지와 삭제 30일 후 원문 영구 삭제
- 회원 탈퇴 시 개인정보 파기와 후기·방문의 개인 연결 제거
- 법정 보존 대상 기록의 운영 데이터 분리

**완료 조건**

- 체크인하지 않은 사용자와 다른 사용자의 방문 기록으로는 후기를 작성할 수 없다.
- 방문 기록당 후기 한 건의 고유 제약과 중복 요청 처리가 검증돼 있다.
- 주입 가능한 `Clock`으로 수정 30일 경계와 영구 삭제 30일 경계를 검증한다.
- 삭제 후 공개 조회에서 즉시 제외되고 영구 삭제 작업을 반복해도 결과가 일치한다.
- 탈퇴 후 개인 연결은 제거되며 지역·콘텐츠·회차별 비식별 집계만 남는다.

### M6. 통합 기술 검증·파일럿 준비

**관련 요구사항:** FR-11~13 완결, PRD 12~14장

**목표**

핵심 흐름 전체를 두 지역 조건에서 재현하고 파일럿 운영에 필요한 배포·관측·예외 대응 준비를 마친다.

**포함 범위**

- 가입 → 탐색 → 홀드 → 예약 → QR 체크인 → 후기의 통합 시나리오
- MySQL·Redis Testcontainers 통합 테스트와 k6 동시성·부하 테스트
- Transactional Outbox 처리, 실패 재시도와 핵심 이벤트 추적
- 공개 지역 홈·목록·상세 캐시와 캐시 무효화
- 로그인·예약·QR 요청 제한의 임계값 검증
- Actuator, 구조화 로그와 운영 지표
- Docker 기반 외부 검증 환경, CI/CD와 배포·롤백 절차
- 운영자 온보딩, 현장 교육, QR 예외와 장애 대응 절차

**완료 조건**

- PRD 13장의 기술 검증 기준과 14장의 출시 수용 기준을 모두 통과한다.
- 상태 전이와 실패 원인을 김해시·동해시, 콘텐츠, 회차와 `requestId` 기준으로 재현할 수 있다.
- Redis 장애가 예약 정합성을 훼손하지 않고 잔여 정원·예약 가능 여부가 캐시되지 않는다.
- 부하 테스트 결과를 근거로 요청 제한과 성능 목표를 정하고 정상 현장 운영을 방해하지 않음을 검증한다.
- 해결되지 않은 P0·P1 리뷰 발견 사항이 없고 테스트·빌드·배포 검증이 통과한다.

### M7. 김해시·동해시 6주 파일럿

**목표**

두 지역에 동일한 운영 절차를 적용해 무료 예약·체크인·후기의 기술적 신뢰성과 최소 운영 가능성을 검증한다.

**진입 조건**

- M6의 출시 수용 기준을 모두 통과했다.
- 지역별 행사·체험 운영자 3곳 이상, 콘텐츠 5개 이상, 회차 15개 이상을 확보했다.
- 운영자 온보딩·현장 교육과 장애·예외 대응 담당자가 준비돼 있다.

**운영 구간**

- 1~2주: 안정화 운영, 배포·권한·현장 QR·운영 API 문제 우선 해소
- 3~6주: 동일 조건의 기술 검증, 예외 사유와 운영 피드백 수집

**완료 조건**

- 양 지역의 정원·홀드·멱등성·권한·QR·후기·개인정보 검증 결과가 남아 있다.
- 현장 예외와 장애가 지역·콘텐츠·회차·원인별로 분류돼 있다.
- 운영자 인터뷰와 사용자 피드백이 정책·UX 개선 후보로 정리돼 있다.
- 사업 KPI와 무관하게 기술 검증의 성공·실패 및 미해결 위험을 판정할 수 있다.

### M8. 확장 의사결정

**목표**

파일럿 증거를 기준으로 현재 MVP 보완, 지역·콘텐츠 확대 또는 후속 제품 단계 진입 여부를 결정한다.

**포함 범위**

- PRD 13~14장 항목별 결과와 미달 원인 정리
- 운영 예외, 보안·개인정보 문제와 기술 부채 정리
- 무료 예약 MVP 보완 또는 지역·콘텐츠 확대 여부 결정
- PRD의 장기 제품 확장 로드맵 중 다음 단계 진입 조건 평가
- 채택된 결정의 ADR·PRD 반영과 후속 마일스톤·이슈 작성

**완료 조건**

- 유지·보완·확장·중단 중 선택한 결론과 근거가 문서화돼 있다.
- 다음 후보인 거래·재방문 확장의 진입 조건 충족 여부와 M9 착수 여부가 기록돼 있다.
- 유료 예약·결제, 쿠폰과 Redis 분산 락은 자동 도입하지 않고 각각 정책·기술 검토 대상으로 분리돼 있다.
- 프런트엔드 프레임워크, 사용자 채널과 알림 채널은 착수하는 경우 별도 ADR로 확정돼 있다.
- 승인된 후속 범위만 활성 상태로 전환되고, 나머지 확장 마일스톤은 후보 상태를 유지한다.

## 5. 조건부 확장 마일스톤 상세

### 5.1 확장 마일스톤 상태

M9~M22는 다음 상태를 사용한다.

| 상태 | 의미 |
| --- | --- |
| 후보 | 장기 제품 방향에는 포함되지만 현재 구현 권한과 일정이 없는 상태 |
| 진입 검토 | 직전 단계의 증거를 바탕으로 정책·데이터·운영 조건을 확인하는 상태 |
| 승인됨 | 해당 단계의 PRD·ADR·API·ERD·수용 기준이 승인된 상태 |
| 계획됨 | 구현 이슈와 담당·일정이 확정된 상태 |
| 진행 중 | 승인된 구현 범위를 수행 중인 상태 |
| 완료 | 승인된 완료 게이트와 검증 증거를 모두 충족한 상태 |
| 보류·기각 | 진입 조건 미달 또는 전략 결정으로 진행하지 않는 상태 |

후보 상태에는 마감일을 부여하지 않는다. 승인된 뒤에도 일정은 별도 릴리스 계획에서 근거와 함께 확정한다.

### M9. 거래·재방문 구현 계약

**근거:** PRD 18.3의 예약·거래와 혜택·참여, PRD 19장의 거래·재방문 확장

**진입 조건**

- M8에서 거래·재방문 단계 착수를 명시적으로 결정했다.
- 무료 예약의 정원·홀드·멱등성과 체크인 데이터 신뢰성을 검증했다.

**후보 범위**

- 유료 예약, 결제 승인·실패·재시도, 취소·환불과 예약·결제 상태 분리
- 결제 실패와 예약·결제 불일치의 전체 관리자 수동 처리
- 체크인 기반 다음 예약 쿠폰의 발급·사용·복구
- 결제·쿠폰 이벤트와 제품 지표
- 유료 거래에서의 정원 홀드 방식과 Redis 분산 락 도입 여부 재검토

**완료 조건**

- 유료 예약 릴리스 PRD와 수용 기준이 승인돼 있다.
- 결제·취소·환불 및 쿠폰 자격·유효기간·사용·복구 정책이 승인돼 있다.
- 예약·결제·쿠폰 상태 전이와 멱등성·실패 복구 방식이 ADR로 채택돼 있다.
- API 명세, ERD, 마이그레이션, 오류 계약과 자동화 테스트 기준이 확정돼 있다.
- 결제 성공·실패율과 쿠폰 발급·사용률의 분자·분모·기간·지역 기준이 확정돼 있다.
- 무료 예약과 유료 예약의 경계 및 승인된 구현 이슈를 추적할 수 있다.

### M10. 유료 예약·결제·취소·환불

**진입 조건:** M9 완료

**목표**

무료 예약 흐름을 훼손하지 않으면서 유료 예약의 결제·취소·환불 상태와 금액 정합성을 보장한다.

**후보 범위**

- 결제사 연동을 격리하는 결제 포트와 어댑터
- 결제 승인·웹훅·실패·취소·환불
- 회차 시작 전 사용자 취소와 운영자 취소의 전액 환불
- 결제 실패·예약 불일치의 전체 관리자 조회와 수동 처리
- 결제 상태·실패 사유·처리 이력의 관측과 감사

**완료 조건**

- 예약과 결제 상태가 분리되고 승인된 상태 전이 밖의 변경을 거부한다.
- 중복 승인·웹훅·취소·환불 요청에도 금액과 상태 효과가 한 번만 발생한다.
- 외부 결제 장애와 처리 순서 역전에서도 승인된 복구 계약에 따라 정합성을 회복하거나 운영 대상으로 식별한다.
- 지역 관리자는 결제 상태를 변경할 수 없고 전체 관리자 처리에는 사유·처리자·시각이 남는다.
- 비밀키·결제 비밀값·개인정보가 로그에 남지 않고 무료 예약 회귀 테스트가 통과한다.

### M11. 체크인 기반 쿠폰·재방문

**진입 조건:** M10의 무료·유료 예약 및 결제 상태가 안정화되고 M9의 쿠폰 계약이 승인됨

**목표**

신뢰할 수 있는 체크인 기록을 다음 예약 쿠폰과 연결해 첫 재방문 동기를 검증한다.

**후보 범위**

- 체크인 완료 방문을 근거로 한 다음 예약 쿠폰
- 쿠폰 조회, 발급·사용·복구와 예약·결제 연결 이력
- 운영자 취소 시 승인된 정책에 따른 쿠폰 복구
- 체크인 사용자 재예약률과 쿠폰 발급 대비 사용률 계측

**완료 조건**

- 유효한 방문 기록에 대해서만 쿠폰이 한 번 발급된다.
- 중복·재시도에도 발급·사용·복구가 한 번만 반영된다.
- 예약·결제·취소·환불과 쿠폰 상태가 승인된 정책대로 일치한다.
- 지역·소유권·감사 경계를 유지하고 쿠폰 효과 지표를 같은 기준으로 재현할 수 있다.
- 스탬프·미션, 현금성 포인트와 다중 쿠폰 조합은 이 마일스톤에 포함하지 않는다.

### M12. 거래·재방문 통합 검증

**진입 조건:** M10~M11 완료

**목표**

유료 거래와 재방문 쿠폰의 신뢰성을 검증하고 지역 참여 확장 진입 여부를 결정한다.

**완료 조건**

- 무료·유료 예약, 결제·취소·환불, 체크인과 쿠폰의 통합 시나리오를 재현할 수 있다.
- 결제·환불·쿠폰의 중복·실패 재시도·순서 역전·운영 예외 테스트가 통과한다.
- 예약·체크인 데이터 신뢰성과 결제·쿠폰 정책·멱등성 검증 결과가 남아 있다.
- 다음 단계의 핵심 입력인 부정 인증 위험, 콘텐츠 밀도와 쿠폰 재방문 효과를 평가할 수 있다.
- M13 진입, 현 단계 보완 또는 보류 중 하나를 근거와 함께 결정한다.

### M13. 지역 참여 구현 계약

**근거:** PRD 18.3의 콘텐츠·방문 인증·후기·혜택, PRD 19장의 지역 참여 확장

**진입 조건**

- M12에서 지역 참여 단계 착수를 승인했다.
- 예약·체크인 데이터 신뢰성과 결제·쿠폰 정책·멱등성을 검증했다.

**후보 범위**

- 가게·관광지 콘텐츠의 등록·승인·탐색
- 예약형 QR과 분리된 비예약 방문 인증
- 후기 사진, 운영자 답글과 신고 처리
- 방문 기반 스탬프북, 지역 미션과 혜택 연결

**완료 조건**

- 가게·관광지의 필수 정보, 소유·승인·공개 정책이 승인돼 있다.
- 비예약 방문의 유효성, 중복·부정 인증과 운영 예외 처리 기준이 승인돼 있다.
- 후기 사진·답글·신고의 공개·보관·삭제·개인정보 정책이 승인돼 있다.
- 스탬프·미션의 자격, 상태, 중복 방지와 방문 무효화 정책이 승인돼 있다.
- 공통 콘텐츠 모델 확장과 방문 인증 방식을 ADR로 채택하고 API·ERD·수용 기준을 확정했다.
- 콘텐츠 밀도와 지역 참여 지표의 정의 및 승인된 구현 이슈가 준비돼 있다.

PRD 18.3은 후기 사진·답글·신고를 장기 기능으로 정의하지만 19장에서 제품 단계를 지정하지 않는다.
이 문서는 방문 유형 확장과 신뢰 정책을 함께 검증하기 위해 M15에 임시 배치하며, M13 승인 과정에서 위치를 조정할 수 있다.

### M14. 가게·관광지·비예약 방문 인증

**진입 조건:** M13 완료

**목표**

가게·관광지 콘텐츠를 공개하고 예약 없이 발생한 현장 참여를 신뢰할 수 있는 방문 기록으로 연결한다.

**후보 범위**

- 공통 콘텐츠 루트에 연결된 가게·관광지 상세
- 해당 유형의 등록·승인·공개·중단·탐색
- 예약 체크인과 다른 승인된 방식의 비예약 방문 인증
- 부정 인증·중복·운영 예외 처리와 감사 이력

**완료 조건**

- 유형별 필수 정보와 지역·운영자 소유 관계가 모든 조회·변경에 적용된다.
- 예약형·비예약형 방문은 서로의 규칙으로 인증되지 않는다.
- 위·변조·재사용·권한 없는 요청을 차단하고 유효한 방문 기록은 한 건만 생성한다.
- 기존 행사·체험 탐색과 예약 QR 체크인의 회귀 테스트가 통과한다.
- 위치 기반 자동 인증과 일반 음식점 좌석 예약은 별도 승인 없이 포함하지 않는다.

### M15. 후기 신뢰 기능 고도화

**진입 조건:** M14의 예약형·비예약형 방문 기록 신뢰성이 검증되고 M13의 후기 정책이 승인됨

**목표**

방문 인증 후기의 표현과 운영 기능을 확장하면서 기존 작성·수정·삭제 및 개인정보 정책을 유지한다.

**후보 범위**

- 인증 후기 사진
- 콘텐츠 운영자의 후기 답글
- 후기 신고와 관리자 처리 이력

**완료 조건**

- 사진 후기에도 유효한 방문 기록과 콘텐츠가 연결된다.
- 운영자는 자신이 소유한 콘텐츠 후기에만 답글을 작성할 수 있다.
- 신고와 처리 결과에 처리자·시각·사유가 남고 지역·관리 권한이 강제된다.
- 기존 후기 수정 30일, 상시 삭제, 즉시 비노출과 영구 파기 정책이 사진·답글·신고 데이터에도 적용된다.
- 이미지 개인정보·악성 파일·보관 정책과 공개 조회 회귀 테스트가 통과한다.

### M16. 스탬프북·지역 미션

**진입 조건:** M14의 부정 인증 방지와 콘텐츠 밀도가 승인된 기준을 충족하고 M13의 참여 정책이 승인됨

**목표**

신뢰할 수 있는 방문 기록을 스탬프와 지역 미션으로 연결해 반복적인 지역 참여를 지원한다.

**후보 범위**

- 방문 기반 스탬프 적립과 스탬프북
- 지역별 미션 참여·진행·완료
- 쿠폰을 포함한 승인된 혜택의 조회와 연결
- 지역 관리자 정책과 전체 관리자 공통 통제

**완료 조건**

- 모든 적립·달성·혜택 지급은 유효한 방문·예약·결제 이력을 근거로 한다.
- 중복·재시도에도 적립·달성·지급이 한 번만 반영된다.
- 방문 무효화와 이미 반영된 참여 기록은 승인된 보정 정책을 따른다.
- 지역 관리자는 담당 지역 정책만 관리하고 전체 관리자는 공통 정책과 예외만 통제한다.
- 스탬프 적립률, 미션 참여·완료율과 혜택 사용률을 승인된 기준으로 재현할 수 있다.

### M17. 지역 참여 통합 검증

**진입 조건:** M14~M16 완료

**목표**

비예약 방문과 참여 기능의 신뢰성을 검증하고 탐색·성과 고도화 진입 여부를 결정한다.

**완료 조건**

- 예약형·비예약형 방문, 후기, 쿠폰, 스탬프와 미션의 연결 이력을 재현할 수 있다.
- 부정 인증 방지, 중복 요청, 방문 무효화와 지역·소유권 경계 테스트가 통과한다.
- 지역별 충분한 콘텐츠 밀도와 쿠폰 재방문 효과를 사전에 승인한 기준으로 평가했다.
- 개인정보·비식별 집계와 운영 예외 처리의 미해결 위험이 기록돼 있다.
- M18 진입, 현 단계 보완 또는 보류 중 하나를 근거와 함께 결정한다.

### M18. 탐색·성과 구현 계약

**근거:** PRD 18.3의 콘텐츠·탐색과 데이터·성과, PRD 19장의 탐색·성과 고도화

**진입 조건**

- M17에서 탐색·성과 단계 착수를 승인했다.
- 부정 인증 방지, 콘텐츠 밀도와 쿠폰 재방문 효과를 검증했다.

**후보 범위**

- 지도 기반 탐색과 추천 코스
- 개인화·AI 추천
- 탐색·예약·방문·재방문·혜택·지역 성과 리포트

**완료 조건**

- 지도·추천 코스·개인화·AI·성과 리포트의 릴리스별 범위를 승인했다.
- 지표의 분자·분모, 집계 기간, 지역·콘텐츠 구분과 목표치를 확정했다.
- 데이터 품질·계보·비식별·보관·접근 정책을 승인했다.
- 추천 근거, 개인정보 최소 사용, 편향과 운영 활용성 평가 기준을 승인했다.
- 지도·추천·성과 데이터의 API·저장 계약, 기술 ADR와 구현 이슈가 준비돼 있다.
- 지도·AI·분석 공급자나 모델은 비교와 승인 없이 선결정하지 않는다.

### M19. 지도·추천 코스

**진입 조건:** M18 완료 및 승인된 데이터 품질 기준을 충족하는 지역·콘텐츠 확보

**목표**

공개된 지역 콘텐츠를 지도에서 탐색하고 최신 운영 정보를 반영한 추천 코스를 제공한다.

**완료 조건**

- 공개 상태, 지역 경계, 위치와 최신 운영 정보가 지도·코스 결과에 일관되게 적용된다.
- 종료·중단·철회 콘텐츠가 캐시로 계속 노출되지 않는다.
- 지도·코스 API의 성능·캐시·데이터 최신성 테스트가 통과한다.
- 지역 홈 대비 상세 진입률과 사용자당 탐색 콘텐츠 수를 승인된 기준으로 재현할 수 있다.
- 위치 기반 자동 방문 인증은 이 마일스톤에 포함하지 않는다.

### M20. 개인화·AI 추천

**진입 조건:** M19의 탐색 데이터 기반이 안정되고 M18의 추천·개인정보·편향 수용 기준이 승인됨

**목표**

신뢰할 수 있는 탐색·방문·재방문 데이터를 사용해 근거를 설명할 수 있는 개인화 탐색을 제공한다.

**완료 조건**

- 추천 결과의 근거와 사용한 데이터 범위를 설명할 수 있다.
- 지역·공개 상태·권한 경계를 넘는 추천이 발생하지 않는다.
- 개인 데이터 사용은 승인된 최소 범위를 넘지 않고 비개인화 대체 흐름을 유지한다.
- 데이터 품질, 추천 품질, 편향, 응답 성능과 운영 활용성 기준을 통과한다.
- RAG, 실시간 채팅과 SSE 대화형 탐색은 별도 승인 없이 포함하지 않는다.

### M21. 운영·지역 성과 리포트

**진입 조건:** M18 완료 및 지표·비식별·접근 정책 승인

**목표**

탐색부터 혜택 사용까지의 비식별 집계를 역할별 운영·지역 판단에 제공한다.

**후보 범위**

- 콘텐츠 발견, 예약·결제, 방문·재방문과 혜택 지표
- 콘텐츠 승인 시간, QR·방문 예외 처리 시간과 운영 가능한 콘텐츠·회차 지표
- 지역별 인증 방문·재방문·혜택 사용과 유료 거래 규모

**완료 조건**

- 모든 지표는 같은 분자·분모·기간·지역·콘텐츠 기준에서 재현된다.
- 운영자는 자신의 콘텐츠, 지역 관리자는 담당 지역, 전체 관리자는 승인된 공통 범위만 조회한다.
- 외부 보고에는 비식별 집계만 사용하고 소수 집계의 재식별 위험을 통제한다.
- 지표 정의와 실제 집계 결과의 정합성 및 데이터 최신성 테스트가 통과한다.

### M22. 탐색·성과 통합 검증

**진입 조건:** M19~M21 중 승인된 릴리스 범위 완료

**목표**

탐색·추천·성과 기능이 데이터 품질과 개인정보 원칙을 지키며 실제 운영 판단에 유용한지 검증한다.

**완료 조건**

- 데이터 품질, 추천 근거, 개인정보·편향과 운영 활용성 기준을 모두 평가했다.
- 지도·코스·개인화·성과 리포트의 지표와 결과를 지역·기간·콘텐츠 기준으로 재현할 수 있다.
- 기존 공개 상태·지역 권한·탐색·예약·방문 흐름의 회귀 테스트가 통과한다.
- 기술 비용, 품질, 성능, 운영 피드백과 미해결 위험이 다음 제품 주기의 판단 자료로 남아 있다.

## 8. 공통 종료 게이트

### 8.1 현재 기반 종료 게이트

M1~M6은 개별 완료 조건과 함께 다음 조건을 모두 만족해야 종료할 수 있다.

- 관련 PRD·API 명세·ERD·ADR와 구현이 일치한다.
- 역할뿐 아니라 현재 DB의 `region_id`와 콘텐츠 소유 관계를 모든 조회·변경에서 검증한다.
- 상태 변경과 시간 기반 작업은 중복 실행에도 같은 결과가 되도록 조건부 전이와 고유 제약을 사용한다.
- 예약·체크인 멱등성은 처리 이력과 도메인 고유 제약을 함께 사용한다.
- 정원 정합성과 MySQL 고유 동작은 H2가 아닌 MySQL Testcontainers로 검증한다.
- 정상·경계·실패·재시도·동시성 조건에 맞는 자동화 테스트가 있다.
- 로그와 오류 응답에 비밀번호, JWT, QR 원문, HMAC 키, 연락처 등 민감정보가 없다.
- `./gradlew test`와 `./gradlew build`가 통과하고 미해결 P0·P1 리뷰 발견 사항이 없다.

### 8.2 확장 마일스톤 종료 게이트

M9~M22가 후보에서 승인됨 상태로 전환된 뒤에는 개별 완료 조건과 함께 다음 조건을 적용한다.

- 직전 단계의 진입 조건과 해당 단계의 구현 계약 마일스톤을 모두 충족했다.
- 현재 기반과 이전 확장 단계의 회귀 테스트가 통과한다.
- 새 엔티티와 API에도 역할·지역·소유 관계, 개인정보·파기와 감사 정책을 적용한다.
- 거래·방문·혜택 상태 변경은 중복·재시도·순서 역전에도 멱등하고 추적 가능하다.
- 외부 시스템 장애가 핵심 데이터 정합성을 훼손하지 않고 승인된 복구 또는 운영 처리 경로가 있다.
- 제품 지표의 정의와 실제 집계가 일치하며 같은 조건에서 결과를 재현할 수 있다.
- 정상·경계·실패·동시성·보안·개인정보 테스트와 성능 검증이 통과한다.
- `./gradlew test`와 `./gradlew build`가 통과하고 미해결 P0·P1 리뷰 발견 사항이 없다.

## 10. 별도 승인 없이는 포함하지 않는 범위

다음 항목은 PRD v1.3의 현재 기반 또는 M9~M22 후보만으로 구현이 승인되지 않는다.

- 위치 기반 자동 방문 인증
- 실시간 채팅, SSE 대화형 탐색과 RAG
- 전국 단위 공공데이터 자동 수집·정제
- 일반 음식점 좌석 예약
- 현금성 포인트·보상, 다중 쿠폰 조합과 복잡한 혜택 지갑
- 여러 판매자 간 자동 정산
- 프런트엔드 프레임워크, 사용자 채널과 알림 전달 채널

필요한 기능은 별도 제품 결정과 PRD·ADR·API·ERD·수용 기준 승인을 거쳐 새 마일스톤으로 추가한다.

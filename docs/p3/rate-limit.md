| 소유 범위 | 로그인, 예약 확정, QR 스캔의 사용자·IP 기준 요청 제한과 `429` 응답 |

> 이 문서는 `FR-13`의 요청 제한 기능 계약을 정의한다. 임계값과 Redis 장애 시 동작은 구현 전에 결정한다.

## 1. 범위

### FR-13. 요청 제한

- 로그인 요청에 사용자·IP 기준 요청 제한을 적용한다.
- 예약 확정 요청에 사용자·IP 기준 요청 제한을 적용한다.
- QR 스캔 요청에 사용자·IP 기준 요청 제한을 적용한다.
- 허용량을 넘는 요청은 핵심 동작을 실행하지 않고 `429` 응답을 반환한다.
- 제한 발생·우회 시도·저장소 장애를 관찰하되 민감 정보를 저장하지 않는다.

## 2. 유저 시나리오

### US-P3-02. 시스템이 중요 요청의 과도한 반복을 제한한다

- **주체:** 로그인 사용자 또는 비인증 요청자, 시스템
- **목표:** 정상 사용자 흐름은 허용하면서 반복·자동화 요청이 인증·예약·현장 운영에 미치는 영향을 줄인다.
- **선행 조건:** 대상 API별 제한 알고리즘, 키 구성, 임계값과 `429` 응답 계약이 확정돼 있다.

#### 기본 흐름

1. 로그인, 예약 확정 또는 QR 스캔 요청이 수신된다.
2. 시스템은 API 유형과 인증 상태에 맞게 사용자·IP 기준 제한 키를 계산한다.
3. 시스템은 Redis에서 원자적으로 현재 허용량을 확인·갱신한다.
4. 허용량 안이면 원래 API 검증과 처리 흐름을 실행한다.
5. 허용량을 넘으면 원래 핵심 동작을 실행하지 않고 API 계약에 정의된 `429` 응답을 반환한다.
6. 시스템은 제한 결과를 개인정보·비밀값 없이 관측 지표와 로그로 남긴다.

#### 예외 흐름

- 인증 전 로그인 요청은 확정된 비인증 식별 기준으로, 인증 후 요청은 사용자 식별자와 IP 기준을 함께 적용한다.
- IP 또는 사용자 식별자를 조작해도 신뢰 경계에서 확정한 방식으로 처리한다.
- Redis 지연·장애가 발생하면 사전에 확정한 허용·거부·축소 정책과 복구 절차를 적용한다.
- 제한을 넘은 요청은 예약 확정, QR 체크인 등 도메인 상태를 부분적으로 변경하지 않는다.

**적용 정책:** `RLT-01`~`RLT-04`

## 3. 요청 제한 정책

- `RLT-01`:
  제한 대상은 로그인, 예약 확정, QR 스캔으로 한정한다.
  각 대상 API는 사용자 식별자·IP 또는 둘의 조합을 사용하는 제한 키와 적용 순서를 API·보안 계약으로 명시한다.
- `RLT-02`:
  허용량을 초과한 요청은 원래 비즈니스 동작을 시작하지 않고 `429` 응답을 반환한다.
  오류 코드, 공개 메시지, 재시도 안내와 헤더 포함 여부는 API 명세서에서 단일 계약으로 정의한다.
- `RLT-03`:
  Redis의 카운터·만료·동시 갱신은 원자적으로 처리한다.
  알고리즘, 기간 창, 키 만료, 다중 인스턴스·프록시 환경과 Redis 장애 시 행동은 구현 전 ADR로 확정한다.
- `RLT-04`:
  요청 제한 저장소·로그·지표에는 비밀번호, JWT 원문, QR 원문과 결제 비밀값을 저장하지 않는다.
  제한 발생량, 대상 API, 익명화된 키 범주, 결과와 저장소 장애는 관측하되 개인을 추적하는 목적으로 사용하지 않는다.

## 4. 구현 전 확정 항목

| 항목 | 확정할 내용 |
| --- | --- |
| 제한 알고리즘 | 고정 창·슬라이딩 창·토큰 버킷 중 선택, 원자 연산과 키 만료 방식 |
| 키 구성 | 로그인 전 식별자, 인증 후 사용자·IP 조합, IPv6·프록시·공유망 처리 |
| 임계값 | API별 허용량·기간, 현장 운영 예외와 부하 테스트 기준 |
| 장애 정책 | Redis 지연·장애 시 허용·거부·축소 동작, 경보·복구 절차 |
| `429` 계약 | 오류 코드, 재시도 안내, 응답 헤더·본문과 클라이언트 동작 |

## 5. 데이터·관측 요구사항

| 대상 | 핵심 정보 | 용도 |
| --- | --- | --- |
| Redis 제한 키 | API 범주, 익명화된 식별 기준, 창·만료 정보 | 요청 허용량 계산 |
| 제한 결과 지표 | API 범주, 허용·거부 수, 기간, 저장소 상태 | 임계값·장애 관찰 |
| 보안 로그 | `requestId`, API 범주, 결과, 익명화된 키 범주 | 우회·오류 조사 |
| API 오류 계약 | `429` 코드·메시지·재시도 정보 | 일관된 클라이언트 처리 |

Redis 키 형식, TTL과 관측 데이터의 보관 기간은 보안·개인정보 검토 후 확정한다.

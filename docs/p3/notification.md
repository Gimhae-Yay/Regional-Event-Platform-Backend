| 소유 범위 | 예약 확정·리마인드·취소·변경·체크인 성공 알림 이벤트 발행과 전달 추적 |

> 이 문서는 `FR-12`의 이벤트 계약을 정의한다. 이메일·문자·푸시 등 실제 전달 채널은 이 문서에서 선택하지 않는다.

## 1. 범위

### FR-12. 알림 이벤트

- 예약이 확정되면 알림 이벤트를 발행한다.
- 행사 시작 전 리마인드가 필요한 시점에 알림 이벤트를 발행한다.
- 예약 또는 행사가 취소·변경되면 알림 이벤트를 발행한다.
- 체크인이 성공하면 알림 이벤트를 발행한다.
- 이벤트는 거래 상태 변경과 원자적으로 저장하고, 전달·재시도·실패를 추적한다.

## 2. 유저 시나리오

### US-P3-01. 거래 상태 변경 후 알림 이벤트가 안전하게 전달 대기한다

- **주체:** 시스템, 예약 방문자
- **목표:** 예약·체크인 결과가 커밋된 뒤 필요한 알림 소비자가 유실 없이 이벤트를 받는다.
- **선행 조건:** 거래 상태 변경과 이벤트 유형·수신자·최소 payload 계약이 확정돼 있다.

#### 기본 흐름

1. 예약 확정, 취소·변경 또는 체크인 성공이 트랜잭션에서 처리된다.
2. 시스템은 해당 거래와 같은 트랜잭션에서 불변 `event_id`를 가진 알림 Outbox 이벤트를 저장한다.
3. 커밋 후 전달 작업자가 대기 이벤트를 점유해 채택된 소비자 또는 전달 어댑터에 전달한다.
4. 전달이 성공하면 이벤트 처리 결과와 시각을 기록한다.
5. 소비자는 `event_id`를 기준으로 이미 처리한 이벤트인지 확인하고 중복 효과를 만들지 않는다.

#### 예외 흐름

- 거래 또는 이벤트 저장 중 하나가 실패하면 둘 다 커밋하지 않는다.
- 전달 대상이 일시 실패하면 거래를 롤백하지 않고 재시도 대상으로 남긴다.
- 전달 성공 뒤 완료 기록 전에 중단돼 이벤트가 재전달돼도 소비자 효과는 중복되지 않는다.
- 반복 실패 이벤트는 격리해 뒤의 이벤트 전달을 막지 않고 권한 있는 운영자가 재처리·종결한다.

**적용 정책:** `NTF-01`~`NTF-04`

## 3. 알림 이벤트 정책

- `NTF-01`:
  예약 확정, 행사 전 리마인드, 취소·변경, 체크인 성공은 알림 이벤트를 발행할 수 있는 거래 사실이다.
  이벤트 유형별 수신자와 발행 시점은 거래 상태 전이와 스케줄 기준을 함께 명시한다.
- `NTF-02`:
  알림 이벤트는 원거래와 같은 MySQL 트랜잭션에서 Outbox에 저장한다.
  Outbox 저장 실패는 원거래도 롤백하며, 커밋 뒤 전달 실패는 원거래를 롤백하지 않는다.
- `NTF-03`:
  전달 보장은 최소 한 번이며, `event_id`는 재시도·재전달·수동 재처리에도 변경하지 않는다.
  소비자는 처리 이력 또는 고유 제약으로 동일 이벤트의 외부 효과를 한 번만 만든다.
- `NTF-04`:
  이벤트 payload에는 전달에 필요한 최소 정보만 포함하며 개인정보, 인증 토큰, QR 원문과 결제 비밀값을 넣지 않는다.
  점유, 재시도, 실패 격리, 수동 재처리와 보관은 ADR-0007의 불변 조건을 따른다.

## 4. 구현 전 확정 항목

| 항목 | 확정할 내용 |
| --- | --- |
| 이벤트 계약 | 유형별 aggregate, 수신자, payload 필드, 버전과 수신 동의 확인 방식 |
| 리마인드 기준 | 행사 시작 전 기준 시각, 시간대, 취소·변경 시 취소·대체 이벤트 처리 |
| 전달 채널 | 소비자·전달 어댑터, 실패 분류, 외부 멱등 키 사용 여부 |
| 운영값 | ADR-0007의 재시도·점유·보관 기본값 적용, 실패 알림과 수동 재처리·폐기 권한 |

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| Outbox 이벤트 | `event_id`, 유형, 집계 유형·식별자, `region_id`, 발생 시각, 상태 | 거래와 이벤트의 원자적 저장 |
| 전달 처리 이력 | 이벤트, 소비자·전달 대상, 시도·결과·시각, 오류 분류 | 재시도·실패 추적 |
| 리마인드 기준 | 예약 또는 회차, 기준 시각, 이벤트 생성 결과 | 중복 없는 예약 전 알림 |
| 수동 처리 이력 | 이벤트, 처리자, 조치, 사유, 시각 | 실패 재처리·폐기 감사 |

상세 엔티티, 컬럼, 관계, 고유 제약과 인덱스는 [ERD](../erd.md)에 확정한다.

## 1. 범위

### FR-01. 인증·역할·지역 권한

- 회원 가입과 로그인을 제공한다.
- 방문자, 운영자, 지역 관리자 역할을 구분한다.
- 서버는 역할, 담당 `region_id`, 운영자-콘텐츠 소유 관계에 따라 접근 범위를 강제한다.
- 지역 관리자는 담당 지역만, 운영자는 자신에게 연결된 콘텐츠·회차·예약만 조회·처리한다.

가입·로그인의 요청·응답, validation, status와 오류 코드는
[API 명세서](../api-specification.md)에서 별도 계약한다.

### FR-09. 운영자 승인·정보 마스킹

- 지역 관리자는 사업자 정보, 담당 지역, 콘텐츠 소유 관계를 수동 확인한 뒤 운영자를 승인한다.
- 승인된 운영자에게 담당 지역과 콘텐츠 권한을 부여한다.
- 운영자에게 노출하는 예약자 이름과 연락처는 확정 형식으로 마스킹한다.

## 2. 역할과 권한

| 역할 | 허용 범위 |
| --- | --- |
| 방문자 | 공개 지역 선택, 콘텐츠 탐색, 본인 무료 예약, 본인 QR 제시, 본인 인증 후기 관리 |
| 운영자 | 자신에게 연결된 콘텐츠·회차 등록 요청, 마스킹된 예약자 조회, 담당 예약 체크인과 예외 기록 |
| 지역 관리자 | 담당 지역의 운영자 승인, 콘텐츠 승인·반려, QR 예외 조회 |

모든 데이터와 권한은 지역과 소유 관계로 격리한다.
현재 MVP에는 전체 관리자 역할이나 지역 범위를 우회하는 권한을 제공하지 않는다.
김해시·동해시와 각 최초 지역 관리자 연결은 배포 전 승인된 초기화 절차로 준비하고 수행 결과를 감사 가능하게 남긴다.
일반 API에서는 지역 생성, 지역 관리자 임명·변경과 공통 운영 기준 변경을 허용하지 않는다.
초기화와 권한 경계의 기술 결정은
[ADR-0009](../adr/0009-exclude-platform-admin-from-initial-mvp.md)를 따른다.

## 3. 운영자 승인 흐름

- **주체:** 지역 관리자
- **선행 조건:** 담당 `region_id`가 지역 관리자 계정에 부여돼 있다.

1. 지역 관리자가 운영자 승인 요청의 사업자 정보, 담당 지역, 콘텐츠 소유 관계를 확인한다.
2. 검증을 통과한 운영자에게 담당 지역과 콘텐츠 권한을 부여한다.
3. 승인된 운영자만 해당 지역과 소유 콘텐츠 범위에서 등록·조회·체크인 기능을 사용한다.
4. 담당하지 않은 지역이나 콘텐츠에 대한 조회·변경 요청은 서버가 거부한다.

## 4. 권한·개인정보 정책

- `AUTH-01`:
  서버는 모든 요청에서 역할, 담당 `region_id`, 운영자-콘텐츠 소유 관계를 검증한다.
  지역 관리자는 담당 지역만 조회·변경할 수 있고, 운영자는 자신에게 연결된 콘텐츠·회차·예약만 조회·처리할 수 있다.
- `AUTH-02`:
  지역 관리자는 운영자 승인 전에 사업자 정보, 담당 지역, 콘텐츠 소유 관계를 수동 확인하고
  검증을 통과한 운영자에게 담당 지역과 콘텐츠 권한을 부여한다.
- `AUTH-03`:
  운영자에게 노출되는 모든 예약 목록과 예약 번호 보조 조회 응답은
  예약자 이름을 `김*수`, 연락처를 `010-****-1234` 형식으로 마스킹한다.
- `AUTH-04`:
  현재 MVP에는 전체 관리자 역할과 지역 범위를 우회하는 전역 관리 API를 두지 않는다.
  김해시·동해시 지역과 최초 지역 관리자 연결은 배포 전 승인된 초기화 절차로 준비하고
  수행 결과를 감사 가능하게 남긴다. 일반 API에서는 지역 생성, 지역 관리자 임명·변경과
  공통 운영 기준 변경을 허용하지 않는다.
- `PRV-01`:
  회원 탈퇴 시 회원정보를 파기하고, 법령에 따라 보존해야 하는 거래기록만
  운영 데이터와 분리해 법정 기간 동안 보관한다.
- `PRV-02`:
  회원 탈퇴 시 후기·방문 데이터의 개인 연결을 제거하고
  지역·콘텐츠·회차별 비식별 집계만 남긴다.

## 5. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 지역 | `region_id`, 공개 상태 | 초기 지역 분리와 확장 |
| 사용자·역할 | `user_id`, role, 담당 `region_id` | 인증·인가·지역 경계 |

상세 엔티티, 컬럼, 관계와 DB 제약은 [ERD](../erd.md)를 기준으로 한다.

# 정원 홀드·무료 예약

| 항목       | 내용                                                  |
|----------|-----------------------------------------------------|
| 상위 명세    | [로컬스탬프 P0 명세](../p0-spec.md)                        |
| 분할 기준 원문 | [로컬스탬프 제품 PRD v1.6](../local-stamp-platform-prd.md) |
| 소유 범위    | 회차 정원, 최대 10분 홀드, 무료 예약 확정, 취소, 만료, 노쇼              |

> 이 문서는 원문을 기반으로 현재 P0 명세와 채택 ADR을 반영한 정원 홀드·무료 예약 구현 계약이다.

## 1. 범위

### FR-05. 정원 홀드와 동시성 제어

- 회차의 잔여 정원을 조건부로 차감하고 `ACTIVE` 상태의 최대 10분 정원 홀드를 하나의 트랜잭션에서 생성한다.
- 예약 확정에서는 정원을 다시 차감하지 않고 활성 홀드 전환과 예약 생성만 처리한다.
- 잔여 정원과 예약 가능 여부는 캐시하지 않으며 예약 정합성의 최종 책임은 MySQL이 가진다.
- 초기 MVP 예약 경로에는 Redis 분산 락을 사용하지 않는다.

### FR-06. 무료 예약 상태 관리

- 활성 홀드를 한 번만 예약으로 전환한다.
- 예약 확정 재시도는 같은 결과를 반환하고 예약과 `ACTIVE → CONSUMED` 전환을 중복 생성하지 않는다.
- 홀드 만료·정책 무효화와 회차 시작 전 사용자 취소는 성공한 최초 상태 전이에서만 정원을 한 번 복구한다.
- 전체 취소, 홀드·예약 만료와 노쇼 상태를 관리한다.

## 2. 유저 시나리오

### US-01. 방문자가 행사·체험을 탐색하고 예약한다

- **주체:** 주말 나들이 방문자
- **목표:** 선택한 지역에서 원하는 행사·체험을 찾고 무료 예약을 완료한다.
- **선행 조건:** 사용자가 로그인했으며 공개 지역이 1개 이상 존재한다.

#### 기본 흐름

1. 사용자가 [지역·콘텐츠 카탈로그](content-catalog.md)의 `FR-02`에 따라 공개된 행사·체험의 회차를 선택한다.
2. 시스템이 잔여 정원을 조건부로 차감하고 `ACTIVE` 정원 홀드를 생성한다.
3. 사용자가 홀드 유효 시간 안에 예약 내용을 확인하고 무료 예약 확정을 요청한다.
4. 시스템은 추가 정원 차감 없이 활성 홀드를 예약으로 전환하고 QR 발급 자격을 만든다.
5. 사용자는 확정된 예약 내역을 확인하고 체크인 창에서 단기 예약 QR을 발급·갱신한다.

#### 예외 흐름

- 잔여 정원이 부족하면 홀드를 만들지 않고 다른 회차 선택을 안내한다.
- 예약을 확정하지 않은 홀드는 상태 조건부로 만료시키고 최초 한 번만 정원을 복구한다.
- 만료된 홀드는 연장하거나 재사용하지 않으며 사용자는 새 홀드를 요청해야 한다.
- 동일 예약 확정 요청이 반복돼도 예약과 홀드 소비 전이는 한 번만 발생하고 정원을 다시 변경하지 않는다.

**적용 정책:** `RSV-01`~`RSV-06`, `QR-01`

## 3. 정원 홀드·예약 정책

- `RSV-01`:
  정원 홀드는 생성 후 최대 **10분** 동안 유효하며 회차 시작이나 정책 무효화가 먼저 도래하면 즉시 종결한다.
  `ACTIVE → CONSUMED`, `ACTIVE → EXPIRED` 또는 `ACTIVE → INVALIDATED`로 전이한다.
  `CONSUMED`는 예약 확정에 사용된 상태로 정원을 변경하지 않는다.
  `EXPIRED`는 10분 만료, `INVALIDATED`는 콘텐츠의 비예약 가능 전이·회차 시작·회차 취소·회원 탈퇴에 사용하고
  각 전이에 성공한 최초 처리만 차감한 정원을 한 번 복구한다.
  종결 홀드는 연장·재사용·재확정하지 않는다.
- `RSV-02`:
  홀드 생성은 콘텐츠가 예약 가능하고 회차가 `SCHEDULED`이며 DB 시각이 회차 시작 전인 경우에만
  활성 회원 상태를 확인한 뒤 MySQL 조건부 정원 차감과 `ACTIVE` 홀드 생성을 하나의 트랜잭션으로 처리한다.
  잔여 정원이 부족하면 홀드를 생성하지 않는다.
  예약 확정은 회원이 여전히 활성 상태이고 콘텐츠와 회차가 예약 가능하며 DB 시각이 회차 시작 전이고
  홀드가 유효한 `ACTIVE`일 때
  추가 정원 차감 없이 `CONSUMED` 전환과 예약 생성을 하나의 트랜잭션으로 처리한다.
  회차 시작 시 남은 `ACTIVE` 홀드는 `INVALIDATED`로 한 번 전환해 정원을 복구한다.
- `RSV-03`:
  예약 확정은 멱등 키 또는 처리 이력으로 중복 요청에 같은 결과를 반환한다.
  동일 사용자의 동일 확정 요청을 반복해도 예약 생성과 `ACTIVE → CONSUMED` 전환은 각각 한 번만 발생하고
  정원은 추가 차감하거나 복구하지 않는다.
- `RSV-04`:
  예약은 `CONFIRMED → CHECKED_IN`, `CONFIRMED → CANCELLED` 또는 `CONFIRMED → EXPIRED`로 전이한다.
  사용자는 회차 시작 전 `CONFIRMED` 예약 전체만 취소할 수 있고 부분 취소는 제공하지 않는다.
  회차 시작 전 `CONFIRMED → CANCELLED`에 성공한 최초 처리만 정원을 한 번 복구하므로
  인원 변경은 전체 취소 후 새로 예약한다. 취소 사유와 관계없이 회차 시작 이후에는 정원을 복구하지 않으며,
  종결 상태의 취소 재요청은 정원을 다시 변경하지 않는다.
- `RSV-05`:
  체크인 창은 MySQL 기준 시각으로 `[checkin_open_at, checkin_close_at)`을 판정하고
  `checkin_close_at`은 회차 종료 시각보다 이르지 않게 설정한다.
  회차가 종료되고 MySQL 기준 시각이 `checkin_close_at` 이상이 된 뒤에도 체크인하지 않은 `CONFIRMED` 예약은
  `EXPIRED`로 한 번 전환해 노쇼로 구분하며 이미 끝난 회차의 정원은 복구하지 않는다.
  체크인과 노쇼 처리는 현재 시각과 `CONFIRMED` 상태를 조건으로 갱신해 경계에서 둘 중 하나만 성공하게 한다.
  노쇼 처리가 끝나면 회차를 `COMPLETED`로 전환한다.
- `RSV-06`:
  소유 운영자가 회차 취소를 요청하면 `SCHEDULED → CANCELLED`를 조건부로 전환해
  신규 홀드와 QR 발급·새 스캔을 먼저 차단한다.
  같은 처리에서 활성 홀드를 `INVALIDATED`로 전환해 정원을 한 번 복구하고
  `CONFIRMED` 예약만 `CANCELLED`로 전환한다. 예약 정원은 취소 사유와 관계없이 회차 시작 전
  성공한 최초 전이에서만 한 번 복구하고 시작 이후에는 복구하지 않는다.
  이미 `CHECKED_IN`인 예약과 방문·후기는 과거 사실로 보존하며 `CANCELLED`·`EXPIRED` 예약은 다시 변경하지 않는다.
  체크인·노쇼·회원 탈퇴와 회차 취소가 경합하면 먼저 성공한 조건부 상태 전이를 기준으로 다른 요청을 거부한다.
  콘텐츠의 `SUSPENDED`·`WITHDRAWN`·`ENDED` 전환만으로 기존 `CONFIRMED` 예약을 자동 취소하지 않는다.
  회차 취소의 사유는 감사 기록으로 남기고 사용자 예약 조회에는 취소 상태를 반영한다.
  별도 전달 알림은 P0 범위에 포함하지 않는다.
  현재 무료 예약 MVP에서는 금전 환불이 발생하지 않는다.

회원 탈퇴 시에는 [인증·프로필](auth-profile.md#prv-02)에 따라 `ACTIVE` 홀드와 미체크인
`CONFIRMED` 예약을 먼저 종결한다. 홀드는 정원을 한 번 복구하고 회차 시작 전 예약 취소만 정원을 복구하며,
종결 처리 후 예약·홀드의 사용자 연결과 시스템 관리 간접 역참조 경로를 제거한다.

QR 발급과 체크인은 [예약 QR·체크인](check-in.md)을 적용한다.
정원 확보와 복구의 트랜잭션 기준은
[ADR-0001](../adr/0001-use-mysql-conditional-update-for-capacity-consistency.md)을 따른다.

## 4. 데이터 요구사항

| 데이터      | 핵심 식별·연결 정보                                         | 용도            |
|----------|-----------------------------------------------------|---------------|
| 행사·체험 회차 | `session_id`, `content_id`, 시작·종료 시각, 정원, 운영 상태, 체크인 창 | 회차 시작 전 무료 예약·현장 QR 가능 단위 |
| 정원 홀드 | `hold_id`, `session_id`, 활성 회원 연결, 인원, 만료 시각, status, 무효화 사유 | 예약 중 정원 확보와 한 번의 복구, 탈퇴 후 사용자 연결 제거 |
| 예약 | `reservation_id`, hold_id, 활성 회원 연결, session_id, status | 사용자 예약·체크인과 탈퇴 후 사용자 연결 제거 |

상세 엔티티, 컬럼, 관계와 DB 제약은 [ERD](../erd.md)를 기준으로 한다.

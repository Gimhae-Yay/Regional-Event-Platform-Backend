# 정원 홀드·무료 예약

| 항목 | 내용 |
| --- | --- |
| 상위 명세 | [로컬스탬프 P0 명세](../p0-spec.md) |
| 분할 기준 원문 | [로컬스탬프 제품 PRD v1.5](../local-stamp-platform-prd.md) |
| 소유 범위 | 회차 정원, 10분 홀드, 무료 예약 확정, 취소, 만료, 노쇼 |

> 이 문서는 원문의 정책을 변경하지 않는 기능별 분할본이다.

## 1. 범위

### FR-05. 정원 홀드와 동시성 제어

- 회차의 잔여 정원을 확인한 뒤 10분 정원 홀드를 생성한다.
- MySQL 조건부 업데이트와 하나의 트랜잭션으로 정원 차감과 상태 전환을 처리한다.
- 잔여 정원과 예약 가능 여부는 캐시하지 않으며 예약 정합성의 최종 책임은 MySQL이 가진다.
- 초기 MVP 예약 경로에는 Redis 분산 락을 사용하지 않는다.

### FR-06. 무료 예약 상태 관리

- 활성 홀드를 한 번만 예약으로 전환한다.
- 예약 확정 재시도는 같은 결과를 반환하고 예약과 정원 차감을 중복 생성하지 않는다.
- 전체 취소, 홀드·예약 만료와 노쇼 상태를 관리한다.

## 2. 유저 시나리오

### US-01. 방문자가 행사·체험을 탐색하고 예약한다

- **주체:** 주말 나들이 방문자
- **목표:** 선택한 지역에서 원하는 행사·체험을 찾고 무료 예약을 완료한다.
- **선행 조건:** 사용자가 로그인했으며 공개 지역이 1개 이상 존재한다.

#### 기본 흐름

1. 사용자가 공개 지역 중 하나를 선택한다.
2. 지역 홈에서 진행 중이거나 임박한 행사·체험을 확인한다.
3. 유형과 예약 가능 여부로 콘텐츠를 필터링한다.
4. 상세 화면에서 위치, 운영 시간, 소개, 유의사항, 날짜·회차, 잔여 정원, 취소 기준, 인증 후기를 확인한다.
5. 날짜·회차·인원을 선택한다.
6. 시스템이 잔여 정원을 확인하고 정원 홀드를 생성한다.
7. 사용자가 홀드 유효 시간 안에 예약 내용을 확인하고 무료 예약 확정을 요청한다.
8. 시스템은 활성 홀드를 예약으로 전환하고 일회성 예약 QR을 발급한다.
9. 사용자는 확정된 예약 내역과 QR을 확인한다.

#### 예외 흐름

- 잔여 정원이 부족하면 홀드를 만들지 않고 다른 회차 선택을 안내한다.
- 예약을 확정하지 않은 홀드는 만료시키고 정원을 복구한다.
- 만료된 홀드는 연장하거나 재사용하지 않으며 사용자는 새 홀드를 요청해야 한다.
- 동일 예약 확정 요청이 반복돼도 예약은 한 번만 생성한다.

**적용 정책:** `RSV-01`~`RSV-06`, `QR-01`

## 3. 정원 홀드·예약 정책

- `RSV-01`:
  정원 홀드는 생성 후 **10분** 동안 유효하며 `ACTIVE → CONSUMED` 또는 `ACTIVE → EXPIRED`로 전이한다.
  홀드는 연장하거나 재사용하지 않고, 10분 안에 확정되지 않으면 만료시키며 차감한 정원을 복구한다.
- `RSV-02`:
  잔여 정원이 부족하면 홀드를 생성하지 않는다.
  활성 홀드만 예약으로 확정할 수 있고, 정원 차감과 홀드·예약 전환은
  MySQL 조건부 업데이트와 하나의 트랜잭션으로 처리해 확정 인원이 회차 정원을 초과하지 않게 한다.
- `RSV-03`:
  예약 확정은 멱등 키 또는 처리 이력으로 중복 요청에 같은 결과를 반환한다.
  동일 사용자의 동일 확정 요청을 반복해도 예약 생성과 정원 차감은 각각 한 번만 발생한다.
- `RSV-04`:
  예약 기본 상태는 `CONFIRMED → CHECKED_IN`이며 예외·종료 상태는 `CANCELLED`, `EXPIRED`다.
  사용자는 회차 시작 전까지 예약 전체를 취소할 수 있고 부분 취소는 제공하지 않으므로
  인원 변경은 전체 취소 후 새로 예약한다.
- `RSV-05`:
  회차 시작 후 취소하지 않고 체크인하지 않은 예약은 `EXPIRED`로 처리해 노쇼로 구분한다.
- `RSV-06`:
  운영자가 회차를 취소하면 해당 회차의 모든 예약을 `CANCELLED`로 전환하고 사용자에게 취소 사실을 안내한다.
  현재 무료 예약 MVP에서는 금전 환불이 발생하지 않는다.

QR 발급과 체크인은 [예약 QR·체크인](check-in.md)을 적용한다.

## 4. 데이터 요구사항

| 데이터 | 핵심 식별·연결 정보 | 용도 |
| --- | --- | --- |
| 행사·체험 회차 | `session_id`, `content_id`, 일정, 정원 | 무료 예약 가능 단위 |
| 정원 홀드 | `hold_id`, `session_id`, user_id, 인원, 만료 시각, status | 예약 중 초과 예약 방지 |
| 예약 | `reservation_id`, user_id, session_id, status | 사용자 예약·체크인 기준 |

상세 엔티티, 컬럼, 관계와 DB 제약은 [ERD](../erd.md)를 기준으로 한다.

# ADR-0017: 회원 행 조건부 전환과 단일 트랜잭션으로 탈퇴를 직렬화한다

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-07-28
- 결정일: 2026-07-28
- 관련 요구사항: [P0 명세](../p0-spec.md)의 `AC-15`, [인증·프로필](../p0/auth-profile.md)의 `PRV-01`, `PRV-02`
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: [ADR-0012](0012-retain-author-unlinked-reviews-and-visits-after-withdrawal.md)의 처리 중 재시도 키·회원 매핑과 부분 처리 재개 방식

## 맥락

ADR-0012는 탈퇴 처리 중 추측 불가능한 처리 키와 회원 매핑을 보관해 재시도에 사용한 뒤, 완료 시 파기하도록
정했다. 그러나 P0 셀프 탈퇴는 콘텐츠 소유 관계가 없는 방문자만 대상으로 하며, 필요한 상태 종결·연결 제거와
계정 파기를 모두 MySQL 데이터 변경으로 처리할 수 있다.

사용자는 별도 탈퇴 작업 테이블이나 영속 재시도 키 대신 회원 행의 조건부 상태 갱신과 행 잠금으로 중복 탈퇴와
신규 회원 명령을 직렬화하고, 실패하면 전체 롤백 후 사용자에게 재시도를 요청하는 방식을 선택했다. 이 결정은
ADR-0012의 후기·방문 보존과 역참조 제거 정책은 바꾸지 않고, 탈퇴 처리권 획득과 실패 재시도 방식만 대체한다.

## 결정 동인과 불변 조건

- 운영 역할·콘텐츠 소유 관계가 없는 방문자만 셀프 탈퇴할 수 있다.
- 탈퇴 성공 뒤 계정·자격 증명·직접 사용자 식별자와 모든 시스템 관리 역참조 경로를 제거한다.
- 활성 홀드·미체크인 예약·미사용 QR의 종결과 정원 복구 규칙은 ADR-0012를 유지한다.
- 탈퇴와 회원이 시작한 홀드·예약 확정·QR·후기 명령은 동시에 성공할 수 없다.
- 실패한 탈퇴는 반쯤 종결된 데이터나 영속 `WITHDRAWING` 상태를 남기지 않는다.
- 개인별 탈퇴 완료 tombstone, 처리 키, 안정 가명이나 재식별 매핑을 보관하지 않는다.
- 외부 I/O나 독립 커밋을 탈퇴 트랜잭션에 넣지 않는다.

## 결정

탈퇴 유스케이스의 첫 SQL은 다음 의미의 조건부 갱신으로 한다.

`UPDATE app_user SET status = 'WITHDRAWING' WHERE user_id = :userId AND status = 'ACTIVE'`

영향 행이 정확히 한 건인 트랜잭션만 탈퇴 처리권을 얻는다. 이 `UPDATE`가 회원 행의 배타 잠금을 획득하며,
트랜잭션 커밋 또는 롤백까지 유지한다. 영향 행이 0건이면 이미 다른 탈퇴 또는 회원 명령이 처리권을 얻었거나
계정이 없으므로 탈퇴를 진행하지 않는다.

처리권을 얻은 하나의 MySQL 트랜잭션에서 Refresh Token 계열 폐기, 운영자 신청 종결·개인정보 제거, 활성
홀드 무효화와 정원 복구, 미체크인 예약 취소, 방문·후기·멱등·감사 actor 연결 제거, 자격 증명·프로필·계정
파기를 완료한다. 모든 회원 시작 변경 명령은 도메인 상태 변경 전에 같은 회원 행을 `FOR UPDATE`로 읽거나
동등한 조건부 갱신으로 잠근 뒤 현재 상태를 확인한다. 회원 상태를 확인하지 않는 스케줄러와 운영자 명령은
각 도메인 상태의 조건부 갱신으로 경합 결과를
판정하고, 자식 행을 먼저 잠근 뒤 회원 행을 잠그지 않는다.

트랜잭션 안의 어느 단계에서든 오류가 발생하면 전체 롤백하고 사용자에게 재시도 가능한 실패를 반환한다.
재시도는 새로운 탈퇴 요청으로 처리하며, 시스템이 부분 처리 작업을 보관·재개하지 않는다. 커밋 성공 뒤
응답만 유실되면 계정과 인증 수단이 이미 파기되므로 개인별 완료 결과를 다시 조회·반환하지 않는다.

`withdrawal_process` 같은 별도 탈퇴 작업 테이블과 처리 키·회원 매핑은 만들지 않는다. ADR-0012의 처리 키와
회원 매핑에 관한 문구 및 부분 처리 재개 방식만 이 ADR로 대체하며, 후기·방문 보존·익명화·역참조 제거의
나머지 결정은 계속 적용한다.

## 결과와 트레이드오프

### 기대 효과

- 회원 행 하나를 조정 지점으로 사용해 중복 탈퇴와 회원 시작 변경 명령을 직렬화한다.
- 탈퇴 처리 상태·재시도 키·회원 매핑을 영속 저장하지 않아 개인정보 경로와 테이블 수를 줄인다.
- 실패 시 전체 롤백하므로 사용자의 새 요청은 일관된 `ACTIVE` 상태에서 다시 시작한다.

### 수용한 단점과 위험

- 모든 회원 시작 변경 명령이 회원 행 잠금과 상태 조건을 빠뜨리지 않아야 한다.
- 긴 트랜잭션이나 외부 I/O를 추가하면 행 잠금 대기와 데드락 위험이 커진다.
- 커밋 뒤 네트워크 응답이 유실된 경우, 사용자별 완료 기록 없이 이전 탈퇴 결과를 반환할 수 없다.
- 시스템 내부에서 부분 처리 탈퇴를 재개할 수 없다. 그런 요구가 생기면 별도 작업 모델을 다시 검토해야 한다.

## 전환과 롤백

아직 구현·migration이 없으므로 데이터 이관이나 호환 계층은 필요 없다. 현재 정책 문서는 이 결정으로 갱신하고,
사용자 요청에 따라 ERD의 `withdrawal_process` 정리는 별도 문서 변경으로 남긴다. ERD가 새 결정과 정렬되기
전에는 이 결정에 따른 migration이나 애플리케이션 구현을 시작하지 않는다.

단일 트랜잭션 범위를 지킬 수 없거나 외부 I/O·장기 비동기 처리가 탈퇴 완료의 일부가 되면, 이 ADR을 대체하는
새 ADR에서 영속 작업 상태·재시도 키·보관 및 개인정보 파기 정책을 다시 결정한다.

## 검증 방법

- 같은 회원의 동시 탈퇴 요청 두 건에서 조건부 갱신은 하나만 성공하고, 다른 요청은 처리하지 않는지 검증한다.
- 탈퇴와 홀드·예약 확정·체크인·후기 요청이 경합할 때 한쪽만 먼저 커밋되고, 탈퇴가 뒤늦게 성공하면 앞선
  결과를 포함해 연결을 제거하는지 검증한다.
- 홀드·예약·신청·방문·후기·멱등·감사 연결 제거 중 각 단계에서 예외를 발생시켜 모든 변경과
  `WITHDRAWING` 전환이 함께 롤백되는지 검증한다.
- 롤백 뒤 사용자의 새 탈퇴 요청이 성공하며, 성공 탈퇴 뒤에는 계정과 모든 직접·간접 역참조가 없는지 검증한다.
- 모든 회원 시작 변경 명령이 회원 행 잠금과 상태 확인 없이 도메인 상태를 바꾸지 않는지 통합 테스트와 코드 리뷰로 확인한다.
- 데드락이 발생하면 트랜잭션 전체를 재시도 가능한 실패로 변환하고, 빈번한 데드락은 잠금 순서·인덱스·
  트랜잭션 시간을 점검하는 운영 지표로 관찰한다.

## 대체 조건

- 탈퇴에 외부 시스템 호출, 장기 파일 파기 또는 독립 커밋이 필수로 들어와 단일 트랜잭션 원자성을 유지할 수 없다.
- 롤백된 탈퇴를 사용자가 직접 재시도할 수 없는 운영 요구가 생긴다.
- 커밋 뒤 응답 유실에도 개인별 탈퇴 완료 결과를 다시 반환해야 한다는 제품·법적 요구가 생긴다.
- 탈퇴 실패·재시도·데드락 관측 결과가 사용자 재시도 방식의 운영 한계를 지속적으로 보여 준다.

# ADR-0032: 전체관리자 기능을 P2에서 P1로 이동한다

- 상태: 채택됨
- 기록 유형: 승격
- 기록일: 2026-07-27
- 결정일: 2026-07-27
- 관련 요구사항: [P1-FR-09](../p1-spec.md#6-기능-요구사항과-소유-문서), [P1-FR-10](../p1-spec.md#6-기능-요구사항과-소유-문서), [ADM-01~ADM-05](../p1/platform-admin.md#3-전체관리자-정책), [P1-AC-10~P1-AC-11](../p1-spec.md#9-테스트-및-출시-수용-기준), [P2-FR-01](../p2-spec.md#6-기능-요구사항과-소유-문서), [P2-FR-07](../p2-spec.md#6-기능-요구사항과-소유-문서)
- 관련 단계: 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: P2에서 전체관리자 기능을 제공한다는 제품 우선순위. P2의 운영 통계·감사·에스컬레이션과 웹 화면은 P1에서 확정된 전체관리자 권한을 소비한다.

## 맥락

전체관리자는 지역과 지역 관리자 역할을 관리하고, 결제 불일치·환불 실패처럼 자동 처리로 종결되지 않은 거래 예외를 증거 기반으로 처리한다. 이 기능은 유료 거래와 환불이 도입되는 P1의 운영 안전성에 직접 필요하다.

전체관리자 기능을 P2까지 미루면 P1에서 새 지역의 운영 상태를 관리하거나 지역 관리자 연결을 제품 기능으로 처리할 수 없고, 거래 예외는 감사 가능한 수동 처리 주체 없이 남는다. 반대로 P2의 운영 통계 대시보드와 웹 프런트엔드는 P1에서 확정된 역할·권한 모델을 전제로 사용할 수 있으므로, 역할 자체를 P1로 앞당겨도 P2의 기능 책임은 유지된다.

## 결정 동인과 불변 조건

- P1 유료 거래의 결제 불일치와 환불 실패에는 승인된 수동 처리 주체, 증빙, 사유, 감사 이력이 필요하다.
- 지역 생성·운영 상태 변경과 지역 관리자 임명·회수는 지역 관리자 권한으로 처리할 수 없다.
- P2의 대시보드·감사·에스컬레이션·웹 채널은 전체관리자 역할을 새로 정의하지 않고 P1 권한 계약을 사용한다.
- 전체관리자의 지역 범위 접근은 명시된 전용 관리 유스케이스로 한정하며, 일반 사용자·운영자·지역 관리자 경로를 우회하지 않는다.
- 수동 거래 처리는 외부 거래 원본과 기존 자동 처리 이력을 임의로 덮어쓰거나 삭제하지 않는다.

## 결정

전체관리자 기능을 P2에서 P1로 이동한다. P1은 다음을 소유한다.

1. 전체관리자 계정의 생성·비활성화와 최초 계정 준비 절차
2. 지역 생성·조회·운영 상태 변경
3. 지역 관리자 역할의 임명·회수
4. 결제 불일치와 환불 실패의 증거 기반 수동 처리
5. 특권 변경과 거래 예외 처리의 감사 이력

P1 구현 전에는 `ADM-01`부터 `ADM-05`의 미확정 항목인 최초 계정 준비, 비활성화 효과, 자기 권한 변경 제한, 수동 처리 권한·증빙 형식을 이 ADR과 후속 API·ERD 계약으로 확정한다.

P2는 전체관리자 역할을 생성·변경하거나 전역 권한을 확장하지 않는다. P2의 운영 통계 대시보드, 감사·에스컬레이션, 웹 프런트엔드는 P1에서 확정된 역할과 권한 범위 안에서 읽기·표시 기능을 제공한다. P2 집계는 P1의 거래·권한 원본 상태를 변경하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- P1 유료 거래의 자동 처리 실패를 책임 주체와 증빙을 갖춘 경로로 처리할 수 있다.
- 지역 추가와 지역 관리자 교체를 P1 운영 범위 안에서 감사 가능하게 처리할 수 있다.
- P2는 이미 확정된 전체관리자 권한 계약을 재사용해 대시보드와 웹 채널을 구현할 수 있다.

### 수용하는 단점과 위험

- P1의 구현·테스트 범위에 특권 계정 보호, 감사 이력, 전용 권한 검증이 추가된다.
- 전체관리자 권한이 일반 경로로 새지 않도록 전용 유스케이스와 회귀 테스트를 유지해야 한다.
- P2의 전역 통계와 에스컬레이션 범위는 P1 전체관리자 역할이 존재한다는 사실만으로 자동 확정되지 않으며, P2 지표·검토 정책에서 별도로 제한한다.

## 전환과 롤백

기능 소유 단계만 P2에서 P1로 변경한다. P2의 대시보드, 후기 운영, 웹 프런트엔드 범위와 P1 거래 원본을 변경하지 않는다. 기존 구현·데이터가 없으므로 데이터 이관이나 호환 계층은 필요하지 않다.

P1에서는 권한 모델과 최초 계정 준비 절차, API·ERD·감사 계약, 전용 유스케이스와 통합 테스트 순으로 구현한다. P2 구현은 P1 권한 계약이 확정된 뒤에만 시작한다. P1 전환이 실패하면 전체관리자 기능을 노출하지 않고, P2 전용으로 기능을 되돌려 구현하지 않는다. 이미 생성된 거래 원본과 감사 이력은 롤백 과정에서도 삭제하지 않는다.

## 검증 방법

- P1-AC-10: 전체관리자가 아닌 사용자가 지역 생성·상태 변경·지역 관리자 임명·회수를 수행할 수 없고, 특권 변경이 감사 이력으로 재현되는지 검증한다.
- P1-AC-11: 거래 예외의 수동 처리에 원인 증빙·처리자·사유·결과가 남고 외부 거래 원본이 덮어써지지 않는지 검증한다.
- P2 대시보드와 웹 채널이 P1에서 확정된 역할·지역 범위를 사용하며, P2 경로가 전역 권한을 새로 부여하거나 확장하지 않는지 검증한다.
- P2 집계·감사·에스컬레이션 조회가 P1의 거래·권한 원본 상태를 변경하지 않는지 검증한다.

## 대체 조건

- 유료 거래와 지역·관리자 수명주기를 P1에서 더 이상 제공하지 않거나, 거래 예외를 제품 기능으로 처리하지 않기로 결정한다.
- 전체관리자 역할에 P2 범위를 넘는 전역 정책 변경, 다중 승인, 별도 운영 주체가 필요한 요구가 추가된다.
- 지역 단위 물리적 데이터 분리로 전체관리자 권한의 데이터 접근 방식이 달라진다.

# ADR-0011: 지역 관리자 승인과 콘텐츠 생성으로 운영자 소유권 부트스트랩

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-07-27
- 결정일: 2026-07-27
- 관련 요구사항: [P0 명세](../p0-spec.md)의 `FR-01`, `FR-03`, `FR-09`, [인증·프로필](../p0/auth-profile.md)의 `AUTH-02`
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

기존 P0 문서는 지역 관리자가 운영자를 승인하기 전에 콘텐츠 소유 관계를 확인하도록 하면서, 승인된 운영자만
콘텐츠를 생성할 수 있다고 정의했다. 콘텐츠가 아직 없으면 소유 관계도 없으므로 첫 콘텐츠 생성 경로를 문자
그대로 구현할 수 없다.

ADR-0002의 공유 스키마, `region_id`와 `operator_id` 기반 소유권 검사와 ADR-0009의 전체 관리자 제외 결정은
유지한다. 현재 MVP에는 운영자 조직, 여러 담당자, 소유권 이전과 전체 관리자를 추가하지 않으면서 최초 소유
관계를 만들 경로가 필요하다.

## 결정 동인과 불변 조건

- 승인되지 않은 신청자는 콘텐츠를 생성하거나 운영자 기능을 사용할 수 없다.
- 지역 관리자는 담당 지역의 운영자 신청만 승인·반려한다.
- 운영자는 승인된 담당 지역 안에서만 콘텐츠를 생성할 수 있다.
- 클라이언트가 콘텐츠의 `region_id` 또는 `operator_id`를 임의로 지정해 권한을 얻을 수 없다.
- 기존 콘텐츠 작업은 저장된 지역과 소유자를 기준으로 권한을 검사한다.
- P0에는 콘텐츠 소유권 이전·재배정과 여러 운영자 공동 소유 기능을 추가하지 않는다.

## 결정

운영자 승인 단계에서는 신청자의 사업자 정보, 요청 지역과 해당 지역에서 운영할 자격을 검토한다. 담당 지역
관리자가 승인하면 운영자 역할과 담당 `region_id`를 부여하며, 아직 존재하지 않는 콘텐츠 소유 관계를 승인
조건으로 요구하지 않는다.

승인된 운영자가 담당 지역에 `PENDING` 콘텐츠를 생성하면 서버는 현재 인증 사용자를 `operator_id`로, 승인된
담당 지역을 `region_id`로 설정하고 콘텐츠 생성과 함께 최초 소유 관계를 만든다. 클라이언트가 보낸 소유자
식별자는 신뢰하지 않으며 다른 운영자나 지역을 지정하면 거부한다.

지역 관리자는 콘텐츠 승인 단계에서 실제 소유·운영 관계와 공개 기준을 확인한다. 생성 이후 수정본, 회차, 예약
조회와 체크인은 저장된 `operator_id`와 `region_id`를 모두 검사한다.

콘텐츠 소유권 이전·재배정, 여러 운영자 공동 소유와 전체 관리자에 의한 owner 지정은 P0 범위에 포함하지 않는다.
ADR-0002의 지역·소유권 격리와 ADR-0009의 전체 관리자 제외·최초 지역 관리자 배포 초기화 결정은 그대로
유지한다.

## 결과와 트레이드오프

### 기대 효과

- 운영자 승인과 첫 콘텐츠 생성의 순환 선행조건을 제거한다.
- 콘텐츠 owner와 region을 신뢰 가능한 서버 권한 정보로 설정한다.
- 전체 관리자나 별도 조직 모델 없이 P0 소유권 경계를 완성한다.
- 기존 콘텐츠 접근은 일관되게 저장된 owner와 region으로 제한할 수 있다.

### 수용한 단점과 위험

- 한 콘텐츠에 한 운영자만 연결되며 담당자 교체나 공동 운영을 지원하지 않는다.
- 잘못 승인한 운영자의 컨텐츠는 지역 관리자의 심사와 운영 절차로 처리해야 한다.

## 전환과 롤백

신규 구현이므로 기존 콘텐츠 소유 관계 이관은 없다. 운영자 승인 상태와 담당 지역을 먼저 구현한 뒤 콘텐츠 생성
트랜잭션에서 인증 actor와 담당 지역으로 owner·region을 설정한다.

잘못 생성된 소유 관계를 다른 운영자로 자동 덮어쓰지 않는다. 공개 전 콘텐츠는 상태별 삭제 정책으로 정리하고,
소유권 이전이 실제로 필요해지면 새 ADR과 API·DB 계약으로 이관 절차를 결정한다.

## 검증 방법

- 승인 전 신청자의 콘텐츠 생성과 운영자 기능 요청이 거부되는지 검증한다.
- 다른 지역 관리자가 운영자 신청을 승인·반려할 수 없는지 검증한다.
- 승인된 운영자의 콘텐츠 생성에서 `operator_id`와 `region_id`가 서버 권한 정보로 설정되는지 검증한다.
- 요청으로 다른 owner나 지역을 지정해도 저장되지 않고 거부되는지 검증한다.
- 다른 운영자가 ID를 직접 지정해 콘텐츠·회차·예약에 접근할 수 없는지 검증한다.
- P0 API에 콘텐츠 소유권 이전·재배정과 전역 owner 지정 경로가 없는지 검증한다.
- 운영자 승인·반려, 최초 owner 설정과 지역·소유권 거부를 actor·region·content·reason과 함께 감사 기록으로
  관찰하고, owner 또는 region이 인증·승인 정보와 다르게 저장된 건이 한 건이라도 있으면 실패로 판정한다.

## 대체 조건

- 한 콘텐츠를 여러 운영자 계정이 공동 관리해야 한다.
- 운영자 퇴사·사업 양도 등으로 소유권 이전 요청이 반복된다.
- 사업체와 담당자 계정을 분리한 조직·멤버십 모델이 필요하다.
- 전체 관리자나 별도 운영 조직이 소유권 분쟁을 애플리케이션에서 처리해야 한다.

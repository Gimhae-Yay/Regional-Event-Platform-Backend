# ADR-0096: 신규 방문 커밋 뒤 미션 진행도를 호출하고 명시적 재호출로 복구

- 기록 유형: 신규
- 기록일: 2026-08-12
- 결정일: 2026-08-12
- 관련 요구사항: [미션 진행도 반영 내부 실행 명세](../api/p1/mission/record-mission-progress.md)의 `실행 계약`, [지역 미션](../p1/regional-mission.md)의 `MSN-03`

- 대체 대상: 없음

## 맥락

ADR-0067은 영속 방문을 미션 진행의 불변 근거로 사용하고 동일 방문의 중복 반영을 막도록 결정했다. 그러나
체크인 멱등 결과 조회나 QR 재스캔으로 기존 방문을 반환할 때도 진행도 어댑터를 다시 호출할지, 진행도 처리 실패를
어떤 경계에서 재호출할지는 정하지 않았다. 체크인 성공 응답과 이미 커밋된 방문은 진행도 처리 실패와 분리해야 하며,
현재 단계는 Outbox, 메시지 브로커, Scheduler와 자동 재시도를 포함하지 않는다.

## 결정 동인과 불변 조건

- 진행도 실패가 이미 커밋된 방문과 체크인 성공 결과를 실패로 바꾸지 않는다.
- 체크인 멱등 결과 조회와 QR 재스캔은 새 방문이나 새로운 진행도 처리 시도를 암묵적으로 만들지 않는다.
- 실패한 방문은 같은 `visitId`를 사용해 안전하게 다시 처리할 수 있다.
- 자동 전달·재시도 인프라를 현재 범위에 추가하지 않는다.

## 결정

새 `visit` 행을 영속화한 체크인 트랜잭션에서만 미션 진행도 어댑터의 커밋 후 실행을 등록한다. 체크인 멱등 결과
재조회와 QR 재스캔이 기존 방문을 반환하면 어댑터를 다시 호출하지 않는다.

진행도 처리 실패는 자동 재시도하지 않는다. 복구가 필요하면 내부 호출 경계가 동일한 영속 `visitId`로
진행도 유스케이스를 명시적으로 재호출한다. HTTP 체크인에서 시작한 실행은 원 요청의 `requestId`를 전달하고,
향후 비-HTTP 호출 경계는 실행마다 `requestId`를 한 번 생성해 모든 대상 참여 처리에 유지한다.

## 결과와 트레이드오프

### 기대 효과

- 체크인 성공과 진행도 처리 실패가 분리되어 방문 원본과 공개 체크인 응답을 보존한다.
- QR 재스캔과 체크인 멱등 재조회가 불필요한 진행도 실행을 반복하지 않는다.
- 명시적 재호출도 기존 진행 근거와 DB 유일 제약을 통해 같은 결과로 수렴한다.

### 수용한 단점과 위험

- 진행도 실패는 별도 내부 재호출이 없으면 자동으로 복구되지 않는다.
- 자동 재시도 운영 지표와 실패 대기열을 제공하지 않는다.

## 전환과 롤백

신규 내부 실행 정책이므로 데이터 이관과 호환 계층은 필요하지 않다. 내부 실행 명세에 유효 방문, 호출 제외,
명시적 재호출과 `requestId` 전달 규칙을 반영한다. 결정을 되돌려 기존 방문 반환 시에도 호출하려면 체크인 호출부와
회귀 테스트를 함께 변경하되, 이미 저장된 방문과 진행 근거는 그대로 유지한다.

## 검증 방법

- 신규 방문 트랜잭션은 커밋 전 실행하지 않고 커밋 뒤 실행하며, 롤백하면 실행하지 않는지 확인한다.
- 체크인 멱등 결과 조회와 QR 재스캔이 기존 방문을 반환할 때 새 방문과 진행 근거를 만들지 않는지 확인한다.
- 같은 `visitId`를 반복·동시·실패 뒤 재호출해도 참여별 진행 근거가 한 건으로 수렴하는지 확인한다.
- 진행도 실패가 체크인 성공 결과를 바꾸지 않고 허용된 비개인 식별자로만 기록되는지 확인한다.

## 대체 조건

- 진행도 실패 자동 복구가 제품 요구사항이 되거나 운영에서 수동 재호출 누락이 반복될 때 전달 보장과 재시도 방식을
  다시 비교한다.
- 체크인 외 방문 생성 경로가 추가되어 단일 호출 경계를 유지할 수 없을 때 재검토한다.

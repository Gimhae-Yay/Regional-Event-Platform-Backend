# ADR-0016: 비공개 S3와 서명 URL로 콘텐츠 대표 이미지를 제공하고 삭제 즉시 원본을 파기

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-07-28
- 결정일: 2026-07-28
- 관련 요구사항: [PRD](../local-stamp-platform-prd.md)의 `FR-03`, `FR-14`, `AUTH-01`, `CON-02`, `CON-05`, `CON-08`, `AC-09`, `AC-10`
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

현재 기술 스택은 콘텐츠 대표 이미지 저장소로 Amazon S3를 선택했다. 그러나 버킷 공개 여부, 업로드·조회 권한,
DB에 저장할 식별 정보와 이미지 교체·삭제 뒤 S3 원본을 언제 파기할지는 정해지지 않았다.

대표 이미지는 공개된 콘텐츠를 소개하는 데 필요하지만, 미공개 콘텐츠와 수정 심사 중인 이미지는 해당 운영자와
담당 지역 관리자만 접근해야 한다. 공개 콘텐츠 수정본은 원본을 유지하다 승인된 후보만 반영해야 하며,
공개 전 콘텐츠만 소프트 삭제할 수 있다. 사용자는 비공개 S3와 서명 URL 방식, 그리고 이미지 삭제 시 즉시
S3 원본을 영구 삭제하는 방식을 선택했다.

이 ADR의 범위는 P0 콘텐츠의 대표 이미지 한 장이다. 후기 사진·갤러리·CDN은 현재 범위에 포함하지 않는다.

## 결정 동인과 불변 조건

- S3 버킷과 객체는 공개 읽기·공개 쓰기를 허용하지 않는다.
- 브라우저는 S3 자격 증명이나 임의 객체 키를 받지 않으며, 서버가 권한 확인 뒤 발급한 짧은 유효기간의 서명 URL만 사용한다.
- 미공개 콘텐츠와 수정본의 이미지는 해당 콘텐츠 소유 운영자와 담당 지역 관리자만 조회할 수 있다.
- 일반 방문자는 `PUBLISHED` 콘텐츠의 현재 대표 이미지만 조회할 수 있다.
- 객체 키와 콘텐츠·수정본 연결은 서버가 만들고 검증한다. 공개 URL, 원본 파일명, 사용자 식별자는 DB의 이미지 식별 정보로 저장하지 않는다.
- 이미지 삭제·교체·수정본 반려·철회로 더는 참조되지 않는 원본은 복구 보관 기간 없이 즉시 S3에서 영구 삭제한다.
- S3 삭제 실패로 원본이 남아도 공개하거나 다시 연결하지 않으며, 삭제가 성공할 때까지 재시도한다.

## 결정

대표 이미지 객체는 비공개 S3 버킷에 저장한다. 서버는 인증된 요청의 지역·소유 관계와 콘텐츠 또는 활성 수정본
문맥을 확인한 뒤에만 서버 생성 객체 키에 대한 업로드 서명 URL을 발급한다. 업로드 권한은 콘텐츠 소유 운영자에게만
부여하고, 담당 지역 관리자는 심사에 필요한 조회만 할 수 있다.

DB에는 서버가 생성한 객체 키, 콘텐츠 유형, 바이트 크기, 무결성 검증값과 콘텐츠 또는 수정본 연결만 저장한다.
파일의 원래 이름, 공개 URL, 사용자 식별 정보는 저장하지 않는다. 공개 조회는 `PUBLISHED` 콘텐츠의 현재 대표
이미지에만 짧은 유효기간의 조회 서명 URL을 발급한다. `PENDING`, `APPROVED`, 수정 심사 중인 후보는 소유
운영자와 담당 지역 관리자만 조회할 수 있고, `SUSPENDED`, `WITHDRAWN`, `ENDED` 상태 전환은 일반 방문자용
새 조회 URL을 발급하지 않는다.

공개 콘텐츠의 이미지 변경은 ADR-0014의 수정본 흐름을 따른다. 후보 이미지는 승인 전 원본을 바꾸지 않으며,
승인된 수정본만 현재 객체 연결을 교체한다. `PENDING` 또는 `APPROVED` 콘텐츠의 삭제, 수정본의 반려·철회,
이미지 교체로 더 이상 참조되지 않는 객체는 DB 연결을 먼저 제거한 뒤 즉시 `DeleteObject`로 영구 파기한다.
공개 이후 상태는 `CON-08`에 따라 콘텐츠 자체를 삭제하지 않으므로 단순 상태 전환만으로 현재 대표 이미지를
파기하지 않는다.

S3와 MySQL은 하나의 트랜잭션으로 묶을 수 없으므로, DB 연결 제거 또는 교체가 커밋된 직후 즉시 S3 삭제를
시도한다. 삭제가 실패하면 해당 객체 키를 비공개 삭제 대기 상태로 보관해 멱등적으로 재시도한다. 이 객체는
DB의 공개·운영 조회 경로에서 참조하지 않으며, 30일 같은 복구 유예 기간을 두지 않는다. 이미 발급된 조회
서명 URL은 만료 전까지 접근될 수 있다는 제한은 수용한다.

## 결과와 트레이드오프

### 기대 효과

- 미공개 콘텐츠와 수정 후보 이미지가 공개 S3 URL로 노출되지 않는다.
- 콘텐츠 상태와 지역·소유 관계를 통과한 요청에만 이미지 접근을 허용한다.
- 삭제된 이미지 원본을 장기 보관하지 않아 저장 공간과 잔여 파일 위험을 줄인다.
- 공개본과 수정 후보 이미지를 분리해 심사 중 현재 공개 이미지가 바뀌지 않는다.

### 수용한 단점과 위험

- 실수로 삭제한 이미지와 승인된 교체 전 원본은 복구할 수 없으며, 새 업로드가 필요하다.
- 서명 URL 발급·만료와 S3 삭제 재시도 구현이 필요하다.
- DB 커밋 뒤 S3 삭제가 실패하면 짧은 기간 동안 비공개 고아 객체가 남을 수 있다.
- 이미 발급된 서명 URL은 만료 전까지 취소할 수 없으므로 상태 변경 직후의 완전한 즉시 차단은 제공하지 않는다.

## 전환과 롤백

신규 구현이므로 기존 이미지 객체의 이관은 없다. 먼저 비공개 버킷 정책, 서버 생성 키 규칙, 이미지 메타데이터와
삭제 대기 상태를 준비한 뒤 업로드·조회 서명 URL과 수정본 연결을 구현한다. 이후에만 대표 이미지가 필요한
콘텐츠 등록·심사 흐름을 연다.

도입 중 문제가 발생하면 새 이미지 업로드·교체 명령을 중지하고 현재 DB 연결을 유지한다. S3에서 이미 영구
삭제한 객체는 복구하지 않으며, 이전 이미지를 되돌려야 하면 새 파일을 다시 업로드해 승인된 수정본으로 반영한다.
공개 읽기 버킷이나 CDN이 필요해지면 캐시 무효화·접근·삭제 보장을 포함한 새 ADR로 대체한다.

## 검증 방법

- S3 버킷과 객체에 공개 읽기·쓰기가 없고, 애플리케이션이 발급하지 않은 키의 업로드·조회가 거부되는지 검증한다.
- 다른 지역 관리자·다른 운영자의 업로드와 미공개·수정 후보 이미지 조회가 거부되는지 검증한다.
- `PUBLISHED` 콘텐츠만 일반 방문자 조회 서명 URL을 받고, URL 만료 뒤 접근이 거부되는지 검증한다.
- 수정 후보 이미지가 승인 전 공개 원본을 바꾸지 않고, 승인·반려·철회 뒤 각각 연결 교체·즉시 삭제가 이루어지는지 검증한다.
- 공개 전 콘텐츠 삭제와 이미지 교체 뒤 기존 객체가 즉시 삭제되며, 삭제 실패 시 객체가 어떤 조회 경로에도
  노출되지 않은 채 재시도되는지 검증한다.
- DB 이미지 메타데이터와 S3 객체에 공개 URL·원본 파일명·사용자 식별 정보가 남지 않는지 검증한다.
- 이미지 삭제 뒤 복구 경로나 30일 보관 객체가 없고, 재업로드만 가능한지 검증한다.

## 대체 조건

- 대량 공개 이미지 트래픽으로 CDN과 캐시 무효화 정책이 필요해진다.
- 이미지 복구·법적 보존·악성 파일 조사 요구가 생겨 즉시 삭제 정책을 유지할 수 없다.
- 후기 사진·갤러리·동영상 등 대표 이미지와 다른 미디어 수명주기 요구가 채택된다.
- 서명 URL의 만료 전 노출 위험을 허용할 수 없는 보안·계약 요구가 생긴다.

# ADR-0097: 무료 예약 결제·환불 상태 조회의 기준 시각으로 예약 확정 시각 사용

## 맥락

담당 운영자의 예약 결제·환불 상태 조회 응답은 항상 `updatedAt`을 반환한다. 유료 예약은 결제,
환불, 결제 불일치의 상태 변경 시각 중 가장 최근 값을 사용할 수 있다. 그러나 확정된 무료 예약은
결제와 환불이 모두 없으므로 해당 세 데이터에서 기준 시각을 산출할 수 없다.

## 결정 동인과 불변 조건

- 무료 예약도 유료 예약과 같은 응답 형태로 `updatedAt`을 반환한다.
- 무료 예약 조회는 결제·환불·불일치 또는 감사 이력을 변경하지 않는다.
- 유료 예약의 `updatedAt` 계산 규칙은 변경하지 않는다.

## 검토한 선택지

| 순서 | 선택지 | 장점 | 단점·실패 위험 | 되돌림 비용 | 현재 단계 적합성 |
| --- | --- | --- | --- | --- | --- |
| 1 | 추천안: 예약 확정 시각 사용 | 이미 확정된 예약의 생성 사실에 근거해 항상 UTC 시각을 반환하며 추가 저장소 변경이 없다. | 예약의 이후 상태 변경 시각은 나타내지 않는다. | 낮음 | 높음 |
| 2 | `updatedAt`을 null로 반환 | 추가 기준 시각이 필요 없다. | 필수 문자열 응답 계약을 위반하고 클라이언트 분기를 강제한다. | 중간 | 낮음 |

## 결정

결제 없이 확정된 무료 예약의 `updatedAt`은 `reservation.confirmedAt`으로 반환한다. 이 값은
무료 예약이 확정되어 조회 대상이 된 시각을 뜻한다. 결제가 존재하는 경우에는 결제, 환불,
불일치의 최신 상태 변경 시각만으로 계속 계산한다.

## 결과와 트레이드오프

### 기대 효과

- 무료 예약도 응답 스키마를 일관되게 유지한다.
- 기존 예약 데이터와 읽기 전용 조회만으로 기준 시각을 제공한다.

### 수용한 단점과 위험

- 무료 예약의 예약 상태가 확정 뒤 변경되어도 이 API의 `updatedAt`에는 반영되지 않는다. 이
  API는 결제·환불 문의 대응을 위한 읽기 모델이므로 예약 상태 이력을 대신하지 않는다.

## 전환과 롤백

신규 API의 응답 규칙이다. 별도 데이터 이관이나 호환 계층은 필요하지 않다. 클라이언트가
`updatedAt`을 사용하기 전에 응답을 배포하며, 후속 계약 변경이 필요하면 새 ADR과 API 문서
개정 Task로 대체한다.

## 검증 방법

- 활성·승인된 담당 운영자가 무료 예약을 조회하면 `payment`와 `refund`는 null이고
  `updatedAt`은 예약 확정 시각인지 검증한다.
- 유료 예약은 결제·환불·불일치의 최신 시각을 반환하는지 검증한다.
- 비관할 또는 비활성 운영자 조회가 `FORBIDDEN`이며 영속 상태를 바꾸지 않는지 검증한다.

## 대체 조건

- 예약 상태 변경 시각을 결제 문의 화면에도 노출해야 하는 제품 요구사항이 확정되는 경우
  `updatedAt`의 의미와 API 계약을 다시 결정한다.

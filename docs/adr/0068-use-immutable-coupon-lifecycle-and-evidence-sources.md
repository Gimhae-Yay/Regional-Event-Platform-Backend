# ADR-0068: 불변 발급 근거와 상태 이력을 가진 쿠폰 모델

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-05
- 결정일: 2026-08-05
- 관련 요구사항: `docs/p1/coupon.md`의 `CPN-01`~`CPN-05`
- 관련 단계: 단계 3. 확장 의사결정
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

쿠폰은 방문 보상·미션 보상·스탬프북 보상에 연결되고, 결제 취소·환불 때 복구될 수 있다. 상태 하나만 저장하면 발급·예약·사용·복구 원인을 재현하기 어렵다. 정책 종료 뒤 이미 발급된 쿠폰의 권리도 보존해야 한다.

## 결정 동인과 불변 조건

- 운영자의 임의 쿠폰 지급은 허용하지 않는다.
- 발급 근거는 실제 방문·미션 보상 수령·스탬프북 보상 중 하나여야 한다.
- 예약 하나에는 쿠폰 하나만 사용하며, 쿠폰 사용·복구·만료는 가격 스냅샷과 함께 추적 가능해야 한다.

| 1 | 추천안: 근거별 FK, 발급 식별 키와 추가 전용 상태 이력 | 참조 무결성·복구 추적·중복 지급 차단이 강하다. | 발급 근거별 식별 키와 제약이 필요하다. | 중간 | 높음 |
| 2 | `source_type`·문자열 ID와 현재 상태만 저장 | 테이블이 작다. | 존재하지 않는 근거·상태 변경 원인을 막기 어렵다. | 높음 | 낮음 |

## 결정

쿠폰 정책은 한 지역 전체의 현재·신규 유료 콘텐츠에 적용하며, 정액 할인과 발급 후 유효 일수만 사용한다. 정책마다 발급 경로는 `VISIT`, `MISSION_REWARD`, `STAMPBOOK_COMPLETION` 중 하나다. 방문 보상은 사용자당 정책별 한 번만 발급한다.

`coupon_issuance`은 `visit`, `mission_reward_claim`, `stampbook_reward_grant` 중 정확히 하나를 FK로 참조한다. 발급 행에는 `coupon_policy_id`, `recipient_user_id`, 서버가 정책·수령자·근거에서 계산하는 `issuance_identity_hash`를 함께 보관한다. 쿠폰과 발급 행의 정책·수령자를 같은 트랜잭션에서 일치시키고, 방문·미션 수령·스탬프북 완료 보상의 각 근거도 해당 정책과 수령 사용자를 증명해야 한다. 미션 수령의 정책은 원본 미션 보상 정책과, 스탬프북 완료 보상의 정책은 원본 스탬프북 보상 정책과 각각 같아야 한다.

`issuance_identity_hash`는 방문 보상에서는 정책·수령자, 미션·스탬프북 보상에서는 정책·수령자·각 보상 근거를 입력으로 한다. 이 키와 `coupon_id`를 유일하게 두고, 미션 보상 수령·스탬프북 완료 보상 근거도 각각 유일하게 둔다. 중복 이벤트는 발급 식별 키 충돌 뒤 기존 쿠폰을 반환한다. 새 쿠폰 발급은 잠근 `coupon_policy.status`가 `PUBLISHED`일 때만 허용하며, `DRAFT`·`PENDING_REVIEW`·`ENDED` 정책은 신규 발급을 시작할 수 없다. 쿠폰 현재 상태는 `AVAILABLE`, `RESERVED`, `USED`, `EXPIRED`, `INVALIDATED`이고, 모든 변화는 `coupon_status_history`에 추가 전용으로 남긴다. 만료 배치가 `EXPIRED`를 기록한다.

스탬프북은 같은 지역의 `STAMPBOOK_COMPLETION` 정책만, 미션은 같은 지역의 `MISSION_REWARD` 정책만 완료 보상으로 연결한다. 두 기능이 공개될 때 보상 정책도 `PUBLISHED`여야 하며, 공개 중인 참조 기능이 하나라도 있으면 그 쿠폰 정책을 종료할 수 없다.

결제 시작 시 홀드 소유자와 쿠폰 소유자, 홀드 지역과 쿠폰 정책 지역, 쿠폰 상태·만료를 함께 검증한 뒤 `AVAILABLE → RESERVED`가 된다. 예약 확정 시 `RESERVED → USED`와 `coupon_redemption(CONFIRMED)`을 같은 트랜잭션으로 기록한다. 사용 이력은 쿠폰·가격 스냅샷·확정 예약을 모두 참조하며, 쿠폰은 스냅샷의 적용 쿠폰과, 예약은 스냅샷의 홀드와 각각 일치해야 한다. 예약당 하나의 사용 이력과 쿠폰당 하나의 `CONFIRMED` 사용 이력만 허용한다. 회차 시작 전 취소·환불로 쿠폰을 복구하면 기존 사용 이력을 `REVERSED`로 남긴 뒤 원래 만료 시각을 유지한 채 사용 가능 상태로 복구한다. 따라서 복구된 쿠폰의 다음 사용은 새 사용 이력으로 남는다.

## 결과와 트레이드오프

### 기대 효과

- 같은 근거·같은 정책의 쿠폰을 한 장으로 수렴시킨다.
- 정책 종료 뒤에도 발급된 쿠폰의 유효 기간과 복구 근거를 분리해 보존한다.

### 수용한 단점과 위험

- 지역 전체 적용 정책은 운영 실수 시 영향 범위가 넓다.
- 공개 중인 미션·스탬프북이 참조하면 쿠폰 정책을 즉시 종료할 수 없고, 먼저 해당 기능을 종료해야 한다.

## 전환과 롤백

P1 신규 테이블로 시작한다. 상태 전이와 이력 삽입은 한 트랜잭션에서 처리한다. 정책 종료는 기존 쿠폰을 소급 변경하지 않는다.

## 검증 방법

- 근거가 없거나 둘 이상인 발급 이력이 생성되지 않는지 확인한다.
- 같은 근거·정책의 동시 발급이 쿠폰 한 장으로 수렴하는지 확인한다.
- `DRAFT`·`PENDING_REVIEW`·`ENDED` 정책으로 새 쿠폰 발급이 거부되고, `PUBLISHED` 정책만 발급되는지 확인한다.
- 다른 지역·발급 경로의 쿠폰 정책을 미션·스탬프북 보상으로 연결할 수 없고, 보상 수령·완료 보상의 정책이 원본 보상 정책과 일치하는지 확인한다.
- 공개 중인 미션·스탬프북이 참조하는 쿠폰 정책의 종료가 거부되는지 확인한다.
- 타인 쿠폰, 다른 지역 쿠폰, 만료·예약·사용 쿠폰이 가격 스냅샷에 연결되지 않는지 확인한다.
- 쿠폰 사용 동시 요청에서 한 건만 `USED`와 같은 스냅샷·예약을 가리키는 `CONFIRMED` 사용 이력을 만드는지 확인한다.
- 0원 예약과 양수 결제 승인 모두 쿠폰 상태·사용 이력·예약 확정이 함께 반영되고, 회차 시작 전 취소·환불 복구가 기존 사용 이력을 `REVERSED`로 남기는지 확인한다.

## 대체 조건

- 정률 할인·복수 쿠폰·지역 간 공동 프로모션이 확정되면 재검토한다.

# ADR-0068: 불변 발급 근거와 상태 이력을 가진 쿠폰 모델

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-05
- 결정일: 2026-08-06
- 관련 요구사항: [쿠폰](../p1/coupon.md)의 `CPN-01`~`CPN-05`, [결제·환불](../p1/payment-refund.md)의 `PAY-05`
- 관련 단계: 단계 3. 확장 의사결정
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

쿠폰은 방문·미션 보상·스탬프북 보상에 연결되고 유료 예약의 가격 스냅샷, 결제와 취소·환불 수명주기를 함께 통과한다.
현재 상태만 저장하거나 모든 방문 식별자를 발급 유일 키에 포함하면 발급 중복, 사용 경합과 복구 원인을 일관되게 재현하기 어렵다.
콘텐츠 운영자가 지역 전체 쿠폰을 운영하면 본인 소유 콘텐츠 범위를 넘어 다른 운영자의 유료 예약에 영향을 줄 수도 있다.

## 결정 동인과 불변 조건

- 콘텐츠 운영자는 본인이 소유한 콘텐츠의 쿠폰 정책만 운영한다.
- 운영자의 임의 쿠폰 지급은 허용하지 않는다.
- 발급 근거는 실제 방문·미션 보상 수령·스탬프북 완료 보상 중 하나여야 한다.
- 방문 쿠폰은 정책·수령자당 한 번만 발급한다.
- 예약 하나에는 쿠폰 하나만 사용하며 쿠폰 사용·복구·만료는 가격 스냅샷과 함께 추적 가능해야 한다.
- 회차 시작 전 사용자·운영자 취소의 전액 환불이 완료된 경우에만 사용 쿠폰을 복구한다.

## 검토한 선택지

| 순서 | 선택지 | 장점 | 단점·실패 위험 | 되돌림 비용 | 현재 단계 적합성 |
| --- | --- | --- | --- | --- | --- |
| 1 | 추천안: 콘텐츠 단위 정책, 근거 유형별 발급 식별 키와 추가 전용 상태 이력 | 운영자 소유권, 중복 지급 차단, 사용·복구 재현이 명확하다. | 지역 공통 프로모션에는 정책을 콘텐츠별로 만들어야 한다. | 중간 | 높음 |
| 2 | 지역 전체 정책, 모든 근거 ID를 포함한 발급 키와 현재 상태만 저장 | 정책 수가 적고 방문마다 반복 보상을 줄 수 있다. | 콘텐츠 소유권을 넘고 반복 방문 쿠폰 누적과 상태 변경 원인 유실 위험이 있다. | 높음 | 낮음 |

## 결정

### 정책 범위와 혜택

쿠폰 정책은 콘텐츠 하나를 가리키며 `content_id`에서 `region_id`를 파생한다. 생성·수정·공개·종료는 해당 콘텐츠 소유 운영자만 수행한다.
정책은 해당 콘텐츠의 유료 예약에만 적용한다. 정액 할인, 최소 결제 금액, 발급 가능 기간과 발급 후 유효 일수를 사용하며 예약당 쿠폰은 최대 하나다.
정책마다 발급 경로는 `VISIT`, `MISSION_REWARD`, `STAMPBOOK_COMPLETION` 중 하나다.

### 발급 근거와 멱등성

`coupon_issuance`는 `visit`, `mission_reward_claim`, `stampbook_reward_grant` 중 정확히 하나를 FK로 참조한다.
발급 행에는 `coupon_policy_id`, `recipient_user_id`, 서버가 계산한 `issuance_identity_hash`를 함께 보관한다.
쿠폰과 발급 행의 정책·수령자를 같은 트랜잭션에서 일치시킨다. 방문 근거는 정책 콘텐츠와 수령 사용자를,
미션·스탬프북 보상 근거는 요청 정책·정책 지역과 수령 사용자를 증명해야 한다.

`issuance_identity_hash`는 방문 보상에서 정책·수령자를, 미션·스탬프북 보상에서 정책·수령자·보상 근거를 입력으로 사용한다.
방문 `source_id`는 자격 증거로 보존하지만 발급 식별 키에는 포함하지 않는다.
발급 식별 키와 `coupon_id`를 유일하게 두고 미션·스탬프북 보상 근거도 각각 유일하게 둔다.
중복 이벤트는 발급 식별 키 충돌 뒤 기존 쿠폰을 반환한다.

새 쿠폰 발급은 잠근 정책이 `PUBLISHED`이고 발급 기간과 전체 발급 한도를 만족할 때만 허용한다.
전체 발급 한도 확인과 사용량 증가는 정책 잠금 또는 동등한 조건부 갱신으로 쿠폰 생성과 같은 트랜잭션에서 처리한다.

### 상태와 사용 확정

쿠폰 현재 상태는 `AVAILABLE`, `RESERVED`, `USED`, `EXPIRED`, `INVALIDATED`이며 모든 변화는
`coupon_status_history`에 추가 전용으로 남긴다.

결제 시작 또는 0원 예약의 가격 확정 시 홀드 소유자와 쿠폰 소유자, 정책 콘텐츠와 홀드 콘텐츠, 쿠폰 상태·만료를 검증한다.
가격 스냅샷에 적용 쿠폰과 할인 금액을 고정하고 `AVAILABLE → RESERVED`를 같은 트랜잭션에서 기록한다.
예약 확정 시 쿠폰이 같은 가격 스냅샷에 `RESERVED`인지 확인한 뒤 `RESERVED → USED`와
`coupon_redemption(CONFIRMED)`을 예약 확정과 같은 트랜잭션에 기록한다. `AVAILABLE → USED` 직접 전이는 허용하지 않는다.

사용 이력은 쿠폰·가격 스냅샷·확정 예약을 모두 참조한다. 쿠폰은 스냅샷의 적용 쿠폰과,
예약은 스냅샷의 홀드에서 생성된 예약과 일치해야 한다. 예약당 하나의 사용 이력과 쿠폰당 하나의 활성 `CONFIRMED` 사용 이력만 허용한다.

결제 또는 홀드가 확정 전에 종료되면 같은 가격 스냅샷의 선점을 해제한다. 원래 만료 시각 전이면 `RESERVED → AVAILABLE`,
만료 시각이 지났으면 `RESERVED → EXPIRED`로 전이한다. 만료 작업은 선점되지 않은 쿠폰을 `AVAILABLE → EXPIRED`로 전이하고 이력을 기록한다.

### 취소·환불 복구

회차 시작 전 사용자 또는 운영자 취소의 전액 환불이 완료되면 기존 사용 이력을 `REVERSED`로 남긴다.
원래 만료 시각 전이면 쿠폰을 `USED → AVAILABLE`, 만료 시각이 지났으면 `USED → EXPIRED`로 전이한다.
환불 보류·실패, 회차 시작 뒤 취소와 부분 환불은 복구 대상이 아니다. 같은 취소·환불 근거의 반복 처리는 새 반전 이력이나 추가 상태 전이를 만들지 않는다.

스탬프북은 같은 지역의 `STAMPBOOK_COMPLETION` 정책만, 미션은 같은 지역의 `MISSION_REWARD` 정책만 완료 보상으로 연결한다.
두 기능이 공개될 때 보상 정책도 `PUBLISHED`여야 하며 공개 중인 참조 기능이 하나라도 있으면 그 쿠폰 정책을 종료할 수 없다.
정책 종료는 신규 발급만 중단하고 기존 쿠폰의 만료 시각과 사용 조건을 변경하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- 방문을 반복해도 같은 정책의 쿠폰이 회원당 한 장으로 수렴한다.
- 콘텐츠 운영자의 정책이 다른 운영자의 콘텐츠 예약에 영향을 주지 않는다.
- 가격 확정부터 예약 확정, 환불 복구까지 쿠폰 상태와 근거를 재현할 수 있다.
- 정책 종료 뒤에도 발급된 쿠폰의 유효 기간과 사용 권리를 보존한다.

### 수용한 단점과 위험

- 지역 공통 프로모션은 콘텐츠마다 정책을 별도로 운영해야 한다.
- 공개 중인 미션·스탬프북이 참조하면 쿠폰 정책을 즉시 종료할 수 없다.
- 가격 스냅샷, 예약 확정과 환불 완료 처리에 쿠폰 상태 잠금과 추가 이력 기록이 필요하다.

## 전환과 롤백

P1 신규 테이블로 시작하므로 기존 쿠폰 데이터 이관은 없다.
정책 소유권, 발급 키와 상태 전이 제약은 첫 migration부터 적용한다.
상태 전이와 이력 삽입은 하나의 트랜잭션에서 처리한다.
구현 전에는 이 ADR과 API·ERD 계약을 함께 되돌릴 수 있지만 운영 데이터가 생성된 뒤에는 새 ADR과 데이터 전환 계획으로 대체한다.

## 검증 방법

- 콘텐츠 비소유 운영자가 정책을 생성·수정·공개·종료할 수 없는지 확인한다.
- 근거가 없거나 둘 이상인 발급 이력이 생성되지 않는지 확인한다.
- 같은 정책·회원의 서로 다른 방문과 동시 발급이 쿠폰 한 장으로 수렴하는지 확인한다.
- 미션·스탬프북 보상은 같은 보상 근거의 반복·동시 요청이 쿠폰 한 장으로 수렴하는지 확인한다.
- 전체 발급 한도가 하나 남은 상태의 동시 발급에서 한 건만 성공하는지 확인한다.
- 다른 콘텐츠·만료·예약·사용 쿠폰이 가격 스냅샷에 연결되지 않는지 확인한다.
- `AVAILABLE → USED` 직접 전이가 거부되고 같은 스냅샷의 `RESERVED → USED`만 허용되는지 확인한다.
- 쿠폰 사용 동시 요청에서 한 건만 예약·스냅샷과 일치하는 `CONFIRMED` 사용 이력을 만드는지 확인한다.
- 0원 예약과 양수 결제 모두 가격 스냅샷 선점과 예약 확정 상태 전이가 같은 규칙을 따르는지 확인한다.
- 회차 시작 전 전액 환불 완료만 사용 이력을 `REVERSED`로 남기며, 만료 여부에 따라 `AVAILABLE` 또는 `EXPIRED`로 복구되는지 확인한다.
- 환불 보류·실패와 같은 환불 근거의 재처리가 쿠폰을 중복 복구하지 않는지 확인한다.

## 대체 조건

지역 관리자 소유의 지역 공통 프로모션, 정률 할인, 복수 쿠폰, 콘텐츠 간 공동 프로모션 또는 부분 환불 쿠폰 복구가 확정되면 재검토한다.

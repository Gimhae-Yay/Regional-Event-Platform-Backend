# ADR-0104: 스탬프북 제목을 NOT NULL 고유 속성으로 저장한다

- 상태: 채택됨

## 맥락

현재 스탬프북은 고유 제목을 저장하지 않으며, 생성·수정 요청과 방문자 목록·상세 응답에도 제목이 없다. 상세 응답의 `targetContents[].title`은 대상 콘텐츠의 현재 제목이므로 스탬프북 자체의 이름으로 사용할 수 없다.

스탬프북을 안정적으로 식별할 제목을 제공하려면, 대상 콘텐츠의 제목·순서·연결 변경과 독립된 값을 저장해야 한다. P1은 아직 실서비스 전이므로 제목 없는 기존 스탬프북 행이나 공개 API 호환 대상은 없다.

## 결정 동인과 불변 조건

- 스탬프북 제목은 대상 콘텐츠의 현재 제목 변화와 무관하게 유지한다.
- 생성·수정·목록·상세 API는 같은 저장된 제목을 사용한다.
- 제목은 `NULL`, 빈 문자열 또는 앞뒤 공백만으로 구성될 수 없다.
- `PUBLISHED`와 `ENDED` 스탬프북의 핵심 값 불변 정책을 제목 도입으로 완화하지 않는다.
- 초기 P1 스키마부터 제목 없는 스탬프북을 저장하거나 공개 응답에 노출하지 않는다.

## 결정

스탬프북 제목은 `stampbook.title VARCHAR(100) NOT NULL`로 저장한다. 생성 요청에서는 제목을 필수로 받고, 수정 요청에서는 `DRAFT` 상태일 때만 제목을 변경할 수 있다. `PENDING_REVIEW`, `PUBLISHED`, `ENDED`에서는 기존 핵심 값 수정 정책과 같이 제목 변경도 거부한다.

입력은 앞뒤 공백을 제거한 뒤 1자 이상 100자 이하인지 검증한다. 빈 문자열·공백만 있는 값·100자 초과 값은 `INVALID_INPUT`으로 거부하며, 내부 공백은 보존한다. 목록과 상세 응답은 저장된 `stampbook.title`을 `title` 필드로 그대로 반환한다.

P1 초기 스키마부터 제목 열과 `NOT NULL` 제약을 함께 만든다. 실서비스 이전이므로 기존 행 백필, nullable 중간 열, 호환 계층과 이관 감사 이벤트는 만들지 않는다.

제목 생성·수정은 기존 `STAMPBOOK` 생성·수정 성공 감사 이벤트와 같은 트랜잭션으로 처리한다. 제목 전용 감사 테이블이나 제목 원문을 감사 이벤트에 추가하지 않으며, 기존 감사의 처리자·상태·사유·시각·`requestId` 계약을 유지한다.

## 결과와 트레이드오프

### 기대 효과

- 방문자 목록·상세와 운영자 생성·수정이 동일하고 안정적인 스탬프북 제목 계약을 사용한다.
- 콘텐츠 제목 변경이나 대상 연결 변경이 이미 공개된 스탬프북 제목을 바꾸지 않는다.
- DB 제약과 API 검증이 제목 부재를 함께 차단한다.

### 수용한 단점과 위험

- 제목 변경 전후 값을 별도로 보존하지 않으므로, 변경 이력 조사에는 기존 수정 감사의 사유·처리자·시각만 사용할 수 있다.
- 제목 길이·공백 검증을 생성과 수정의 모든 저장 경로에서 동일하게 구현해야 한다.

## 전환과 롤백

초기 P1 schema migration에서 `stampbook.title VARCHAR(100) NOT NULL`을 다른 스탬프북 필수 열과 함께 만든다. 기존 행과 실서비스 클라이언트가 없으므로 데이터 이관·호환 계층·단계적 전환은 필요 없다.

구현·배포 실패 시 제목을 포함하는 아직 사용되지 않은 P1 schema와 애플리케이션을 함께 되돌릴 수 있다. 실서비스가 시작된 뒤 공개 계약을 철회하거나 nullable로 바꾸려면, 저장된 제목을 보존하는 호환·이관 계획을 별도 ADR로 정한다.

## 검증 방법

- 생성 요청이 앞뒤 공백을 제거한 1~100자 제목을 저장하고, 누락·공백·100자 초과 제목을 거부하는지 확인한다.
- `DRAFT` 수정에서만 제목이 변경되고, `PENDING_REVIEW`·`PUBLISHED`·`ENDED`에서는 기존 상태 충돌 응답을 반환하는지 확인한다.
- 목록·상세 응답의 `title`이 저장값과 일치하고, 대상 콘텐츠 제목 변경이나 대상 연결 변경 뒤에도 바뀌지 않는지 확인한다.
- 초기 schema의 제목 열이 `NOT NULL` 제약을 갖고, 생성된 모든 스탬프북이 제목을 포함해 조회되는지 확인한다.
- 생성·수정, 성공 감사 이벤트가 하나의 트랜잭션으로 함께 커밋 또는 롤백되는지 확인한다.

## 대체 조건

- 실서비스 시작 뒤 제목이 없는 기존 행을 도입하거나 외부 클라이언트 호환이 필요한 전환 요구가 확정된다.
- 제목 변경의 전·후 값을 보존해야 하는 감사·규제 요구가 확정된다.
- 다국어 제목, 검색용 별칭 또는 제목 고유성 제약이 제품 요구사항으로 확정된다.

# ADR-0028: 인증 후기 목록에 페이지 번호 기반 페이지네이션을 사용한다

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-07-29
- 결정일: 2026-07-29
- 관련 요구사항: [FR-08 인증 후기](../p0/review.md#fr-08-인증-후기), [후기 목록 API](../api/p0/review/get-content-reviews.md)
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

콘텐츠 상세에 공개 인증 후기를 제공하려면 목록 결과의 범위와 반복 조회의 경계를 명시해야 한다. 공통 페이지 계약은
페이지 기반 목록의 응답 틀만 정의하고 페이지 번호, 크기, 메타데이터를 확정하지 않았다. 사용자는 인증 후기 목록에
커서 기반 방식 대신 페이지 번호 기반 페이지네이션을 선택했다.

## 결정 동인과 불변 조건

- 공개 목록은 `PUBLISHED` 후기만 포함하며 빈 결과도 성공 응답으로 반환한다.
- `page`, `size`, 전체 건수와 페이지 수는 같은 조회 조건으로 계산한다.
- 요청 범위를 벗어난 페이지·크기는 서버가 임의 보정하지 않고 입력 오류로 거부한다.
- 목록은 작성자 계정 식별자, 방문 식별자와 삭제 후기 원문을 노출하지 않는다.

## 검토한 선택지

| 순서 | 선택지 | 장점 | 단점·실패 위험 | 되돌림 비용 | 현재 단계 적합성 |
| --- | --- | --- | --- | --- | --- |
| 1 | 커서 기반 페이지네이션 | 대량 데이터에서 다음 페이지 탐색 비용을 낮추고 삽입 중복을 줄이기 쉽다. | 커서 형식·정렬 키·이전 페이지 계약을 별도로 관리해야 한다. | 중간 | 사용자가 선택하지 않았다. |
| 2 | 페이지 번호 기반 페이지네이션 | 페이지 이동과 전체 건수 표시가 단순하고 콘텐츠 상세의 일반적인 목록 UI에 바로 적용할 수 있다. | 새 후기가 등록되면 페이지 경계가 이동할 수 있고 전체 건수 조회 비용이 든다. | 중간 | 사용자가 선택했으며 P0의 단순한 공개 목록에 적합하다. |

## 결정

인증 후기 목록은 `page`와 `size`를 사용하는 페이지 번호 기반 방식으로 제공한다. `page`는 0부터 시작하고 기본값은
0이며, `size`의 기본값은 20이고 허용 범위는 1~100이다. 응답은 `content`, `page`, `size`, `totalElements`,
`totalPages`를 포함한다. 후기 목록의 기본 정렬은 최신 작성순(`createdAt` 내림차순, 같은 시각이면 `reviewId`
내림차순)이다.

## 결과와 트레이드오프

### 기대 효과

- 클라이언트가 페이지 이동과 전체 건수 표시를 일관된 공통 계약으로 구현할 수 있다.
- 이후 페이지 기반 목록 API도 같은 메타데이터와 입력 범위를 사용한다.

### 수용한 단점과 위험

- 새 후기 등록·삭제 중 페이지 경계가 달라질 수 있으므로 페이지 간 결과의 완전한 스냅샷 일관성은 보장하지 않는다.
- `totalElements` 계산 비용은 데이터 증가 시 관찰 대상이며, 성능 근거 없이 캐시나 커서 방식으로 바꾸지 않는다.

## 전환과 롤백

신규 API이므로 이관할 기존 클라이언트나 데이터는 없다. 이후 커서 방식이 필요하면 현재 `page` 계약을 유지하는
호환 기간 또는 새 API 버전을 정한 후 후속 ADR로 전환한다.

## 검증 방법

- 기본값, 첫 페이지, 마지막 페이지, 빈 결과에서 페이지 메타데이터와 `content`가 같은 조회 결과인지 HTTP 테스트로 검증한다.
- 음수 `page`, 1 미만 또는 100 초과 `size`가 `INVALID_INPUT`으로 거부되는지 검증한다.
- `PUBLISHED`가 아닌 후기와 삭제 후기 원문이 목록에 포함되지 않는지 검증한다.

## 대체 조건

- 후기 수가 증가해 전체 건수 조회가 서비스 목표를 반복적으로 넘긴다.
- 무한 스크롤 또는 변경 중 중복·누락 완화가 제품 요구사항이 된다.

# ADR-0033: 사용자 소유 임시 이미지 객체를 연결해 생성 즉시 심사 요청

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-07-30
- 결정일: 2026-07-30
- 관련 요구사항: [PRD](../local-stamp-platform-prd.md)의 `FR-03`, `FR-14`, `CON-01`, `CON-02`, `CON-05`, `CON-08`
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: [ADR-0014](0014-store-published-content-edits-in-relational-revision-tables.md)의 반려 수정본을 새 수정본으로만 보정하는 범위, [ADR-0016](0016-use-private-s3-presigned-urls-and-immediate-image-deletion.md)의 기존 콘텐츠·수정본 문맥에서만 업로드 URL을 발급하고 이미지 객체에 사용자 식별자를 저장하지 않는 범위

## 맥락

콘텐츠와 수정본을 별도 초안으로 먼저 만들고 해당 루트에 대표 이미지를 업로드한 뒤 심사를 요청하는 방식도 검토했다.
사용자는 콘텐츠와 수정본 모두 생성 즉시 심사 요청 상태가 되도록 정책을 선택했다.
그런데 대표 이미지 업로드는 콘텐츠 생성 전에 끝나야 하므로, 기존 루트 기반 업로드 권한 검증만으로는 이미지의
소유자·단일 연결·고아 객체 정리를 보장할 수 없다.

사용자는 인증된 운영자에게 귀속되는 임시 이미지 객체를 먼저 발급하고, 콘텐츠 또는 수정본 생성 때 그 객체를
연결·검증하는 방식을 선택했다. 이는 심사 요청 생성에 필요한 완전한 대표 이미지와 사용자 소유권을 함께
검증하기 위한 변경이다.

## 결정 동인과 불변 조건

- 콘텐츠는 생성 즉시 완전한 필드·대표 이미지·유효 회차를 가진 `PENDING`이어야 하며 별도 초안 상태를 두지 않는다.
- 공개 콘텐츠 수정본은 생성 즉시 완전한 후보와 대표 이미지 스냅샷을 가진 `EDIT_REQUESTED`여야 하며 별도 초안 상태를 두지 않는다.
- 임시 객체는 승인된 `OPERATOR`에게만 발급하며, 콘텐츠·수정본 루트와 연결되기 전에는 발급 사용자·만료 시각을 가진다.
- 콘텐츠 또는 수정본 생성·반려 보완은 임시 객체의 사용자 소유, 미연결 상태, 만료와 S3 객체의 매체 유형·크기·체크섬을 검증해야 한다.
- 한 임시 객체는 한 번만 연결할 수 있고, 연결 성공 시 임시 소유자·만료를 제거한 불변 `ACTIVE` 객체가 된다.
- 임시 객체는 일반 방문자와 지역 관리자에게 조회·재연결할 수 없고, 만료된 미연결 객체는 비공개 삭제 경로로만 처리한다.
- 연결 뒤 대표 이미지 참조와 삭제 안전성은 ADR-0029의 직접 FK·참조 0건 검사 규칙을 유지한다.

## 결정

`POST /operator/uploads/presigned-url`은 승인된 운영자의 요청에 대해 서버 생성 객체 키와 `TEMPORARY`
`image_object`를 만든다. 이 행에는 `temporary_owner_user_id`, 유한한 `temporary_expires_at`, 업로드 검증에
사용할 매체 유형·크기·SHA-256 Base64 체크섬을 저장한다. 업로드 서명 URL은 `x-amz-checksum-sha256` 헤더를
서명하므로 클라이언트는 저장한 체크섬과 같은 값을 이 필수 헤더로 PUT해야 한다. 응답에는 임시 객체 식별자,
짧은 유효기간의 업로드 서명 URL과 서명된 체크섬 헤더 계약만 제공한다.
임시 상태는 콘텐츠·수정본 FK가 없으므로 일반 조회나 심사 조회에서 노출하지 않는다.

`POST /operator/contents`는 완전한 콘텐츠 필드, 유효 회차와 `representativeImageObjectId`를 받아 생성 즉시
`PENDING` 콘텐츠와 생성 로그를 만든다. 같은 트랜잭션에서 임시 객체 행을 잠그고 요청자 소유·만료 전·미연결
상태를 확인하며, S3 `HEAD` 결과의 매체 유형·크기·SHA-256 체크섬이 저장한 값과 일치하는지 검증한다. 모두 통과하면 해당
객체를 대표 이미지 FK에 한 번만 연결하고 `TEMPORARY → ACTIVE`, 임시 소유자·만료 제거, 콘텐츠 생성·로그·감사
기록을 원자적으로 커밋한다. 실패하면 콘텐츠·로그·연결을 만들지 않는다.

`POST /operator/contents/{contentId}/revisions`도 완전한 후보 필드로 `EDIT_REQUESTED` 수정본을 즉시 만든다.
대표 이미지 변경이 있으면 같은 임시 객체 연결·검증 규칙을 적용하고, 변경이 없으면 현재 대표 이미지 객체를 후보
스냅샷으로 복사한다. 반려 콘텐츠와 `EDIT_REJECTED` 수정본의 보완은 대표 이미지가 바뀔 때만 새 임시 객체를 연결하며,
이미지가 바뀌지 않으면 기존 후보 스냅샷을 유지한다. 재요청만 각각 `REJECTED → PENDING`,
`EDIT_REJECTED → EDIT_REQUESTED`로 전이한다. 수정본의 심사 요청·승인·반려·철회 결정은 상태·처리자·사유·시각을
추가 전용 이력으로 남겨 재요청 뒤에도 기존 반려 사유를 보존한다. `PENDING`, `APPROVED`, `EDIT_REQUESTED`의
심사 중 데이터는 직접 편집하지 않는다.

임시 객체가 만료되면 배치 작업이 행을 잠근 뒤 `TEMPORARY → DELETE_PENDING`, 임시 소유자·만료 제거를 같은
트랜잭션에서 처리하고 S3 삭제를 재시도한다.
만료 정리의 최대 보관 시간은 구현 설정에서 유한하게 정하되, 만료 전 객체는 연결하지 않으면 어떤 공개·심사
조회 경로에도 노출하지 않는다. S3 삭제 실패와 연결 경합은 `DELETE_PENDING` 재시도와 `TEMPORARY` 조건부 전이로
멱등 처리한다. 연결 성공 후에는 임시 소유자 연결을 제거하므로 이미지 객체에 영구 사용자 식별자를 보관하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- 콘텐츠·수정본이 생성 순간부터 완전한 심사 후보여서 심사 중 값이 바뀌지 않는다.
- 콘텐츠 루트가 생기기 전에도 업로드 권한을 사용자와 유한한 임시 객체에 제한한다.
- 객체 재사용·다중 연결·만료 객체 연결을 행 잠금과 상태 전이로 차단한다.
- 연결된 대표 이미지의 공개·심사 조회와 참조 기반 삭제 규칙을 유지한다.

### 수용한 단점과 위험

- 임시 객체의 만료 정리, S3 메타데이터 검증과 실패 재시도 운영이 추가된다.
- 업로드는 성공했지만 생성 명령이 실패한 객체가 만료 전까지 비공개로 남을 수 있다.
- 사용자는 콘텐츠·수정본 생성 전에 대표 이미지를 먼저 업로드해야 하며, 임시 URL 만료 뒤에는 다시 발급받아야 한다.

## 전환과 롤백

구현 전 정책 변경이므로 기존 데이터 이관은 없다. Flyway로 `image_object`에 임시 소유자·만료와 `TEMPORARY`
상태 제약을 추가한 뒤, 임시 객체 발급·S3 검증·생성 연결·만료 정리 순서로 구현한다. 별도 초안 상태 제약은 두지 않고,
생성 요청에 완전한 필드와 임시 객체 식별자를 요구한다.

도입 중 문제가 발생하면 새 임시 객체 발급과 콘텐츠·수정본 생성 명령을 함께 중지하고, 이미 연결된 `ACTIVE`
객체와 기존 공개 조회를 유지한다. 임시 객체를 공개 객체로 승격시키거나 다른 사용자에게 이전하지 않으며, 만료·삭제
처리 실패는 비공개 `DELETE_PENDING` 재시도로만 복구한다.

## 검증 방법

- 승인된 운영자만 자신의 임시 객체 ID와 업로드 URL을 받고, 다른 사용자·다른 지역 관리자·일반 사용자는 발급·연결·조회할 수 없는지 검증한다.
- 콘텐츠와 수정본 생성이 완전한 필드·유효 회차·검증된 이미지 없이 `PENDING` 또는 `EDIT_REQUESTED`를 만들지 않는지 검증한다.
- 동일 임시 객체로 동시에 두 생성 요청을 보내도 하나만 `ACTIVE`로 연결되고 다른 요청은 상태를 만들지 못하는지 MySQL 통합 테스트로 검증한다.
- 만료 객체, S3 객체 부재, 매체 유형·크기·SHA-256 체크섬 불일치가 콘텐츠·수정본·상태 로그를 만들지 않는지 검증한다.
- 업로드 서명 URL이 `x-amz-checksum-sha256`을 서명하고, 누락하거나 저장값과 다른 헤더의 PUT이 거부되는지 검증한다.
- 반려 보완과 수정본 재요청에서 대표 이미지를 바꿀 때만 새 임시 객체를 검증·연결하고, 기존 반려 사유 이력이 보존되는지 검증한다.
- 만료된 미연결 객체와 참조가 제거된 객체가 공개·심사 경로에 노출되지 않고 S3 삭제 실패 시 재시도되는지 검증한다.
- 연결 성공 뒤 `temporary_owner_user_id`와 `temporary_expires_at`이 제거되고, 이미지 객체에 영구 사용자 식별자가 남지 않는지 검증한다.

## 대체 조건

- 생성 뒤 심사 전 공동 편집·다수 이미지·임시 저장 UX가 P0 범위에 다시 포함된다.
- 악성 파일 검사, 법적 보존 또는 복구 기간 때문에 임시 객체의 즉시 삭제·유한 보관 정책을 유지할 수 없다.
- 외부 CMS·대량 가져오기에서 사용자 소유 임시 업로드 대신 서버 간 객체 이전 계약이 필요해진다.

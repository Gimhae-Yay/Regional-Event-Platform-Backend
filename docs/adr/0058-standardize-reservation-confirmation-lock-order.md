# ADR-0058: 예약 확정 잠금 순서를 콘텐츠·회차·홀드 순으로 통일

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-03
- 결정일: 2026-08-03
- 관련 요구사항: [활성 홀드의 무료 예약 확정](../api/p0/reservation/confirm-reservation-hold.md#4-활성-홀드의-무료-예약-확정), [공개 콘텐츠 운영 중단](../api/p0/region-content/suspend-content.md), [SES-02 콘텐츠 상태와 예약 연계 정책](../p0/content-catalog.md#ses-02)
- 관련 단계: 단계 1. MVP 구현·검증
- 관련 이슈: [#262](https://github.com/Gimhae-Yay/Regional-Event-Platform-Backend/issues/262), [PR #340](https://github.com/Gimhae-Yay/Regional-Event-Platform-Backend/pull/340)
- 대체 대상: 없음

## 맥락

예약 확정은 콘텐츠가 `PUBLISHED`, 회차가 `SCHEDULED`이고 시작 전이며 홀드가 미만료 `ACTIVE`인 경우에만
성공해야 한다. 콘텐츠 운영 중단은 `content → content_session → capacity_hold` 순서로 관련 행을 잠근 뒤
활성 홀드를 무효화하고 정원을 복구한다. 회차 취소도 `content_session`을 잠근 뒤 해당 회차의 활성 홀드를
처리한다.

기존 공개 콘텐츠 운영 중단 API 명세는 예약 확정의 잠금 순서를 `content → capacity_hold`로 적었지만,
예약 확정 구현은 회차 상태와 시작 시각을 직렬화하기 위해 `content_session`을 홀드보다 먼저 잠갔다. PR #340은
콘텐츠 운영 중단과의 경합을 직렬화하기 위해 예약 확정 경로의 `content` 잠금을 명시하고 MySQL 실제 잠금 대기를
검증했다. 구현과 명세를 일치시키고 콘텐츠 중단·회차 취소·예약 확정이 공통 순서로 잠금을 획득하도록 결정할
필요가 있다.

이 결정은 [ADR-0001](0001-use-mysql-conditional-update-for-capacity-consistency.md)의 MySQL 조건부 갱신을
최종 정합성 기준으로 사용하는 원칙과
[ADR-0047](0047-record-capacity-hold-and-reservation-confirmation-audits.md)의 예약 확정 감사 원자성을 변경하지
않는다. 멱등 키 점유와 권한 조회는 이 ADR의 도메인 행 잠금 순서 범위에 포함하지 않는다.

## 결정 동인과 불변 조건

- 콘텐츠 운영 중단·회차 취소·예약 확정이 같은 행에 경합해도 순환 잠금 대기로 교착하지 않아야 한다.
- 예약 확정은 콘텐츠·회차·홀드 조건을 잠금 또는 조건부 전이 시점에 다시 확인해야 한다.
- 콘텐츠 또는 회차 상태 전이와 홀드의 `ACTIVE → CONSUMED`가 경합하면 먼저 커밋된 결과만 유효해야 한다.
- 홀드의 종결 상태 전이는 한 번만 성공하고 정원을 중복 차감하거나 복구하지 않아야 한다.
- MySQL 조건부 갱신을 최종 정합성 기준으로 유지한다.

## 결정

예약 확정의 콘텐츠·회차·홀드 상태 전이와 관련된 도메인 행 잠금 및 조건부 전이는
`content → content_session → capacity_hold` 순서로 수행한다.

1. 대상 `content` 행을 잠그고 `PUBLISHED`이며 삭제되지 않았는지 확인한다.
2. 대상 `content_session` 행을 잠그고 `SCHEDULED`이며 MySQL 기준 현재 시각이 시작 전인지 확인한다.
3. 대상 `capacity_hold`를 미만료 `ACTIVE`와 소유자 조건으로 `ACTIVE → CONSUMED` 조건부 갱신한다.
4. 어느 조건이든 충족하지 않으면 예약과 성공 감사 이벤트를 생성하지 않고 예약 확정 충돌로 처리한다.

홀드 생성 시 이미 확보한 정원은 예약 확정에서 다시 변경하지 않는다. 조건부 갱신과 하나의 MySQL 트랜잭션을
최종 정합성 기준으로 사용하는 ADR-0001의 결정도 유지한다.

## 결과와 트레이드오프

### 기대 효과

- 콘텐츠 운영 중단과 예약 확정이 콘텐츠 행에서 먼저 직렬화되어 먼저 커밋된 상태 전이를 일관되게 따른다.
- 회차 취소와 예약 확정이 `content_session → capacity_hold` 순서를 공유해 반대 방향 잠금 대기를 피한다.
- 콘텐츠·회차·홀드의 현재 상태와 시간 조건을 각각 잠금 또는 조건부 전이 시점에 검증한다.
- 구현, 예약 확정 명세와 콘텐츠 운영 중단 명세의 잠금 순서가 일치한다.

### 수용한 단점과 위험

- 같은 콘텐츠의 서로 다른 회차 예약 확정도 콘텐츠 행에서 직렬화될 수 있다.
- 긴 트랜잭션이나 인기 콘텐츠에서는 콘텐츠·회차 행의 잠금 대기와 타임아웃이 증가할 수 있다.
- 새 상태 전이 경로가 같은 행을 다른 순서로 잠그면 다시 교착 가능성이 생기므로 공통 순서를 계속 검토해야 한다.

## 전환과 롤백

PR #340의 예약 확정 경로와 MySQL 경합 테스트를 이 순서의 구현 기준으로 사용하고, 예약 확정 및 공개 콘텐츠
운영 중단 API 명세를 같은 변경에서 정합화한다. 스키마·데이터 이관이나 호환 계층은 필요하지 않다.

배포 전 MySQL 경합 검증에서 교착 또는 정합성 위반이 발견되면 배포하지 않는다. 채택된 순서를 변경해야 하면
이 ADR을 수정하지 않고 새 ADR로 대체한 뒤 관련 API 명세, 구현과 경합 테스트를 함께 전환한다.

## 검증 방법

- Testcontainers MySQL에서 중단이 먼저 커밋되면 경합한 예약 확정이 거부되고 활성 홀드 정원이 한 번 복구되는지 검증한다.
- 예약 확정이 먼저 커밋되면 소비된 홀드와 `CONFIRMED` 예약은 유지되고 나머지 활성 홀드만 무효화되는지 검증한다.
- `performance_schema.data_lock_waits`에서 후행 트랜잭션의 실제 행 잠금 대기를 확인한 뒤 선행 트랜잭션을 커밋한다.
- 회차 취소와 예약 확정의 양쪽 커밋 순서에서 `CANCELLED` 회차에 새 예약이 생기거나 소비·무효화가 중복되지 않는지 검증한다.
- 전체 테스트와 빌드가 성공하고 MySQL 교착 또는 잠금 대기 시간 초과가 발생하지 않아야 한다.
- 운영에서는 MySQL 교착 횟수, 잠금 대기 시간과 예약 확정 충돌·타임아웃 비율을 관찰한다.

## 대체 조건

- 콘텐츠 행 직렬화로 예약 확정 처리량 또는 잠금 대기가 합의한 운영 SLO를 지속적으로 위반한다.
- 회차 취소·중단·확정의 상태 전이 모델이 바뀌어 현재 공통 잠금 순서를 유지할 수 없다.
- 다중 리전 또는 다른 저장소로 전환해 하나의 MySQL 트랜잭션에서 세 행을 순서대로 잠글 수 없다.

# ADR-0013: P0에서 Transactional Outbox 구현 보류

- 상태: 채택됨
- 기록 유형: 소급
- 기록일: 2026-07-28
- 결정일: 2026-07-27
- 관련 요구사항: [P0 명세](../p0-spec.md)의 5.2 비목표와 [8.8 감사 및 운영 로그](../p0-spec.md#88-감사-및-운영-로그)
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: [ADR-0007](0007-use-transactional-outbox-with-spring-scheduler.md)의 P0 단계 Outbox 저장·Scheduler 폴링·외부 전달·재시도·소비자 멱등성·정리·관측 적용 부분, [ADR-0008](0008-evolve-clean-architecture-by-use-case.md)의 P0에서 거래와 Outbox 저장 원자성 및 Outbox 흐름을 전제한 참조 부분

## 맥락

ADR-0007은 MySQL Transactional Outbox와 Spring Scheduler로 알림·분석 이벤트를 전달하는 방식을 초기 MVP에
적용하도록 기록했다. 그러나 2026-07-27에 확정된 현재 P0 범위는 외부 이벤트의 발행·전달·재시도·소비를
포함하지 않고, 상태 전이와 실패 사유의 감사 재현만 요구한다.

따라서 P0에 Outbox 테이블, 전달기와 운영 절차를 추가하면 아직 정해지지 않은 알림·분석 전달 대상 없이 DB 쓰기,
폴링, 재시도와 장애 복구 비용만 선행하게 된다. 반대로 P0의 상태 전이 감사 요구를 외부 전달 이벤트와 혼동하면
감사 기록의 범위와 전달 보장의 범위가 불명확해진다.

이 결정은 2026-07-27의 P0 범위 문서에 이미 반영되어 있었으나, 채택된 ADR-0007과 ADR-0008의 P0 적용 범위와
명시적으로 연결되지 않았다. 당시 대안 비교의 전체 기록은 남아 있지 않으므로, 이 ADR은 확인 가능한 P0 범위와
현재 사용자의 재확인만을 근거로 소급 기록한다.

## 결정 동인과 불변 조건

- P0의 예약·체크인·콘텐츠 상태 전이는 외부 알림·분석 전달의 가용성에 의존하지 않는다.
- P0에는 Outbox 테이블·Flyway migration·도메인 적재·Scheduler 폴링·외부 전달·재시도·수동 재처리·정리와
  소비자 `event_id` 멱등성 계약을 구현하지 않는다.
- Outbox를 생략하는 대신 외부 알림·분석 호출을 P0의 DB 트랜잭션 안에서 동기로 실행하지 않는다.
- [ADR-0001](0001-use-mysql-conditional-update-for-capacity-consistency.md)의 정원 원자성,
  [ADR-0003](0003-use-persisted-idempotency-for-reservation-and-checkin.md)의 예약·체크인 멱등성과 현재 P0의
  권한·상태 전이 불변 조건은 유지한다.
- `FR-11`의 감사 기록과 구조화 로그는 P0 범위에 계속 남으며, 이 ADR은 감사 저장 모델을 새로 결정하지 않는다.
- 콘텐츠 자동 공개, 홀드 만료와 노쇼 처리처럼 도메인 상태를 위한 Scheduler 작업은 Outbox 전달기와 별개로
  유지할 수 있다.
- P0 기간에 외부 이벤트의 저장·재생·사후 전달은 보장하지 않으며, 이후 Outbox를 도입해도 P0 과거 상태 전이를
  자동으로 보정 적재하지 않는다.

## 결정

P0에서는 Transactional Outbox를 구현하지 않는다. 예약·체크인·콘텐츠 상태 전이에서 Outbox 행을 적재하지 않고,
Outbox 전달용 `@Scheduled` 작업, 외부 알림·분석 호출, 전달 재시도·수동 재처리·보관 정리와 소비자 멱등성 계약을
추가하지 않는다.

P0의 `FR-11`은 상태 전이와 실패 사유를 감사 기록과 구조화 로그로 재현하는 범위로 유지한다. 감사 기록은 외부
전달 이벤트가 아니며, 그 영속 모델·보관·탈퇴 익명화의 구체적인 기술 결정은 이 ADR의 범위에 포함하지 않는다.

알림·분석 같은 외부 전달 요구가 실제 릴리스 범위에 채택되면 ADR-0007을 자동으로 다시 적용하지 않는다. 전달
대상, 이벤트 계약·개인정보, 전달 보장, 재시도·보관, 운영 지표와 P0 과거 데이터 보정 적재 필요성을 비교하는 새
ADR을 먼저 채택한다.

## 결과와 트레이드오프

### 기대 효과

- P0 구현은 예약·체크인·권한·감사 재현의 핵심 계약에 집중한다.
- 전달 대상이 없는 Outbox 테이블, 폴링, 실패 격리와 운영 화면을 만들지 않는다.
- 외부 전달 장애가 P0 거래의 성공·실패 의미에 영향을 주지 않는다.
- 감사 기록과 외부 이벤트 전달의 책임을 분리해 후속 설계의 출발점을 명확히 한다.

### 수용한 단점과 위험

- 예약 확정·취소·체크인 등의 외부 알림과 분석 이벤트를 P0에서 제공하지 않는다.
- P0 기간의 상태 전이를 나중에 신뢰성 있는 외부 이벤트로 재생할 수 있다는 보장은 없다.
- 후속 단계에서 Outbox를 도입할 때 전달 계약, 스키마와 운영 절차를 별도 설계·검증해야 한다.

## 전환과 롤백

현재 저장소에는 Outbox migration, 엔터티·저장소, 전달 Scheduler와 외부 소비자 구현이 없다. 따라서 P0 범위를
이 결정에 맞추는 데 데이터 이관, 호환 계층이나 운영 중단은 필요하지 않다.

후속 외부 전달 도입 전에는 새 ADR로 Outbox 재채택 여부와 실제 전달 계약을 확정한다. 그 뒤에만 새 Outbox
스키마와 발행자·소비자를 단계적으로 추가한다. 이미 구현된 P0 상태 전이를 되돌리거나 기존 ADR-0007을
수정해 롤백하지 않는다.

## 검증 방법

- P0 범위 문서와 기술 스택 문서에서 Outbox 전달이 P0 구현 의무로 남아 있지 않은지 확인한다.
- P0 코드와 Flyway migration에 Outbox 테이블·적재·전달 Scheduler·외부 이벤트 전송이 없는지 검사한다.
- 예약 정원, 예약·체크인 멱등성, QR과 권한의 기존 P0 수용 기준이 Outbox 없이 유지되는지 검증한다.
- `FR-11` 감사 기록이 상태 전이와 실패 사유를 재현하되 외부 전달 보장을 주장하지 않는지 확인한다.
- ADR 번호, 대체 범위와 링크를 확인하고 `git diff --check`를 통과한다.

## 대체 조건

- 알림·분석·외부 연동에 전달 보장이나 재시도가 필요한 기능이 실제 릴리스 범위에 채택된다.
- 외부 계약 또는 규제가 상태 전이의 전달·보관·감사 보장을 요구한다.
- 후속 단계에서 전달 지연, 재생, 다수 소비자 분기 또는 소비자 멱등성의 운영 목표가 정의된다.
- P0 과거 상태 전이를 외부 시스템에 보정 적재해야 할 구체적인 요구가 생긴다.

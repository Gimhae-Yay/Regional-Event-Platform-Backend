# ADR-0091: 콘텐츠 공통 예약 가격을 결제 생성 시 스냅샷으로 고정한다

## 맥락

결제 생성 API는 `reservation_price_snapshot.base_amount`를 기준으로 쿠폰 할인과 양수·0원 분기를 처리하지만, 기존 P0 콘텐츠·회차 모델에는 가격 원천이 없다. 회차별 가격을 도입하면 회차 생성·수정과 가격 운영을 함께 확장해야 한다. 사용자는 콘텐츠 하나의 모든 회차에 같은 예약 가격을 적용하는 방식을 선택했다.

## 결정 동인과 불변 조건

- 하나의 콘텐츠에 속한 모든 예약 회차는 같은 기본 예약 가격을 사용한다.
- 가격은 정수 KRW이며 0 이상이다. 0은 외부 결제 없는 기존 무료 예약 대상이다.
- 결제 생성을 시작한 뒤에는 콘텐츠 가격이나 쿠폰 정책 변경이 해당 홀드의 결제 금액을 바꾸지 않는다.
- 공개 콘텐츠의 가격 변경은 심사 없는 직접 수정으로 반영하지 않는다.

## 결정

`content.reservation_price`를 콘텐츠 공통 예약 가격으로 둔다. 값은 정수 KRW이고 0 이상이며, 콘텐츠 생성 요청에서 필수로 입력한다.

콘텐츠 가격 변경은 콘텐츠 수정본의 후보 `reservation_price`로 제출하고 기존 수정본 심사·승인 절차를 통과한 뒤에만 원본에 반영한다. 가격을 포함한 공개 콘텐츠 수정본이 승인돼도 이미 생성된 `reservation_price_snapshot`은 변경하지 않는다. 결제 생성은 잠근 콘텐츠의 현재 `reservation_price`와 적용 쿠폰을 사용해 홀드당 하나의 스냅샷을 만든다.

기존 무료 예약 확정 경로는 잠근 콘텐츠의 `reservation_price = 0`일 때만 허용한다. 양수 가격 콘텐츠는 가격 스냅샷·결제 생성 전의 빈 P1 연결만으로 무료 확정을 허용하지 않고 `RESERVATION_CONFIRM_CONFLICT`로 거부한다. 공개 회차 예약 정보와 최초·수정본 심사 응답은 현재 또는 후보 가격을 노출하며, 수정본 승인에서는 후보 가격을 원본에 다른 후보 필드와 같은 트랜잭션으로 반영한다.

## 결과와 트레이드오프

### 기대 효과

- 양수 결제와 쿠폰 할인 뒤 0원 확정의 기준 금액이 명확하다.
- 같은 콘텐츠의 여러 회차는 일관된 가격을 사용하고, 결제 재시도는 홀드 스냅샷으로 같은 금액을 유지한다.

### 수용한 단점과 위험

- 한 콘텐츠의 회차별 가격 차등은 지원하지 않는다.
- 공개 가격 변경은 수정본 심사·승인 뒤에만 반영되므로 즉시 가격 변경이 불가능하다.

## 전환과 롤백

기존 P0 `content`와 `content_revision`에는 모두 `reservation_price = 0`을 먼저 채운 뒤 `NOT NULL`과 `0 이상` 제약을 적용해 호환성을 유지한다. 특히 심사 대기(`EDIT_REQUESTED`) 수정본도 이관 대상에 포함해, 상세 조회와 승인에서 후보 가격 누락 없이 기존 수정본 절차를 계속 처리한다. 이후 콘텐츠 생성·수정본·수정본 승인 반영과 공개 회차 조회가 이 필드를 사용하도록 순방향 migration과 코드 변경을 적용한다. 결제 생성은 이 가격 원천과 가격 스냅샷 구현이 함께 배포되기 전까지 활성화하지 않는다. 회차별 가격이 필요해지면 새 ADR로 이 결정을 대체하고 기존 콘텐츠·스냅샷의 이관 규칙을 정의한다.

## 검증 방법

- 콘텐츠 생성은 0 이상 정수 KRW 가격을 저장하고, 음수·누락 가격을 거부하는지 확인한다.
- 가격이 0인 콘텐츠의 무료 확정만 성공하고, 양수 가격 콘텐츠는 P1 연결이 아직 없어도 `RESERVATION_CONFIRM_CONFLICT`로 거부하는지 확인한다.
- 공개 회차 예약 정보가 `content.reservation_price`를 반환하고, 최초·수정본 심사에서 각각 현재·후보 가격을 검토할 수 있는지 확인한다.
- 기존 `content`·`content_revision`을 0으로 이관한 뒤 `NOT NULL`과 `0 이상` 제약을 적용하고, 이관된 `EDIT_REQUESTED` 수정본의 상세 조회와 승인이 정상 동작하는지 확인한다.
- 수정본 승인 전에는 원본 가격이 바뀌지 않고 승인 후에만 후보 가격이 반영되는지 확인한다.
- 같은 콘텐츠의 서로 다른 회차 홀드가 동일한 콘텐츠 가격을 스냅샷 기본 금액으로 사용하는지 확인한다.
- 가격 변경과 결제 생성이 경합할 때 잠금 뒤 읽은 가격으로 하나의 스냅샷만 만들어지고, 기존 스냅샷이 바뀌지 않는지 MySQL 통합 테스트로 확인한다.

## 대체 조건

- 회차별 가격, 시간대별 요금, 수량별 가격 또는 통화 다변화가 제품 요구사항으로 채택되면 가격 소유 단위와 스냅샷 입력을 재검토한다.

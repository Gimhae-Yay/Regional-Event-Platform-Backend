# ADR-0059: 문서·프로덕션 코드·테스트 Task의 문서 변경 경계를 분리한다

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-01
- 결정일: 2026-08-01
- 관련 요구사항: [Java 코드 컨벤션의 도메인과 API 경계](../code-convention.md#33-도메인과-api-경계), [엔티티·테이블·관계 기준](../erd.md), [GitHub Task 이슈 생성 절차](../../.agents/skills/issue-create/SKILL.md)
- 관련 단계: 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: [ADR-0058](0058-freeze-public-contracts-during-task-implementation.md)의 모든 Task에서 공개 계약 문서 변경을 금지한 범위

## 맥락

ADR-0058은 구현 Task에서 공개 계약을 변경하지 않도록 정했지만, 문서 생성·수정 자체가 완료 조건인 `Docs` Task까지 문서 변경을 막는 것으로 해석될 수 있다. 또한 Entity, migration 또는 런타임 설정 변경으로 DB 스키마가 바뀌는 경우에는 프로덕션 코드 구현 전에 ERD를 갱신해야 한다.

사용자는 문서 작업은 독립된 `Docs` Task에서 허용하고, 프로덕션 코드 구현과 테스트 전용 Task에서는 문서를 읽기 전용으로 유지하기로 결정했다.

## 결정 동인과 불변 조건

- 문서 생성·수정 Task는 이슈에 명시된 문서를 실제로 완료할 수 있어야 한다.
- 프로덕션 코드·migration·런타임 설정 변경은 확정된 API·ERD·정책 계약만 구현한다.
- 테스트 전용 Task는 계약을 검증하며, 검증 중 발견한 문서 불일치를 임의로 고치지 않는다.
- 정책 결정은 코드·테스트 구현 전에 ADR로 확정하고, 원격 이슈 생성은 사용자 승인을 거친다.

## 결정

`Docs` 라벨의 문서 작업 Task는 이슈에 명시된 문서를 생성·수정하고 링크·참조·형식을 검증한다. 이 모드에서는 프로덕션 코드, migration, 런타임 설정과 테스트 소스를 변경하지 않는다.

프로덕션 코드 구현 Task와 테스트 전용 Task는 문서를 읽기 전용으로 사용한다. 기존 GitHub Task TODO 체크박스의 완료 표시만 예외로 허용한다. Entity, migration 또는 런타임 설정 변경으로 ERD·API·PRD·아키텍처 문서의 변경이 필요하면, 관련 Docs Task를 먼저 완료한 뒤 구현 Task를 시작한다.

프로덕션 코드 구현 또는 테스트 전용 Task에서 문서 문제가 발견되면, 재현 가능한 구현·계약 불일치는 Bug Issue 초안으로 분리하고, 정책 미확정은 ADR로 전환하며, 동작에 영향을 주지 않는 문서 오류는 Docs Task로 분리한다. 원인이 불명확하면 먼저 troubleshooting으로 원인을 확인한다.

이 결정은 ADR-0058의 공개 계약 문서 변경 금지 원칙을 프로덕션 코드 구현·테스트 전용 Task에만 적용하도록 대체한다.

## 결과와 트레이드오프

### 기대 효과

- Docs Task가 문서 생성·수정의 완료 조건을 직접 충족한다.
- 프로덕션 코드와 테스트 변경이 문서 계약 변경과 섞이지 않는다.
- DB 스키마 변경 전에 ERD를 확정해 migration과 엔티티의 근거를 보존한다.

### 수용한 단점과 위험

- 하나의 기능에 Docs Task와 구현 Task가 나뉘어 의존성 관리가 늘어난다.
- 긴급한 문서 정정도 Docs Task 절차를 거쳐야 한다.
- 문서 불일치의 Bug·ADR·Docs Task 분류를 잘못하면 처리 경로가 지연될 수 있다.

## 전환과 롤백

Task 구현 스킬과 코드 컨벤션에서 작업 모드별 경계를 적용한다. 기존 진행 중 Task는 이 결정 이후 시작하는 작업부터 적용하며, 현재 코드·DB 이관은 필요 없다.

Docs Task 분리로 인해 구현 대기가 반복적으로 문제 되면, Docs Task와 구현 Task의 의존성·우선순위만 조정한다. 모든 Task에서 문서 변경을 다시 허용하려면 이 ADR을 대체하고 검토·승인 경계를 다시 결정한다.

## 검증 방법

- Docs Task가 문서 이외의 프로덕션·테스트 파일을 변경하지 않는지 확인한다.
- 프로덕션 코드 구현과 테스트 전용 Task가 TODO 표시 외 문서를 변경하지 않는지 확인한다.
- 스키마 변경 Task가 구현 시작 전에 ERD를 갱신한 Docs Task에 의존하는지 확인한다.
- 문서 불일치가 Bug Issue, ADR 또는 Docs Task로 근거에 따라 분리됐는지 확인한다.
- 원격 Bug Issue가 사용자 승인 없이 생성되지 않는지 확인한다.

## 대체 조건

- Docs Task 분리 때문에 반복적인 긴급 장애 대응이나 배포 지연이 확인된다.
- 이슈 템플릿과 검토 절차가 코드·문서 변경을 같은 Task에서 안전하게 분리·승인할 수 있도록 바뀐다.
- ERD·API·정책 문서의 선행 갱신을 자동 검증할 수 있는 CI 규칙이 확정된다.

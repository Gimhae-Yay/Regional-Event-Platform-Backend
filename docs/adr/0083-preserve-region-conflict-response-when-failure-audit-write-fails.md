# ADR-0083: 지역 전환 실패 감사 저장 장애에도 원래 충돌 응답을 유지

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-07
- 결정일: 2026-08-07
- 관련 요구사항: [전체관리자](../p1/platform-admin.md)의 `P1-FR-09`, `ADM-02`, `ADM-05`
- 관련 단계: 단계 3. 확장 의사결정
- 관련 이슈: 없음
- 대체 대상: [ADR-0082](0082-store-evidence-reference-in-region-visibility-failure-audits.md)의 실패 감사 저장 자체가 실패한 경우의 응답·관측 범위

## 맥락

[ADR-0082](0082-store-evidence-reference-in-region-visibility-failure-audits.md)은 비삭제 콘텐츠 조건으로 거부된
지역 공개 여부 변경을 롤백한 뒤, 실패 감사 이벤트를 별도 트랜잭션으로 기록하도록 정했다. 그러나 별도 감사
트랜잭션 자체가 실패했을 때 원래 `409 REGION_AVAILABILITY_CONFLICT`를 유지할지 `500`으로 바꿀지와 감사 누락을
어떻게 관찰할지는 정하지 않았다.

지역 비공개 전환의 거부 판정과 롤백은 감사 저장 전에 이미 확정된다. 이후 감사 저장 장애를 새로운 도메인 처리
실패로 응답하면 클라이언트가 재시도해도 같은 상태 조건 때문에 다시 거부되고, 실제 원인과 다른 `500`을 받게 된다.
[ADR-0063](0063-record-failed-session-creation-after-ended-content-check.md)은 같은 독립 실패 감사 경계에서 감사 저장
실패가 원래 거부 응답을 바꾸지 않고 구조화 로그로 관찰되도록 정한 선례를 제공한다.

## 결정 동인과 불변 조건

- 비삭제 콘텐츠가 있는 지역의 `true → false` 거부와 롤백 결과는 감사 저장 장애와 무관하게 유지해야 한다.
- 감사 저장 실패를 성공으로 숨기거나 원래 변경 트랜잭션을 재시도해서는 안 된다.
- 감사 누락은 `requestId`와 비개인 대상 정보로 운영자가 탐지할 수 있어야 한다.
- 구조화 로그와 알림에 증빙 참조, 토큰, 비밀값과 개인정보를 포함하지 않아야 한다.
- 감사 저장 재시도가 요청 처리 시간을 무기한 늘리거나 중복 이벤트를 만들어서는 안 된다.

## 결정

비삭제 콘텐츠 조건을 확인한 지역 공개 여부 변경은 변경 트랜잭션을 롤백한 뒤 실패 감사를 별도 트랜잭션으로 한 번
기록한다. 실패 감사 저장이 성공하면 기존 계약대로 `409 REGION_AVAILABILITY_CONFLICT`를 반환한다.

실패 감사 저장 자체가 실패해도 다음 결과를 유지한다.

- 지역 상태와 `updated_at`은 변경하지 않는다.
- 원래 `409 REGION_AVAILABILITY_CONFLICT` 응답을 `500`이나 성공으로 바꾸지 않는다.
- 원래 변경 요청 또는 실패 감사 저장을 요청 처리 경로에서 자동 재시도하지 않는다.
- 애플리케이션 경계에서 `error` 수준의 구조화 로그를 한 번 기록한다.
- 구조화 로그에는 `requestId`, `targetType = REGION`, `targetId = regionId`,
  `originalErrorCode = REGION_AVAILABILITY_CONFLICT`, `auditWriteResult = FAILURE`만 포함한다.
- 구조화 로그를 기준으로 실패 감사 저장 장애를 운영 알림 대상으로 삼는다.

로그와 알림에는 요청의 `reasonCode`, `evidenceReference`, 토큰, 비밀값과 개인정보를 포함하지 않는다. 자동 복구나
감사 이벤트 사후 보정 저장소는 P1에 추가하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- 같은 도메인 상태가 항상 같은 공개 오류 코드로 응답된다.
- 감사 DB 장애가 지역 상태 변경이나 클라이언트 재시도를 유발하지 않는다.
- 감사 누락을 비개인 구조화 로그와 운영 알림으로 추적할 수 있다.

### 수용한 단점과 위험

- 감사 저장 장애가 발생한 요청은 `audit_event`에 영구적으로 누락될 수 있다.
- 운영자는 구조화 로그와 `requestId`를 근거로 누락 사건을 조사해야 한다.
- P1에서는 자동 재처리와 사후 감사 보정을 제공하지 않는다.

## 전환과 롤백

P1 지역 공개 여부 변경 API가 구현 전이므로 데이터 이관은 없다. API 명세, P1 정책과 ERD에 응답 유지·구조화
로그·알림 계약을 반영한 뒤 구현한다. 실패 감사 저장 장애를 재현하는 테스트에서 `409`, 지역 미변경과 로그 생성을
확인하기 전에는 API를 활성화하지 않는다.

감사 누락을 허용할 수 없게 되면 이 ADR을 수정하지 않고 후속 ADR에서 Outbox 또는 재처리 저장소, 중복 방지 키,
보관 기간과 기존 누락 사건의 보정 절차를 함께 정한다.

## 검증 방법

- 비삭제 콘텐츠 조건 실패와 실패 감사 저장 성공에서 409, 지역 미변경과 실패 감사 한 건을 확인한다.
- 실패 감사 저장 예외를 주입해도 409와 지역 미변경이 유지되고 감사 이벤트는 없는지 확인한다.
- 감사 저장 장애 로그가 한 건만 기록되고 지정된 비개인 필드만 포함하는지 확인한다.
- 로그와 알림에 요청 사유, 증빙 참조, 토큰, 비밀값과 개인정보가 없는지 확인한다.
- 요청 처리 경로가 원래 변경과 실패 감사 저장을 자동 재시도하지 않는지 확인한다.

## 대체 조건

- 감사 누락이 법률·감사 또는 운영 수용 기준을 위반한다.
- 감사 저장 장애가 반복되어 수동 조사만으로 복구 목표를 충족하지 못한다.
- Outbox나 영속 재처리 저장소가 P1 이후 공통 감사 범위로 확정된다.

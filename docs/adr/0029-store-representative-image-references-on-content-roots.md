# ADR-0029: 대표 이미지 참조를 콘텐츠와 수정본 루트에 직접 저장

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-07-29
- 결정일: 2026-07-29
- 관련 요구사항: [PRD](../local-stamp-platform-prd.md)의 `FR-03`, `FR-14`, `CON-02`, `CON-05`
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: [#50](https://github.com/Gimhae-Yay/Regional-Event-Platform-Backend/issues/50), [#76](https://github.com/Gimhae-Yay/Regional-Event-Platform-Backend/pull/76)
- 대체 대상: [ADR-0026](0026-rebuild-initial-p0-flyway-schema.md)의 `V1__initial_p0_schema.sql` 내 대표 이미지 연결 테이블 구성과 이후 이관 범위

## 맥락

대표 이미지 모델은 현재 콘텐츠와 수정본의 이미지 객체 연결을 각각 별도 테이블에 저장한다. 그러나 연결 자체에는
`assigned_at` 외 별도 상태·행위·이력이 없고, 대표 이미지는 `Content` 또는 `ContentRevision`의 속성이다.

[ADR-0026](0026-rebuild-initial-p0-flyway-schema.md)는 P0 전체 스키마를 단일 V1으로 재구성하면서 당시 ERD의
두 대표 이미지 연결 테이블을 포함했다. 이 ADR은 단일 V1을 기준으로 삼는 결정은 유지하고, 대표 이미지 연결의
물리 모델과 그 이후 증분 이관 범위만 대체한다.

PR #76의 검토에서 하나의 `image_object`가 두 연결 테이블에 동시에 연결될 수 있고, 한쪽 연결 제거 뒤 즉시 S3
원본을 삭제하면 다른 쪽 조회 경로가 깨질 수 있음이 확인됐다. 이는
[ADR-0016](0016-use-private-s3-presigned-urls-and-immediate-image-deletion.md)의 즉시 삭제 정책과 충돌한다.

수정본은 승인 전 후보를 원본과 분리하고, 승인 뒤에는 후보 값을 `Content`에 반영한 뒤 `EDIT_APPROVED` 이력으로
보존한다. 후보 대표 이미지도 승인 시 현재 콘텐츠의 대표 이미지로 이동하며, 수정본의 후보 이미지 참조는 제거한다.

## 결정 동인과 불변 조건

- 콘텐츠와 수정본은 각각 대표 이미지 객체를 최대 한 개만 가질 수 있다.
- `ACTIVE` 이미지 객체는 현재 콘텐츠 또는 활성 수정본 후보 중 정확히 한 곳에서만 참조된다.
- 이미지 교체·승인·반려·철회·삭제 경합에서 같은 이미지 객체를 중복 연결하거나 참조 중인 객체를 삭제하지 않는다.
- 수정본 심사 중 현재 공개 콘텐츠와 이미지는 바뀌지 않으며, 승인 반영·수정본 종결·감사 기록은 하나의 MySQL
  트랜잭션에서 처리한다.
- [ADR-0016](0016-use-private-s3-presigned-urls-and-immediate-image-deletion.md)의 비공개 S3, 서명 URL, 참조 제거 뒤 즉시 삭제와 실패 재시도 정책은 유지한다.

## 결정

`content.representative_image_object_id`와 `content_revision.candidate_image_object_id`를 각각
`image_object.image_object_id`의 nullable FK로 둔다. 두 컬럼은 각 테이블에서 `UNIQUE`이며, 연결 시각은 각
루트의 `representative_image_assigned_at`, `candidate_image_assigned_at`에 저장한다. 기존
`content_representative_image`, `content_revision_representative_image` 테이블은 사용하지 않는다.

이미지 객체를 연결·교체·제거하는 모든 명령은 대상 `image_object` 행을 잠그고, 두 직접 FK가 모두 비어 있는지
또는 허용된 현재 소유자인지 같은 MySQL 트랜잭션에서 검사한다. 두 이미지 객체를 함께 처리할 때는 ID 오름차순으로
잠가 교착 상태를 피한다. 참조 제거 뒤에는 두 FK를 다시 검사해 참조가 없을 때만 `DELETE_PENDING`으로 바꾸고,
커밋 뒤 S3 삭제를 시도한다.

수정본 승인 시 후보 이미지 FK를 `content`로 이동하고 `content_revision`의 후보 FK를 비운다. 수정본 행은
`EDIT_APPROVED` 심사 이력으로 보존하며, 이미지 연결을 중복 보존하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- 대표 이미지를 소유한 콘텐츠·수정본 루트에서 직접 읽고 변경할 수 있다.
- 연결 테이블, 공유 PK 매핑, 추가 조인을 제거한다.
- 수정본 승인 때 후보 이미지를 현재 콘텐츠로 이동하는 수명주기가 명확해진다.

### 수용한 단점과 위험

- 서로 다른 두 테이블의 FK 값이 같지 않아야 한다는 규칙은 단일 `UNIQUE` 또는 FK만으로 강제할 수 없다.
- 이미지 명령이 `ImageObject` 행 잠금 규약을 빠뜨리면 중복 참조 또는 삭제 경합이 생길 수 있다.
- 기존 연결 테이블이 적용된 데이터베이스는 Flyway에서 직접 FK로 이관하고, 검증 뒤에만 기존 테이블을 제거해야 한다.

## 전환과 롤백

Flyway로 두 직접 FK와 연결 시각 컬럼을 먼저 nullable로 추가한다. 기존 연결 테이블의 값을 같은 트랜잭션 단위로
각 루트 컬럼에 이관하고, 교차 중복·누락이 없는지 검증한다. 애플리케이션의 조회·연결·교체·삭제 경로를 직접 FK와
잠금 규약으로 전환한 뒤 기존 연결 테이블을 제거한다.

전환 중 검증에 실패하면 새 연결 명령을 중지하고 기존 연결 테이블을 기준으로 되돌린다. S3 삭제는 직접 FK 이관과
조회 전환이 완료된 뒤에만 수행하므로, 전환 실패가 참조 중 객체의 삭제로 이어지지 않게 한다.

## 검증 방법

- 콘텐츠와 수정본이 각각 이미지 객체 한 개만 연결하고, 동일 테이블 내 중복 연결이 거부되는지 검증한다.
- 같은 이미지 객체를 콘텐츠와 수정본에 동시에 연결하려는 동시 요청 중 하나만 성공하는지 검증한다.
- 수정본 승인 시 후보 이미지가 콘텐츠로 이동하고 수정본에는 남지 않으며, 기존 현재 이미지가 참조되지 않을 때만
  삭제 대기가 되는지 검증한다.
- 반려·철회·교체·공개 전 콘텐츠 삭제에서 참조 중인 객체가 삭제되지 않고, S3 삭제 실패 객체가 어떤 조회 경로에도
  노출되지 않은 채 재시도되는지 검증한다.
- 이관 전후 대표 이미지 조회 결과와 `ACTIVE`·`DELETE_PENDING` 객체의 참조 조건이 일치하는지 검증한다.

## 대체 조건

- 콘텐츠당 여러 이미지, 순서·캡션·노출 기간 또는 복수 이미지 역할이 P0 범위에 들어온다.
- 대표 이미지 연결 자체의 변경 이력이나 별도 승인 상태를 조회 계약으로 제공해야 한다.
- 이미지 객체 행 잠금과 두 FK 검사로 동시성·성능 목표를 충족하지 못한다.

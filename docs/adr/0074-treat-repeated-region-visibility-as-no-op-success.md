# ADR-0074: 동일 지역 공개 여부 요청을 무변경 성공으로 처리

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-07
- 결정일: 2026-08-07
- 관련 요구사항: [P1 명세](../p1-spec.md)의 3.1 재시도 가능한 운영 흐름, [전체관리자](../p1/platform-admin.md)의 `P1-FR-09`, `ADM-02`, `ADM-05`
- 관련 단계: 단계 3. 확장 의사결정
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

지역 공개 여부 변경 API는 목표 상태를 `isPublic` 절대값으로 받는다. 기존 계약은 현재 값과 요청 값이 같으면 `409 REGION_AVAILABILITY_CONFLICT`를 반환하고 실패 감사 이벤트를 기록했다.

이 방식에서는 최초 요청이 지역 변경과 성공 감사를 커밋한 뒤 응답만 유실된 경우, 같은 요청의 재시도가 `409`와 실패 감사로 남는다. 하나의 논리적 변경 의도가 성공과 실패로 동시에 기록되어 P1의 재시도 가능성과 감사 일관성 요구를 충족하지 못한다.

별도 멱등 키 저장소 없이 같은 목표 상태의 반복 요청을 안전하게 처리하려면, 실제 상태 전이가 없는 요청을 무변경 성공으로 정의하고 동시 요청의 상태 비교와 변경을 직렬화해야 한다.

## 결정 동인과 불변 조건

- 유효한 동일 상태 요청은 현재 지역 표현을 반환해야 한다.
- 동일 상태 요청은 지역 행과 `updatedAt`을 변경하지 않고 성공·실패 감사 이벤트도 생성하지 않아야 한다.
- 실제 상태 전이와 성공 감사 이벤트는 하나의 트랜잭션에서 함께 커밋되어야 한다.
- 비삭제 콘텐츠가 있는 공개 지역의 `true → false` 전환은 계속 `409 REGION_AVAILABILITY_CONFLICT`와 실패 감사 대상이다.
- 인증·인가와 요청값 검증은 현재 상태 비교 전에 수행하여 잘못된 요청이 무변경 성공으로 우회되지 않게 해야 한다.
- 같은 목표 상태의 동시 요청은 실제 상태 전이와 성공 감사를 한 번만 만들어야 한다.

## 결정

지역 공개 여부 변경은 인증·인가와 요청값 검증을 완료한 뒤, 같은 트랜잭션에서 대상 `region` 행을 쓰기 잠금으로 조회한다.

현재 `is_public`과 요청 `isPublic`이 같으면 다음과 같이 처리한다.

- `200 OK`와 현재 지역 표현을 반환한다.
- 지역 행을 갱신하지 않으며 `updatedAt`을 유지한다.
- 성공 또는 실패 감사 이벤트를 생성하지 않는다.

현재 값과 요청 값이 다르면 기존 전이 조건을 평가한다. `true → false` 전환에 비삭제 콘텐츠가 있으면 `409 REGION_AVAILABILITY_CONFLICT`를 반환하고, 변경 트랜잭션 롤백 뒤 실패 감사 이벤트를 별도 트랜잭션으로 기록한다. 허용된 실제 전이는 지역 변경과 성공 감사 이벤트를 같은 트랜잭션으로 커밋한다.

같은 지역에 대한 동시 요청은 지역 행 잠금으로 직렬화한다. 같은 목표 상태를 요청한 경우 첫 요청만 실제 상태 전이와 성공 감사를 만들고, 이후 요청은 잠금 획득 뒤 변경된 현재 값을 확인하여 무변경 성공으로 끝난다.

P1에서는 이 API에 별도 멱등 키나 처리 결과 저장소를 도입하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- 응답 유실 뒤 반복 요청이 실패로 바뀌지 않고 현재 상태로 수렴한다.
- 하나의 실제 상태 전이에 성공 감사 이벤트가 한 번만 생성된다.
- 멱등 키의 범위와 보관 정책을 추가하지 않고 P1 요구를 충족한다.

### 수용한 단점과 위험

- 최초 응답의 `requestId`와 응답 시각을 그대로 재생하지 않고 재시도 시점의 현재 지역 표현을 반환한다.
- 모든 공개 여부 변경 요청이 대상 지역 행의 쓰기 잠금을 획득한다.
- 최초 요청 뒤 다른 요청이 반대 상태로 다시 변경한 경우, 원래 요청의 재시도는 새로운 실제 전이를 만들 수 있다. 요청 단위의 정확한 멱등성은 보장하지 않는다.

## 전환과 롤백

P1 지역 공개 여부 변경 API는 아직 구현 전이므로 데이터 이관은 없다. 구현 전에 API 명세와 테스트 계약에 동일 상태 무변경 성공, 행 잠금, 감사 미생성 규칙을 반영한다.

이 결정을 되돌릴 때는 이 ADR을 수정하지 않고 후속 ADR에서 멱등 키의 범위, 보관 기간, 충돌 응답, 처리 결과 저장 모델과 기존 클라이언트 전환 정책을 함께 정의한다.

## 검증 방법

- 권한과 입력이 유효한 동일 상태 요청이 `200 OK`와 현재 지역을 반환하는지 확인한다.
- 동일 상태 요청 전후에 `region.updated_at`과 감사 이벤트 수가 변하지 않는지 확인한다.
- 실제 상태 전이가 한 번 발생하면 성공 감사 이벤트도 한 건만 생성되는지 확인한다.
- 같은 목표 상태의 동시 요청이 한 번의 상태 전이와 한 건의 성공 감사로 수렴하는지 확인한다.
- 비삭제 콘텐츠가 있는 `true → false` 요청은 `409`를 반환하고 실패 감사 한 건을 남기는지 확인한다.
- 인증·인가 또는 입력 검증에 실패한 요청은 현재 상태와 같더라도 성공으로 처리되지 않는지 확인한다.

## 재검토 조건

- 최초 응답의 정확한 재생이나 논리 요청 단위의 감사 상관관계가 요구된다.
- 지역 행 잠금 경합이 운영 목표를 반복적으로 위반한다는 측정 근거가 축적된다.
- 중간의 반대 상태 변경이 있는 재시도까지 같은 논리 요청으로 식별하고 차단해야 한다.

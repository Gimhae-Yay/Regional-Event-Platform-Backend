# ADR-0036: 심사용 상세 조회에만 사업자 정보 원문을 노출한다

- 상태: 채택
- 기록 유형: 후속 결정
- 기록일: 2026-07-30
- 결정일: 2026-07-30
- 관련 요구사항: [FR-09 운영자 승인·정보 마스킹](../p0/auth-profile.md#fr-09-운영자-승인정보-마스킹), [AUTH-02](../p0/auth-profile.md#auth-02)
- 관련 단계: 단계 0. 정책·경계 확정
- 관련 이슈: 없음
- 대체 대상: [ADR-0026](0026-select-signup-role-and-create-operator-application.md)의 사업자 정보 응답 노출 금지 범위

## 맥락

ADR-0026은 운영자 신청의 사업자 정보를 응답과 로그에 노출하지 않도록 정했다. 그러나 `FR-09`와 `AUTH-02`는 담당 지역 관리자가 사업자 정보와 요청 지역을 수동 확인해 운영자를 승인·반려하도록 요구한다.

목록과 상세 응답에서 모두 사업자 정보 원문을 제거하면 담당 지역 관리자가 심사 근거를 확인할 수 없다. 반대로 모든 운영자 신청 응답에 원문을 포함하면 최소 공개 원칙과 로그 유출 위험을 위반한다.

## 결정 동인과 불변 조건

- 담당 지역의 `REGION_ADMIN`은 심사 전에 사업자 정보 원문을 확인할 수 있어야 한다.
- 다른 지역 관리자, 운영자, 방문자와 일반 사용자 대상 응답에는 원문을 노출하지 않는다.
- 애플리케이션·접근 로그와 감사 이벤트에는 원문을 기록하지 않는다.
- 서버가 인증된 지역 관리자와 신청의 요청 지역 일치를 강제한다.

## 결정

운영자 신청의 `businessInformation` 원문은 `GET /api/v1/region-admin/operator-requests/{requestId}` 심사용 상세 조회에서만 반환한다. 이 응답은 신청의 `requested_region_id`와 인증된 `REGION_ADMIN`의 담당 지역이 같은 경우에만 반환한다.

대기 목록과 회원가입·재신청·승인·반려를 포함한 그 밖의 HTTP 응답에는 원문을 포함하지 않는다. 애플리케이션 로그, 접근 로그, 감사 이벤트에도 원문을 기록하지 않는다. 감사 이벤트에는 상태 전이와 처리자 등 심사 추적에 필요한 비식별 메타데이터만 남긴다.

이 결정은 ADR-0026의 사업자 정보 응답 노출 금지 범위를 대체한다. ADR-0026의 가입 시 역할 선택, `PENDING` 신청 생성 및 승인 전 권한 차단 결정은 그대로 유지한다.

## 결과와 트레이드오프

### 기대 효과

- 지역 관리자가 계약된 심사 화면에서 사업자 정보를 확인하고 승인·반려할 수 있다.
- 목록과 일반 응답에서는 원문을 배제해 노출 범위를 최소화한다.
- 감사 추적성과 사업자 정보 보호를 분리해 유지한다.

### 수용한 단점과 위험

- 보호된 상세 응답 자체는 민감 정보 전달 경로이므로 권한 검사와 응답 로그 비기록이 필수다.
- 클라이언트가 상세 응답을 자체 로그·분석 도구에 저장하지 않도록 운영 통제가 필요하다.

## 전환과 롤백

현재는 문서 계약 단계이므로 데이터 이관은 없다. 구현 전 상세 조회의 권한 검사와 로그 마스킹 정책을 적용한다.

사업자 정보의 구조·암호화·보관 정책이 확정되면 별도 ADR에서 상세 응답 형식과 저장 방식의 변경 여부를 결정한다. 그 전까지 원문은 목록과 일반 응답에 추가하지 않는다.

## 검증 방법

- 담당 지역의 `REGION_ADMIN`만 상세 응답에서 `businessInformation`을 받는지 검증한다.
- 타 지역 관리자와 다른 역할은 상세 조회에서 `403` 또는 `404`로 차단되고 원문을 받지 않는지 검증한다.
- 대기 목록과 회원가입·재신청·승인·반려 응답에 원문이 없는지 검증한다.
- 애플리케이션 로그와 감사 이벤트에 원문이 기록되지 않는지 검증한다.

## 대체 조건

- 운영자 심사가 외부 사업자 검증 서비스 또는 별도 온보딩 시스템으로 이전된다.
- 사업자 정보의 구조·암호화·보관 정책이 확정되어 원문 텍스트를 상세 응답으로 제공할 수 없게 된다.

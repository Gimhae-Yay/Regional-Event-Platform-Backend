# ADR-0059: 모든 회차가 종결된 콘텐츠를 조정 스케줄러로 자동 종료

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-03
- 결정일: 2026-08-03
- 관련 요구사항: [지역·콘텐츠 카탈로그](../p0/content-catalog.md#fr-04-승인자동-공개종료)의 `FR-04`·`CON-04`와 [지역·콘텐츠 카탈로그 API 명세서](../api/p0/content-catalog/content-catalog.md)의 종료 계약
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: 없음. [ERD의 콘텐츠 종료 판정 미확정 계약](../erd.md#11-미확정-계약)을 확정한다.

## 맥락

콘텐츠는 여러 회차를 가지며 각 회차는 `COMPLETED` 또는 `CANCELLED`로 종결된다. 기존 정책은 모든 회차가
종결된 뒤 종료일이 지나거나 정상 종료 처리되면 콘텐츠를 `ENDED`로 전환한다고 설명하지만, `content`에는 별도
종료 예정 시각이 없고 종료 판정 기준도 ERD의 미확정 계약으로 남아 있다. 이 상태에서는 마지막 회차가 종결돼도
콘텐츠가 계속 `PUBLISHED`로 노출되거나, 구현마다 종료 시각을 다르게 추정할 수 있다.

회차는 노쇼·완료 스케줄러와 회차 취소 API처럼 서로 다른 경계에서 종결된다. 어느 한 경계에만 콘텐츠 종료를
결합하면 다른 경로에서 마지막 회차가 종결된 콘텐츠를 놓칠 수 있다. 반대로 모든 경계에 종료 책임을 복제하면
트랜잭션과 경합 규칙이 분산된다. 사용자는 모든 회차 종결을 콘텐츠 자동 종료 조건으로 선택했다.

## 결정 동인과 불변 조건

- 소프트 삭제되지 않은 `PUBLISHED` 콘텐츠만 `ENDED`로 전환할 수 있어야 한다.
- 연결된 모든 회차가 `COMPLETED` 또는 `CANCELLED`일 때만 자동 종료해야 한다.
- `PENDING`, `SCHEDULED`, `REJECTED` 회차가 하나라도 있으면 자동 종료하지 않아야 한다.
- 콘텐츠 상태, `ENDED` 콘텐츠 로그, 성공 감사 기록은 같은 MySQL 트랜잭션에서 함께 커밋하거나 롤백해야 한다.
- 수동 정상 종료, 회차 종결과 자동 종료가 경합해도 콘텐츠 종료와 관련 기록은 최대 한 번만 발생해야 한다.
- 자동 종료는 시스템 처리로 기록하고 별도 사용자 처리자를 연결하지 않아야 한다.

## 결정

애플리케이션 내부 조정 스케줄러는 소프트 삭제되지 않은 `PUBLISHED` 콘텐츠 중 연결된 모든
`content_session.status`가 `COMPLETED` 또는 `CANCELLED`인 대상을 조회한다. 콘텐츠에는 하나 이상의 회차가
항상 존재하므로 빈 회차 집합을 종료 조건으로 해석하지 않는다. 미래 시각의 회차라도 이미 `CANCELLED`이면 종결
회차로 계산하며, 별도 콘텐츠 종료 예정 시각이나 `ended_at` 컬럼은 추가하지 않는다.

스케줄러는 수동 정상 종료 API와 같은 공통 종료 서비스를 호출한다. 공통 서비스는 현재 콘텐츠가
`PUBLISHED`이고 `deleted_at IS NULL`이며 모든 회차가 종결 상태인지 다시 확인한 뒤 `PUBLISHED → ENDED`를
조건부로 적용한다. 성공한 전이에만 `actor_id = NULL`, `reason = NULL`인 `ENDED` 콘텐츠 로그와 시스템 성공
감사 기록을 같은 MySQL 트랜잭션에서 추가한다. 실제 종료 시각은 `content_log.status = ENDED`인 행의 `date`로
판정한다.

수동 정상 종료와 자동 종료가 경합하면 `PUBLISHED` 조건부 전이에 먼저 성공한 처리만 상태·로그·감사를 기록한다.
회차 종결과 경합할 때 스케줄러는 커밋된 회차 상태만 판정하며 종결되지 않은 회차를 하나라도 확인하면 변경하지
않고 다음 실행에서 재시도한다. 콘텐츠 종료 트랜잭션은 남아 있는 `ACTIVE` 홀드를 공통 홀드 무효화 서비스로
`INVALIDATED` 처리하고 정원을 한 번만 복구해 기존 정상 종료 계약과 같은 결과를 보장한다.

## 결과와 트레이드오프

### 기대 효과

- 마지막 회차가 완료 또는 취소된 경로와 무관하게 콘텐츠가 자동으로 `ENDED`에 수렴한다.
- 수동·자동 종료가 하나의 상태 조건과 공통 서비스로 같은 로그·감사·정원 결과를 만든다.
- 별도 콘텐츠 종료일이나 `ended_at` 없이 기존 회차 상태와 콘텐츠 로그를 단일 기준으로 사용한다.
- 스케줄러 재실행과 다중 인스턴스 경합이 중복 종료 기록을 만들지 않는다.

### 수용한 단점과 위험

- 마지막 회차 종결부터 다음 스케줄러 실행까지 콘텐츠가 일시적으로 `PUBLISHED`로 남을 수 있다.
- 미래 회차를 모두 취소하면 원래 회차 종료 시각을 기다리지 않고 자동 종료 대상이 된다.
- `REJECTED` 또는 `PENDING` 회차가 남은 콘텐츠는 다른 운영 처리가 끝날 때까지 자동 종료되지 않는다.
- 공통 종료 서비스가 홀드 무효화·정원 복구를 포함하므로 해당 처리 실패는 콘텐츠 종료도 함께 롤백한다.

## 전환과 롤백

현재 운영 데이터의 스키마 이관은 필요 없다. 먼저 제품 정책과 ERD의 미확정 종료 기준을 이 결정에 맞추고, 자동
종료 내부 처리 명세를 확정한다. 구현 시 수동 정상 종료와 자동 종료가 재사용할 공통 종료 서비스를 만든 뒤
조정 스케줄러를 연결한다.

문제가 발생하면 자동 종료 스케줄러 실행을 중지하고 기존 지역 관리자 정상 종료 API를 사용한다. 이미 성공한
`ENDED` 전이와 콘텐츠 로그·감사 기록은 삭제하거나 `PUBLISHED`로 되돌리지 않으며, 잘못된 종료가 확인되면 별도
후속 정책과 전진 수정으로 처리한다.

## 검증 방법

- 모든 회차가 `COMPLETED` 또는 `CANCELLED`이면 콘텐츠가 한 번만 `ENDED`로 전환되는지 검증한다.
- `PENDING`, `SCHEDULED`, `REJECTED` 회차가 하나라도 있으면 콘텐츠·로그·감사가 변경되지 않는지 검증한다.
- 수동 종료, 마지막 회차 완료·취소와 스케줄러가 경합해도 상태·`ENDED` 로그·감사 이벤트가 최대 한 건인지 검증한다.
- 스케줄러 중복 실행과 다중 인스턴스 실행에서 같은 콘텐츠가 중복 처리되지 않는지 검증한다.
- 콘텐츠 갱신, 로그·감사 삽입 또는 홀드 무효화·정원 복구 중 하나가 실패하면 전체 변경이 롤백되고 다음 실행에서 재시도되는지 검증한다.
- 자동 종료 건수, 지연 시간과 실패 사유를 구조화 로그로 관찰한다.

## 대체 조건

- 콘텐츠가 모든 기존 회차 종결 뒤에도 새 회차 모집을 위해 공개 상태를 유지해야 한다는 요구가 확정된다.
- 별도 계약 종료일·노출 종료일이 도입되어 회차 상태와 독립된 종료 예정 시각이 필요해진다.
- 스케줄러 지연이 공개·예약 운영 기준을 지속적으로 위반해 마지막 회차 종결 트랜잭션과의 즉시 결합이 필요해진다.
- `ENDED` 콘텐츠의 재개 또는 새 회차 추가가 P0 범위로 채택된다.

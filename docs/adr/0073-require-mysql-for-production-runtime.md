# ADR-0073: 운영 런타임은 MySQL 데이터소스를 명시적으로 요구한다

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-07
- 결정일: 2026-08-07
- 관련 요구사항: [기술 스택](../local-stamp-platform-tech-stack.md)의 DB·배포와 [P0 명세](../p0-spec.md#82-설계-원칙)의 MySQL 최종 정합성
- 관련 단계: 단계 1. MVP 구현·검증
- 관련 이슈: [#471 ECR 이미지 기반 EC2 Compose 배포 자동화 및 운영 검증](https://github.com/Gimhae-Yay/Regional-Event-Platform-Backend/issues/471)
- 대체 대상: 없음

## 맥락

현재 애플리케이션 설정에는 운영 데이터소스 URL·계정·비밀번호가 없고, H2가 런타임 의존성에 포함되어 있다.
Spring Boot는 외부 데이터소스 설정이 없을 때 클래스패스의 임베디드 H2를 선택할 수 있다. ASG 인스턴스 교체로
배포하는 EC2에서 이런 기동을 허용하면, API가 RDS가 아닌 인스턴스 임시 데이터베이스를 사용해 요청을 처리하고
교체 때 데이터를 잃을 위험이 있다.

프로젝트의 최종 정합성 저장소는 MySQL이며, 운영 배포는 외부 RDS를 사용한다. H2는 테스트와 명시적인 로컬
개발에만 유용하며 운영 데이터소스의 대체 수단이 될 수 없다.

## 결정 동인과 불변 조건

- 운영 프로필은 MySQL/RDS JDBC URL·계정·비밀번호 없이는 준비 상태가 되거나 요청을 처리하면 안 된다.
- 운영 환경의 데이터소스가 H2 또는 다른 임베디드 데이터베이스로 바뀌어서는 안 된다.
- 자격 증명은 Compose 파일, 이미지, GitHub 이슈와 로그에 넣지 않고 EC2 런타임 구성에서만 주입한다.
- Flyway migration과 JPA 연결은 같은 운영 MySQL 데이터소스를 사용한다.
- H2는 테스트와 명시적인 로컬 개발 프로필에만 허용한다.

## 결정

운영 프로필은 MySQL/RDS 데이터소스만 허용한다. JDBC URL·사용자명·비밀번호가 없거나 MySQL 연결이 성립하지
않으면 애플리케이션은 준비 상태가 되지 않고 트래픽을 받지 않는다. H2는 운영 이미지의 런타임 대체 경로로
사용하지 않으며, 테스트와 명시적인 로컬 개발 구성에만 둔다.

EC2 Compose 배포는 운영 프로필을 명시하고, 데이터소스·Redis·JWT·QR·S3 관련 값을 외부 런타임 구성으로
주입한다. 이 결정은 RDS의 네트워크·백업·고가용성 구성 또는 MySQL 스키마를 변경하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- RDS 설정 누락이 임시 H2 기동이나 데이터 유실이 아니라 빠른 배포 실패로 드러난다.
- Flyway와 JPA가 MySQL 전용 제약·쿼리·트랜잭션 경계를 일관되게 검증한다.
- ASG 교체 뒤에도 업무 데이터의 기준 저장소가 RDS로 유지된다.

### 수용한 단점과 위험

- RDS 접속 정보 또는 네트워크가 잘못되면 새 인스턴스는 즉시 준비 상태에 도달하지 못한다.
- 개발자가 H2로 실행하려면 명시적인 로컬 프로필을 선택해야 한다.
- 잘못된 운영 변수는 자동 복구하지 않으며, 수정 후 새 인스턴스를 기동해야 한다.

## 전환과 롤백

운영 프로필과 Compose 런타임 변수 계약을 먼저 추가하고, H2가 운영 경로에 포함되지 않도록 의존성과 설정을
정리한다. 테스트·로컬 H2 경로는 운영 프로필과 분리해 검증한다. 이후 RDS 연결·Flyway·Health가 모두 정상인
인스턴스만 ASG 배포 완료로 판정한다.

배포 중 설정 오류가 발견되면 H2로 우회하지 않는다. 오류가 난 인스턴스는 비정상 상태로 두고, 올바른 RDS 설정을
주입한 이미지 또는 구성으로 재배포한다. 이미 운영 MySQL에 적용된 Flyway migration은 되돌리지 않으며,
후속 migration으로만 수정한다.

## 검증 방법

- 운영 프로필에서 MySQL JDBC URL·사용자명·비밀번호 중 하나라도 없으면 애플리케이션이 기동 또는 준비 상태 확인에 실패하는지 검증한다.
- 운영 프로필에 H2 JDBC URL을 넣으면 기동이 거부되는지 검증한다.
- 유효한 MySQL Testcontainers 또는 RDS 검증 환경에서 Flyway migration과 JPA 연결이 같은 데이터소스로 성공하는지 검증한다.
- H2가 테스트와 명시적인 로컬 프로필에서만 사용되고 운영 이미지의 대체 데이터소스가 아닌지 검증한다.
- Compose와 EC2 로그에 JDBC 비밀번호·JWT·QR 키가 출력되지 않는지 확인한다.

## 대체 조건

- 운영 데이터 저장소를 MySQL/RDS에서 다른 관계형 데이터베이스로 공식 전환한다.
- 로컬 개발 환경에서 H2를 더 이상 지원하지 않거나, 모든 개발 환경을 MySQL 컨테이너로 통일한다.
- 별도 설정 관리 시스템이 데이터소스 계약을 애플리케이션 기동 전 강제하고 H2 자동 구성 위험을 동등하게 제거한다.

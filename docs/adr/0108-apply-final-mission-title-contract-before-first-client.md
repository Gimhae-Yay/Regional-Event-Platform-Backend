# ADR-0108: 최초 운영자 클라이언트 전에 미션 제목 최종 계약을 직접 적용한다

- 기록일: 2026-08-18
- 결정일: 2026-08-18
- 관련 요구사항: [지역 미션 `MSN-01`·`MSN-05`](../p1/regional-mission.md#3-지역-미션-정책), [P1 ERD 지역 미션](../p1-erd.md#53-지역-미션), [미션 생성·수정 API](../api/p1/mission/mission.md#기능별-api-명세)

- 대체 대상: [ADR-0106](0106-store-mission-title-on-mission.md)의 `전환과 롤백`·backfill 검증 범위, [ADR-0107](0107-deploy-compatible-server-before-mission-title-clients.md)의 전환·롤백·호환 검증 전체

## 맥락

ADR-0106과 ADR-0107은 제목 없는 기존 미션 행과 제목을 보내지 않는 운영자 클라이언트가 존재한다는 전제에서
nullable 열, 호환 서버, backfill, 최종 서버와 후속 `NOT NULL` migration을 순서대로 배포하도록 정했다.

2026-08-18 확인 결과 운영 migration과 애플리케이션 시작 코드에는 미션 행을 만드는 seed가 없고, 프로젝트
운영 책임자는 운영 미션 생성 API 사용 이력과 배포된 운영자 클라이언트가 없음을 확인했다. 운영 DB를 직접
조회한 결과는 아니므로 이 결정은 해당 운영 확인을 사실로 사용한다. 제목 열을 추가하는 V45는 같은 날 `dev`에
처음 병합됐고 `main`과 운영 배포에는 포함되지 않았다.

따라서 보존하거나 backfill할 기존 미션과 호환할 클라이언트가 없으며, 전환 전용 코드와 여러 migration을 운영에
배포할 필요가 없다.

## 결정 동인과 불변 조건

- 최초 운영 미션부터 제목이 존재하고 최종 API 계약만 외부에 노출한다.
- `mission.title`의 최종 `VARCHAR(255) NOT NULL` 계약과 ADR-0106의 검증·수정·응답 범위는 유지한다.
- V20처럼 이미 운영 배포에 포함된 migration은 수정하지 않는다.
- 제목 값은 감사 이벤트, 구조화 로그와 운영 지표에 기록하지 않는다.
- 제목 이외의 미션 식별자·조건·상태·보상·시각과 기존 조회 계약은 변경하지 않는다.

## 결정

운영에 아직 적용되지 않은 V45에서 `mission.title VARCHAR(255) NOT NULL`을 영구 기본값 없이 추가한다. 기존 행
backfill, nullable 중간 열, 제목 누락 fallback, 호환 누락 계측과 후속 `NOT NULL` migration은 운영 계약으로
배포하지 않는다. 이미 운영 배포에 포함된 V20은 수정하지 않는다.

애플리케이션은 ADR-0106의 최종 계약을 바로 적용한다. 생성·수정 제목을 필수 검증하고, 세 방문자 조회에 저장된
제목을 반환하며, 운영자·지역 관리자 조회와 공개 미션 상세 응답은 변경하지 않는다. 제목 필수 서버를 먼저
배포하고 정상 상태를 확인한 뒤, 제목을 항상 전송하는 최초 운영자 클라이언트를 배포한다.

## 결과와 트레이드오프

### 기대 효과

- 최초 운영 미션부터 애플리케이션과 DB가 같은 제목 필수 계약을 사용한다.
- 사용되지 않은 호환 코드와 운영 계측, 데이터 backfill, 추가 배포 게이트를 제거한다.
- 프론트엔드는 임시 계약 없이 최종 요청·응답만 구현한다.

### 수용한 단점과 위험

- 운영 사용 이력 확인은 DB 직접 조회가 아니라 seed 부재와 운영 책임자 확인에 의존한다.
- 서버 배포 전 예상하지 못한 미션 행이 있으면 직접 전환 전제를 위반하며 배포를 중단해야 한다.
- 최종 서버 배포 뒤 구버전 운영자 클라이언트를 새로 사용하면 제목 누락 요청이 `400 INVALID_INPUT`으로 실패한다.

## 전환과 롤백

1. V45를 `title VARCHAR(255) NOT NULL` 직접 추가 migration으로 확정한다.
2. 제목 필수 생성·수정과 세 방문자 조회를 구현한 최종 서버를 배포한다.
3. 서버 health와 제목 포함 생성·수정 계약을 확인한다.
4. 제목을 항상 전송하는 최초 운영자 클라이언트를 배포한다.

V45 적용 전에 실패하면 애플리케이션과 migration을 함께 되돌린다. V45 적용 뒤 애플리케이션을 제목 미지원
버전으로 되돌려야 하면 제목 값을 보존한 채 새 forward migration으로 열을 nullable로 변경한 다음 서버를
롤백한다. 적용된 V45를 수정하거나 삭제하지 않는다. 운영 미션이 생성된 뒤에는 제목 열을 제거하지 않는다.

## 검증 방법

- V45 적용 뒤 `mission.title`이 길이 255의 `NOT NULL` 열이고 영구 기본값이 없는지 검증한다.
- migration 전체를 새 DB에 적용하고 제목 없는 미션 삽입이 DB에서 거부되는지 검증한다.
- 생성·수정 제목 누락·null·공백·길이 초과를 `400 INVALID_INPUT`으로 거부하고 유효 제목을 정규화해 저장하는지 검증한다.
- 세 방문자 조회가 저장 제목을 반환하고 기존 필터·본인 범위·진행 집계·정렬·페이지 메타데이터를 유지하는지 검증한다.
- 운영자·지역 관리자 조회와 공개 미션 상세 응답 필드가 바뀌지 않았는지 회귀 검증한다.
- 배포 전에 운영 미션 생성 API와 운영자 클라이언트 사용 이력에 대한 운영 책임자 확인을 기록한다.

## 대체 조건

- V45 운영 적용 전에 기존 미션 행 또는 운영 미션 생성 API 사용 이력이 확인된다.
- 제목을 보내지 않는 운영자 클라이언트를 지원해야 한다는 요구가 생긴다.
- 서버와 최초 운영자 클라이언트를 독립적으로 배포할 수 없는 제약이 확인된다.

# ADR-0106: k6 응답시간 러너는 컨테이너와 RDS fixture 대상을 분리한다

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-17
- 결정일: 2026-08-17
- 관련 요구사항: [인증 조회 응답시간 러너](../../performance/k6/run-authenticated-read-response-time.ps1), [쓰기 응답시간 러너](../../performance/k6/run-write-api-response-time.ps1)
- 관련 단계: 해당 없음
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

두 k6 응답시간 러너는 대상 API URL과 무관하게 실행기 로컬 Docker의 MySQL 컨테이너에 fixture SQL을 적용한다. 따라서 `-BaseUrl`만 성능 환경 API로 바꾸면 성능 환경 API와 로컬 DB fixture가 서로 달라 정상 요청과 측정 결과를 보장할 수 없다.

로컬 개발자는 현재 Docker 기반 실행을 계속 사용해야 하고, 성능 환경 실행기는 성능 전용 RDS의 fixture를 초기화해야 한다. 쓰기 러너는 각 독립 라운드 전에 fixture를 초기화하므로 대상 DB를 잘못 지정하면 데이터 손실 위험이 있다.

## 결정 동인과 불변 조건

- 기존 로컬 명령과 기본 `Container` 동작은 호환되어야 한다.
- RDS 모드는 명시적으로 선택하고, 성능 전용 DB에만 fixture SQL을 적용해야 한다.
- 비밀번호는 명령 인자, 결과 파일, 로그에 남기지 않고 실행 프로세스 환경 변수에서만 읽어야 한다.
- 원격 대상의 DNS, 포트, 데이터베이스 이름, 사용자와 명시적 fixture 초기화 승인이 모두 없으면 실행 전에 실패해야 한다.
- API URL과 fixture DB는 같은 성능 환경을 가리키도록 실행자가 확인해야 하며, 운영 DB를 자동으로 판별하거나 초기화하지 않는다.

## 결정

두 러너에 `FixtureDatabaseMode`를 추가한다. 기본값은 기존 동작과 호환되는 `Container`이며, `Rds`는 명시적으로 선택했을 때만 MySQL CLI로 지정 RDS에 연결한다.

`Rds` 모드는 DB host, port, name, user, password 환경 변수 이름 및 원격 fixture 초기화 승인 switch를 모두 요구한다. 비밀번호 값은 기본 `PERF_FIXTURE_DB_PASSWORD` 환경 변수에서 읽고, 명령줄 인자나 출력으로 전달하지 않는다. 성능 실행기는 RDS 보안 그룹에서 허용된 사설망에 배치하고, DB 사용자는 성능 전용 스키마에 필요한 fixture 권한만 가진다.

## 결과와 트레이드오프

### 기대 효과

- 동일한 스크립트와 결과 형식으로 로컬 Docker 및 성능 환경 RDS 측정을 실행한다.
- 쓰기 API의 라운드별 fixture 초기화가 실제 성능 API가 사용하는 데이터와 일치한다.
- 원격 초기화는 기본 경로가 아니며 명시적인 실행 의도와 Secret 주입이 있어야만 시작한다.

### 수용한 단점과 위험

- RDS 실행기는 MySQL CLI 설치, RDS 접근 보안 그룹 및 Secret 관리가 필요하다.
- 명시적 승인도 잘못된 성능 DB 이름이나 자격 증명을 완전히 방지하지 못하므로, 운영 DB와 네트워크·계정·스키마를 분리해야 한다.
- RDS 결과에는 네트워크와 실제 DB I/O가 포함되어 로컬 Docker 결과와 절대 수치를 직접 비교할 수 없다.

## 전환과 롤백

기존 인자 없이 실행하면 `Container` 모드를 유지한다. 성능 환경에서는 RDS 모드 인자와 Secret 환경 변수, 원격 초기화 승인을 모두 제공한다. RDS 연결 또는 fixture 적용에 실패하면 k6 실행 전에 중단한다. 문제가 생기면 RDS 모드를 사용하지 않고 기존 컨테이너 모드로 실행한다. 데이터 이관과 API 호환 계층은 필요하지 않다.

## 검증 방법

- 두 러너가 PowerShell 구문 분석을 통과하고, 기본 `Container` 모드가 기존 컨테이너 설정을 계속 요구하는지 확인한다.
- `Rds` 모드에서 필수 인자, 승인 switch, 비밀번호 환경 변수가 빠진 경우 k6 실행 전에 실패하는지 확인한다.
- 격리된 성능 RDS에서 fixture 적용 뒤 조회·쓰기 각 1라운드의 정상 응답과 결과 파일 생성을 확인한다.
- RDS 보안 그룹과 DB 권한이 성능 실행기 및 성능 전용 스키마로 한정되는지 배포 설정에서 확인한다.

## 대체 조건

- 성능 fixture를 안전하게 초기화할 수 있는 별도 테스트 데이터 서비스가 감사·권한·격리 요구를 만족하면, DB 직접 접속을 대체하는 결정을 검토한다.
- 로컬과 RDS 실행의 fixture·결과 집계 요구가 독립적으로 진화해 하나의 러너 유지 비용이 중복 러너보다 커지면 분리를 재검토한다.

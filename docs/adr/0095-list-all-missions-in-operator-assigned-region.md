# ADR-0095: 운영자 미션 목록을 담당 지역 전체로 조회

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-11
- 결정일: 2026-08-11
- 관련 요구사항: [P1 명세](../p1-spec.md)의 `P1-FR-03`, [지역 미션](../p1/regional-mission.md)의 `MSN-05`, [운영자 미션 목록 API](../api/p1/mission/list-operator-missions.md)
- 관련 단계: 단계 1. MVP 구현·검증
- 관련 이슈: [#630 운영자 미션 목록 조회 API 구현](https://github.com/Gimhae-Yay/Regional-Event-Platform-Backend/issues/630)
- 대체 대상: [ADR-0002](0002-isolate-regions-in-a-shared-schema.md)의 `GET /api/v1/operator/missions` 콘텐츠 소유 관계 검증 범위만 대체

## 맥락

운영자 미션 목록 API는 인증 운영자의 담당 지역 미션을 상태 필터와 페이지 단위로 조회하도록 확정돼 있다.
반면 P1 사용자·권한 일반 규칙과 ADR-0002는 운영자 조회에서 담당 지역과 콘텐츠 소유 관계를 함께 검증하도록 정한다.

현재 미션은 `region_id`에 직접 연결되지만 작성 운영자 식별자를 가지지 않는다. 보상 쿠폰 정책과 목표 콘텐츠에는
운영자가 연결될 수 있으나, 어느 관계를 미션 목록 소유 기준으로 사용할지는 제품·API 계약에 정의돼 있지 않다.
따라서 현재 모델에서 소유 운영자를 추론하지 않고 이 목록 API의 권한 범위를 명시적으로 결정해야 한다.

## 결정 동인과 불변 조건

- 운영자는 현재 활성 `OPERATOR` 배정의 담당 지역 밖 미션을 조회할 수 없다.
- 목록의 지역 범위는 서버가 현재 DB 역할 배정과 `mission.region_id`로 검증한다.
- 상태 필터를 생략하면 담당 지역의 모든 미션 상태를 조회한다.
- 목록 범위 결정으로 생성·수정·검토 요청 등 변경 권한을 확대하지 않는다.
- 목록 응답은 확정된 API 필드만 노출하고 보상·대상 콘텐츠 상세를 추가하지 않는다.

## 결정

`GET /api/v1/operator/missions`는 현재 활성 `OPERATOR` 배정의 담당 `region_id`와 `mission.region_id`가 같은
모든 미션을 조회한다. 상태 필터를 지정하면 해당 상태만, 생략하면 `DRAFT`, `PENDING_REVIEW`, `PUBLISHED`,
`ENDED` 전체를 조회한다.

목록 조회에는 보상 쿠폰 정책 또는 목표 콘텐츠의 운영자 소유 관계를 추가 필터로 사용하지 않는다. 따라서 같은 지역의
다른 운영자와 연결된 보상 정책 또는 목표 콘텐츠가 있는 미션도 포함한다. 다른 지역 미션은 항상 제외한다.

이 결정은 운영자 미션 목록 API에만 적용한다. 미션 생성·수정·검토 요청과 콘텐츠·쿠폰 정책의 소유 관계 검증,
운영자 미션 상세와 다른 API의 권한 범위는 변경하지 않는다. ADR-0002의 지역 격리와 다른 소유 관계 검증은 유지하고,
ADR-0066의 담당 콘텐츠 작성 범위도 변경하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- Issue #630과 API 명세의 담당 지역 조회 계약을 현재 데이터 모델로 일관되게 구현할 수 있다.
- 지역 관리자 목록과 같은 지역·상태·고정 정렬 조회 기반을 재사용할 수 있다.
- 정의되지 않은 관계를 이용해 미션 소유자를 추론하지 않는다.

### 수용한 단점과 위험

- 같은 지역의 운영자는 다른 운영자와 연결된 공개 전 미션의 식별자, 상태, 조건 유형과 종료 예정 시각을 볼 수 있다.
- 향후 운영자별 작업함이 필요해지면 미션 소유자를 명시하는 모델과 기존 데이터 귀속 정책이 필요하다.

## 전환과 롤백

문서와 API 계약을 먼저 확정한 뒤 Issue #630 구현에서 현재 역할 배정의 담당 지역으로 목록을 제한한다. 기존 데이터
이관과 스키마 변경은 없다.

담당 지역 전체 조회를 철회하려면 새 ADR에서 미션 소유자 기준, 기존 미션 귀속과 API 호환 범위를 먼저 확정한다.
그 전에는 보상 정책이나 목표 콘텐츠의 소유자를 임시 목록 필터로 사용하지 않는다.

## 검증 방법

- 현재 활성 `OPERATOR`가 담당 지역의 모든 상태 미션을 `missionId` 내림차순으로 조회하는지 검증한다.
- 같은 지역의 다른 운영자와 연결된 보상 정책 또는 목표 콘텐츠가 있는 미션도 목록에 포함되는지 검증한다.
- 다른 지역 미션이 상태 필터와 페이지 위치에 관계없이 제외되는지 검증한다.
- 역할 없음, 비활성 사용자·배정과 담당 지역 없음이 `FORBIDDEN`으로 거부되는지 검증한다.
- 기존 생성·수정·검토 요청의 콘텐츠 소유 검증 회귀 테스트가 유지되는지 확인한다.

## 대체 조건

- 운영자별 미션 작업함 또는 같은 지역 운영자 사이의 공개 전 정보 분리가 제품 요구사항으로 확정된다.
- 미션 작성 운영자를 직접 저장하는 모델과 기존 데이터 귀속 정책이 확정된다.
- 법률·계약 또는 개인정보 정책이 같은 지역 운영자 사이의 미션 목록 공유를 금지한다.

# ADR-0098: 병렬 CI 테스트 실행 데이터를 통합해 JaCoCo 커버리지를 검증한다

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-14
- 결정일: 2026-08-14
- 관련 요구사항: [P0 명세의 테스트 및 출시 수용 기준](../p0-spec.md#9-테스트-및-출시-수용-기준), [ADR-0092](0092-shard-testcontainers-ci-by-deterministic-class-name.md)
- 관련 단계: 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: [ADR-0039](0039-run-dev-integration-ci-with-github-actions.md)의 커버리지 임계값 미적용 범위

## 맥락

JaCoCo 플러그인과 로컬 `test` task의 리포트 생성 설정은 존재하지만, `dev` CI는 `fastTest`와
두 Testcontainers shard task를 별도 runner에서 병렬 실행한다. 따라서 기존 `test` task에만 연결된
JaCoCo 리포트와 검증은 CI에서 실행되지 않으며, 세 job의 실행 결과를 한 기준으로 평가할 수 없다.

병렬 테스트 실행을 직렬 `test` 재실행으로 되돌리지 않고, 모든 테스트가 합친 결과를 품질 게이트로
검증해야 한다. 사용자는 전체 라인 커버리지 85% 이상과 브랜치 커버리지 70%를 먼저 검토했다.
실제 전수 실행 결과는 라인 14,574/17,055(85.45%), 브랜치 3,277/5,223(62.74%)이므로,
사용자 결정에 따라 브랜치 60%를 기준으로 적용한다.

## 결정 동인과 불변 조건

- `fastTest`, `containerTestShard1`, `containerTestShard2`의 모든 실행 데이터가 통합 결과에 정확히 한 번 포함돼야 한다.
- 커버리지 산출을 위해 테스트를 재실행하거나 ADR-0092의 병렬 분할을 훼손하지 않는다.
- `dev` 대상 PR과 `dev` 푸시에서 통합 라인 커버리지 85% 이상, 브랜치 커버리지 60% 이상을 모두 만족해야 한다.
- 실행 데이터 누락, 리포트 생성 실패, 임계값 미달은 CI 실패로 처리한다.
- 문서 전용 PR에서 기존 테스트 job이 생략되는 정책은 유지한다.

## 결정

각 병렬 테스트 job은 자기 Gradle `Test` task가 만든 JaCoCo `.exec` 파일을 고유 artifact로 보관한다.
테스트 job이 성공하면 후속 `coverage` job은 세 artifact를 내려받아 동일 커밋의 컴파일 결과와 함께
단일 JaCoCo 리포트를 생성한다. JaCoCo 리포트 task에는 세 `.exec` 파일을 동시에 입력으로 전달해
coverage를 합산한다.

`coverage` job은 통합 리포트에만 품질 게이트를 적용한다. 전 프로젝트 `LINE/COVEREDRATIO`는
0.85 이상, `BRANCH/COVEREDRATIO`는 0.60 이상이어야 한다. 개별 shard에는 임계값을 적용하지
않는다. XML·CSV·HTML 통합 리포트는 7일간 artifact로 보관한다.

## 결과와 트레이드오프

### 기대 효과

- 병렬 분할된 모든 테스트를 합친 실제 커버리지를 `dev` 병합 전후에 일관되게 검증한다.
- 커버리지 하락을 테스트 실패와 같은 CI 실패로 발견한다.
- 통합 HTML·XML 리포트로 누락된 클래스와 분기를 확인할 수 있다.

### 수용한 단점과 위험

- 마지막 테스트 job 뒤에 checkout, 컴파일, artifact 다운로드, 리포트·검증을 수행하는 coverage job 시간이 추가된다.
- GitHub Actions artifact 서비스 장애나 `.exec` 파일 누락도 CI 실패 원인이 된다.
- 전역 비율은 새 코드의 테스트 충실도를 완전히 나타내지 않으므로, 도메인·API의 정상·경계·실패 테스트 의무를 대체하지 않는다.

## 전환과 롤백

1. CI 전용 각 `Test` task가 고유 JaCoCo 실행 데이터를 생성하도록 구성한다.
2. 세 실행 데이터를 artifact로 업로드하고, 후속 coverage job에서 내려받는다.
3. 통합 리포트와 라인 85%·브랜치 60% 검증 task를 추가한다.
4. `dev` 대상 PR에서 세 테스트 job, coverage job, 통합 리포트 artifact를 확인한다.

브랜치 60%는 현재 전수 측정값 62.74%보다 낮은 하한이다. 이후 70% 상향이 필요하면 누락 테스트를
보완하고 새 ADR로 기준을 다시 정한다. CI 운영 비용 또는 지연이 수용할 수 없게 되면 coverage job과 관련
Gradle task·artifact를 되돌릴 수 있다. 테스트 분할과 로컬 `test` task의 기존 JaCoCo 리포트는 그대로 유지한다.

## 검증 방법

- 로컬에서 세 CI 전용 테스트 task를 실행해 각 task의 고유 `.exec` 파일이 생성되는지 확인한다.
- 세 실행 데이터를 별도 경로에 모은 뒤 통합 리포트·검증 task를 실행해 라인 85%와 브랜치 60%를 모두 통과하는지 확인한다.
- 한 실행 데이터 파일을 제외한 상태에서는 coverage job 또는 Gradle task가 성공하지 않는지 확인한다.
- `dev` 대상 PR과 `dev` 푸시에서 모든 테스트 job 성공 후 coverage job이 실행되고 XML·CSV·HTML artifact가 7일간 보관되는지 확인한다.
- 문서 전용 PR에서는 기존 정책대로 테스트와 coverage job이 생략되는지 확인한다.

## 대체 조건

- CI coverage job 추가로 최근 10회 중 3회 이상 전체 CI가 15분 제한을 넘는다.
- artifact 다운로드·보관 장애로 최근 10회 중 2회 이상 재실행이 필요하다.
- 전체 비율 대신 변경 코드 기반 커버리지 또는 모듈별 임계값이 릴리스 합격 조건으로 확정된다.

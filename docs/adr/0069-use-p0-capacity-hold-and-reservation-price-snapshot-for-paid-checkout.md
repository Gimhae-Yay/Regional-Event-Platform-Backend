# ADR-0069: P0 홀드와 예약 가격 스냅샷을 재사용하는 유료 결제

- 상태: 제안됨
- 기록 유형: 신규
- 기록일: 2026-08-05
- 결정일: 2026-08-05
- 관련 요구사항: `docs/p1/payment-refund.md`의 `PAY-01`~`PAY-04`, `docs/p0/reservation.md`의 `RSV-01`~`RSV-04`
- 관련 단계: 단계 3. 확장 의사결정
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

유료 결제 중에도 좌석은 선점돼야 하지만, P0 예약을 결제 대기 상태로 확장하면 기존 예약 상태 계약을 바꾼다. 쿠폰·가격은 결제 재시도 중 바뀌면 안 되며, 0원 최종 금액은 외부 결제를 만들 이유가 없다.

## 결정 동인과 불변 조건

- P0 `capacity_hold`의 최대 10분 정원 선점과 단일 소비 규칙을 유지한다.
- 결제 외부 호출 중 DB 잠금을 오래 잡지 않는다.
- 같은 홀드의 재시도는 같은 금액·쿠폰 스냅샷을 사용한다.

## 검토한 선택지

| 순서 | 선택지 | 장점 | 단점·실패 위험 | 되돌림 비용 | 현재 단계 적합성 |
| --- | --- | --- | --- | --- | --- |
| 1 | 추천안: 홀드에 불변 가격 스냅샷을 연결하고 승인 때 예약 생성 | P0 정원 규칙을 재사용하고 결제 대기 예약이 없다. | 홀드 만료와 결제 결과 경합을 처리해야 한다. | 중간 | 높음 |
| 2 | `PENDING_PAYMENT` 예약을 먼저 생성 | 결제와 예약 연결이 즉시 보인다. | P0 예약 상태·취소·QR 계약을 넓게 바꾼다. | 높음 | 낮음 |

## 결정

유료 체크아웃은 활성 `capacity_hold`에 불변 `reservation_price_snapshot`을 한 건 만들고, 최종 금액이 양수일 때만 `payment` 시도를 만든다. 홀드 하나에는 진행 중 결제를 최대 하나만 허용하며, 결제 생성 키는 종결 결과 뒤 24시간 보관한다.

서버 검증 승인 시 같은 트랜잭션에서 홀드를 소비하고 `reservation(CONFIRMED)`을 생성한 뒤 결제를 연결한다. 최종 금액이 0원이면 P0 무료 예약 확정 흐름을 그대로 사용하고 PortOne 결제 행을 만들지 않는다.

## 결과와 트레이드오프

### 기대 효과

- 정원 차감·복구의 검증된 P0 동시성 규칙을 유지한다.
- 결제 실패와 재시도에도 가격·할인 조건이 바뀌지 않는다.

### 수용한 단점과 위험

- 홀드 만료 뒤 늦게 외부 결제가 성공하면 예약을 자동 확정하지 못하고 불일치로 조사해야 한다.
- 한 결제 시도 중에는 다른 결제 수단으로 즉시 전환할 수 없다.

## 전환과 롤백

P0 예약 상태를 추가하지 않는다. P1 결제 기능을 중단할 때는 새 결제 생성을 막고 활성 홀드는 기존 P0 만료 규칙으로 종결한다.

## 검증 방법

- 같은 홀드의 동시 결제 생성이 한 진행 중 결제만 만드는지 확인한다.
- 승인과 홀드 만료 경합에서 예약·정원이 중복 변경되지 않는지 확인한다.
- 0원 가격 스냅샷이 PortOne 호출 없이 P0 예약으로 확정되는지 확인한다.

## 대체 조건

- 장기 결제 대기·가상계좌·예약금 모델이 요구되면 재검토한다.

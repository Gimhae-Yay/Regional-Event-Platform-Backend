# ADR-0012: 회원 탈퇴 후 작성자 연결을 제거하고 후기 원문과 방문 사실 유지

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-07-27
- 결정일: 2026-07-27
- 관련 요구사항: [P0 명세](../p0-spec.md)의 `AC-15`, [인증·프로필](../p0/auth-profile.md)의 `PRV-01`, `PRV-02`, [후기 문서](../p0/review.md)의 `REV-02`
- 관련 단계: 단계 0. 정책·설계 확정, 단계 1. MVP 구현·검증
- 관련 이슈: 없음
- 대체 대상: 없음

## 맥락

기존 P0 정책은 회원 탈퇴 시 후기·방문 데이터의 개인 연결을 제거하고 비식별 집계만 남기도록 했다. 선택지 비교
과정에서 사용자는 집계만 유지하는 추천안 대신 사용자 연결을 제거한 후기 원문과 개별 방문 기록을 유지하는
방향을 선택했다. 구체적인 사업상 선택 이유는 별도로 확인되지 않았다.

이 결정의 셀프 탈퇴 대상은 운영자·지역 관리자 역할과 콘텐츠 소유 관계가 없는 방문자 회원이다. 운영 역할
계정은 ADR-0011의 owner 불변 조건과 ADR-0009의 지역 관리자 초기화 경계를 깨지 않고 즉시 탈퇴시킬 수 없으므로
역할 해제·담당 지역 변경·소유권 이전을 포함한 오프보딩을 P0 범위에서 제외한다.

후기 원문과 방문 사실을 유지하면서 탈퇴 회원을 다시 식별할 수 있는 연결을 남기면 회원정보 파기 정책을 충족할
수 없다. 도메인 데이터뿐 아니라 예약·홀드, 감사와 멱등 기록을 경유한 간접 연결도 함께 제거할 불변 조건이
필요하다.

## 결정 동인과 불변 조건

- 탈퇴한 회원의 자격 증명, 프로필과 직접 사용자 식별자는 파기한다.
- 운영 역할 또는 콘텐츠 소유 관계가 남은 계정의 셀프 탈퇴는 허용하지 않는다.
- 보존된 후기·방문에서 시스템이 관리하는 구조화 식별자와 관계 경로로 탈퇴 회원을 역참조할 수 없어야 한다.
- 재식별 매핑, 가역 암호화 식별자와 사용자별 안정 가명을 남기지 않는다.
- 기존 `PUBLISHED` 후기의 별점·텍스트와 공개 상태는 유지한다.
- 개별 방문의 콘텐츠·회차·체크인 시각은 유지한다.
- 탈퇴 처리 전에 활성 홀드, 미체크인 예약과 미사용 QR을 더 이상 사용할 수 없는 종결 상태로 만든다.
- 활성 홀드는 무효화의 최초 상태 전이에서 정원을 한 번 복구한다.
- 미체크인 예약은 회차 시작 전에 취소한 경우에만 정원을 한 번 복구한다.
- 이미 `DELETED`인 후기는 복구하지 않고 기존 파기 시계를 유지한다.
- 재가입한 사용자는 과거 후기의 작성자 권한을 회복하지 않는다.

## 결정

사용자가 선택한 세 번째 안을 운영 역할이 없는 방문자 회원에게 채택한다. 탈퇴가 완료되면 계정 자격 증명,
프로필, 이름·연락처와 직접 사용자 식별자를 파기한다. 후기와 방문에서는 `user_id`를 포함한 직접 연결뿐 아니라
예약·홀드, 감사와 멱등 기록을
따라 탈퇴 회원으로 역참조할 수 있는 시스템 관리 간접 연결을 비가역적으로 제거한다.

탈퇴를 시작하면 회원 상태를 `ACTIVE → WITHDRAWING`으로 조건부 전환해 새 홀드·예약 확정·QR·후기 명령을 차단한다.
연결 제거에 앞서 `ACTIVE` 홀드는 `INVALIDATED`, 아직 체크인하지 않은 `CONFIRMED` 예약은 `CANCELLED`로
전환하고 미사용 QR은 즉시 무효화한다. 홀드가 성공적으로 무효화되면 차감한 정원을 한 번 복구한다.
예약은 회차 시작 전에 취소한 경우에만 정원을 한 번 복구하고 시작 이후에는 복구하지 않는다.
이미 `CHECKED_IN`인 예약과 방문은 과거 사실로 보존한다.

탈퇴 시작과 예약 확정·체크인·후기 명령이 경합하면 회원 상태와 각 도메인 상태의 조건부 전이를 먼저 커밋한
처리를 기준으로 한다. 도메인 명령이 먼저 성공하면 탈퇴 흐름이 그 결과를 취소하거나 작성자 연결 제거 대상에
포함하고, 탈퇴 시작이 먼저 성공하면 새 도메인 명령을 거부한다.

운영자 승인 신청이 있으면 `PENDING` 신청은 `CANCELLED`로 종결하고 모든 신청 상태에서 신청자 연결과 사업자
개인정보를 제거한다. 승인 트랜잭션은 신청자가 `ACTIVE`인지 함께 검사한다. 승인이 먼저 성공해 운영자 역할이
부여되면 셀프 탈퇴를 거부하고, 탈퇴 시작이 먼저 성공하면 승인 요청을 거부해 두 결과가 동시에 성립하지 않게 한다.

기존 `PUBLISHED` 후기의 별점·텍스트와 공개 상태는 유지하고 작성자는 사용자별 가명이 아닌 공통 표시인
“탈퇴한 사용자”로 노출한다. 개별 방문은 콘텐츠, 회차와 체크인 시각을 유지한다. 지역·콘텐츠·회차별 집계는
탈퇴 전후 같은 값을 유지한다.

멱등 응답 표현과 구조화 로그에 사용자 식별 정보나 역참조 가능한 결과 스냅샷이 있으면 탈퇴 처리에서 함께
제거하거나 비개인 결과 참조로 대체한다. 탈퇴 처리 중에는 추측 불가능한 처리 키와 회원 매핑을 개인정보로
취급해 재시도에 사용하고, 완료 시 해당 키와 회원 매핑을 파기한다. 감사 actor가 필요하면 탈퇴자별 tombstone이
아닌 모든 탈퇴 방문자에게 같은 공통 값 `WITHDRAWN_MEMBER`를 사용한다.

모든 종결과 연결 제거가 성공하면 계정과 처리 중 회원 매핑을 파기하고 사용자별 `WITHDRAWN` 레코드는 남기지 않는다.

탈퇴 처리는 후기 삭제가 아니다. `PUBLISHED` 후기는 `DELETED`로 바뀌지 않으며, 이미 `DELETED`인 후기는
익명화로 복구하거나 삭제 후 30일 파기 시계를 다시 시작하지 않는다. 작성자 관계를 제거한 뒤에는 기존 계정이나
재가입 계정이 해당 후기를 수정·삭제할 수 없다.

보존된 후기 텍스트 자체에 작성자가 입력한 개인정보가 포함될 가능성은 수용한 위험으로 남는다. 이 결정에서
“익명 후기 원문”은 법적 익명성을 단정하지 않고 “작성자 계정 연결이 제거된 후기 원문”을 뜻한다.

## 결과와 트레이드오프

### 기대 효과

- 공개 후기 콘텐츠와 개별 방문 단위 운영·분석 근거를 유지한다.
- 회원 계정과 후기·방문 소유 관계를 분리한다.
- 집계값을 다시 계산하거나 탈퇴 때문에 과거 운영 지표를 줄이지 않는다.

### 수용한 단점과 위험

- 자유 입력 후기 텍스트에 개인정보가 남아 간접 재식별될 수 있다.
- 예약·감사·멱등 기록 전체에서 역참조 경로를 제거하는 작업이 복잡하다.
- 작성자 관계 제거는 비가역적이므로 잘못 처리해도 기존 소유권을 복원하지 않는다.
- 개인 단위 부정 사용 조사와 후기 소유권 분쟁 대응 근거가 줄어든다.

## 전환과 롤백

신규 구현이므로 기존 탈퇴 데이터 이관은 없다. 탈퇴 처리 전에 보존할 콘텐츠·회차·체크인 사실과 제거할 직접·
간접 식별 경로를 명시하고, 한 번의 탈퇴 흐름에서 계정 파기와 관계 제거를 완료한다.

작성자 연결 제거 중 일부 단계가 실패하면 완료 상태로 표시하지 않고 재시도한다. 작업은 멱등하게 구성하며 이미 제거한
작성자 관계를 백업이나 재가입 계정으로 복원하지 않는다. 원문 보존 정책을 폐기 방향으로 바꾸는 것은 가능하지만
파기 후 다시 보존하는 방향으로는 되돌릴 수 없다.

## 검증 방법

- 탈퇴 후 사용자 ID, 이름, 연락처와 인증 자격 증명이 남지 않는지 검증한다.
- 운영 역할 또는 콘텐츠 소유 관계가 남은 계정의 셀프 탈퇴가 거부되는지 검증한다.
- 운영자 승인과 방문자 탈퇴를 동시에 실행해 역할 부여와 계정 파기가 함께 성공하지 않는지 검증한다.
- 탈퇴 시 미종결 신청이 `CANCELLED`가 되고 모든 신청의 신청자 연결·사업자 개인정보가 제거되는지 검증한다.
- 후기→방문→예약→홀드, 감사와 멱등 기록의 구조화 관계를 따라 탈퇴 사용자를 역참조할 수 없는지 검증한다.
- 탈퇴 시 활성 홀드와 미체크인 예약이 종결되고 미사용 QR이 즉시 거부되는지 검증한다.
- 홀드 무효화는 정원을 한 번 복구하고, 예약 취소는 회차 시작 전일 때만 정원을 한 번 복구하는지 검증한다.
- `PUBLISHED` 후기의 별점·텍스트·공개 상태와 개별 방문의 콘텐츠·회차·체크인 시각이 유지되는지 검증한다.
- 공개 작성자 표시가 사용자별 가명이 아닌 공통 “탈퇴한 사용자”인지 확인한다.
- 이미 삭제된 후기가 복구되지 않고 기존 파기 시각을 유지하는지 검증한다.
- 탈퇴 처리를 반복해도 추가 삭제나 집계 변화가 발생하지 않는지 검증한다.
- 재가입 계정이 과거 후기의 수정·삭제 권한을 얻지 못하는지 검증한다.
- 탈퇴 처리 실패·재시도, 관계 제거 건수와 잔여 역참조 검사를 비개인 지표로 관찰하고,
  시스템 관리 직접·간접 역참조가 한 건이라도 남으면 탈퇴 완료로 판정하지 않는다.

## 대체 조건

- 법률·계약 또는 개인정보 검토에서 후기 원문이나 개별 방문 보존이 허용되지 않는다.
- 후기 텍스트를 통한 재식별 사례가 발생하거나 개인정보 탐지·마스킹 요구가 생긴다.
- 개별 방문 보존 없이 집계만으로 운영·분석 요구를 충족할 수 있다.
- 사용자가 탈퇴 후 공개 후기 원문까지 삭제해야 한다는 제품 정책을 채택한다.

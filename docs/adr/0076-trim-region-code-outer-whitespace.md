# ADR-0076: 지역 코드의 앞뒤 공백을 제거하고 내부 공백을 거부

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-07
- 결정일: 2026-08-07
- 관련 요구사항: [전체관리자](../p1/platform-admin.md)의 `P1-FR-09`, `ADM-02`
- 관련 단계: 단계 3. 확장 의사결정
- 관련 이슈: 없음
- 대체 대상: [ADR-0073](0073-normalize-region-code-to-uppercase.md)의 입력 공백 허용 범위

## 맥락

[ADR-0073](0073-normalize-region-code-to-uppercase.md)은 지역 코드 입력의 앞뒤 공백을 제거한 뒤 대문자로 정규화하도록 결정했다. 그러나 같은 ADR의 불변 조건은 공백을 허용하지 않는다고 표현해, `" jeonju "`처럼 앞뒤 공백이 있는 입력을 허용하는지 구현과 테스트가 다르게 해석할 수 있다.

관리자 입력 편의를 위해 선택한 대문자 정규화 방식을 유지하면서, 제거 가능한 외부 공백과 코드 구성에 포함되는 내부 공백을 구분해야 한다.

## 결정 동인과 불변 조건

- 앞뒤 공백만 다른 입력은 같은 정규형으로 수렴해야 한다.
- 앞뒤 공백을 제거한 뒤 남는 내부 공백은 지역 코드로 허용하지 않아야 한다.
- 길이와 ASCII 형식 검증은 앞뒤 공백을 제거한 값을 기준으로 수행해야 한다.
- 저장·응답·유일성 검사는 ADR-0073의 대문자 정규형을 계속 사용해야 한다.

## 결정

지역 생성 API는 `regionCode` 입력의 앞뒤 공백을 먼저 제거한다. 제거한 값이 비어 있거나 50자를 초과하면 `400 INVALID_INPUT`으로 거부한다.

그다음 `^[A-Za-z][A-Za-z0-9]*(?:-[A-Za-z0-9]+)*$`를 검증하므로 내부 공백, 탭과 줄바꿈을 포함해 코드 구성 중간에 남은 모든 공백 문자는 허용하지 않는다. 검증된 ASCII 값을 `Locale.ROOT` 기준 대문자로 변환해 저장·응답·유일성 검사에 사용한다.

따라서 `" jeonju "`는 `JEONJU`로 저장하고, `"JEON JU"`, `"JEON\tJU"`는 `400 INVALID_INPUT`으로 거부한다. 이 결정은 ADR-0073의 입력 공백 허용 범위만 대체하며 대문자 정규형, 허용 문자, 이관과 유일성 결정은 유지한다.

## 결과와 트레이드오프

### 기대 효과

- API 문서와 ADR의 공백 처리 결과가 하나로 일치한다.
- 저장된 지역 코드에는 공백이 포함되지 않는다.
- 관리자 입력의 우발적인 앞뒤 공백은 별도 오류 없이 정규화된다.

### 수용한 단점과 위험

- 클라이언트가 전송한 원래 앞뒤 공백은 보존하지 않는다.
- 서버와 클라이언트가 입력 원문을 그대로 비교하면 정규화된 응답과 다를 수 있다.

## 전환과 롤백

ADR-0073의 기존 데이터 정규형 검사와 이관 절차를 그대로 사용하므로 추가 데이터 이관은 없다. API 명세와 테스트에서 검증 순서를 앞뒤 공백 제거, 길이·형식 검증, 대문자 변환 순으로 고정한다.

모든 공백 입력을 거부하는 방식으로 바꾸려면 후속 ADR에서 기존 클라이언트 입력과 오류 응답의 호환 영향을 검토한다.

## 검증 방법

- 앞뒤 공백이 없는 대문자·소문자·혼합 대소문자 입력이 같은 대문자 정규형으로 저장되는지 확인한다.
- 앞뒤 공백이 있는 입력이 공백 제거 뒤 같은 정규형으로 저장되는지 확인한다.
- 내부 스페이스·탭·줄바꿈, 공백 제거 뒤 빈 값과 50자 초과 값이 `400 INVALID_INPUT`인지 확인한다.
- 정규화된 값으로 순차·동시 유일성 충돌을 판정하는지 확인한다.

## 대체 조건

- 외부 행정구역 코드 표준이 공백을 정식 구성 문자로 사용한다.
- 관리자 입력이 사라지고 신뢰된 시스템 간 원문 코드만 수신해 앞뒤 공백 자동 제거가 불필요해진다.

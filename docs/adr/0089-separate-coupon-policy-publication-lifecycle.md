# ADR-0089: 쿠폰 정책 공개 수명주기를 지역 관리자 심사에서 분리

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-08
- 결정일: 2026-08-08
- 관련 요구사항: [쿠폰 `CPN-01`](../p1/coupon.md#3-쿠폰-정책), [지역 미션 `MSN-01`](../p1/regional-mission.md#3-지역-미션-정책), [P1-FR-03·P1-FR-05](../p1-spec.md#6-기능-요구사항과-소유-문서)
- 관련 단계: 단계 0. 정책·설계 확정
- 관련 이슈: 없음
- 대체 대상: [ADR-0066](0066-require-regional-admin-approval-for-p1-benefit-publication.md)의 쿠폰 정책 공개 승인과 수명주기 범위

## 맥락

ADR-0066과 [P1 정책 결정 로그 43번](../p1-policy-decision-log.md#4-쿠폰)은 스탬프북·미션·쿠폰 정책이 모두 지역
관리자 승인 뒤 공개되도록 결정했다. 이후 쿠폰 정책의 적용 범위가
지역 전체가 아니라 콘텐츠 하나로 좁혀지고, 현재 제품·API·ERD 계약은 콘텐츠 소유 운영자가 쿠폰 정책을 직접
`DRAFT → PUBLISHED → ENDED`로 전이하도록 구체화됐다. 반면 지역 미션 정책에는 미션 작성·수정·검토 요청 때
존재하지 않는 쿠폰 정책 상태인 `PENDING_REVIEW`도 연결할 수 있다고 남아 있어 API·ERD 계약과 충돌한다.

이 충돌을 해소하려면 현재 쿠폰 공개 계약을 유지하거나 쿠폰 정책에 지역 관리자 심사 상태와 API를 다시 도입해야 한다.
선택에 따라 쿠폰 API 범위와 미션이 참조할 수 있는 보상 정책 상태가 함께 달라진다.

## 결정 동인과 불변 조건

- 미션 보상 정책은 미션과 같은 지역이며 `issuance_type = MISSION_REWARD`여야 한다.
- 공개 미션은 실제 발급 가능한 `PUBLISHED` 쿠폰 정책만 참조해야 한다.
- `ENDED` 쿠폰 정책을 새 미션에 연결하거나 미션 검토 대상으로 제출할 수 없다.
- 쿠폰 정책의 상태와 공개 API는 제품·API·ERD에서 같은 수명주기를 사용해야 한다.
- P1에 확정되지 않은 지역 관리자용 쿠폰 심사 API를 정합화만을 위해 새로 추가하지 않는다.

## 결정

쿠폰 정책은 콘텐츠 소유 운영자가 직접 공개하며 `DRAFT → PUBLISHED → ENDED` 수명주기를 사용한다. 이 결정은
ADR-0066 중 쿠폰 정책에 지역 관리자 승인과 `PENDING_REVIEW`를 적용한 범위만 대체한다. 스탬프북과 미션의
`DRAFT → PENDING_REVIEW → PUBLISHED → ENDED` 수명주기와 지역 관리자 공개 승인은 유지한다.

미션 생성·수정·검토 요청은 같은 지역의 `MISSION_REWARD` 쿠폰 정책 중 `DRAFT` 또는 `PUBLISHED`만 연결할 수 있다.
`ENDED` 정책은 거부한다. 미션 승인 시에는 잠근 보상 정책이 여전히 `PUBLISHED`인지 재검증하며, `DRAFT` 정책을
참조한 미션은 해당 정책이 공개되기 전까지 승인할 수 없다.

쿠폰 정책용 `PENDING_REVIEW` 상태와 지역 관리자 심사 요청·승인·반려 API는 추가하지 않는다.

## 결과와 트레이드오프

### 기대 효과

- 미션 정책, 쿠폰 정책, API와 ERD가 실제로 존재하는 쿠폰 상태만 사용한다.
- 현재 확정된 쿠폰 API 범위를 유지해 불필요한 심사 API와 상태 전이를 추가하지 않는다.
- 미션 작성과 쿠폰 정책 준비는 병행하되 미션 공개 시점의 발급 가능성은 `PUBLISHED` 재검증으로 보장한다.

### 수용한 단점과 위험

- 쿠폰 정책 공개 전에 지역 관리자의 별도 혜택 검토가 없다.
- 콘텐츠 소유 운영자가 잘못된 할인·발급 조건을 공개할 위험을 API 검증, 소유권 확인과 감사 이력으로 통제해야 한다.
- 미션이 `DRAFT` 쿠폰 정책을 참조한 채 검토 대기 상태가 될 수 있으므로 승인자는 정책 공개 여부를 다시 확인해야 한다.

## 전환과 롤백

P1 쿠폰·미션 기능은 아직 구현되지 않아 데이터 이관이나 호환 계층이 필요하지 않다. 지역 미션 정책에서
`PENDING_REVIEW` 쿠폰 정책 참조를 제거하고, 쿠폰 정책·미션 API·ERD가 모두 `DRAFT`·`PUBLISHED` 연결과 승인 시
`PUBLISHED` 재검증을 사용하도록 맞춘다.

적용 중 문제가 발견되면 구현을 시작하지 않고 문서 변경을 되돌릴 수 있다. 운영 데이터가 생성된 뒤 지역 관리자 심사를
도입하려면 새 ADR로 이 결정을 대체하고 상태 마이그레이션, 심사 API, 기존 `DRAFT`·`PUBLISHED` 정책의 전환 계획을
함께 확정한다.

## 검증 방법

- 쿠폰 정책 문서·API·ERD에 `PENDING_REVIEW` 상태나 지역 관리자 심사 API가 없는지 확인한다.
- 미션 생성·수정·검토 요청이 `DRAFT`·`PUBLISHED` 쿠폰 정책만 허용하고 `ENDED` 정책을 거부하는지 확인한다.
- `DRAFT` 보상 정책을 참조한 미션의 승인이 거부되고, 잠근 정책이 `PUBLISHED`일 때만 미션이 공개되는지 확인한다.
- 다른 지역 또는 `MISSION_REWARD`가 아닌 정책 연결이 계속 거부되는지 확인한다.
- 쿠폰 정책 공개·종료에 콘텐츠 소유 운영자 권한과 성공·실패 감사 계약이 적용되는지 확인한다.

## 대체 조건

- 쿠폰 오발급·과도한 할인 등 운영 사고로 지역 관리자 사전 심사가 필요하다는 증거가 축적되거나, 지역 단위 혜택
  거버넌스가 제품 요구사항으로 채택되면 재검토한다.

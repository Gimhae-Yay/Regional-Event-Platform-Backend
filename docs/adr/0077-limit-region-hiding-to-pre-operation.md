# ADR-0077: 지역 비공개 전환을 콘텐츠 운영 전 노출 취소로 제한

- 상태: 채택됨
- 기록 유형: 신규
- 기록일: 2026-08-07
- 결정일: 2026-08-07
- 관련 요구사항: [전체관리자](../p1/platform-admin.md)의 `P1-FR-09`, `ADM-02`
- 관련 단계: 단계 3. 확장 의사결정
- 관련 이슈: 없음
- 대체 대상: [ADR-0072](0072-use-allowlisted-reason-codes-for-region-changes.md)의 비공개 전환 `REGION_OPERATION_ENDED` 허용 범위

## 맥락

[ADR-0065](0065-use-is-public-for-region-availability-and-history-roles.md)는 비삭제 콘텐츠가 하나라도 있는 공개 지역을
비공개로 전환하지 않도록 정했다. P0 콘텐츠 계약은 `PUBLISHED`, `SUSPENDED`, `WITHDRAWN`, `ENDED` 콘텐츠를
소프트 삭제하지 않고 이력으로 보존한다. 따라서 콘텐츠를 한 번이라도 공개한 지역은 비삭제 콘텐츠가 계속 남아
P1의 `true → false` 전이 조건을 충족할 수 없다.

그러나 ADR-0072는 비공개 전환 사유로 `REGION_OPERATION_ENDED`를 허용했다. 현재 데이터 수명주기에서 실행할 수
없는 운영 종료 사유를 공개 계약에 두면 클라이언트가 가능한 전이로 오해하고, 재시도해도 성공할 수 없는 요청을
반복하게 된다.

## 결정 동인과 불변 조건

- ADR-0065의 비삭제 콘텐츠 보호 조건을 유지해야 한다.
- P0의 공개 이후 콘텐츠 이력을 삭제하거나 우회해서는 안 된다.
- API의 허용 사유는 실제로 수행 가능한 상태 전이만 표현해야 한다.
- 지역 전체 운영 종료·일시 중단 정책은 예약·혜택·알림과 함께 별도로 결정해야 한다.

## 결정

ADR-0065의 `region.is_public = true → false` 조건을 유지한다. 비공개 전환은
`content.region_id = regionId AND content.deleted_at IS NULL`인 콘텐츠가 하나도 없는 지역에서만 허용하며,
P1에서는 콘텐츠 운영 전 공개 노출을 취소하는 용도로 한정한다.

비공개 전환의 허용 `reasonCode`는 `REGION_PREPARATION`, `ADMINISTRATIVE_REORGANIZATION`만 사용한다.
`REGION_OPERATION_ENDED`는 허용 목록에서 제거하며 요청되면 도메인 변경과 감사 이벤트 생성 전에
`400 INVALID_INPUT`으로 거부한다.

P0 계약에 따라 공개 이후 콘텐츠는 삭제하지 않으므로 `PUBLISHED`, `SUSPENDED`, `WITHDRAWN`, `ENDED` 이력이
있는 지역의 운영 종료·비공개 기능은 P1에서 제공하지 않는다. 지역 전체 운영 종료나 일시 중단이 필요하면
`is_public`만 변경하지 않고 예약·혜택·알림·콘텐츠 노출에 대한 상위 정책을 먼저 확정한다.

## 결과와 트레이드오프

### 기대 효과

- 허용 사유와 실제 상태 전이 가능 범위가 일치한다.
- 공개 이후 콘텐츠 이력 보존과 지역 공개 정책이 충돌하지 않는다.
- 성공할 수 없는 `REGION_OPERATION_ENDED` 재시도를 차단한다.

### 수용한 단점과 위험

- 콘텐츠를 한 번이라도 공개한 지역은 P1에서 비공개로 전환할 수 없다.
- 행정구역 개편도 비삭제 콘텐츠가 있으면 별도 이관·종료 정책 없이는 비공개 전환할 수 없다.
- 운영 종료 요구가 생기면 여러 도메인을 포함한 후속 결정이 필요하다.

## 전환과 롤백

P1 지역 공개 여부 변경 API가 아직 구현 전이므로 데이터 이관과 호환 계층은 필요 없다. API 명세, 허용 코드 검증,
P1 정책과 테스트에서 `REGION_OPERATION_ENDED`를 함께 제거한 뒤 구현한다. 이미 작성된 클라이언트 초안이 있다면
해당 코드를 보내지 않도록 같은 변경에서 수정한다.

이 결정을 되돌릴 때는 `REGION_OPERATION_ENDED`만 다시 추가하지 않는다. 후속 ADR에서 지역 운영 종료가 콘텐츠,
예약, 혜택과 알림에 미치는 영향, 기존 데이터 전환과 롤백 절차를 확정한 뒤 새 계약으로 전환한다.

## 검증 방법

- `REGION_PREPARATION`, `ADMINISTRATIVE_REORGANIZATION`은 비삭제 콘텐츠가 없는 `true → false` 요청에서 허용되는지 확인한다.
- `REGION_OPERATION_ENDED`가 `400 INVALID_INPUT`이고 지역과 감사 이벤트를 변경하지 않는지 확인한다.
- 비삭제 콘텐츠가 있는 `true → false` 요청은 `409 REGION_AVAILABILITY_CONFLICT`인지 확인한다.
- 공개 이후 상태의 콘텐츠가 있는 지역은 콘텐츠 삭제 API로 전이 조건을 우회할 수 없는지 확인한다.
- API 문서와 클라이언트 허용 목록에 제거된 코드가 남아 있지 않은지 검사한다.

## 대체 조건

- 운영 이력이 있는 지역의 종료·일시 중단이 제품 요구사항으로 확정된다.
- 지역 비공개가 예약·혜택·알림·콘텐츠 노출보다 우선한다는 상위 정책이 채택된다.
- 행정구역 통폐합을 위해 기존 지역의 콘텐츠와 거래 이력을 다른 지역으로 이관해야 한다.

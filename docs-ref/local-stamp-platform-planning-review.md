# 로컬스탬프 기획 검토 및 보완 제안

> 검토 대상: [상세 기획서 (제안서)](local-stamp-platform-proposal.md), [페르소나](local-engagement-stamp-reward-platform-personas.md)

## 1. 검토 요약

현재 기획의 중심 흐름인 **지역 콘텐츠 탐색 → 행사·체험 예약·결제 → 현장 방문 인증 → 인증 후기**는 명확합니다. 특히 온라인 관심이 실제 방문으로 이어졌는지를 검증한다는 차별점도 잘 정의되어 있습니다.

다만 MVP 착수 전에는 아래 다섯 가지를 확정해야 합니다.

1. **리워드 출시 순서**: 쿠폰은 MVP에 포함하고, 스탬프·미션은 쿠폰의 재방문 효과를 검증한 뒤 도입합니다.
2. **파일럿 범위**: 행사·체험·가게·관광지를 한 번에 운영하면 콘텐츠 형식, QR 방식, 운영 절차가 세 갈래로 늘어납니다.
3. **예약 거래의 정합성**: 정원 차감, 결제 성공 콜백, 예약 확정, 취소·환불의 상태와 동시 요청 처리가 아직 정의되지 않았습니다.
4. **현장 QR의 신뢰성**: 정적 현장 QR만으로는 QR 사진 공유나 대리 인증을 충분히 막기 어렵습니다.
5. **최소 운영 도구**: 관리자 화면을 제외하더라도 콘텐츠 승인, QR 예외 처리, 예약자 조회를 실제로 수행할 최소 수단은 필요합니다.

### 권장 MVP 정의

첫 파일럿은 **“유료 또는 무료 예약형 행사·체험의 실제 참여율을 검증하는 지역 방문 플랫폼”**으로 좁히는 것을 권장합니다.

- 고객: 주말 나들이 방문자
- 공급자: 체험·행사 운영자(공방 포함)
- 검증할 가설: 예약·결제한 사용자가 QR 체크인을 완료하고, 인증 후기와 다음 예약용 쿠폰을 사용하는가
- 보조 콘텐츠: 가게·관광지는 탐색용으로만 먼저 노출하거나, 예약형 흐름이 안정된 다음 현장 QR 인증을 추가
- 출시 후 확장: 쿠폰 사용 데이터를 근거로 스탬프 → 지역 미션 순서로 도입

이렇게 하면 결제·정원·체크인이라는 거래의 핵심을 깊이 검증하면서도, 일반 매장의 상시 QR 운영까지 동시에 품질 보장해야 하는 부담을 줄일 수 있습니다.

## 2. 두 기획 문서 간 정합성 보완

| 주제 | 현재 서술 | 보완 제안 |
| --- | --- | --- |
| 스탬프·쿠폰 | 쿠폰은 MVP에 포함하고, 스탬프·미션은 이후 단계로 분리 | **QR 체크인 후 다음 예약용 쿠폰을 발급**하는 흐름으로 통일합니다. 스탬프·미션은 쿠폰의 발급·사용률을 검증한 뒤 확장합니다. |
| 우선 타깃 | 상세 기획서는 방문자·운영자·관리자 전반, 페르소나는 주말 방문자와 소상공인에 집중 | 첫 파일럿의 핵심 타깃을 **주말 나들이 방문자 + 예약형 체험·행사 운영자**로 명시합니다. 주민, 지역 관리자, 일반 가게 운영자는 보조 또는 다음 단계 타깃으로 둡니다. |
| 콘텐츠 범위 | 행사·가게·관광지를 모두 등록·승인·인증 대상으로 정의 | 초기에는 예약형 행사·체험을 인증까지 완결합니다. 가게·관광지는 콘텐츠 조회만 제공하거나, 운영자 확인 방식이 검증된 뒤 인증 대상으로 확대합니다. |
| 운영자 기대 | 페르소나는 예약자 명단, 취소·환불, 통계, 후기 관리까지 기대 | MVP에서는 **회차 등록, 예약자 조회, QR 체크인, 예외 기록**까지만 약속합니다. 자동 환불, 성과 대시보드, 후기 답글은 후속 단계로 분리합니다. |
| 관리자 기능 | 역할은 있으나 별도 관리 화면은 MVP 제외 | “관리 화면 없음”은 실제 운영 불가로 이어질 수 있습니다. 콘텐츠 승인·반려와 QR 예외 조회를 할 수 있는 **내부용 최소 화면 또는 보호된 운영 API**는 MVP 범위에 포함합니다. |
| 가치 제안 | 페르소나는 추천 코스·혜택을 기대, 상세 기획서는 탐색과 신뢰 검증에 집중 | 첫 출시 메시지를 “혜택 플랫폼”보다 **신뢰할 수 있는 지역 체험 예약과 실제 참여 인증**으로 통일합니다. 추천 코스와 혜택은 방문 데이터가 축적된 뒤의 재방문 장치로 설명합니다. |

## 3. 우선순위별 보완 사항

### P0 — 구현 전에 정책과 모델을 확정할 항목

| 항목 | 왜 필요한가 | 결정·정의할 내용 |
| --- | --- | --- |
| 파일럿 운영 범위 | 세 콘텐츠 유형과 두 인증 방식은 운영 복잡도를 크게 높임 | 첫 지역, 첫 콘텐츠 유형(권장: 행사·체험), 참여 운영자 수, 최소 회차·정원, 출시 기간을 정합니다. |
| 예약·결제 상태 전이 | 결제 중복, 정원 초과, 결제 성공 후 예약 누락을 막아야 함 | `예약대기 → 결제진행 → 예약확정 → 체크인완료`, 그리고 `결제실패·취소·환불·노쇼·만료` 상태와 각 전이 주체를 정의합니다. 결제 요청·웹훅은 멱등 처리합니다. |
| 정원 및 동시성 제어 | 같은 회차에 여러 사용자가 동시에 결제하면 초과 예약될 수 있음 | 정원 확인 시점, 결제 중 임시 홀드 시간, 홀드 만료 방식, 락 전략, 초과 시 응답을 정의하고 동시 요청 테스트로 검증합니다. |
| QR 인증 정책 | 방문 인증은 서비스 신뢰의 근거이므로 사진 공유·중복 인증·오스캔을 줄여야 함 | 예약형은 **운영자가 사용자별 일회성 예약 QR을 스캔**하는 방식으로 시작합니다. QR에는 만료 시각·예약 ID·서명을 포함하고, 체크인 API는 멱등 처리합니다. 비예약형 현장 QR은 회전형 코드 또는 운영자 확인 절차를 도입한 뒤 확장합니다. |
| 취소·환불·노쇼 | “단순 처리”만으로는 고객과 운영자가 같은 기준으로 행동할 수 없음 | 취소 마감, 환불 비율, 부분 취소 가능 여부, 운영자 취소, 결제 취소 실패 시 수동 처리 책임자, 노쇼 기준을 1페이지 정책으로 확정합니다. |
| 권한·운영자 검증 | 운영자가 다른 지역·다른 콘텐츠의 예약자 정보를 보면 안 됨 | 운영자 계정 승인 방식, `운영자-콘텐츠-지역` 소유 관계, 예약자 연락처 마스킹 범위, 지역 관리자 권한 범위를 정의합니다. |
| 개인정보·약관 | 연락처, 결제, 방문 이력, 후기는 개인정보 및 민감한 운영 데이터가 될 수 있음 | 수집 목적·보관 기간·삭제/탈퇴 처리·동의 문구·후기 공개 범위·예약자 정보 열람 권한을 정의합니다. |

### P1 — 첫 파일럿 품질과 검증력을 높일 항목

| 항목 | 보완 방향 | 완료 기준 예시 |
| --- | --- | --- |
| 콘텐츠 표준화 | 유형별 필수 필드를 분리합니다. 행사·체험에는 회차·정원·가격·연령/준비물·취소 기준, 장소에는 주소·운영 시간·연락처·인증 방식을 둡니다. | 필수 정보가 누락되면 승인 요청을 완료할 수 없고, 공개 전 체크리스트를 통과합니다. |
| 후기 정책 | 방문 1건당 후기 1건인지, 수정·삭제 가능 기간, 별점 계산, 신고·숨김 기준을 정합니다. | 체크인되지 않은 사용자는 작성할 수 없고, 중복 후기는 정책대로 차단 또는 수정됩니다. |
| 알림 | 예약 확정, 행사 전 리마인드, 취소/변경, QR 체크인 성공만 우선 제공합니다. | 예약 확정과 변경 시 고객·운영자에게 같은 기준의 메시지가 전달됩니다. |
| 지표 설계 | 단순 카운트뿐 아니라 지표의 분모, 기간, 지역·콘텐츠·회차별 구분을 정의합니다. | 이벤트 명세와 대시보드/조회 쿼리로 `상세조회→예약`, `예약확정→체크인`, `체크인→후기` 전환율을 재현합니다. |
| 성공 기준 | 측정만 하면 의사결정을 내리기 어렵습니다. | 예: 파일럿 종료 시 예약 대비 체크인율, QR 실패율, 운영자 처리 시간의 목표·중단 기준을 사전에 합의합니다. |
| 초기 공급 확보 | 플랫폼은 수요보다도 운영 가능한 콘텐츠 확보가 선행 조건입니다. | 파트너 온보딩 체크리스트, QR 설치 책임, 운영자 교육, 행사 취소 시 공지 담당을 정합니다. |
| 장애·예외 흐름 | 네트워크 오류, 사용자 휴대전화 분실, 중복 스캔, 결제 웹훅 지연을 기본 시나리오로 다룹니다. | 운영자가 예약 번호로 보조 조회하고, 사유·처리자·시각을 남길 수 있습니다. |

### P2 — 검증 후 도입할 확장 항목

- **스탬프북**: 쿠폰 사용 데이터와 체크인 데이터가 안정적으로 쌓인 뒤, 콘텐츠별 방문 횟수 또는 테마 완주를 스탬프로 전환합니다.
- **고도화된 쿠폰·혜택 지갑**: 매장 현장 할인, 복수 혜택 조합, 판매자 정산은 기본 쿠폰 흐름이 안정된 뒤 도입합니다.
- **지역 미션·추천 코스**: 최소한의 지역 콘텐츠 밀도와 이용 데이터를 확보한 뒤 도입합니다.
- **일반 가게·관광지의 현장 인증**: 정적 QR 사진 공유 위험을 줄이는 회전 QR·운영자 확인·부정 인증 모니터링 정책이 준비된 뒤 확대합니다.
- **지역 관리자 성과 리포트**: 지표 정의와 데이터 품질이 안정된 뒤 제공합니다.

## 4. 권장 핵심 흐름과 수용 기준

### 예약형 행사·체험의 권장 흐름

1. 사용자가 회차와 인원을 선택하고, 남은 정원을 조회한다.
2. 시스템이 짧은 시간의 정원 홀드를 생성한 뒤 결제를 시작한다.
3. 결제 성공 웹훅을 확인하면 예약을 확정하고 사용자별 일회성 QR을 발급한다. 실패·시간 초과 시 홀드를 해제한다.
4. 현장에서 해당 행사 운영자가 QR을 스캔한다. 시스템은 QR 만료, 회차 일치, 이미 체크인했는지를 확인한다.
5. 성공 시 방문 기록을 생성하고, 해당 방문 기록에만 후기 작성 권한을 연결한다.

이 흐름에서 특히 다음을 테스트 케이스로 고정하는 것이 좋습니다.

- 마지막 1자리를 두 사용자가 동시에 결제할 때 한 명만 예약 확정된다.
- 같은 결제 성공 알림이 여러 번 도착해도 예약과 결제가 중복 생성되지 않는다.
- 이미 체크인한 QR을 다시 스캔하면 이전 결과를 반환하고 방문 기록은 하나만 유지한다.
- 취소·환불된 예약 또는 다른 회차 QR은 체크인할 수 없다.
- 운영자는 자신이 담당한 콘텐츠의 예약자만 조회·체크인할 수 있다.

## 5. 지표를 ‘의사결정 가능한 지표’로 바꾸는 제안

현재 성과 지표 방향은 좋지만, 아래처럼 정의를 고정하면 지역·회차별 비교와 다음 단계 판단이 쉬워집니다.

| 목표 | 권장 지표 정의 | 해석 시 유의점 |
| --- | --- | --- |
| 탐색 품질 | 콘텐츠 상세 진입 사용자 수 / 지역 홈 방문 사용자 수 | 콘텐츠 수가 적으면 전환율이 높아도 선택지가 부족할 수 있으므로 공개 콘텐츠 수도 함께 봅니다. |
| 예약 전환 | 예약 확정 사용자 수 / 예약 가능한 콘텐츠 상세 방문 사용자 수 | 결제 실패와 재고/정원 마감을 별도로 분리합니다. |
| 실제 참여 | 체크인 완료 예약 수 / 예약 확정 수 | 행사 취소, 사용자 취소, 노쇼를 분리해야 원인을 판단할 수 있습니다. |
| 인증 신뢰성 | QR 인증 실패 건수 / QR 인증 시도 건수 | 사용자 취소나 잘못된 회차를 단순 장애로 합산하지 않습니다. 실패 사유를 분류합니다. |
| 후기 품질 | 후기 작성 방문 수 / 체크인 완료 방문 수 | 혜택 도입 전후를 같은 기준으로 비교해 리워드 효과를 검증합니다. |
| 운영 효율 | 콘텐츠 승인 요청부터 처리까지의 중앙값·P95, QR 예외 처리 시간 | 평균만 보면 일부 장기 미처리가 가려질 수 있습니다. |

파일럿 시작 전에 각 지표의 목표치와 “유지·개선·중단” 판단 기준을 합의해야 합니다. 목표치는 초기에는 절대적인 시장 기준보다 팀의 파트너 수, 회차 수, 운영 인력에 맞춘 내부 가설로 설정하면 됩니다.

## 6. 참고 문서에서 현재 기획에 활용할 수 있는 항목

| 참고 항목 | 현재 기획에 적용하는 방법 | 권장 시점 | 기대 효과 / 유의점 |
| --- | --- | --- | --- |
| 동시성 제어 | 행사 회차의 잔여 정원 차감과 결제 중 임시 홀드에 적용합니다. 비관/낙관 락 등 선택 근거와 동시 요청 시험 결과를 남깁니다. | **MVP 필수** | 초과 예약을 방지하는 거래 핵심입니다. 단순히 재고를 조회한 뒤 감소시키는 방식은 피합니다. |
| 결제 정합성·상태 관리 | 결제 시도 ID, 결제사 콜백, 예약 상태, 환불 상태를 분리하고 각 요청을 멱등 처리합니다. | **MVP 필수** | 결제 성공인데 예약이 없는 상황과 중복 결제를 줄입니다. |
| 테스트·CI | 예약 확정, 정원 초과, 중복 QR, 권한, 결제 웹훅, 취소 정책을 단위·통합 테스트로 만들고 자동 실행합니다. | **MVP 필수** | 데모용 정상 경로뿐 아니라 거래 예외를 재현 가능하게 만듭니다. |
| 인증·인가 | 방문자/운영자/지역 관리자 권한을 토큰과 소유 관계로 검증하고, 지역 경계를 서버에서 강제합니다. | **MVP 필수** | 예약자 개인정보 및 지역별 운영 권한을 보호합니다. |
| 타입 안전 조회·페이징 | 지역, 콘텐츠 유형, 공개 상태, 예약 가능 여부, 기간으로 콘텐츠를 필터링하고 정렬·페이징합니다. | **MVP 필수** | 지역 홈과 운영자 예약 목록이 커져도 조회 조건을 안전하게 유지합니다. |
| 구조화 로그·모니터링 | `requestId`, 예약/결제/방문 ID, 상태 전이, QR 실패 사유를 구조화해 기록합니다. 오류율, QR 실패율, 결제 웹훅 지연을 관찰합니다. | **MVP 필수** | 현장 문제를 빠르게 추적하고 기획 지표의 신뢰도를 높입니다. 개인정보와 QR 원문은 로그에 남기지 않습니다. |
| 배포·CI/CD·비밀 관리 | 외부 테스트 환경, 빌드→테스트→배포 파이프라인, 결제 키·JWT 키의 안전한 관리를 구성합니다. | **MVP 필수** | 실사용 파일럿을 운영할 기본 조건입니다. |
| 성능 측정·캐싱 | 지역 홈, 공개 콘텐츠 목록, 콘텐츠 상세처럼 읽기 비중이 큰 데이터에 캐시를 검토하고 전후 수치를 기록합니다. | 파일럿 전 또는 부하 징후 후 | 가격·정원·예약 가능 여부는 오래 캐시하면 안 됩니다. 캐시 대상과 만료 정책을 분리합니다. |
| 트래픽 제어 | 로그인, 결제 시작, QR 스캔 API에 사용자/IP 기준 제한과 `429` 응답 정책을 적용합니다. | 파일럿 전 | QR 사진 공유·자동화 요청 및 결제 API 오남용 완화에 도움이 됩니다. 정상 운영자 스캔을 막지 않도록 임계값을 측정해 정합니다. |
| 비동기 이벤트 처리 | 결제 확정 뒤 알림 발송, 분석 이벤트 적재, 후기 작성 알림을 예약 확정 트랜잭션과 분리합니다. Outbox 또는 재시도 가능한 이벤트 방식을 검토합니다. | 예약 흐름 안정화 후 | 알림 실패가 예약 확정을 실패시키지 않게 합니다. 초기에는 과도한 메시지 인프라보다 재시도·중복 방지부터 검증합니다. |
| AI 구조화 출력 | 운영자가 입력한 행사 소개를 바탕으로 요약문·태그·누락 정보 후보를 JSON 형식으로 생성하되, 운영자/관리자의 승인 후에만 반영합니다. | 후속 기능 | 콘텐츠 등록 품질을 높일 수 있습니다. 가격·일정·취소 규정처럼 사실성이 중요한 값은 AI가 확정하지 않게 합니다. |
| Tool Calling 기반 지역 탐색 도우미 | “이번 주말 아이와 갈 수 있는 2명 체험”처럼 자연어 조건을 입력받아 콘텐츠 검색과 실시간 잔여 정원 조회를 조합합니다. | 후속 기능 | 검색 UX를 개선할 수 있으나, 핵심 예약 API와 장애를 분리해야 합니다. |
| RAG 기반 추천 | 인증 후기와 운영자가 검수한 콘텐츠 설명이 충분히 축적된 뒤, 의미 기반 탐색과 근거 출처 표시 추천을 제공합니다. | 데이터 축적 후 | 초기에는 데이터가 부족해 품질을 보장하기 어렵습니다. 추천 근거와 최신 예약 가능 여부를 함께 보여야 합니다. |
| SSE 멀티턴 대화 | 지역 탐색 도우미가 실제 사용자 가치와 재방문을 만든다는 근거가 생긴 뒤 적용합니다. | 장기 검토 | 현재 핵심 흐름에 필수는 아닙니다. 결제·체크인을 먼저 안정화합니다. |
| 실시간 메시징 | 대기열, 행사 운영자-참여자 채팅처럼 명확한 사용 사례가 생길 때만 검토합니다. | 현재는 제외 | 단순 알림은 비동기 알림으로 충분하며, 채팅을 먼저 만들 이유는 낮습니다. |

## 7. 다음 산출물 제안

상세 기획 다음에는 아래 순서로 문서를 만들면 구현 범위와 예외 처리를 팀 전체가 같은 기준으로 볼 수 있습니다.

1. **도메인 용어·상태 전이 문서**: 콘텐츠, 회차, 정원 홀드, 예약, 결제, 체크인, 방문, 후기의 정의와 상태 전이
2. **운영 정책 문서**: 취소·환불·노쇼, QR 예외, 콘텐츠 승인 기준, 후기 숨김 기준, 개인정보 보관
3. **유저 스토리와 수용 기준**: 방문자·운영자·지역 관리자별 정상/실패 흐름
4. **ERD와 권한 모델**: 지역 경계와 `운영자-콘텐츠-회차-예약` 소유 관계를 포함
5. **API 명세**: 결제 웹훅·멱등 키·QR 체크인 응답·오류 코드까지 포함
6. **파일럿 지표/이벤트 명세**: 각 전환율의 분자·분모와 이벤트 속성
7. **기술 선택 및 검증 기록**: 정원 동시성 전략, 캐시 적용 여부, 부하·동시성 테스트 결과, 배포와 모니터링 선택 근거

이 순서라면 기본 쿠폰 흐름을 포함해, 실제 예약이 안정적으로 체크인과 인증 후기·재예약으로 이어지는지를 정확히 검증할 수 있습니다.
